# M2.0 业务竖切① E2E 记录：DLQ 诊断 → 审批 → 重投 → 核验 → 审计

> 日期：2026-09-12 ｜ 场景：DIAG-08 + OPS-01 ｜ 环境：本地 15 服务 + RocketMQ 5.1.4（192.168.0.142:9876）
> 结论：**链路跑通（intent→审批→effect 实测）**；模型自主编排工具取证；变更操作未经审批不执行；全程审计可查。
> ⚠️ **settlement 为已知缺陷（RV08）**：3s 快照窗口漏判"消费失败再入 DLQ"（实测 cart 7→8）；RV10 已改为异步 10 分钟核验器（按 DLQ_ORIGIN_MESSAGE_ID 匹配）。

## 2. Agent 工具编排证据

- 系统提示约束下，模型自主选择工具链：`dlq_topic_list` → `dlq_message_detail`（含 ES 首错关联）；工具注册 27 个（自研 3 + ES MCP 4 + Prometheus MCP 20）。
- 关键字段完整输出：msgId=`AC110001B8B454BEDEF238817228000B`、originMsgId、reconsumeTimes=4、bornTime、body 摘要、审批单号。
- SSE（经网关 JWT 鉴权）：`event:tool`（工具结果）→ `event:delta`（流式文本）→ `event:done`。

## 3. 审计与数据落库

- `ai_audit`：`dlq.topic_list` / `dlq.message_detail` / `approval.created` / `dlq.redeliver.intent` / `effect.start` / `settled` / `approval.once` 完整链（params 脱敏，密钥形态自动打码）。
- `ai_approval`：raw_input + sha256 指纹 + result（effect/settlement JSON）。
- `ai_message`：用户/助手消息按 session 归档（e2e-dlq-001/002/003）。
- `ai_session`：会话创建与更新时间。

## 4. 已知边界（诚实声明）

1. **首错日志关联**受数据限制：ES 日志未携带 RocketMQ msgId，工具已实现 originMsgId→msgId→keys 回退检索并如实返回 `found:false` + 检索口径；后续可在业务日志中补 msgId 字段提升命中率。
2. **settlement 口径（已修）**：原 3s 快照判据被实测证伪（重投消息再入 DLQ）；RV10 改为 `RedeliverVerifier` 异步核验（10 分钟窗口按 `DLQ_ORIGIN_MESSAGE_ID` 匹配，命中=消费失败）；消费位点核验仍为 M2.x。
3. **审批超时 fail-closed / 跨实例 pub-sub**（D02 §10）未实现：当前单实例同步执行；M2.x 补齐。
4. Agent 偶发把过渡语当最终答复（模型行为）：已通过提示词规则 + temperature 0.2 缓解；M4 评测周纳入用例观测。
