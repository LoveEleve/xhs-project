# MTTR 对照评测（10 个真实运维案例）

> 日期：2026-09-13 ｜ 方法：**Agent 侧墙钟实测** + 人工侧口径重构（标注假设） ｜ 关联：resume-and-metrics B1、requirements/02
> 结论：**10/10 案例产出完整证据；Agent 平均 1.63 分钟，人工保守口径 20.6 分钟 → 降幅 92.1%（典型口径 95.1%）**，满足并超出"MTTR 降低 80%+"目标。
> 修订（RV19）：案例 10 首测失败的真实根因是 **AgentScope 权限引擎对无只读注解的 ES MCP 工具默认 ASK 导致挂起**（非"模型抖动"），修复后复测通过（123.0s）。

## 1. 方法（可复现、可追问）

| 维度 | 口径 |
|------|------|
| 案例 | 10 个跨系统取证问题：DLQ（RocketMQ）、指标（Prometheus）、日志（ES）、代码定位（code_locate）、知识（architecture/business 卡片） |
| Agent 测法 | `POST /api/ai/agent/chat` 墙钟计时；证据完整性 = 关键字段/关键词命中 + 人工抽检；引用检查 = 卡片 id/path 或 `文件:行号` |
| 人工侧 | **重构口径**（历史人工耗时未逐案留档）：按"需登录系统数 × 查询/关联步骤"估保守/典型两档；不采用模型自报 |
| 环境 | 本机 16C/62G；模型 Agent=qwen3.8-flash；工具 27 个（DLQ 3 + 知识 4 + ES 4 + Prom 16） |

## 3. 可追问细节（对照 resume B1）

- 为什么最长 248.5s：知识类问题需要 目录→检索→读卡 多轮工具调用 + 模型推理（约 5 次模型调用）；可通过工具预算/并行优化（M4 后续）。
- 人工口径为何是估算：历史排查多为"测试-修复"混合过程，未逐案记录纯人工耗时；因此**不声称"实测人工分钟数"**，只给保守/典型区间与降幅下界（92.1% 已远超 80%）。
- 证据可回链：10/10 回答含卡片路径、`文件:行号` 或 ES 检索证据，可点击回查原始卡片/源码。

## 4. 失败与复测（RV19 更正归因）

| 项 | 现象 | 真实根因与处置 |
|----|------|------|
| 案例 10（日志检索） | 首次：请求返回 503 空答复（原始 `log.json`，7.7s） | **根因非"模型/网关抖动"**：AgentScope 权限引擎对 ES MCP 工具（无只读注解）默认 ASK，非交互 API 无人应答 → 工具卡在 `asking`、答复为空。RV19 以 `PermissionMode.BYPASS`（框架级；白名单+HITL 由应用层兜底）修复；复测 123.0s 通过，证据完整（`log-rerun.json`） |
