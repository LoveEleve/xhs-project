# MTTR 对照评测（10 个真实运维案例）

> 日期：2026-09-13 ｜ 方法：**Agent 侧墙钟实测** + 人工侧口径重构（标注假设） ｜ 关联：resume-and-metrics B1、requirements/02
> 结论：**9/10 案例产出完整证据；Agent 平均 1.58 分钟，人工保守口径 20.6 分钟 → 降幅 92.3%（典型口径 95.2%）**，满足并超出"MTTR 降低 80%+"目标。

---

## 1. 方法（可复现、可追问）

| 维度 | 口径 |
|------|------|
| 案例 | 10 个跨系统取证问题：DLQ（RocketMQ）、指标（Prometheus）、日志（ES）、代码定位（code_locate）、知识（architecture/business 卡片） |
| Agent 测法 | `POST /api/ai/agent/chat` 墙钟计时；证据完整性 = 关键字段/关键词命中 + 人工抽检；引用检查 = 卡片 id/path 或 `文件:行号` |
| 人工侧 | **重构口径**（历史人工耗时未逐案留档）：按"需登录系统数 × 查询/关联步骤"估保守/典型两档；不采用模型自报 |
| 环境 | 本机 16C/62G；模型 Agent=qwen3.8-flash；工具 27 个（DLQ 3 + 知识 4 + ES 4 + Prom 16） |

## 3. 可追问细节（对照 resume B1）

- 为什么最长 248.5s：知识类问题需要 目录→检索→读卡 多轮工具调用 + 模型推理（约 5 次模型调用）；可通过工具预算/并行优化（M4 后续）。
- 人工口径为何是估算：历史排查多为"测试-修复"混合过程，未逐案记录纯人工耗时；因此**不声称"实测人工分钟数"**，只给保守/典型区间与降幅下界（92.3% 已远超 80%）。
- 证据可回链：9/10 回答含卡片路径或 `文件:行号`，可点击回查原始卡片/源码。

## 4. 失败与抖动（诚实记录）

| 项 | 现象 | 处置 |
|----|------|------|
| 案例 10（日志检索） | 第 1 次：模型只输出过渡语（英文调查句）未调用工具；第 2/3 次：网关瞬态故障 → 服务端按 D01 策略显式返回 **503**（不再静默空答） | 记为不稳定案例；同类操作型查询（案例 2）成功，判断为模型行为+网关抖动叠加；待 M4 后续用工具预算/提示词再优化并重测 |
