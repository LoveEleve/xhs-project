# 01 · 产品需求（PRD v0.1）

> 状态：评审中｜日期：2026-09-12｜范围：v1（运行态诊断 + 系统知识问答）

## 1. 目标

把 xhs 的排查与理解成本从"人肉翻 5 个系统"降到"一次对话拿到证据链"：
- **诊断**：输入现象/ID（traceId/orderNo/msgId/服务名），输出带证据（日志/指标/trace/DLQ）的结论与建议
- **知识**：输入自然语言问题，输出带出处的系统知识回答（架构/业务/代码）
- **可控**：变更类操作必须 HITL 审批 + 审计；只读查询默认放行

## 2. 范围

### v1 包含
1. 对话入口（单轮 + SSE 流式）
2. 运行态诊断工具集：健康检查、日志检索、指标查询、trace 查询、DLQ 查询/重投（审批）、XXL-Job 状态
3. 系统知识问答：三层知识（架构/业务/代码）+ 代码检索/导航
4. 多租户会话与记忆（userId/sessionId 隔离；长期记忆）
5. HITL 审批与工具权限
6. 可观测（OTel → Langfuse）与成本/延迟指标
7. 评测：知识问答与诊断的回归用例集

- **v1.5（ADR-23 增补）**：官方 MCP 直接接入（Elastic/Prometheus/Grafana）；数据库改为受控只读查询（三层防护）；工具集按需加载

### v1 不包含（非目标）
- 自动改代码/自动提交/自动发布
- 真实支付渠道、压测执行、混沌演练编排
- 多 Agent 团队（v2 再评估 subagent 编排）
- Temporal 长流程（v2 评估，先用 AgentScope 状态 + HITL）

## 3. 角色

| 角色 | 场景 |
|------|------|
| 研发 | "订单 500 了，帮我定位" / "这个类谁改过、为什么这样设计" |
| 运维 | "DLQ 有哪些消息、帮我重投这条"（走审批） |
| 新人 | "三级扣减是什么、和 TCC 什么关系" |

## 4. 功能需求与验收条件

### FR-1 对话入口
- `/api/ai/chat`（同步）与 `/api/ai/chat/stream`（SSE）
- **AC-1.1** 携带 `userId`（JWT）与 `sessionId` 调用，返回模型回复；无效凭证 401
- **AC-1.2** SSE 按事件流输出（文本增量/工具调用/工具结果/结束），断开可重连并从会话恢复
- **AC-1.3** 同一 `(userId, sessionId)` 跨进程重启后上下文可恢复（状态存储：MySQL/Redis）

### FR-2 运行态诊断
- **AC-2.1** `traceId` 查询：返回「最后命中服务 → 主类/方法 → 最近提交/blame → 方法级源码片段」四联信息（数据源：SkyWalking/ES/代码仓）
- **AC-2.2** 日志检索：按服务/关键字/时间窗返回命中日志（ES），带分页与截断保护
- **AC-2.3** 指标查询：按服务/指标名返回时间序列（Prometheus）
- **AC-2.4** 健康检查：15 服务批量状态（actuator），输出异常清单
- **AC-2.5** DLQ：查询 `%DLQ%<group>` 积压与消息详情；重投为变更操作，必须 HITL 审批后执行并写审计
- **AC-2.6** 每个结论必须返回证据引用（查询语句/来源/时间窗），无证据不得编造结论

### FR-3 系统知识问答
- **AC-3.1** 架构/业务/代码三层知识均可检索，回答带出处（文件/章节/commit）
- **AC-3.2** 代码检索：返回 `topHit + hits`，含类/方法/文件与最近改动
- **AC-3.3** 冷启动评测集 ≥50 条问答用例，回归通过率 ≥90%（全量自动执行）
- **AC-3.4** 回答中引用的文件路径/方法名必须真实存在（可用静态校验拦截幻觉）

### FR-4 会话与记忆
- **AC-4.1** 会话隔离：用户 A 无法读取用户 B 的会话/记忆（负向用例）
- **AC-4.2** 长期记忆写入需经过内容过滤（敏感信息/密钥不入库）
- **AC-4.3** 会话列表/历史查询接口带鉴权与分页

### FR-5 HITL 审批
- **AC-5.1** 工具按风险分级：只读 allow；变更 approve；高危 deny
- **AC-5.2** approve 流程：Agent 暂停 → 审批接口（批准/拒绝）→ 继续/终止，全程事件可见
- **AC-5.3** 每次审批与执行写审计（who/when/what/result），可按 traceId 追溯

### FR-6 可观测与治理
- **AC-6.1** 全链路 trace 上报（OTel → Langfuse），一次对话可按 traceId 查看模型调用、工具调用、耗时与 token
- **AC-6.2** 模型调用具备超时/重试/降级（主模型不可用切备用模型）
- **AC-6.3** 对话接口限流（按用户），超限返回统一错误码

### FR-7 评测
- **AC-7.1** 评测集与运行器入库；`mvn test -Peval`（或独立任务）可一键跑分
- **AC-7.2** 每次变更 PR 必须附评测结果（通过率/耗时/token 成本）

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 流式首字 ≤2s（P95）；只读工具调用单次 ≤3s；对话端到端 P95 ≤15s |
| 可用性 | 模型/工具故障时给出明确降级提示，不挂起 |
| 安全 | 密钥仅存 `.env.local`（gitignored）/环境变量；日志脱敏；只读账号最小权限 |
| 可移植 | 单机 Docker Compose 可起；配置全部外置 |
| 工程质量 | 单测覆盖核心逻辑 ≥80%；静态检查 0 🔴；CI 全绿才可合并 |

## 8. 风险

| 风险 | 缓解 |
|------|------|
| AgentScope 2.0 相对较新 | 先做最小对话 PoC（M1）验证；锁定版本；关键路径封装隔离 |
| 知识资产质量参差 | 入库前治理（来源标注/去重/时效），评测兜底 |
| SkyWalking trace 查询链路复杂 | M2 先支持 ES 日志 + traceId 关联，SkyWalking API 逐步接入 |
| Embedding 与向量检索 | **v1 默认不用**：结构化卡 + BM25/元数据（D12/RV09）；仅当 KB EVAL 基线 <90% 且失败以词汇不匹配为主才启动向量实验，无 ≥5% 提升即止损删除 |
