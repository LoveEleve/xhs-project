## 3. 配置默认值（面试可报的精确数字）
- 预算：日 500,000 tokens、软限 0.8、Redis 用量 TTL 2 天；并发：单用户 2/全局 8；幂等 TTL 600s
- 摘要：保留最近 20 条、批 ≥20（force 2）、输入 ≤12000 字符、单次 ≤5 会话/10min、min-messages 50
- 保留：message 90d/audit 365d/state 空闲 30d→再 7d、cron 4:30
- 审批：超时 10min、补执行延迟 120s/批 20、executing 卡死 600s、核验窗口 10min/poll 30s
- 模型：retry 2/backoff 500ms/breaker 3 次/冷却 60s；chat=deepseek-v4-pro、agent=qwen3.8-flash、降级=deepseek-v4-flash
- 超时：chat 120s、agent 300s、ES/Prom connect 5s/request 15s

## 4. 机制细节（加分项）
- 审计链：`SHA256(prev|traceId|actor|action|target|canonical(params)|result)`，GENESIS 起始、result 截 1024、单事务 `FOR UPDATE` 链头；写失败仅 warn（边界）
- 审批指纹：顶层键排序 SHA-256（不递归）+ 常量时间比较；执行前复核篡改 fail-closed
- 重投核验：offsetMsgId/newMsgId 双匹配 + 队列级 `consumerOffset > queueOffset`
- 幂等：SET NX EX 600 → DONE JSON 回放；Redis 异常 fail-open
- 重建：状态键 `xhs-ai:state:{uid}/{uid}:{sid}:agent_state`；重建 6 条×500 字 + `【历史摘要】` 前缀
- PromQL 除零保护 `clamp_min(...,0.000001)`；工具 schema tokens=JSON 字符/4（实测 3428）
- 工具预算：工具数 >36 WARN、>40 启动失败；schema 软预算 12000

## 6. 暴露的"未接线/小瑕疵"（诚实边界，也可当"下一步"）
1. `ai_message.tool_calls/tokens_in/tokens_out` 恒空（SessionRepository 调用方传 null/0）
2. `capture_mode/content_categories/redaction_count` 与 `ai_feedback` 表无任何代码读写（设计已落库、实现未接线）
3. **跨实例审批事件"只发不收"**：除指标监听器外无业务订阅者（`ApprovalEventBus.java:64-67`）
4. 并发护栏是 JVM 内存态（多实例各放行 8）
5. `ai_agent_tools_total` 用原始 int 注册 gauge（弱引用风险），而同文件 schema gauge 已用 AtomicInteger
6. `/chat` 不计预算、流式端点无幂等
7. DLQ 明细"尾部扫描"（每队列最多回溯 200 条、findByOriginMsgId ≤100）
8. 知识索引 ES URL 默认空 vs EsLogClient 默认 127.0.0.1:19200（默认值不一致）
9. jdtls 未实现（code_locate 文本扫描，8000 文件上限）
