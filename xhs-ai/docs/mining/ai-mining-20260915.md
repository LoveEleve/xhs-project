## 4. 机制细节（加分项）
- 审计链：`SHA256(prev|traceId|actor|action|target|canonical(params)|result)`，GENESIS 起始、result 截 1024、单事务 `FOR UPDATE` 链头；写失败仅 warn（边界）
- 审批指纹：顶层键排序 SHA-256（不递归）+ 常量时间比较；执行前复核篡改 fail-closed
- 重投核验：offsetMsgId/newMsgId 双匹配 + 队列级 `consumerOffset > queueOffset`
- 幂等：SET NX EX 600 → DONE JSON 回放；Redis 异常 fail-open
- 重建：状态键 `xhs-ai:state:{uid}/{uid}:{sid}:agent_state`；重建 6 条×500 字 + `【历史摘要】` 前缀
- PromQL 除零保护 `clamp_min(...,0.000001)`；工具 schema tokens=JSON 字符/4（实测 3428）
- 工具预算：工具数 >36 WARN、>40 启动失败；schema 软预算 12000

# 第三轮：设计决策与论证（面试答辩素材）

## 14. 专项设计关键决策
- **D01 模型网关**：五段流水线 Route→Retry→Circuit→Budget→Call；任务分级路由（主链 pro/轻量 flash/降级只读检索）；计量以网关为准不采信模型自报；连接 2s/首字 10s/总 120s；出流后不重试
- **D02 工具治理**：策略引擎 last-match-wins + 默认 ask + deny 短路；`deny+*` 直接从工具列表隐藏（"不可见>可见但拒绝"）；审批三态 + 关闭/超时 fail-closed；跨副本恢复"登记先行+等待不占线程+pub/sub 续跑"；执行契约"永不向循环抛异常" + 变更三段式
- **D03 观测合规**：双平面（业务含内容→Langfuse 受 capture 控制；OTLP content-free 恒可发）；默认 sanitized = **先脱敏再截断**；遥测 failsafe 不阻塞回合、TraceState 256+LRU
- **D04 代码导航**：双轨 LSP(jdtls)+JGit+文本兜底；行号/路径即引用校验输入；**jdtls 归 v1.1、评测触发才上**
- **D05 MCP 集成**：只桥接 Tools、双白名单、env 清洗、`<server>__<tool>` 前缀；v1.5 仅官方三件；调用 10s/帧 8MiB；禁止全量注册
- **D07 容量成本**：单机约 **10 并发诊断会话**，第一瓶颈 LLM 配额；多副本无粘性扩展；向量迁移阈值 >5 万 chunk 或 knn P95>300ms；成本控制优先级 截断>prompt 缓存>flash>硬限
- **D08/D09 扩展与生态**：永不复刻 in-process full-trust 插件；能力 ⊆ manifest；"安装≠启用"；受控只读 SQL 三层（AST 白名单+READ ONLY 事务 1792+只读账号）
- **D12 检索与知识**：不建默认 RAG 的三条依据（语料 1-2k chunk/精确标识符查询/引用可回链）+ 触发与止损（<90% 且词汇不匹配为主才试验；无 ≥5% 提升即删除向量路径）
- **FMEA 金句**：Redis 挂不做本地内存兜底（多副本状态分叉恢复后不可判定）；F1 降级到"只读检索模式"（模型挂仍可当检索用）；F5 状态只在提交点发布

## 15. 研究报告结论
- R01 数据源：ES 字段级实测（traceId 第一跳）；**RocketMQ Dashboard 因 CSRF 不适合服务端集成 → 用 Admin SDK**；SW GraphQL 未验证→仅增强不强依赖；模型 siyu-all 兼容、pro 含 reasoning_content
- R02 AgentScope：**不自研 Harness**；State 用 Redis(Sentinel)+CAS，MySQL 只放业务表；v1 不启用沙箱（无不可信代码执行）；源码级核验关掉 6 项；坑位（必须传 RuntimeContext/IsolationScope 定死/本地 state+远程 filesystem 会抛错）
- R03 五个头部项目：可借鉴 12 条（窄腰核心/Capability Seam/双轨 hook/注册即 effect+disposer/审批一等公民/Context Epoch/intent→effect→settlement/录播回放…）；明确不采纳 micro-compaction（破坏 prompt cache）

## 16. 评审关键结论
- RV02 8 项 DELTA：审批同构 opencode（CompletableFuture/reject 级联/always 批量唤醒/**dispose 全 pending fail-closed**）；策略合并 deny>ask>allow；"Model-visible⟺logged"、"决策必须在执行点强制"
- RV05：C1 禁 text2sql→受控只读；C2 v1 不接 MCP→v1.5；C4 补 F16-18；R1 工具膨胀 P0（每请求全量 schema→场景 Toolset+tool_search）
- RV09 三问金句："**不引入它损失什么？替代方案是什么？什么数据出现时删除它？答不出就不引入**"
- RV10 P0：LAST_INSERT_ID 无事务并发错配→KeyHolder；状态转移与执行非事务→原子化+重试；"调用成功≠业务成功，核验必须异步+窗口化"
- RV16 8 个 P1：IDOR/熔断半开/出流不重放/MCP 缓存 TTL/重建清空/管理端点收敛/symlink/指标标签

## 17. SLO 与 STRIDE
- SLO：首字 P95≤2s、端到端≤15s；工具只读≤3s/变更≤10s；命中率≥90%、引用 100%、拒答≥95%；并发≥50；会话 100k tokens；审计≥180d；可用性≥99.5%
- STRIDE 六项对策（归属校验/审计+指纹/CAS/默认脱敏/限流+预算/**不可信内容按数据块隔离+决策在执行点强制**）；供应链 catalog+pin+CI 声明=实现
