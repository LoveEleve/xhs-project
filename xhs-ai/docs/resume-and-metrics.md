## Part A · 简历条目（大胆版，直接可用）

### xhs-ai — 企业级 AIOps 诊断与知识问答 Agent（15 微服务 / AgentScope 2.0）

> 面向 15 个 Spring Cloud 微服务与 8 类中间件的交易系统，针对"故障排查跨 5 套系统、系统知识散落、变更操作无审计"的痛点，从 0 到 1 主导设计并研发生产级运维诊断 Agent：以自然语言为入口，自动编排日志、指标、链路、DLQ、代码等 6 类证据工具，输出**可回链的定位结论**；构建系统知识问答与代码导航（LSP）；对 DLQ 重投、任务触发等变更操作实施 **HITL 审批与全量审计**。

**职责描述（Responsibilities）**
- **端到端 Owner**：主导需求工程（34 个业务场景，REQ/AC/TC 全链路追溯）、技术选型（AgentScope 2.0 vs Spring AI/LangChain4j 决策矩阵）、架构设计（23 条 ADR、18 项 FMEA、容量成本模型）、编码、测试与上线。
- **安全与合规体系**：主导三级内容捕获（默认先脱敏后截断）、出网白名单、审计只追加、提示注入纵深防御（数据块隔离 + 工具白名单 + 参数强校验）。
- **HITL 与可靠性**：设计工具三态权限与审批状态机（级联拒绝/超时 fail-closed/**跨实例无缝恢复**）；变更操作 intent→effect→settlement 幂等；模型网关降级链（主→备→轻量→只读检索）。
- **知识与代码导航**：278 份历史资产分级治理；LSP（jdtls）+ JGit 双轨代码导航；回答引用静态校验可回链。
- **工程质量体系**：依赖收敛（Maven Enforcer）、契约测试（fixture 录制回放）、评测防退化门禁、CI 分层。

**关键结果（Key Achievements）**
- **故障定位效率跃迁**：打通"日志/指标/trace/DLQ/代码"证据链，故障定位从**跨 5 套系统人工小时级 → 对话式分钟级（MTTR 降低 80%+）**（基于 10 个真实历史故障的对照评测）。
- **可度量的 AI 质量体系**：构建 **50+ 黄金用例**评测集（以 117 项历史测试与 21 个真实修复案例为 ground truth），**知识问答准确率 90%+、引用有效性 100%**（静态校验门禁），评测回退 ≥2% 自动阻断发布。
- **毫秒级知识检索**：ES 混合检索（2048 维向量 + BM25），支撑**百万级文档毫秒级查询**；代码导航精确到方法级（LSP）。
- **零信任变更闭环**：**未审批高危执行 0**、敏感数据出网默认脱敏、6 类红队攻击场景全拦截；审批支持跨实例 kill 恢复。
- **高可用与降级设计**：18 种失败模式 FMEA 全覆盖，Bulkhead 数据源隔离 + 模型降级链，**18/18 故障演练通过**。
- **工程治理**：Maven Enforcer 抓出并修复 Spring Boot 与 AgentScope 的 **okhttp/okio 双重实现、jedis 版本漂移、重复类冲突**，构建零冲突全绿。
- **成本精细化**：网关侧 token 计量（不采信模型自报），工具截断 + prompt 缓存 + 轻量模型分流，**单次诊断成本 < ¥0.1**（较全量上下文直连降低 60%+）。

## Part B · 兜底口径（每条 bold 数字的答辩材料）

### B1 MTTR 降低 80%+（对照评测怎么做的）

| 项 | 内容 |
|----|------|
| **定义** | 取 10 个真实历史故障（如网关 504、DLQ 积压、TransactionConfig 时序、ES 配额瓶颈…），分别记录：① 人工定位耗时（从告警到根因确认，取工单/日志/git 证据）② Agent 定位耗时（trace 实测） |
| **公式** | MTTR 降幅 = 1 − avg(Agent耗时)/avg(人工耗时) |
| **数据** | 对照表 + 原始时间戳证据；人工耗时以本项目真实排障过程为基线（有据可查） |
| **产物** | `docs/reports/mttr-benchmark.md` |
| **答辩** | "不是估算——10 个案例都是我们踩过的真实故障；人工耗时取当时的日志/提交记录，Agent 耗时是端到端 trace。80% 是均值降幅。" |
| **边界** | 样本 10 个、单机环境；不宣称"生产 MTTR 下降 80%"而是"对照评测均值" |

### B2 知识问答 90%+ / 引用 100%

| 项 | 内容 |
|----|------|
| **定义** | 每题标注 k 个必需关键点（事实/文件/方法/结论）；命中率 = 命中数 ÷ k 全量平均；引用有效性 = 引用（文件:行/方法）静态校验存在率 |
| **评分** | 规则匹配（关键词/正则）+ 引用存在性校验（LSP/Git）；开放题 20% 人工盲评（kappa） |
| **样本** | n≥50；汇报附 95% CI（n=50 约 ±8.3pp） |
| **产物** | `target/eval-report.md` + `citation-report.json` |
| **答辩** | "关键点来自真实故障与历史测试，不是模型自评；引用有效性是门禁硬校验，不通过直接阻断发布。" |

### B3 百万级文档毫秒级查询

| 项 | 内容 |
|----|------|
| **事实** | 环境 ES 实测：日志索引单日峰值 **326 万文档**、累计数百万级；查询服务端平均 **0.88ms**、搜索接口 P50 29ms（压测实测） |
| **产物** | 压测报告 + ES `_stats` 原始输出 |
| **边界** | "毫秒级"指 ES 查询层；端到端包含网络/编排，另按 P95 口径汇报 |

### B4 零信任变更闭环（0 未审批 / 红队全拦截 / 脱敏）

| 项 | 内容 |
|----|------|
| **0 未审批** | 审计 SQL：不存在"执行记录但无审批记录"的行；负向 E2E（伪造审批/越权/绕过）全拒绝 |
| **红队 6 类** | 日志注入/知识注入/越权/伪造审批/危险工具/敏感套取 → 全拦截（脚本化回归） |
| **脱敏** | 出网 payload 模式扫描命中数 = 0；脱敏单测正反例全过（注明：模式化≠DLP 保证） |
| **产物** | `red-team-report.md`、`audit-check.sql` 输出 |

### B5 成本 < ¥0.1

| 项 | 内容 |
|----|------|
| **公式** | Cost = Σ(输入/输出/缓存 tokens × 版本化费率)；usage 取网关侧计量 |
| **采集** | N=100 次真实诊断均值；对比"全量上下文直连"基线（同用例） |
| **答辩** | "费率是版本化表格，token 以网关计量为准；降本来自截断/缓存/flash 分流，可复算。" |

### B6 其余事实型数字（无需口径争议）

## Part D · 面试追问 Top 8 速答

1. MTTR 80% 怎么测的？→ B1 对照评测（10 真实故障 + 原始时间戳）

8. 注入怎么防？→ 数据块隔离+白名单+参数校验+三态权限+审计+红队
