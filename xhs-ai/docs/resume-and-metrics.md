## Part A · 简历条目（对标样例风格）

### xhs-ai — 企业级 AIOps 诊断与知识问答 Agent（15 微服务 / AgentScope 2.0）

> 针对交易系统"故障排查需跨 5 套系统、系统知识散落、变更操作无审计"的痛点，主导设计并研发生产级运维诊断 Agent：以自然语言为入口，自动编排日志、指标、链路、DLQ、代码等 6 类证据工具，输出可回链的定位结论；构建系统知识问答与代码导航能力；对 DLQ 重投、任务触发等变更操作实施 HITL 审批与全量审计。

**职责描述（Responsibilities）**
- 端到端负责平台需求工程（28 个业务场景，REQ/AC/TC 全链路追溯）、技术选型（AgentScope 2.0 与 Spring AI/LangChain4j 对比决策）、架构设计（15 条 ADR、FMEA、容量成本模型）、编码、测试与上线。
- 主导安全与合规体系：三级内容捕获模式（默认先脱敏后截断）、出网白名单、审计只追加、提示注入纵深防御（含红队用例）。
- 主导 HITL 与可靠性：工具三态权限、审批状态机（级联拒绝/超时 fail-closed/跨实例恢复）、变更操作 intent→effect→settlement 幂等；模型网关降级链（主→备→轻量→只读检索）。
- 建设知识工程与代码导航：278 份历史资产分级治理；LSP（jdtls）+ JGit 双轨代码导航；回答引用静态校验可回链。
- 建设工程质量体系：依赖收敛（Maven Enforcer）、契约测试（fixture 录制回放）、评测防退化门禁（回退 ≥2% 阻断）、CI 分层。

**关键结果（Key Achievements）**
- **故障定位闭环**：覆盖 15 个微服务 + 8 类数据源，支持 traceId 全链路定位与"最后命中服务 → 主类/方法 → 最近提交"四联证据；诊断结论强制附证据引用，无证据不得编造。
- **质量可度量**：构建 50+ 用例评测集（以 117 项历史测试与 21 个真实修复案例为 ground truth），**引用有效性静态校验 100%**、拒答正确率与 6 类红队攻击场景全拦截（目标值，M4 出报告）。
- **安全合规**：敏感数据出网默认脱敏（三级捕获模式）；**未审批高危执行 0**（审计可证）；提示注入经数据块隔离 + 工具白名单 + 参数强校验多层拦截。
- **可靠性设计**：15 种失败模式 FMEA 全覆盖 + 降级链与 Bulkhead 隔离；HITL 跨实例恢复（kill 持有副本后另一副本审批续跑）。
- **工程治理**：Maven Enforcer 抓出并修复 Spring Boot BOM 与 AgentScope 的 okhttp/okio 双重实现、jedis 版本漂移与重复类冲突，构建零冲突（`mvn validate` 全绿）。
- **成本可控**：以网关侧计量 token 成本（不采信模型自报），通过工具结果截断 + prompt 缓存 + 轻量模型分流降低单次诊断成本（目标值，M4 压测报告）。

## Part B · 指标口径卡（每个数字的"四件套"）

### B1 知识问答"命中率 ≥90%"（被追问最多）

| 项 | 内容 |
|----|------|
| **定义** | 每条评测题标注 k 个**必需关键点**（事实/文件/方法/结论）；回答命中关键点数 ÷ k，全量取平均 |
| **数据来源** | `src/test/resources/eval/cases/*.yaml`；ground truth 来自 RQ01 场景库 + 117 项历史测试结论 + 21 个真实修复案例 |
| **采集方法** | `mvn test -Peval` 运行评测器：先规则匹配（关键词/正则 + **引用存在性校验**），开放题再人工盲评抽检 20%（记录一致性 kappa） |
| **样本量** | n≥50；n=50 时点估计 90% 的 95% CI ≈ ±8.3pp（汇报附置信区间） |
| **产物** | `target/eval-report.md`（逐题得分、失败样例、引用校验结果、抽检记录） |
| **话术** | "不是模型自评——关键点由我们从真实故障与测试结论标注；评分以规则+引用校验为主，LLM judge 仅用于开放题的少量抽检；报告含样本量与置信区间。评测集与运行器都在仓库里，可复跑。" |
| **诚实边界** | 规则匹配会低估同义表述；评测集 50 条规模有限 → 对外表述为"目标 ≥90% 且回归回退 ≥2% 阻断"，不宣称"生产准确率 90%" |

## Part C · 怎么真正拿到这些数字（M4 评测周）

1. **评测集**：从 RQ01/R05 提炼 50+ 用例（KB 30 / DIAG 15 / SEC 5），每条标注关键点与期望引用
2. **运行器**：`mvn test -Peval`（离线桩）→ 生成报告；`-Peval-live` 手动全量
3. **压测**：wrk（SSE/HTTP）+ Python 会话脚本；输出 P50/P95/P99 与错误率原始 CSV
4. **红队**：6 类攻击脚本（注入/越权/伪造审批/危险工具/敏感套取/无解诱导）
5. **演练**：按 FMEA 清单逐项（停 ES/Redis failover/kill jdtls/滚动重启…）记录恢复时间
6. **汇总**：`docs/reports/` 归档所有报告 → 简历数字逐一回填为**实测值**（附报告链接）

## Part D · 面试追问预演（Top 8）

1. **90% 怎么来的？** → B1 口径卡：关键点标注 + 规则评分 + 引用校验 + 20% 人工抽检 + 置信区间
2. **LLM judge 偏差？** → 不用 LLM 自评做主指标；规则+引用校验为主，LLM 只辅助抽检并记录一致性
3. **引用 100% 怎么保证？** → 静态校验器（LSP/文件行存在性）进评测门禁，不通过即阻断
4. **成本怎么算？** → 网关侧 usage × 版本化费率；缓存 token 单列；不采信模型自报
5. **可用性/并发怎么测？** → 单机环境不吹 SLA；用失败模式演练通过率 + 会话级压测（含通过标准与原始数据）
6. **为什么 AgentScope 2.0？** → 对比矩阵：内置 Harness（HITL/分布式状态/技能/子代理），避免自研；JDK17 与团队栈一致
7. **依赖冲突（okhttp/jedis）怎么发现/修的？** → Enforcer 三规则；pin 覆盖、排除重复类、上游重叠登记豁免+退出条件
8. **提示注入怎么防？** → 数据块隔离 + 工具白名单/参数校验 + 三态权限 + 审计 + 红队回归
