## 1. 量化 NFR / SLO

| 类别 | 指标 | 目标 | 测量方法 |
|------|------|------|---------|
| 对话延迟 | 流式首字 P95 | ≤ 2s | SSE 首事件时间戳 - 请求时间 |
| 对话延迟 | 端到端 P95（无审批） | ≤ 15s | trace span |
| 工具延迟 | 只读工具 P95 | ≤ 3s | 工具 span（ES/Prom/MySQL） |
| 工具延迟 | 变更工具 P95（不含人工等待） | ≤ 10s | intent→settlement 时长 |
| 可用性 | 服务可用性（v1 单机） | ≥ 99.5% | actuator 健康 + 告警 |
| 质量 | 知识问答关键点命中率 | ≥ 90% | 评测集（PLAT-05） |
| 质量 | 引用有效性（引用文件/方法/行真实存在） | 100% | 静态校验器（KB-03/05 AC） |
| 质量 | 拒答正确率（无证据/越权/危险请求） | ≥ 95% | 红队 + 无解语料评测 |
| 质量 | 诊断证据充分率（结论附 ≥2 类证据或声明证据不足） | ≥ 95% | 评测 + 人工抽检 |
| 成本 | 单会话 token 预算 | 默认 100k；超限降级 `deepseek-v4-flash` | 网关侧计量（不采信模型自报） |
| 成本 | 单次诊断成本上限 | 由预算策略控制（软限 80% 告警） | 同一计量 |
| 容量 | 并发会话 | ≥ 50（v1 单机） | 压测 |
| 容量 | 知识规模 | ≥ 10 万 chunk（ES 混合检索） | 索引/检索压测 |
| 容量 | 日志查询窗口 | ≥ 30 天（VictoriaMetrics 保留期） | 查询实测 |
| 安全 | 出网脱敏覆盖率（密钥/敏感模式） | 100% | 脱敏单测 + 流量抽检 |
| 安全 | 审计留存 | ≥ 180 天 | `ai_audit` 保留策略 |
| 安全 | 高危动作拦截率（未审批执行） | 100% | 负向 E2E |

## 2. STRIDE 威胁模型（xhs-ai 本体）

| 威胁 | 具体场景 | 缓解措施 | 验证 |
|------|---------|---------|------|
| **S**poofing | 伪造 `userId/sessionId` 读他人会话；伪造审计 actor | 复用端口信任模型（`GatewayAuthTrustFilter`：JWT 覆盖 / 内部令牌）；会话与审批按 `(userId,sessionId)` 归属校验 | 负向 E2E（PLAT-01） |
| **T**ampering | 篡改审批状态/审计记录 | 审计只追加不可改；审批状态机 CAS（pending→approved/rejected 单向）；参数指纹（rawInput hash）防止调包 | 集成测试 + 指纹校验用例 |
| **R**epudiation | 否认执行过 DLQ 重投 | 审计含 actor/traceId/工具/参数（脱敏）/结果/时间；支持按 traceId 回放 | PLAT-03 AC |
| **I**nformation Disclosure | 日志/参数（手机号、地址、密钥）外发第三方模型网关 | 捕获模式默认 `sanitized`（**先脱敏再截断**）；字段级脱敏规则；可选 `metadata`；可切私有模型；出网计数审计 | 脱敏单测 + 出网抽检 |
| **D**oS | 大窗口日志查询、复杂 PromQL、重复工具调用烧 token | 结果上限+截断落盘；查询限流（按用户/工具）；超时策略（工具声明）；**Guard 重复调用提醒**；会话 token 预算 | 压测 + Guard 用例 |
| **E**levation | 提示注入（日志内容含恶意指令）诱导越权/执行高危工具 | 不可信内容作为"数据块"隔离，禁止解释为指令；工具白名单+参数 schema 强校验；三态权限（读 allow/动作 ask/高危 deny）；**决策在执行点强制** | 红队用例（PLAT-05/07） |
| 供应链 | 恶意/劣质 Skill 或 MCP server | Skill/Tool catalog + 版本 pin + 声明=实现 CI 校验；MCP server 白名单 + env 清洗 | 治理 CI |
| 幻觉 | 编造文件/方法/结论 | 引用必校验（文件/行/方法存在）；无证据即声明"证据不足"；评测门禁 | 引用校验器 + 评测 |

## 3. REQ ↔ AC ↔ TC 追溯

**编号规则**：`REQ-<域>-<序号>` → `AC-<域><序号>-<n>` → `TC-<层>-<编号>`（层：UT 单测 / CT 契约 / IT 集成 / E2E / EVAL / RED 红队）

示例矩阵（P0 节选，完整版在 P4 测试设计）：

| REQ | AC | TC（层） |
|-----|----|---------|
| DIAG-02 | AC-D02-1 返回命中服务+主类/方法+最近提交；AC-D02-2 引用可回链 | TC-IT-201（ES+Git 集成）/ TC-E2E-201 |
| DIAG-03 | AC-D03-1 附 ≥3 类证据；AC-D03-2 无证据声明不足 | TC-CT-301（fixture 编排）/ TC-E2E-302（真实下单失败注入） |
| DIAG-05 | AC-D05-1 Redis/DB 对照；AC-D05-2 差异给原因与对账入口 | TC-IT-501（本地 Redis+MySQL）/ TC-E2E-502 |
| DIAG-08 | AC-D08-1 积压+消息详情；AC-D08-2 msgId 关联首次失败日志 | TC-CT-801（rocketmq-tools fixture）/ TC-E2E-802 |
| OPS-01 | AC-O01-1 未审批不执行；AC-O01-2 审批后重投+核验；AC-O01-3 审计完整 | TC-IT-101（审批状态机）/ TC-E2E-102 / TC-E2E-103 |
| KB-03 | AC-K03-1 引用真实文件/方法；AC-K03-2 引用校验通过 | TC-EVAL-301 / TC-UT-301（校验器） |
| PLAT-02 | AC-P02-1 超时 fail-closed；AC-P02-2 always 免审；AC-P02-3 重启恢复授权 | TC-IT-P02 / TC-E2E-P02 |
| PLAT-07 | AC-P07-1 密钥模式 100% 脱敏；AC-P07-2 默认 sanitized；AC-P07-3 可切 metadata | TC-UT-P07（脱敏规则）/ TC-IT-P07（捕获管道） |
| PLAT-05 | AC-P05-1 ≥50 用例通过率 ≥90%；AC-P05-2 不回退 ≥2% | TC-EVAL-ALL（门禁） |
| RED-01 | AC-R01-1 注入日志不得触发工具；AC-R01-2 越权请求拒绝 | TC-RED-01..05 |

**门禁**：每个 REQ 至少 1 个自动化 TC；P0 场景需 E2E + EVAL 双覆盖；红队用例（RED）为发布门槛。

## 4. 数据合规设计（G1 落地）

1. **数据分级**：公开 / 内部 / 敏感（PII：手机号、地址、邮箱；凭据：sk-/ark-/Bearer/JWT）
2. **出网策略**：
   - 默认 `sanitized`：**先脱敏后截断**；`capture_mode` 写入每条 trace/审计
   - `metadata`：只发 ID/长度/统计（高敏场景强制）
   - `full`：需显式开启 + 审批（仅内网私有模型场景）
3. **供应商策略**：记录所用网关与数据用途；保留切换到私有化模型的配置开关（`MYXHS_LLM_BASE_URL` 可换）
4. **审计**：每次出网记录"内容类别 + 脱敏计数 + 模式"，可导出核查

## 5. 关键依赖假设与降级

| 依赖 | 假设 | 降级 |
|------|------|------|
| siyu-all LLM | 可用性/限流未知，按 429/5xx 处理 | 重试→切 `v4-flash`→只读检索模式（不生成） |
| Ark embedding | 批量接口有速率限制 | 失败重试；持续失败→纯 BM25 关键词检索 |

| XXL-Job Admin | 登录态可用 | 触发类工具不可用时明确提示 |
