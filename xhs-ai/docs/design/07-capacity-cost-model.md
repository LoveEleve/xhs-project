# D07 · 容量与成本模型

> 面试视角：架构师必须能回答"能扛多少并发、瓶颈在哪、怎么扩、花多少钱"
> 数据来源：2026-09-12 宿主机实测（16C/62GB，可用 38GB；磁盘 50G 用 42G，扩容后 65G）

## 1. 现有平台资源快照

| 资源 | 现状 | 余量 |
|------|------|------|
| CPU | 16 核；15 JVM + 中间件常态负载 ~4-6 | 充足 |
| 内存 | 62GB；已用 23GB（15 JVM ≈15GB + Docker 中间件 ≈7GB） | **~38GB** |

| Redis | Sentinel 1主2从（容器），内存充足 | 充足 |

## 3. 向量检索资源评估（实验路径，评测触发才启用；D12/RV09）

| chunk 规模 | 原始向量 | 图/开销估算 | ES heap 需求 | 结论 |
|-----------|---------|------------|-------------|------|
| 5k | 41MB | ~60MB | 512MB 可用 | v1 起步 ✅ |
| 2 万 | 164MB | ~250MB | 512MB 紧张 → 建议 1-2GB | v1 上限 |
| 5 万 | 410MB | ~600MB | ≥2GB | 接近迁移阈值 |
| 10 万 | 819MB | ~1.2GB | ≥4GB（需加节点/堆） | **迁移阈值：专用向量库（Milvus/pgvector）** |

- v1 策略：知识卡 **≤2k**（BM25，无需向量）；若评测触发向量实验：控制在 ≤2 万 chunk，ES heap 提至 1GB，knn 前按 `layer/service` 过滤
- 演进：chunk > 5 万或 knn P95 > 300ms → 独立向量库；接口经 `Retriever` 抽象，迁移不改工具契约

## 4. 并发与吞吐（瓶颈测算）

假设单次诊断：10-30 次工具调用、30-80k tokens、耗时 30-90s

| 路径 | 单诊断消耗 | 10 并发诊断/分钟 | 瓶颈判断 |
|------|-----------|-----------------|---------|
| LLM | 20-40 次调用，50k tokens | **~200 次/分钟、500k TPM** | **第一瓶颈**（网关限流/配额）→ 队列+限流+flash 分流 |
| ES 查询 | ~20 次 | ~3-7 QPS | 远低于实测 683 RPS ✅ |
| ES knn（知识） | ~5-10 次 | ~1-2 QPS | 2 万 chunk 内可用 ✅ |
| MySQL 只读 | ~10 次 | ~2 QPS | 可忽略 |
| Redis | ~20 次 | ~3 QPS | 可忽略 |
| jdtls | ~5 次 | ~1 QPS | 单例可承受（查询毫秒级） |

> 工具 schema 成本：MCP 工具全量装载可达数万 token/请求，须按场景工具集装载（D02 §11），否则输入成本显著上升。

**v1 容量结论**：单机可支撑 **~10 个并发诊断会话**（受限 LLM 配额），50 会话需排队+限速；水平扩展方式：多副本（状态在 Redis，无粘性）+ 网关排队；工具调用无状态可直接扩展。

## 5. 成本模型

- 公式：`Cost = Σ(in_tokens×p_in + out_tokens×p_out + cache_read×p_cache)`
- 单次诊断估算（示例费率 ¥1/M in、¥2/M out）：
  - 输入 40k × ¥1/M = ¥0.04；输出 4k × ¥2/M = ¥0.008；**≈ ¥0.05/次诊断**
  - flash 分流后成本再降 60-80%；embedding 成本可忽略
- 成本控制优先级：**工具结果截断（D02 maxBytes）> prompt 缓存 > flash 分流 > 预算硬限**
- 价值对照：一次诊断替代人工 30-60 分钟 → ROI 显著；KPI 建议：诊断次数、平均耗时、证据充分率、成本/次

## 6. 扩展与演进阈值（何时动架构）

| 阈值 | 动作 |
|------|------|
| 并发诊断 > 20 / LLM RPM 触顶 | 增加 xhs-ai 副本 + 网关排队；LLM 配额度提升 |
| 知识 > 5 万 chunk / knn P95 > 300ms | 迁移专用向量库；ES heap 扩容 |
| jdtls RSS > 2GB 或崩溃频繁 | 降级 tree-sitter/JavaParser 静态导航（D04 已留降级） |
| 审计表 > 5000 万行 | 按时间分区 + 冷归档 |
| 磁盘 > 80% | 清理（日志/缓存）+ 扩容（自愈脚本已支持） |
| 日均成本 > 预算 | 强化缓存/截断/小模型分流 |

## 8. 坦白局限（面试诚实项）

1. 上述并发/成本为**单机量级估算**，未做生产压测；M4 用 wrk/自研脚本做会话级压测校准
2. LLM 网关（siyu）实际 RPM/TPM 配额未知——需向上游确认后修订 §4
3. 单机无跨 AZ 高可用；生产化需将 Redis/MySQL/ES/xhs-ai 按可用区部署（超出当前环境范围，列为演进项）
