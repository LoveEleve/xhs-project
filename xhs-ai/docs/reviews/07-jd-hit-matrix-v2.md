## 3. 关键红线与应对

1. **JD18**："仅做聊天机器人、简单知识库问答、开源 Demo 调试经验，不符合专家级岗位要求" → 应对：M2.0 竖切闭环 + 真实案例 + EVAL 报告（非 Demo 证据链）。
2. **JD2/JD8**："AI 落到真实业务，而不是停留在 Demo"/"真实业务场景落地项目经历（硬性）" → 应对：7 张真实案例卡复活（订单下降/支付/内容/5xx/DLQ），全部可回放。
3. **JD5**："复杂任务自动化，并非传统问答/RAG" → 应对：诊断+变更（DLQ 重投）闭环、工具编排、HITL，不做纯问答。
4. **JD8**："业务感知硬性（销售/采购/库存/人事/财务）" → 应对：订单/支付/库存/优惠券等交易领域语言与真实表结构。
5. **JD13**："可解释性/溯源/分层透明度" → 应对：证据链+引用校验+审计+置信度声明（已有设计，M2.0 落地）。

## 4. 补位话术（缺口 → 克制讲法）

| 缺口 | 说法 |
|------|------|
| 多智能体未做 | "单 Agent + 强治理优先；多 Agent 会放大权限与成本，JD18 也强调 Supervisor-Worker 之前先把单 Agent 工作流/评测做扎实" |
| 长期 Memory 未做 | "会话状态（Redis AgentState）与知识库已分离；长期 Memory 四态边界（会话/任务/知识/案例）有设计，M2.5 落地" |
| 无微调 | "诊断场景走确定性工具+结构化输出；微调收益低于工具质量与评测回报，作为学习项而非项目刚需" |
| 无 A2A | "同进程共享 Harness，无跨系统通信需求；理解协议趋势，克制不引入" |
| 无多租户 | "企业内部单组织（ADR-006），用户级认证+审计先行" |
| 向量库用 ES | "ES 混合检索满足 v1（≤2 万 chunk）；JD18 清单含 ES；50 万 chunk/P95>300ms 迁移 Milvus（阈值已定义）" |
| Python 缺口 | "Java 主线练通；可用本项目为底补 Python/LangGraph 对照版" |

## 5. 投递结论

- **直接投（9 份）**：JD1 JD4 JD5 JD6 JD8 JD9 JD10 JD14 JD16。
- **补 Python 后投（3 份）**：JD13 JD17 JD18。
- **不主投（5 份）**：JD2 JD3 JD7 JD11 JD15；JD12 投前核实。
- **核心定位**：Java + AgentScope Harness + 真实交易系统案例 + MCP 工具治理 + 评测/可观测工程化；弱项（多智能体/微调/A2A/长期 Memory）以"克制讲法"处理。
- **成败关键**：M2.0 竖切①必须在简历投递前完成并产出证据（E2E 记录 + 1 条 EVAL + 审计 SQL），否则命中矩阵多数仍停在"规划"。
