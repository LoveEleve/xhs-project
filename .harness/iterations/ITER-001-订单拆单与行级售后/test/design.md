# 测试设计: 订单拆单与行级售后改造

> 机器可读的迭代协议产物之一。定义**验证策略与观测方式**，是 test/cases.md 与 test/report.md 的上游。

## 验证策略

- **单测为主**（项目规则：不跑运行时环境，编译 + 单测为验证口径）：
  - 纯函数优先：聚合函数 `computeParentStatus`、`DiscountAllocator` —— 表驱动穷尽；
  - 服务层单测（Mockito）：创建拆单、状态推进、终结、售后行级闸门；
  - 回归：四模块全量重编测试（删 `target/test-classes` 防增量假绿）。
- **集成/E2E**：不做（无运行时环境）；跨服务契约以单测断言 Feign 请求体 + 编译期 DTO 校验覆盖。
- **手工验证**：REQ-10 文档产出（修订记录、wiki 回流）——人工检查。
