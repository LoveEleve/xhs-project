# 测试设计: 渠道契约对齐支付宝

> 机器可读的迭代协议产物之一。定义**验证策略与观测方式**，是 test/cases.md 与 test/report.md 的上游。

## 验证策略

- **单测为主**（项目规则：无运行时环境；编译 + 单测为验证口径）：
  - 签名/验签：`AlipaySignatureUtilTest`（roundtrip / 空值剔除 / 中文与特殊字符 / 篡改 / 错钥）；
  - 通知端点：`AlipayNotifyControllerTest`（**standalone MockMvc**：不依赖 Spring 上下文；覆盖验签/二次校验/四态分流/重复/异常）；
  - 模拟服务器：`SimulatedAlipayServerTest`（台账迁移 / 通知参数完整性 / 重试调度与放弃 / query/close/refund / 退款幂等 / 故障注入）——通知投递以 `AlipayNotifySender` mock 断言（不真起 HTTP）；
  - 策略与业务：`AlipayPayStrategyTest`（四态映射 / 同步退款 / close）；`PaymentServiceTest` 存量改写（换渠道先查后决矩阵 / 退款同步三分支 / 退款回调整链删除后的用例清理 / 微信删除后的用例清理）；
  - 全链路 roundtrip：模拟服务器构造通知 →（mock sender 捕获）→ 直调端点方法 → 验签通过 → 处理断言（进程内闭环，不起网络）。
- **集成/E2E**：不做（无运行时）；脚本更新以 review + 冒烟口径记录（后续有环境时可用）。
- **手工验证**：网关白名单两行、deploy 迁移补齐（文件比对）。
