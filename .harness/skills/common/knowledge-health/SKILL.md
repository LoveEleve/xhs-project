# Knowledge Health — 知识健康检查

扫描 `.harness/wiki/` 与 `.harness/tech/`，处理迭代积累的知识库病灶：重复、冲突、失效链接、无来源结论。

> **定位**: 只读检测 + 产出修复清单的技能，按 `.harness/rules/知识库治理规则.md` 执行。修复动作（合并/删除/改链接）在清单中标注，重大裁决留人。

---

## 1. 何时使用

- 定期（每迭代 / 每月）知识库体检
- 发现 Agent 检索到矛盾或过时的知识
- 知识回流（archive.md）后核对一致性

## 2. 检测项

| 病灶 | 检测方法 | 处理 |
|------|---------|------|
| **重复主题** | 按 title / category 聚类，同概念多份文档 | 建议合并，列出去重清单 |
| **冲突 status** | 同一事实两份文档结论相左，或 status 与内容矛盾 | 追查 source 裁决，标注冲突 |
| **失效链接** | 扫描所有 `](...)` 相对链接，指向不存在文件 | 修复路径或标记废弃 |
| **无来源结论** | frontmatter 缺 `source` 字段 | 补齐来源或删除 |
| **复制代码** | 文档大段重述方法逻辑（违反「不复制代码」） | 删实现描述，只留链路位置 |

## 3. 执行流程

### Step 1: 收集
列出 `.harness/wiki/`、`.harness/tech/` 下所有知识文件（含 frontmatter）。

### Step 2: 逐项检测
按上表逐文件/跨文件检测，每项记录：文件路径 + 病灶类型 + 证据 + 建议修复。

### Step 3: 出体检报告
写 `.harness/retro/knowledge-health-<日期>.md`：

```markdown
# 知识健康检查: <日期>

## 总览
- 知识文件: wiki X 个 / tech Y 个
- 病灶: 🔴 X 处 / 🟡 Y 处

## 修复清单
| 优先级 | 病灶 | 文件 | 证据 | 建议 |
|--------|------|------|------|------|
| 🔴 | 冲突 | <path> | <…> | 追查 source 裁决 |
| 🟡 | 失效链接 | <path> | <…> | 修路径 |
```

### Step 4: 修复
- 🟡 机械可修（失效链接、补 source、删复制代码）→ 自动修复并逐条报告
- 🔴 需裁决（冲突、合并）→ 列出选项请人类决策

## 4. 纪律

- 只按 `知识库治理规则.md` 判定，不引入额外标准
- 删除/合并知识是**不可逆**的，重大操作留人确认
- 报告保留证据（文件路径 + 具体问题），不写空泛结论

## 5. 完成标志

- 体检报告已落盘，含总览 + 修复清单
- 🟡 项已修复并报告，🔴 项已列选项交人类
