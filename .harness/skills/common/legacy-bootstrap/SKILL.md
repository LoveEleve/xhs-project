# Legacy Bootstrap — 老系统冷启动

老项目知识分散、文档完整度不一，不能像新项目那样从第一天按 AI 友好方式组织。本技能把存量代码与资料**关联**进工作空间，再从代码与凌乱资料中**清洗**出结构化知识，最后用采访稿补齐只存在人脑中的业务知识。

> **定位**: 老系统接入 Harness 的启动技能，配合 `/apply-harness` 的棕地模式使用。核心原则：**不要等到知识库完善才开始用，在每次需求迭代中滚动完善，形成知识飞轮。**

---

## 1. 何时使用

- 已有代码库，要接入 Harness 研发体系
- 知识分散在多个仓库、文档、人脑中，文档完整度不一致
- 需要从存量代码/资料中提取结构化业务知识

## 2. 四步接入流程

### Step 1: 关联代码仓库（Git submodule）

把相关代码仓库通过 Git submodule 关联到 `src/` 目录：

```bash
git submodule add <repo-url> src/<repo-name>
```

- 关联而不复制：代码仓库保持独立演进，工作空间只持有引用
- 多个前端/后端/离线数据工程仓库，按业务域分目录挂载

### Step 2: 挂载原始材料（raw/）

把已有的产品文档、设计稿、接口文档、历史笔记等**未经改写**的材料挂到 `raw/` 目录：

- 不改写原文，只按来源归档（产品材料 / 技术设计 / 历史变更 / 会议纪要）
- 每条材料保留来源元数据（谁、何时、什么场景）

### Step 3: 清洗 SKILL（从代码/资料抽取知识）

设计一个「清洗 SKILL」，从 `src/` 代码和 `raw/` 资料中清洗出结构化知识：

- **从代码挖业务规则** → 沉淀到 `.harness/wiki/`（业务概念/规则/口径）
- **从代码/架构推链路** → 沉淀到 `.harness/tech/`（跨系统链路/废弃状态/观测方式）
- **严格遵守** `.harness/rules/知识库治理规则.md`：不复制代码、事实来源必填、链接用相对路径

### Step 4: 采访稿补齐人脑知识

用访谈转录工具（如钉钉 AI 听记）对核心开发、产品进行采访：

1. 针对知识缺口设计采访提纲（哪些规则只存在于人脑、哪些历史决策没有文档）
2. 采访原稿给到 Coding Agent，整理进 `.harness/wiki/` / `.harness/tech/`
3. 采访沉淀的术语同步进 `.harness/CONTEXT.md`

## 3. 知识飞轮（启动后持续）

冷启动只是起点。之后每次需求迭代归档时（`archive.md`），把确认的长期知识回流 wiki/tech：

```
冷启动 → 关联 src/ + 挂 raw/ → 清洗知识 → 采访补缺
   ↓
每次迭代 → PRD/方案/测试校验知识 → 归档回流 wiki/tech → 知识越来越完善
```

## 4. 完成标志

- `src/` 已 submodule 关联相关仓库，`raw/` 已挂载原始材料
- 清洗 SKILL 已产出首版结构化知识（wiki + tech）
- 采访稿已整理进知识库，术语已进 CONTEXT.md
- 知识缺口清单已登记，交由后续迭代滚动补齐
