# 知识库治理规则

> **作用域**: 定义 `.harness/wiki/` 与 `.harness/tech/` 的知识分层、编写纪律与健康检查。
> **理念**: 知识库不复制代码；长期知识分「业务（wiki）」与「技术上下文（tech）」两层；事实来源必填、链接用相对路径。

---

## 1. 分层

| 目录 | 保存什么 | 面向谁 | 反面 |
|------|---------|--------|------|
| `.harness/wiki/` | 业务概念、规则、口径、角色、流程、异常处理 | 产品 / 运营 / 测试 / Agent | 复制代码实现 |
| `.harness/tech/` | 跨系统链路、接口数据关系、新旧切换、废弃状态、运行态拓扑、观测方式 | 开发 / Agent | 逐方法重述代码 |
| `.harness/CONTEXT.md` | 术语定义（Ubiquitous Language） | 所有人 | 存规格/草稿/实现决策 |

> 业务知识可来自已有产品材料，也可从代码中挖掘（清洗 SKILL 或 legacy-bootstrap）；技术上下文只写「调哪个接口/方法 + 链路位置」，特别重要且反复使用的逻辑才保留稳定摘要。

## 2. 编写纪律

- **不复制代码**：每个类/方法重述一遍 = 与代码竞争的文档，生成快、失效也快，禁止。
- **事实来源必填**：每个知识文件 frontmatter 必须填 `source`（一手事实：wiki 相对路径 / 采访稿 / PRD / 代码文件）。
- **链接用相对路径**：知识之间用相对路径关联，禁止绝对路径（换环境即失效）。
- **tech 反连 wiki**：技术上下文用 `wiki_ref` 字段关联业务知识，保证「业务规则 ↔ 技术链路 ↔ 源代码」可双向检索。
- **有主见**：同一概念多个词，选最好的一个，其余进 `CONTEXT.md` 的 `_Avoid_`。

## 3. 知识飞轮（迭代驱动）

- 知识建设是产品迭代的**副产物**，不必先建成完美知识库再开始。
- 每个迭代归档时（`archive.md`）执行**知识回流**：确认的业务规则→wiki、链路→tech、难逆转决策→ADR、术语→CONTEXT.md。
- 每次迭代同步更新功能和知识，减少「代码已变、文档停在旧版」的漂移。

## 4. 健康检查（`/knowledge-health`）

定期扫描 `.harness/wiki/` 与 `.harness/tech/`，处理迭代积累的：

- **重复主题** — 同一概念多份文档 → 合并
- **冲突 status** — 同一事实不同结论 → 追查来源裁决
- **失效链接** — 相对路径指向不存在的文件 → 修复或标记
- **无来源结论** — 缺 `source` 字段 → 补齐来源或删除

> 知识健康检查是机械可执行的技能（`harness-core/skills/knowledge-health/`），随迭代周期性运行。
