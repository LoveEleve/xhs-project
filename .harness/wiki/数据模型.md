# 数据模型

> 本项目的核心数据模型定义、存储方案。
> （2026-10-16 ITER-001 拆单改造后回流）

## 核心模型

| 模型 | 说明 | 存储 |
|------|------|------|
| 父订单（`t_order`） | 交易/支付维度：金额、支付单绑定、**聚合状态**（0待付款/1已付款/2已发货/3已完成/4已取消/5已退款） | MySQL 分片（user_id，4 库 × 4 表） |
| 子订单（`t_sub_order`） | 商家维度：履约/售后入口/结算维度；状态 0待付款/1待发货/2已发货/3已完成/4已取消/5已退款 | 同上（绑定表组） |
| 订单行（`t_order_item`） | SKU 维度：数量、小计、**分摊优惠 `discount_share`**（行实付 = 小计 − 分摊）、`sub_order_id`/`seller_id` | 同上 |
| 售后单（`t_aftersale`） | **行级售后**：`item_id` 锚点；唯一键 `(item_id, type)`；`discount_share`/`refund_amount` 为本次申请口径（自洽：应退 = 本次金额 − 本次分摊） | MySQL 公共库（`my_xhs_order`，不分片） |
| 订单事件流（`t_order_event`） | Event Sourcing；父单状态流转事件（含拆单聚合事件 `ORDER_ALL_SUBS_SHIPPED` / `ORDER_ALL_SUBS_COMPLETED`） | 分片 |
| 订单快照（`t_order_snapshot`） | 状态点快照（父单维度；聚合流转时记录） | 分片 |
| 商品 SKU（`t_sku`） | `seller_id`（0=平台自营；下单按商家拆单的分组依据） | MySQL 商品库 |

## 存储方案

- **分片**：`t_order` / `t_sub_order` / `t_order_item` / `t_local_message` / `t_order_snapshot` / `t_order_event` 同一分片键 `user_id`（hash 路由，绑定表组避免笛卡尔积）；
- **公共库（不分片）**：`t_aftersale` / `t_order_no_mapping`（量级小，按 order_no/aftersale_no 查询）；
- **金额守恒**：行实付 = `total_amount − discount_share`（下单时最大余数法落库）；子单金额 = Σ行；**父单实付 = Σ子单 = Σ行**；
- **状态聚合**：父单状态 = f(子单状态)（穷尽规则 + CAS 收敛，见 `SubOrderService#computeParentStatus`）；
- **幂等锚点**：行（`item_id`）是售后粒度；子单号（`sub_order_no`）是履约粒度。
