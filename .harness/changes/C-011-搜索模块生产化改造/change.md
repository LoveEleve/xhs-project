## 用户故事

作为搜索域开发者，我想要把 ES 索引链路从"补偿不收敛 + 重建半新半旧 + 兜底缺口"升级到
"**收敛的补偿 + 别名切换的零中断重建 + 全兜底**"，并让搜索域与已改造模块的水准对齐。

## 边界情况

- 补偿批中"ES 版本已更新"的文档 → 豁免（视为成功），**不再回填失败集**（收敛）
- 确定性失败（商品文档构建失败）→ 丢弃 + 告警（不回填循环）
- 重建失败（v2 半成品）→ 别名不切换（线上仍 v1）；断点续传写入同一 v2
- 重建期间更新 → 切换后窗口重放（updated_at >= rebuildStart）补齐
- 物理删 → 版本化墓碑（deletedAt）→ 超龄清理（防泄漏 + 防复活）
- legacy 部署（无别名，索引名=配置名）→ 重建回退原地模式（告警）

## 非功能需求

| 维度 | 指标 |
|------|------|
| 性能 | 别名切换原子（毫秒级）；窗口重放按 updated_at 索引扫描 |
| 可靠性 | 补偿收敛（无永久循环）；重建零中断（搜索始终见完整索引）；物理删防复活 |
| 可观测 | 别名切换/窗口重放/墓碑清理指标与日志 |
| 安全 | 三控制器公开端点限流 |

## 设计约束

- 读路径透明：配置名即别名（消费/搜索/重建无需改配置）；
- 与 C-007/8/9/10 口径对齐：部分失败窗口闭合、注释零漂移、DLQ 兜底；
- 无运行时：别名逻辑以单测 + 代码审查为验证口径（ES 操作全 mock）。
