# C-009 计数与社交分析生产化改造

> **立项（2026-10-18）**：内容域第一站。**深度探索（代码优先）**：07/08 两模块 27 条线索逐条核实 + 与 C-007/8 同型比对。
> 核心 = **颤振双向变体（D1：粉丝侧↔关注侧修复互相打架，永不收敛）+ like 数据穿越三环（D2：清零已止血/只修值不修集合/crash 丢事件窗口）+ 机制统一（D3 版本门 N 份拷贝 / D4 DLQ ×5 / D6 三代计数）**。
> 联合理由：两者是同一"互动计数系统"（analytics 权威 + counter 展示 + 双侧对账），重问题全在"缝"上——分开修会互相打架（颤振本身就是两次独立变更叠加的产物）。
> 规划详见 `.harness/iterations/ITER-009-计数与社交分析生产化改造/`。

## 用户故事

作为内容域开发者，我想要把互动计数（赞/藏/关注）从"多套权威互相打架 + 永久漂移"升级到"**单一收敛语义（证据判别 + 完成态幂等 + 可重建）**"，
并补齐 DLQ/测试/工程债，以便学习的是最终形态，且与交易域各模块的改造水准对齐。

## 边界情况

- follow/unfollow 的 Step B 失败（粉丝侧残留/缺失）→ 对账以"另一侧证据"判别，收敛不颤振
- like 事件 crash 丢事件 → 完成态版本门 + 重投可重处理（幂等前提核验）
- analytics 权威 Set 缺失（TTL/丢失）→ 从 t_like/t_favorite 重建（不再"跳过等人工"）
- counter like:set 分叉 → 对账重建（SUNIONSTORE 复制）
- counter 镜像键（2:6/7）无读取方 → 评估后移除（有读取方则收敛语义）

## 非功能需求

| 维度 | 指标 |
|------|------|
| 性能 | 对账重建用单命令（SUNIONSTORE 复制）；大集合重建有上限保护（沿用 RELATION_REBUILD_MAX 模式） |
| 可靠性 | 颤振收敛；like/follow 数据有重建路径；版本门完成态（崩溃不丢）；DLQ ×5 兜底 |
| 安全 | 无 |
| 可观测 | 对账修复/重建/守卫指标补齐；cron 注释与部署基准一致 |

## 设计约束

- 权威模型锚定：**关注关系以 follower 的 FOLLOW_LIST（Step A，原子+失败即抛）为事实源**；like 以 analytics Set 为权威（缺则从 t_like 重建）；
- 完成态幂等语义（对齐 C-008）：只读 stale 检查 + 完成后单调推进；
- 生产标准：业务/工程/分布式/微服务/性能/可观测全维度；不改文章正文（走修订记录）。
