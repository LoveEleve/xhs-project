## 一、领域模型

**聚合根：Change（变更 = 一次需求的交付单元）**

```
Project（接入的项目）
  ├─ id / name / path / language / framework / buildTool
  └─ assetsPath（.harness/）

Change ★
  ├─ id / projectId / title / requirement
  ├─ status（状态机）/ currentStage
  ├─ StageRun[]（阶段执行记录）
  │     ├─ stage（HARNESSING/CODING/TEST_WRITE/REVIEW/CI/DEPLOY_VERIFY）
  │     ├─ attempt / status（PENDING/RUNNING/PASSED/FAILED）
  │     ├─ promptHash / startedAt / finishedAt / error
  │     └─ GateResult[]（门禁结果）
  │           ├─ gateType（AC_TESTABLE/COMPILE/TEST/COVERAGE/LINT/STATIC/ARCH/SMOKE/HEALTH）
  │           ├─ command / exitCode / durationMs / outputRef
  │           └─ passed
  └─ Artifact[]（产物）
        └─ type（PRD/SOLUTION/TEST_DESIGN/TEST_CASES/TEST_REPORT/DIFF/REVIEW/VERIFY）
           / version / path / sha256 / createdAt

LlmCall（模型调用记录）
  └─ stageRunId / model / promptTokens / completionTokens / latencyMs / status（OK/FALLBACK/REJECTED）
```

**状态机（Change）**

```
CREATED ─▶ HARNESSING ─▶ CODING ─▶ TEST_WRITE ─▶ REVIEW ─▶ CI ─▶ DEPLOY_VERIFY ─▶ DONE
              │ 任一阶段失败 ─▶ FAILED（可重试回当前阶段）
              │ 任一阶段可 ─▶ PAUSED（可恢复）/ CANCELLED（终态）
```

规则：
- 只能"顺序推进"或"当前阶段重试"，不能跳阶段
- 阶段通过 = 该阶段所有门禁 PASS
- 终态：DONE / CANCELLED

**重入与幂等（重点设计）**
- `StageRun` 唯一键：`(changeId, stage, attempt)`
- 副作用幂等：产物按 `(changeId, type, version)` 覆盖写；LLM 调用按 attempt 记录；命令执行天然可重跑
- 断点续跑：从 `currentStage` 恢复；已 PASS 的阶段不重复执行（除显式 `force`）
- 重试语义：FAILED 阶段重试 = `attempt + 1`，保留历史 attempt（可对比分析）

## 二、模块划分（Maven 多模块）

```
harness-runner/
├── harness-runner-domain     # 领域模型 + 状态机（纯 Java，无框架依赖）
├── harness-runner-assets     # .harness 资产解析（frontmatter / 技能清单 / 占位符渲染）
├── harness-runner-llm        # LLM 编排（provider / 路由 / 降级 / 预算 / 计量）
├── harness-runner-gate       # 门禁执行器（ProcessBuilder / 输出解析 / 判定）
├── harness-runner-engine     # 引擎：阶段执行器 + 编排 + 产物对账
└── harness-runner-app        # Spring Boot 启动 + REST API + 持久化（MyBatis-Plus）
```

依赖方向：`app → engine → {domain, assets, llm, gate}`；`domain` 无外部依赖（可纯单测）。

## 三、技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| JDK | 17 | 对齐 xhs；LTS；本机 `/env/javaEnv/jdk17` |
| 框架 | Spring Boot 3.2.x | 对齐 xhs；生态成熟 |
| 持久化 | MyBatis-Plus + **H2 文件模式**（默认，零安装）+ MySQL 8（可选 profile） | 单机资源受限（可用内存 ~5.5G，MySQL 未运行）；H2 单文件、进程内；schema 同构可切 MySQL |
| 状态机 | **自研**（枚举 + 转移表 + 持久化） | 阶段固定 6 个 + 门禁关卡语义 + 断点恢复；Spring StateMachine 抽象偏重 |
| LLM | OpenAI 兼容 HTTP（RestClient） | 可换 DeepSeek/OpenAI，无厂商锁定 |
| 门禁 | ProcessBuilder + 超时 + 并发读流 | 通用（任意命令）、真实退出码、进程隔离 |
| 观测 | Micrometer + Prometheus | 对齐 xhs 观测体系 |
| 测试 | JUnit 5 + Mockito + JaCoCo | 对齐 xhs |
| 部署 | Docker Compose | 单机可跑 |

## 四、关键设计决策（ADR 式）

| # | 决策 | 备选与取舍 |
|---|---|---|
| D1 | **服务形态**（而非纯 CLI 库） | 需要状态持久化、多项目、可观测、可查询；CLI 只做薄客户端（v1 可先只做 API） |
| D2 | **状态机自研** | 备选 Spring StateMachine：抽象重、与持久化恢复结合复杂；自研代码量小、可控、可测 |
| D3 | **门禁走子进程**（而非 Maven Invoker API） | 通用性（未来可跑 npm/go test）+ 真实退出码；**坑：stdout/stderr 必须并发读，否则缓冲区满导致子进程阻塞** |
| D4 | **LLM 独立模块** | 路由/降级/预算/计量是横切关注点，各阶段共用；便于 mock 单测 |
| D5 | **v1 只做 Java/Maven** | 门禁命令与工程结构强绑定语言；先做深一条线（跑通 xhs），再横向扩语言 |
| D6 | **阶段产物 + 门禁**（而非让 LLM 一口气做完） | 每阶段可校验、可重入、可追责；一口气做完无法定位失败点、无法留证据 |
| D7 | **存储默认 H2 文件模式**（MySQL 可选 profile） | 单机资源受限；H2 零安装、单文件、进程内；schema 同构，未来可切 MySQL |
| D8 | **目标项目可配置**（不绑定 xhs） | 门禁命令 / 部署命令全部参数化；xhs 用于 ①-⑤（纯静态门禁），⑥ 用自带演示项目 |

## 五、LLM 编排设计

- **Prompt 渲染**：技能 `SKILL.md` → 提取指令 → 注入上下文（技术栈、`.harness/rules`、`CONTEXT.md`、已有产物、代码片段）→ 完整 prompt
- **上下文预算**：token 估算 + 截断策略（规则优先、产物摘要）
- **结构化输出**：每阶段定义 schema（如 ① → `{req, ac[]}`）；JSON 解析失败重试 ≤2 次，仍失败标记阶段 FAILED
- **多模型路由 + 降级链**（M5）：主 → 备用 → 轻量；仅传输类错误重试（已出流不重放）
- **Token 预算三段**（M5）：真实计量 → 软限 80% 切轻量 → 硬限 429
- **并发护栏**：单 change 串行；全局并发上限（可配）

## 六、门禁设计（v1 清单）

| 门禁 | 阶段 | 命令 / 判定 | 通过条件 |
|---|---|---|---|
| AC_TESTABLE | ① | LLM 判定 + 规则校验 | 每条 AC 可映射测试、边界 ≥3 |
| COMPILE | ②⑤ | `mvn -q compile` | exit 0 |
| TEST | ③⑤ | `mvn test` | exit 0 且失败 = 0 |
| COVERAGE | ③⑤ | 解析 JaCoCo 报告 | 核心逻辑 ≥80%（可配） |
| LINT | ⑤ | checkstyle | 0 violation（可配） |
| STATIC | ⑤ | spotbugs | 0 high |
| ARCH | ⑤ | ArchUnit 测试 | 全通过 |
| SMOKE | ⑥ | 冒烟脚本（可配，默认指向自带演示项目） | exit 0 |
| HEALTH | ⑥ | 健康检查端点（可配） | 200 |

执行器要点：超时（可配）+ 进程树清理 + 输出环形缓冲（防 OOM）+ 结果落库 + 日志文件。

环境注入（必做）：目标项目的构建环境（`JAVA_HOME` / `PATH` 等）**按项目配置注入子进程**——例如 xhs 需 JDK17 而宿主默认 JDK21；执行器不接受"继承宿主环境"的默认行为，避免"本地能跑、换机就挂"。

## 七、数据模型（表）

| 表 | 关键字段 |
|---|---|
| `project` | id, name, path, language, framework, build_tool, created_at |
| `change` | id, project_id, title, requirement, status, current_stage, created_at, updated_at |
| `stage_run` | id, change_id, stage, attempt, status, prompt_hash, started_at, finished_at, error |
| `gate_result` | id, stage_run_id, gate_type, command, exit_code, passed, duration_ms, output_ref |
| `artifact` | id, change_id, type, version, path, sha256, created_at |
| `llm_call` | id, stage_run_id, model, prompt_tokens, completion_tokens, latency_ms, status |
| `event_log` | id, change_id, event, payload, created_at（状态流转审计） |

## 八、API 设计（v1）

```
POST /api/projects                      接入项目（扫描技术栈）
GET  /api/projects/{id}
POST /api/changes                       创建变更 {projectId, requirement}
GET  /api/changes?projectId=&status=
GET  /api/changes/{id}                  详情（阶段时间线 + 产物 + 门禁）
POST /api/changes/{id}/advance          推进（执行当前阶段，返回执行结果）
POST /api/changes/{id}/retry            重试当前阶段
POST /api/changes/{id}/pause | cancel
GET  /api/changes/{id}/artifacts        产物列表 / 下载
GET  /api/changes/{id}/gates            门禁结果
GET  /api/metrics/summary               统计（拦截 / 覆盖率 / 周期 / Token）
```
