# Harness Runner · 执行规划（v0.3）

> **本版为当前唯一执行基准**，取代 v0.1（00 项目规划）与 v0.2（本文件旧版）。
> 目标：≤5 个工作日，产出"**可讲、可演示、经得起追问**"的 Java 项目（简历项目二）。

---

## 0. 一页纸总览（决策完备，无开放项）

| 维度 | 决策 | 理由 |
|---|---|---|
| 目标 | 面试可讲的最小可信系统（不是完整产品） | 时间有限；追问密度集中在核心 |
| 必做 | 状态机（✅D1）+ 门禁执行器 + 最小引擎 + LLM ① 阶段 + xhs 真实门禁 | 缺任何一个，"AI 引擎"故事不成立 |
| 设计不实现 | LLM ② 编码闭环、多模型降级、Token 预算、知识库、看板、Docker、多语言 | 讲设计 + 主动划边界 |
| 存储 | **文件仓储（默认）**，Repository 接口留 H2 适配器 | 单机零依赖；接口化本身是设计加分 |
| 形态 | **CLI 优先**；Spring Boot + REST 为 stretch | CLI 一天可成；服务化视 D5 时间 |
| LLM | DeepSeek / OpenAI 兼容接口（只做 ① 阶段） | 半天成本，换取"真 AI" |
| 时间 | 5 天，含 fallback（见 §5） | |

## 1. 面试叙事（先定这个，再定技术）

**一句话**：把 Markdown 形态的研发流水线做成可执行的 Java 引擎——**管状态、跑门禁、留证据**。

**讲述骨架（10 分钟版）**
1. 背景：AI 编码没有流程/门禁/证据；技能包只是提示词，缺运行时
2. 我做了什么：状态机 + 门禁执行器 + 编排 + LLM ① 阶段（只讲实现的部分）
3. 最亮的点：门禁执行器——真跑 `mvn`，踩过"流阻塞假死/超时清理/进程树"的坑
4. 真实数据：xhs 上的编译/测试/覆盖率门禁结果（含红→绿）
5. 边界（主动）：降级/预算/看板/服务化是设计

**口径表（讲什么/不讲什么，随实现进度校准）**

| 内容 | 口径 |
|---|---|
| 状态机、重入、幂等 | 讲（已实现，有单测） |
| 门禁执行器 | 讲（已实现，有日志） |
| LLM ① AC 生成 | 讲（已实现，有记录） |
| 引擎编排 / 产物 / 事件日志 | 讲（已实现） |
| LLM ②、降级、预算、知识库 | **设计**，主动划边界 |
| REST API / DB | 按实际：做了讲，没做说"设计" |
| 看板 / Docker / 多语言 | **设计**，不展开 |

### D5.5 ✅（门禁有效性基准 · 补齐自拷打 P1-3 的"度量"）

- 交付：`GateEffectivenessBenchmarkTest`（`HARNESS_BENCH=1` 开启，9 次真实 `mvn`）
- 结果：**故障检出 5/5（100%）**——编译错误 / 失败测试 / 无测试 / 全部跳过 / 覆盖率跌破；**基线 3/3 全绿**（无假阳性）；当时已知漏检 1（假测试）
- 顺带修复：TEST 门禁"全部测试被跳过"假绿变体（`testsRun - skipped <= 0` 判红），基准实测验证
- 证据：`evidence/benchmark/gate-effectiveness.md` + 9 份全量日志（README 附复现命令）
- 测试基线：136 + 2 环境开关（gate 真实 Maven IT / benchmark）

### D5.6 ✅（变异门禁 · 闭合假测试漏检）
- 交付：`GateType.MUTATION` + `PitReportParser`（PIT mutations.xml，抽取 KILLED/SURVIVED/NO_COVERAGE）+ `MavenGateCommandFactory.mutation()`（`test-compile` → `pitest:mutationCoverage -DoutputFormats=XML`）+ `GateRunner` 阈值判定；XML 安全解析抽为共享 `XmlDocuments`
- 基准升级：**故障检出 6/6（100%）**、基线 **4/4** 全绿；`fake_test` 对照（TEST 绿）vs `fake_test_mutation`（MUTATION 红，得分 0%）
- 前提（诚实边界）：变异门禁要求项目声明 `pitest-maven` + `pitest-junit5-plugin`（JUnit5 生态前提）；覆盖率门禁无前提
- 测试：gate 45（44+1IT）/ app 7（6+benchmark）——总计 **143 + 2 环境开关**
- 证据：`evidence/benchmark/gate-effectiveness.md`（11 行场景 + 全量日志）

### D5.7 ✅（事件哈希链 · 闭合自拷打 P1-5"防篡改"）
- 交付：`ChangeEvent` 增加 `prevHash/hash`；`EventHasher`（SHA-256 规范化哈希，链首 GENESIS）；`FileEventLog.append` 自动链化；`EventChainVerifier` + CLI `verify` 命令（篡改定位到行，exit 1）
- 实测：同一变更 8 条事件链完整 → 篡改 1 条 → `第 2 条事件哈希不匹配（疑似篡改）`（`evidence/d5-hashchain/`）
- 诚实边界：防局部篡改；**整链重写需外锚**（SCM/WORM/TSA/签名）——自证性证据的内在局限
- 兼容性：历史证据包事件未链化 → verify 统计"跳过历史未链化 N 条"，不影响新链
- 测试：engine 32（+5）/ app 8（+1）——总计 **149 + 2 环境开关**
- 附带：harness-runner 已迁入 xhs-project 仓库（`xhs-project/harness-runner/`），构建独立（不加入 xhs 根 reactor）

### D5.8 ✅（增量覆盖率门禁 · 治 Goodhart 与存量债）
- 交付：`GateType.DIFF_COVERAGE`；`DiffProvider`/`GitDiffProvider`（`git diff --unified=0`）；`UnifiedDiffParser`（hunk → 变更行区间，含新文件/重命名/删除）；`IncrementalCoverageEvaluator`（JaCoCo 行级索引 × 变更行交集）；`GateSpec.diffBase` + 阈值判定
- 判定口径：增量覆盖率 = 变更可执行行中的覆盖行 / 变更可执行行；**无可执行行 → 跳过阈值**（不误红）
- 基准新增两场景：`diff_coverage_baseline`（新增已测方法 → 100% ≥ 80% 绿）、`diff_coverage_drop`（新增 10 个未测方法 → 0% < 80% 红）；总计 **故障 7/7 检出、基线 5/5 全绿**
- 测试：gate 54（53+1IT）——总计 **158 + 2 环境开关**
- 边界：基线 ref 由调用方给定；测试代码行不计入（JaCoCo 只插桩主代码）；多包同名文件按路径后缀匹配
