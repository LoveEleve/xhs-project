## 一、它是什么（一句话 + 一个例子）

**一句话**：给 AI 编码装一条"流水线 + 质检线"——把"AI 在聊天框里生成代码"变成"可编排、可验证、可追溯的交付流程"。

**一个具体例子**：

```
输入：创建变更 --项目 xhs-project --需求 "完善读写分离：从库延迟监控 + 强制主库路由注解"

引擎执行（6 阶段，每阶段产物过门禁才推进）：
  ① harnessing     → LLM 生成 5 条 AC（每条可测试）→ 门禁 AC_TESTABLE（每条 AC 必须映射到测试）✓
  ② coding-skill   → 渲染编码 prompt（注入 .harness 规则 + CONTEXT 术语）→ 产出代码 diff → 门禁 COMPILE ✓
  ③ unit-test-write→ 生成测试 → 门禁 TEST + COVERAGE（≥80%）✓
  ④ expert-reviewer→ 双轴评审（Spec + Standards）→ 门禁 0 个 🔴 ✓
  ⑤ unit-test-ci   → 全量门禁（compile/test/lint/spotbugs/archunit）✓
  ⑥ deploy-verify  → 冒烟脚本 + 健康检查 ✓

输出：一个可交付的变更（代码 + 测试 + 评审报告 + 门禁证据），全程状态可查、失败可重入重试
```

## 二、为什么做它（问题与价值）

**现状问题**
1. AI 编码是"聊天框生成"——没有流程、没有门禁、没有证据、不可追溯
2. 技能包（SKILL.md）只是提示词，靠 AI"自觉执行"，**没有强制力**
3. 需求→代码→测试→评审→CI→验证 散落在对话里，**无法机器对账**
4. 门禁（编译/测试/覆盖率/静态分析）没有被机械化串进流程

**它提供什么（价值）**
- **强制力**：门禁不过，阶段不推进（红灯即停）
- **可追溯**：每个阶段留档（prompt、输出、命令、退出码、报告）
- **可恢复**：状态持久化，失败可重入 / 断点续跑
- **可观测**：阶段耗时、Token 成本、门禁拦截统计

## 三、目标与非目标

**目标（v1）**
- 单机可跑的 Spring Boot 服务，管理"项目 → 变更 → 阶段 → 门禁 → 产物"
- 6 阶段流水线状态机（可暂停 / 重试 / 续跑）
- 门禁执行器：真实执行 Java/Maven 工具链并判定
- LLM 编排：阶段化 prompt + 结构化输出 + 降级 / 预算
- 在 xhs-project 真实跑通 ≥1 个需求，产出证据

**非目标（明确不做，防范围蔓延）**
- 不做 IDE 插件；不做完整 PRD 解析平台（那是参考实现的领域）
- 不做多语言（v1 只 Java/Maven，Go/Python 留 v2）
- 不做分布式 / 多节点调度
- 不做复杂前端（v1：REST API + 简单静态看板）
- 不替代人的决策（不可逆操作留人确认，沿用技能包的人机协同）

## 四、用户与核心场景

**用户**：使用 AI 编码工具的 Java 开发者 / 团队；第一个用户是自己（给 xhs-project 跑需求）

**场景**
1. 接入项目：扫描技术栈 → 生成 / 校验 `.harness/` 资产
2. 创建变更：一句话需求 → 进入流水线
3. 阶段推进：渲染 prompt → 调 LLM → 产出 → 门禁判定 → 通过才推进
4. 失败处理：重试 / 重跑 / 暂停 / 取消；产物版本化
5. 查看：变更详情、阶段时间线、门禁结果、产物、证据
6. 统计：交付周期、门禁拦截次数、覆盖率变化、Token 成本

## 五、里程碑与验收（14 天）

| 里程碑 | 内容 | DoD（完成定义） |
|---|---|---|
| **M1（D1-2）** 骨架 + 领域 + 状态机 | Maven 多模块骨架（JDK17 构建通过）；状态机 + 转移规则 + 单测 | `mvn test` 绿；状态机单测覆盖合法/非法转移与重试语义 |
| **M2（D3-5）** 资产解析 + LLM 编排 + ① 阶段端到端 | `.harness/` 解析（frontmatter/技能清单/占位符渲染）；LLM provider + 结构化输出 + 重试；跑通 ① | 对真实需求生成 ≥3 条可测 AC 并通过 AC_TESTABLE 门禁 |
| **M3（D6-8）** 门禁执行器 + 产物 + API | ProcessBuilder 执行器（超时/流读取/解析）；COMPILE/TEST/COVERAGE 门禁；REST API + 持久化 + 产物落盘 | ②③ 阶段端到端（真实跑 `mvn`） |
| **M4（D9-10）** xhs 接入 + 真实跑通 + 取证 | 接入 xhs-project：①-⑤ 静态门禁（`mvn -pl <模块> -am` 精准构建，**不起服务**）；⑥ 用自带演示项目（H2 + 健康检查 + 冒烟） | 一个变更从 ① 走到 ⑥；产出变更记录 + 门禁证据 + 覆盖率报告 + 周期数据 |
| **M5（D11-14）** 加分项（按剩余时间选做） | 多模型路由 + 降级链 + Token 预算三段；知识库检索注入；ArchUnit 门禁；静态看板；审计哈希链 | 每项独立可演示 |

> M1-M4 为必须；M5 全部可砍。M4 若时间紧，可降级为"①-③ 跑通"。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| LLM 输出不稳定 | 结构化校验 + 重试（≤2 次）+ 降级；schema 尽量简单 |
| 门禁耗时长（mvn 全量） | 按阶段裁剪命令；M4 用单模块试点 + `-pl/-am` 精准构建 |
| 范围蔓延 | 非目标清单 + M5 可砍 |
| xhs 多模块编译慢 / 依赖重 | 先单模块；固定 JDK17（`JAVA_HOME=/env/javaEnv/jdk17`） |
| 时间不够 | M1-M4 保底，M5 可选 |
| **机器资源紧张**（可用内存 ~5.5G、MySQL 未运行、xhs 平台起不动） | 引擎用 H2 文件模式；门禁单模块精准构建；⑥ 用自带演示项目；不启动 xhs 平台容器 |

## 七、面试映射（做完能讲什么）

| 模块 | 可讲的考点 |
|---|---|
| 状态机 + 重入幂等 | 状态机设计、幂等、断点恢复、并发 |
| 门禁执行器 | 进程管理、超时、**流阻塞坑**、命令注入防护 |
| LLM 编排 | Prompt 工程、结构化输出、重试 / 降级、成本治理 |
| 产物对账 | 一致性、可追溯、审计 |
| 多模块 + Docker | 工程结构、部署 |
| xhs 跑通 | 真实数据（拦截次数、覆盖率、周期） |

## 八、与技能包 / 上游的关系

- 技能包 = 方法论资产（`.harness/` 提示词），本项目 = **运行时**（执行 + 门禁 + 状态）
- 参考实现（PRD 平台）做"文档解析"，本项目做"**执行引擎**"——定位互补不冲突
- 可给上游提 PR：opencode 注册适配、多模块 Maven 检测等
