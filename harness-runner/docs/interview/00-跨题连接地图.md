# 跨题连接地图（面试串联用）

> 单题答得好是及格；能把题串成"系统叙事"才是高分。以下是 harness 体系的叙事链与连环追问路径。
> 配套：`00-题目索引.md`、`专题-决策追问演练.md`、`专题-深度自拷打.md`。

## 一、八条叙事链（被追问时的展开路径）

**链 1 · 完整交付链（最常被串："你这套东西跑一遍给我看看？"）**
`07 LLM①`（需求 → AC 草案）→ `04 假绿`（AC_TESTABLE 形式校验）→ `03 门禁执行器`（编译）→ `03`（测试：真跑 mvn）→ `02 状态机`（阶段通过=全门禁绿 → advance）→ `05 覆盖率`（CI 阶段）→ `06 证据链`（产物/事件/日志落盘）
一句话：**"需求变成可测的 AC，AC 变成门禁，门禁全绿状态机才推进，每一步都留证据。"**

**链 2 · 验证可信链（问法："我凭什么信你的绿灯？"）**
`04 假绿`（不信 exitCode：要 surefire 汇总 + testsRun>0）→ `05 覆盖率`（不信控制台：解析 XML 报告）→ `03 进程坑`（不信"卡住"：超时强杀 + 进程树）→ `06 证据`（不信记忆：全量日志 + 产物版本 + 事件流）→ `专题-深度自拷打 1/10`（**承认边界：假测试防不住、证据可篡改**）
一句话：**"绿灯要有证据、失败要有原因、证据要能搬运；同时承认它防不了'假测试'和'篡改'——这是路线图不是已解决。"**

**链 3 · 进程执行链（问法："跑外部命令有什么坑？"）**
`03 假死`（并发读流，管道的锅）→ `03 超时`（waitFor + destroyForcibly）→ `03 进程树`（ProcessHandle.descendants）→ `03 截断`（内存保尾部 + 全量日志）→ `03 启动失败`（结果而非异常）→ `专题-深度自拷打 6`（信任边界：无沙箱）
一句话：**"假死是管道缓冲、超时要收整棵树、内存截断日志全量、启动失败算门禁失败不算崩溃。"**

**链 4 · 状态与恢复链（问法："进程挂了/点了两次会怎样？"）**
`02 转移表`（非法转移不改状态）→ `02 attempt`（重试+1 留历史）→ `02 rehydrate`（恢复一致性校验）→ `06 原子写`（不留半文件）→ `06 重启续跑`（换实例继续推）→ `专题-深度自拷打 4/5`（**崩溃点矩阵 + 并发 P0 认账**）
一句话：**"状态显式、重试留痕、恢复校验、写入原子；write-ahead evidence 保证崩溃重跑安全；并发锁 + 版本 CAS 已落地（D5）。"**

**链 5 · LLM 治理链（问法："模型输出你敢信吗？"）**
`07 结构化`（JSON mode + 解析 + 代码块剥离）→ `07 校验`（AcValidator 形式校验）→ `07 留证`（prompt/响应原文 + 调用索引）→ `07 fake fallback`（无 Key 的诚实演示）→ `专题-深度自拷打 3/8/9`（**规格 GIGO / 重试策略 / 注入传播**三项认账）
一句话：**"把模型输出当不可信输入：格式校验、内容校验、全量留证；判定权在机器手里；① 阶段规格有人工确认闸门（HITL 已落地）——重试/误报治理仍是缺口。"**

**链 6 · 方法论↔运行时↔试点（问法："技能包和引擎什么关系？"）**
`01 定位`（方法论资产 vs 运行时）→ `14 技能包`（6 阶段/SDD-TDD/双轴评审/软闸门/参数化）→ `07`（技能包的 harnessing 技能变成引擎的 LLM 任务）→ `17 xhs 复盘`（真实工程证据）→ `00 讲述稿`（简历叙事）
一句话：**"技能包解决'让 AI 守规矩'，引擎解决'规矩被真的执行'，xhs 证明'真的跑得动'——三层互为证据。"**

**链 7 · 安全链（问法："你这工具安全吗？"）**
`10 安全`（命令注入：模板+list 形式）→ `10`（路径注入：changeId 白名单，探针实测）→ `专题-深度自拷打 7`（workspace/project 信任模型）→ `专题-深度自拷打 6`（构建即代码：无沙箱）→ `专题-深度自拷打 9`（prompt 注入 + 脱敏）
一句话：**"注入面：命令、路径、prompt 三条；前两条已修，prompt 与沙箱是边界——讲清信任模型比吹安全更可信。"**

**链 8 · 规模化演进链（问法："多项目多用户怎么扩？"）**
`06 文件仓储`（单机 + 证据可搬运）→ `11 规模化`（H2/MySQL 适配器 + 乐观锁）→ `11`（执行 worker 池 + 队列 + 隔离）→ `11`（多租户 + RBAC）→ `专题-深度自拷打 5/6`（并发与沙箱）
一句话：**"存储换 DB、执行变工作池、权限加多租户；文件仓储的'可搬运'是特性不是缺陷——但扩容方案要诚实说'设计'。"**

## 二、连环追问路径（面试官视角的"下钻路线"）

| 入口问题 | 下钻路线 | 终点（必须能答的部分） |
|---|---|---|
| "介绍一下这个项目" | 讲述稿 → 01 → 链1 | 三层结构与一个真实数字 |
| "你怎么验证它有效" | 链2 → 04 → 05 → 17 | 红→绿证据包 + 假绿修复 |
| "跑外部命令有什么坑" | 链3 → 03 → 深度自拷打6 | 假死/进程树 + 信任边界 |
| "挂了怎么办" | 链4 → 02 → 06 → 深度自拷打4/5 | 崩溃点矩阵 + 并发 P0 |
| "AI 部分做了什么" | 链5 → 07 → 深度自拷打3 | ① 阶段链路 + HITL 缺口 |
| "和 skills 包什么关系" | 链6 → 01 → 14 | 两层结构与 0→1 归属 |
| "有什么没做" | 深度自拷打弱点清单 → 18 缺口 | P0×2 + P1×4 逐条 |
| "为什么是你" | 链6 + 能力矩阵（进程/并发/状态机/LLM/安全/测试） | 一个项目六种能力 |

## 三、与 xhs 项目的串联（两项目互相引用）

- xhs 是 runner 的**被服务方与证据来源**（93 测试 / 22% 覆盖率 / 红绿演练）。
- runner 的假绿修复、门禁设计，可回到 xhs 面试文档的"测试治理/假测试四模式/CI 指纹校验"议题上形成呼应。
- 两套面试文档共用一枚"王炸"：**"指标可以骗人，证据不会"**——xhs 讲"DLQ 指标恒 0 是算错"，harness 讲"exitCode=0 可以是假绿"。
