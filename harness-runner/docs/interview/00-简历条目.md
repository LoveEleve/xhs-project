## 项目介绍

harness-runner 是一个把"需求分析 → 编码 → 单测 → 评审 → CI → 部署验证"六阶段流程做成可执行系统的 Java 引擎，配套我从 0 到 1 建设的 Harness 技能包（6 语言参数化、30+ 技能、约 5 万行文档）作为方法论资产。引擎 6 个 Maven 模块、7,000 行 Java、158 个单测，包含：自研变更状态机、真跑外部构建命令的门禁执行器、证据链、LLM 需求分析（AC 生成 + 人工确认）、CLI 工具。技术栈 JDK 17、JUnit 5、ProcessBuilder、JaCoCo、PIT、OpenAI 兼容 API，单机运行、无外部服务依赖。已在 15 微服务电商工程（xhs my-xhs-common）完成真实演练：六阶段跑通，注入的失败测试被门禁拦截，修复后重试转绿直到 DONE。

## 职责描述（Responsibilities）

- 流水线与方法论：设计六阶段交付流水线（需求 → 编码 → 单测 → 评审 → CI → 部署验证），配套 SDD-TDD、双轴评审（Spec 匹配 / 规范合规）、软闸门（存量债只减不增）；技能包用占位符做 6 语言参数化（语言基础块 + 框架差异块，一处改动全语言生效，覆盖百余框架），引擎与技能包同源，方法论直接作为运行时规格。
- 变更状态机与恢复：6 阶段转移表为唯一事实源，`StageRun` 唯一键 `(changeId, stage, attempt)`，失败重试 attempt+1 且历史保留可对比；从持久化恢复时校验状态一致性；产物按 `(type, version)` 只增不改 + SHA-256；替换引擎实例可从当前阶段断点续跑。
- 门禁执行器：ProcessBuilder list 形式（不经过 shell）；stdout/stderr 并发读流，避免管道缓冲写满导致"命令假死"；超时 `destroyForcibly` + `ProcessHandle.descendants()` 清理整棵进程树（Maven 会 fork JVM）；内存 256KB 保尾部截断、全量日志落盘；启动失败按门禁失败返回而非抛异常。选型放弃 Maven Invoker API，换取任意命令、真实退出码与进程隔离。
- 测试与覆盖率门禁：测试门禁 fail-closed——必须解析到 surefire 汇总且有效执行数 > 0，无汇总 / 0 测试 / 全部被跳过一律判红，红时 reason 带失败数证据（命令模板固定 `-B -ntp`，因为 `mvn -q` 会吞摘要）；覆盖率解析 JaCoCo XML 报告而非控制台文本，并处理"外部 DTD 被 JDK 安全解析拦截"的问题（关闭外部 DTD 加载，保留 XXE 防护）。
- 变异与增量门禁：接入 PIT 解析 `mutations.xml`，变异得分 = `KILLED / (KILLED + SURVIVED + NO_COVERAGE)`，用于识别断言为空的"假测试"；增量覆盖率用 `git diff` 变更行与 JaCoCo 行级覆盖求交，只卡变更行，无可执行行则跳过阈值。两项均为 opt-in（变异需项目声明 `pitest-junit5-plugin`，增量需 git 仓库 + base ref）。
- 证据链与防篡改：一个变更对应一个自包含目录（状态快照 / 阶段运行 / 事件流 / 版本化产物 / LLM prompt 与响应原文）；文件写入原子化（tmp + ATOMIC_MOVE）；changeId 白名单校验防路径穿越（用 `../../evil` 探针实测越界后修复）；事件流 SHA-256 链式哈希 + `verify` 命令可定位篡改行；JSONL 读取容忍崩溃半写。
- HITL 与并发控制：LLM 生成的规格草案必须人工 `approve` 才能进入编码（`AWAITING_APPROVAL` 状态，approve 校验待审批产物存在，未审批推进返回独立退出码 3）；per-change 锁（跨进程 FileLock + 进程内 Semaphore）使推进串行化，save 增加版本前置条件（文件版 CAS，版本未前进即拒）。
- LLM 阶段与交付形态：OpenAI 兼容客户端（JDK HttpClient，可换模型/端点）+ prompt 模板 + JSON 结构化输出（含代码块剥离）+ AC 可测性校验；调用计量与 prompt/响应全量留证；无 API Key 走 fake provider 保证可演示。CLI 提供 create/advance/approve/verify/status 五个命令与语义化退出码，`java -jar` 单文件运行；覆盖率门禁零侵入（插件坐标由 CLI 注入），已并入 xhs 工程仓库独立构建。

## 关键结果（Key Achievements）

- 真实工程演练（15 微服务 xhs）：注入失败测试被门禁拦截（`94 tests / 1 failure / exit=1`，变更置 FAILED），修复后 attempt 2 转绿，CI 行覆盖率 22.0% ≥ 阈值 20.0%，最终走到 DONE；7 次阶段执行、红绿双份报告与全量日志归档，可完整回放。
- 门禁有效性基准（故障注入，真实执行 mvn）：7 类故障 100% 检出（编译错误、失败测试、无测试、全部跳过、覆盖率跌破、假测试、新增未测代码），5 项基线零假阳性；基准反向暴露 2 个"假绿"盲区（0 测试、全部跳过）并当场修复；同一假测试在 TEST 门禁为绿、在变异门禁判 0% 红。
- 异常与边界实测：20 万行输出不阻塞（并发读流）；400ms 超时强杀 `sleep 30` 且子进程写标记用例通过；路径穿越探针越界后修复为白名单；事件链篡改精确定位到行（exit 1）；文件写入无 `.tmp` 残留；换引擎实例断点续跑。
- 规模与资产：技能包 30+ 技能 / 6 语言 / 百余框架 / 约 5 万行规范与文档；引擎 6 模块 / 7,000 行 Java / 158 单测 + 2 组真实环境用例（真实 Maven 集成、故障基准）；4 个证据包 60+ 文件；两次提交 212 文件并入 xhs 仓库。
- 接入与交付：任意 Maven 工程可接入，覆盖率门禁零侵入、变异与增量门禁 opt-in；CLI 单文件运行，无外部服务依赖。
- 边界主动披露：LLM ② 编码闭环、多模型降级、token 预算、知识库注入、REST API + H2 均为设计未实现。
