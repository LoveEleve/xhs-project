# 第03题 | 门禁执行器：进程假死、超时、进程树、输出截断

> 难度：★★★★★｜频率：★★★★★｜区分度：高
> 关键词：ProcessBuilder、并发读流、假死、destroyForcibly、ProcessHandle.descendants、输出截断、全量日志

## 问题

问题：门禁要"真跑 mvn"。子进程假死了怎么办？超时了怎么收尸？输出几 MB 怎么处理？

## 面试可讲版（五段式）

**① 业界背景**
Java 里执行外部命令有三个层次：`Runtime.exec`（玩具）、`ProcessBuilder`（标准，但要自己处理流/超时/进程树）、`commons-exec`/Maven Invoker（封装但绑定或同 JVM）。**"命令假死"是经典事故**：`Process` 的 stdout/stderr 是有限缓冲管道，父进程不读，子进程写满缓冲区就永久阻塞——表现为"命令永远不结束"。

**② 项目选择**
自研 `ProcessExecutor`，四件事做到位：
- **并发读流**：stdout/stderr 各一个 daemon 线程持续读，边读边做两件事——写内存有界缓冲 + 写全量日志文件；
- **超时与进程树**：`waitFor(timeout)` 超时后，先快照 `ProcessHandle.descendants()`，再 `destroyForcibly` 父进程与所有后代（Maven 会 fork JVM，只杀父进程会留孤儿）；
- **输出治理**：内存默认 256KB 上限，**保留尾部**（mvn 的汇总/错误在尾部）+ "省略前 N 字符"标记；完整日志落盘，`outputRef` 进证据；
- **启动失败也是结果**：命令不存在/工作目录不存在 → 返回 exitCode=-1 + 原因，而不是抛异常炸引擎（门禁失败要让上层状态机处理）。

**③ 坑**
- **假死用例**：跑 20 万行输出，断言"能在超时前完成 + 内存输出被截断"——如果没并发读，子进程会卡死在管道上，测试超时失败；
- **进程树用例**：`(sleep 1; touch marker) & sleep 30`，300ms 超时强杀后等 2 秒断言 marker 不存在——只杀父进程的话子进程会活下来写 marker；
- **日志文件名**：`类型-时间戳.log` 同毫秒会撞车 → 加原子序号（review 时发现）；
- **中断路径**：线程被中断时先 kill 再 drain/close，避免丢日志（review 时补）。

**④ 兜底**
- 已知局限：`Runtime.exec` 级的 PATH 解析依赖环境继承；Windows 需 cmd 包装（未做，单机 Linux 定位）；
- 超大输出且需要**头部**证据时（如"第一行报错"）目前会丢——设计上靠全量日志文件兜；
- 快照与父进程死亡间的竞态窗口极小，但理论存在。

**⑤ 话术**
> "门禁执行器的价值就在这些坑里：并发读流防假死、超时清整棵进程树、内存截断保尾部、全量日志留证据。这三个用例——假死/超时/进程树——全部是真实进程，不是 mock。"

## 追问与参考回答

**追问1：为什么不用 Maven Invoker API？** 三个理由：通用性（未来要跑 npm/go test/自定义脚本）、进程隔离（Maven 崩了不影响引擎）、真实退出码；代价就是流/超时/进程树要自己处理——这些坑也是价值。
**追问2：超时时间怎么定？** 按门禁类型给默认（compile 3 分钟 / test 10 分钟 / coverage 15 分钟），可按项目覆盖；超时保证"最坏有界等待"。
**追问3：退出码语义？** 超时用 `timedOut` 标志 + `isAlive ? -1 : exitValue`（Linux 强杀通常是 137）；门禁判定是 `!timedOut && exitCode==0`，不依赖具体信号码。
**追问4：环境变量怎么注入（JAVA_HOME）？** `GateCommand.env` 合并到继承环境之上；CLI/测试里显式注入 `JAVA_HOME=/env/javaEnv/jdk17`，避免用默认 JDK 跑错版本。
**追问5：孙进程持有管道会不会让你卡住？** 我专门验证过：不会。JDK 在直接子进程退出时会 drain 并关闭管道（`ProcessImpl.processExited()`），实测 49ms 返回；我把"以为会卡 4 秒"的假设证伪后留了记录——**不靠感觉，靠探针**。

## 面试官评分点

**高级开发级**：能说清假死根因（管道缓冲）、超时后清进程树、并发读流必要性。
**架构师加分**：启动失败语义（结果而非异常）、输出截断策略（保尾部）、日志证据链、对 JDK 行为的源码级求证。
**危险信号**：`readLine` 单线程读一个流、超时只 destroy 不清理、把几 MB 输出全塞内存。
