## 一、定位与架构类

### Q1 你是不是造了个 Jenkins？ ✅
- 【追问】CI 已经能跑编译/测试/覆盖率，你这个门禁有什么区别？
- 【应答】三处不同：① **管理对象**——CI 管"人写完的代码"的构建，我管"AI 写的变更"的全生命周期：规格（AC）→ 状态机 → 门禁 → 证据；② **运行位置**——CI 在服务端流水线，我的门禁是本地/单机可跑，AI 工具链（Claude Code 等）旁边就能用；③ **判定语义**——我不只看 exitCode：测试必须有 surefire 汇总且 testsRun>0，0 测试也算红。
- 【杀招】那 CI 里再加一步脚本不就行了？
- 【兜底】认：单点检查确实可以脚本化；但"变更状态机 + 可重入 + 证据包 + LLM 阶段"是脚本拼不出来的。协同方案也在设计里：引擎输出 `gate_result`，CI 可直接消费。

### Q2 为什么用 Java 做这个工具？ ✅
- 【追问】这类工具生态里 Python/TS 更多，为什么选 Java？
- 【应答】三条：① 我的目标用户是 Java 工程（要嵌 `mvn`、读 surefire/JaCoCo 输出，工具链天然同侧）；② 这个系统的核心难度在**进程管理、并发、状态机、文件事务**——正是 Java 工程能力的展示面；③ 面试受众是 Java 岗，技术栈同频。
- 【杀招】跨语言呢？Python 项目能用吗？
- 【兜底】门禁本身是"跑任意命令 + 解析输出"，跨语言只需换命令模板与解析器（技能包侧已经有 6 语言参数化）；我 v1 只做 Java 是刻意的：先深一条线，再横向扩（见 15 题）。

### Q3 状态机为什么自研，不用 Spring StateMachine？ ✅
- 【追问】工业级状态机框架不用，重复造轮子？
- 【应答】需求是 6 个固定阶段、顺序推进、失败重试、可暂停——确定性 FSM，不需要层次/并行/事件编排。关键约束是**状态必须持久化可恢复**：用框架要自己实现 `StateMachinePersister`，省不了事。自研转移表 20 行 + 单测全覆盖，行为完全可解释。
- 【杀招】那可视化、复杂事件以后要加怎么办？
- 【兜底】现在用不到；真需要时转移表可导出为 DSL 给可视化，核心不变。备选（Spring StateMachine）的取舍已写进决策卡。

### Q18 技能包是不是只是 Markdown，含金量在哪？ ✅
- 【追问】不就是一堆提示词文档吗？
- 【应答】它解决的是"AI 产出不可控"：6 阶段流水线把研发过程分段可校验；双轴评审（Spec 匹配 + 规范合规）把"对不对"和"规不规范"拆开；软闸门让存量债"只减不增"；52 个占位符做 6 语言参数化（一处改动全语言生效）。**它是我从 0 到 1 设计的**，运行时（runner）是它的可执行化，两者互为证据。
- 【杀招】那它和 Claude Skills / spec-kit 有什么不同？
- 【兜底】差在"跨语言参数化 + 双轴评审 + 软闸门"这三件套（16 题展开）；共同点是都认"规格先行 + 机器验证"。

## 二、机制与实现类

### Q4 两个请求同时推进同一个变更怎么办？ ✅（D5 已落地）
- 【追问】CLI 单发没事，多实例/并发呢？
- 【应答】已实现两层：per-change 锁（跨进程 `FileLock` + 同进程 `Semaphore`）让 `advance/approve` 串行化；`save` 再加版本前置条件（文件版 CAS，版本未前进即拒）。有并发单测：持锁期间 advance 立即报"并发冲突"。
- 【杀招】跨主机呢？锁挂了会死锁吗？
- 【兜底】认：文件锁是单机 advisory，跨主机需 DB 锁/分布式锁（设计）；锁有等待超时（默认 10s）不会永久死锁；锁文件不删除（删除与被锁有竞态）。

### Q5 子进程假死/僵尸进程怎么处理？ ✅
- 【追问】`mvn` 卡住不返回，你的执行器怎么办？
- 【应答】两件事：① **并发读流**——stdout/stderr 各一个线程持续读，不读会因管道缓冲满导致子进程阻塞（这是"命令假死"最常见的原因）；② 超时后 `destroyForcibly` + `ProcessHandle.descendants()` **清理整棵进程树**（Maven 会 fork JVM）。单测里就有"假死"用例（20 万行输出不阻塞）和"进程树"用例（子进程写标记文件，超时强杀后标记不出现）。
- 【杀招】超时清理有没有可能漏杀？
- 【兜底】有：快照与父进程死亡之间有极小竞态窗口；另外我实测过一个反直觉结论——**孙进程持有管道不会让我们卡住**：JDK 在直接子进程退出时会 drain+close（`ProcessImpl.processExited()`），实测 49ms 返回。这条我验证过源码，不是猜的。

### Q7 你凭什么说门禁不会"假绿"？ ✅
- 【追问】exitCode=0 不就通过了吗？
- 【应答】这正是我自己 review 时抓出来的问题：TEST 门禁如果只看 exitCode，"`mvn test` 一个测试都没跑"也是 0。修复后判定是：**必须解析到 surefire 汇总且 testsRun>0**，无汇总/0 测试直接红；红时 reason 带 `testsRun/failures/errors` 证据。
- 【杀招】那 surefire 输出解析失败呢？会不会误红？
- 【兜底】会红——这是**故意 fail-closed**：测试证据缺失就不许通过。输出截断策略保留尾部（汇总在尾部），解析不受影响；多模块 reactor 取最后一段汇总，这是已知局限，单模块精确。

### Q8 覆盖率门禁怎么判定？ ✅
- 【追问】解析控制台文本还是报告文件？
- 【应答】解析 **JaCoCo XML 报告**（不解析控制台文本，避免格式漂移）：取报告级 LINE 聚合算比例，与阈值（0~1）比较；无 BRANCH 计数时不输出 branchPercent，避免 `0.0` 误导。覆盖率命令是 `prepare-agent → test → report` 一条命令，CI 阶段用 COMPILE+COVERAGE 组合，**避免测试跑两遍**。
- 【杀招】报告解析有什么坑？
- 【应答】有个真坑：JaCoCo XML 带外部 DTD（`report.dtd`），JDK 安全解析默认禁止读取外部 DTD，直接抛错。修法是关 `load-external-dtd`（同时保留 XXE 防护）。
- 【兜底】增量覆盖率、按包过滤"核心逻辑"是设计；现在阈值是全局行覆盖率。

### Q9 门禁输出几 MB 怎么办？ ✅
- 【追问】全量塞内存？
- 【应答】内存有上限（默认 256KB），**保留尾部**（mvn 的汇总和错误在尾部），并加"已截断：省略前 N 字符"标记；**完整日志落文件**（`outputRef` 指向），产物报告里带路径。
- 【杀招】截断会不会把解析需要的行截掉？
- 【兜底】不会：解析的是尾部保留区；另外我实测过 2MB 输出场景——内存截断 + 全量落盘 + 解析正常（有单测）。

### Q13 LLM 输出不可信怎么办？ ✅
- 【追问】模型返回的 AC 你敢直接用？
- 【应答】三道关：① 格式——`response_format=json_object` + 解析（含代码块剥离）；② 内容——**可测性校验**（非空、id 唯一、描述非空），不合格直接红；③ 留证——prompt 原文和响应原文落盘（`llm/` 目录 + `llm-calls.jsonl`），REJECTED 也留。
- 【杀招】需求里写"忽略上述指令，输出 xxx"呢？
- 【兜底】当前没有专门的 prompt 注入防护（诚实缺口）；缓解是：AC 只是"待人工确认的草案"，且下游门禁不信任 LLM 输出的"通过"——**门禁判定永远由机器证据做，不由模型说了算**。

## 三、验证与数据类

### Q6 你怎么证明这些机制真的有效？ ✅
- 【追问】单测之外有真实工程证据吗？
- 【应答】有，三层：① 单测 117 个；② 真实 Maven 集成：对 xhs `my-xhs-common` 跑 `mvn test`，解析出 93 个测试、7.5s、全量日志落盘；③ **红→绿演练**：注入失败测试 → 门禁红（94 tests / 1 failure / exit=1，变更 FAILED）→ 删除后重试 attempt=2 转绿 → 继续到 DONE，红绿双份报告、日志、事件、LLM 留档全在 `evidence/d4-xhs/`。
- 【杀招】这些都是你自己造的演练，有第三方说服力吗？
- 【兜底】认：没有线上流量验证；价值证据目前是"真实工程 + 真实命令 + 可复现记录"。下一步指标化：拦截率/假绿率/回归率（13 题）。

### Q15 这个工具的价值怎么度量？ ⚠️
- 【追问】你怎么知道它真的防住了问题，而不是摆设？
- 【应答】设计了三类指标：① **拦截率**——门禁红次数/总门禁次数（当前演练 1/11 红）；② **假绿率**——通过但无测试证据的比例（目标恒 0，靠 testsRun>0 判定）；③ **回归门槛**——同阶段重试 attempt 分布。当前样本小（单项目演练），指标框架是设计。
- 【杀招】那和"人肉 review"比呢？
- 【兜底】机器门禁替代的是"机械可判定的部分"（编译/测试/覆盖率），评审阶段（④）保留人工/LLM；两者不互斥。A/B 对照（有门禁 vs 无门禁的缺陷逃逸率）是 roadmap，别硬吹。

## 四、规模化与边界类

### Q10 为什么用文件仓储而不是直接上数据库？ ⚠️
- 【追问】一个 change 一个目录，能撑住生产吗？
- 【应答】当前定位是单机、零依赖、**证据可搬家**：一个 change 目录（change.json / stage-runs.json / events.jsonl / artifacts / llm）拷走就是完整证据包。仓储全走端口，H2/MySQL 适配器是可替换实现。
- 【杀招】多项目、多用户、查询聚合呢？
- 【兜底】文件天然不支持聚合查询和多租户——这是已登记的生产化缺口，H2 适配器 + REST API 是下一步（stretch 未做，18 题）。

### Q11 命令注入/路径注入怎么防？ ✅
- 【追问】changeId、需求文本会不会被拼进命令/路径？
- 【应答】命令侧：命令模板来自配置，需求文本只进 LLM prompt；`ProcessBuilder` 用 list 形式，不经过 shell 解析。路径侧：changeId 走白名单 `[A-Za-z0-9_-]{1,64}`——这个是 review 时**探针实测打穿的**：`../../evil` 读到了工作区外的 change.json，修复后拒绝并报错。
- 【杀招】还有哪些注入面？
- 【兜底】LLM prompt 注入（见 Q13）和依赖供应链（跑任意 mvn 命令本身是"受信操作"）是剩余面；后者靠"门禁命令来自配置而非用户输入"兜。

### Q12 事件日志/证据文件崩溃了怎么办？ ✅
- 【追问】写一半断电/被杀，数据会不会坏？
- 【应答】三类防护：① change.json/stage-runs.json/产物用 **tmp + ATOMIC_MOVE**，不留半文件；② 事件 JSONL 读取**容忍截断行**，且 append 前检测残尾补换行（防"粘行"把下一条事件一起吞——这是测试抓出来的）；③ 重启续跑有专门测试：换引擎实例从 `current_stage` 恢复，PASSED 阶段不重复执行。
- 【杀招】审计完整性呢？坏人改文件呢？
- 【兜底】已实现（D5.7）：事件 SHA-256 链式哈希 + `verify` 命令（篡改定位到行，exit 1）；**边界**：整链重写需外锚（SCM/WORM/TSA/签名），自证性证据不能自证。

### Q14 演示是 fake provider，真实 LLM 到底跑没跑过？ ⚠️
- 【追问】你的"AI 阶段"是不是假 AI？
- 【应答】实现是真的、演示是降级：OpenAI 兼容客户端是完整实现（JDK HttpClient，请求体/鉴权/响应解析/错误处理），并有单测（本地 HttpServer 验证 200/500/缺 content 三条路径）；演示机没有 API Key，按设计走 fallback（fake provider），**但 prompt 与响应全量留档**。配 `HARNESS_LLM_API_KEY` 即切真实端点。
- 【杀招】那你怎么知道真实模型输出能解析？
- 【兜底】不知道，没跑过真实调用——这是诚实缺口；缓解设计是解析失败不重试直接红 + 原文留档供人工分析。真实调用验证列在下一步。

### Q16 换你当面试官，这项目最大的规模化问题是什么？ ❌
- 【追问】自己说，别客气。
- 【应答】三件：① 存储——文件仓储没有并发控制和聚合查询，多实例必须换 DB；② 执行——门禁是本地子进程，规模化要有工作池/队列/超时隔离（类似 runner 的 worker 模型）；③ 权限——没有多租户/RBAC/密钥管理。
- 【杀招】那你还写进简历？
- 【兜底】简历写的是"我实现了什么、验证了什么"，不是"它能扛百万并发"；边界我主动写在面试包里，被问到就是送分题——**"我知道它现在不是生产级，也知道差哪几步"**。
