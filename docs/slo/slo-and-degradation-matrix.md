## 四、本轮修复案例（可讲故事）
1. **home 线程池饥饿**（P99 1.6s→307ms）：外层请求与内层 Feign 任务共用 `aggregatorPool`（核心线程被外层占满 + LinkedBlockingQueue 不触发扩容）→ 内层任务饿死等超时。修复：内层 future 统一走独立 `batchFeignPool`；layer1 超时 3s→可配 800ms。
2. **限流语义**：`BizException(40202)` 原先统一 HTTP 200；改为 **HTTP 429**（网关/业务语义一致，监控可见）。单测覆盖。
3. **发布脚本自引用软链**：回滚时把 `current` 指向自身导致无法启动；已加校验。
4. **网关高吞吐误判**：8k~16k RPS 实为 429 快速通道（限流放行 50 QPS）。
