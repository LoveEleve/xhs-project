# 00 · 购物车域：深度探索与学习路线

> **口径**：先讲**生产环境/行业常见做法**，再对照本项目；代码不代表应然标准。
> 本文按"域发现 9 步"做探索（入口→执行流→侧扫→设计决策→分类→依赖→拓扑→覆盖），再给学习路线。
>
> **一句话**：购物车 = **购买意图暂存区**；核心不是 CRUD，而是 **Redis 权威 + 顺序同步 + 下单清车/取消回补**。
>
> **系列 8 篇**：00 总纲 → 01 模型/Redis 三结构 → 02 写路径（7 Lua）→ 03 同步链路（顺序/CAS/CLEAR）
> → 04 读路径/匿名合并 → 05 对账/Redis 恢复 → 06 下单清车/取消回补（C-006）→ 07 工程收口。

## 1. 入口与主流程（9 步之 1–2）

**入口**：`CartApplication` + `CartController`（add/update/remove/check/checkAll/clear/list/merge/count）；
消费者（`OrderCreatedCartConsumer`/`OrderTerminationCartConsumer`/`CartSyncConsumer`/`CartEventSinkConsumer`）；
Job（`CartReconcileJob`）。

**流程 A：写路径**

```
Controller → CartService（skuExists 校验，商品服务不可用降级放行）
→ Lua 原子操作（7 脚本）→ 异步顺序消息 CART_TOPIC:{action}（userId 分区）
```

**流程 B：读路径**

```
getCartList：Pipeline 一次 RTT 取 items/checked/sort
→ 批量 Feign 查 SKU（失效降级标记）
→ 组装 valid/invalidReason + checkedAmount（仅有效项）
→ Redis 为空：cleared 标记 → 空车；否则 MySQL 恢复回写
```

**流程 C：同步链路**

```
CART_TOPIC:{action} → CartSyncConsumer（ORDERLY，upsert t_cart_item）
                    → CartEventSinkConsumer（ORDERLY，append t_cart_event）
时间戳 CAS + CLEAR 屏障（进程内，有界）
```

**流程 D：下单清车/取消回补（C-006）**

```
ORDER_TRANSACTION_TOPIC → 仅 source=CART → removeBySkus（cart_remove_batch.lua）
ORDER_TERMINATION_TOPIC → items → merge 回补（max + checked=true）
三标记：cleared / restore-pending / restored + 定序握手
```

**流程 E：对账/恢复**

```
CartReconcileJob：Redis↔MySQL 三场景；水位线 300s；防双份全丢（items 不存在且无 cleared → 跳过删除）
```

**流程 F：匿名合并**

```
mergeAnonymousCart：客户端带入匿名 items → 逐项 merge（max + 上限）
```

## 2. 目录侧扫与设计决策（9 步之 3–4）

## 5. 现状（C-006 之后）

| 项 | 当前状态 |
|---|---|
| 下单清车 | ✅ 事件订阅（ORDER_TRANSACTION_TOPIC，仅 source=CART）；批量原子删；cleared 去重 |

| 匿名车 | ⚠️ 客户端带入（服务端不存）；换设备丢车/可伪造 |
| 库存可见 | ❌ 列表不返回库存；真实校验在下单 |
| 优惠试算 | ❌ 只有 `Σ 单价×数量`；结算价在 order |
| 失效项 | ⚠️ 只标 `valid/invalidReason`，不自动清理 |
| 退款回补 | ❌ 不做（非标准行为） |
| 联动对账 Job | ❌ 不做（靠 order Outbox+DLQ；演进） |
| CLEAR 屏障 | ⚠️ 进程内（有界；ORDERLY 假设；重启后退化时间戳 CAS） |
| 对账锁 | ⚠️ 固定 600s；大批量超时窗口 |
| skuExists | ⚠️ 商品服务不可用降级放行（列表 valid 兜底） |

## 7. 缺口与风险（不藏）

1. **无库存可见/无优惠试算**：购物车只是"意图暂存"，价格/库存以订单为准；
2. **匿名车客户端**：换设备丢车、可伪造（服务端不存）；
3. **失效项不自动清理**：只展示标记；
4. **退款不回补**：非标准行为；
5. **联动无对账 Job**：靠 order Outbox + DLQ + 标记 TTL；
6. **CLEAR 屏障进程内**：依赖 ORDERLY；重启/rebalance 降级时间戳 CAS；
7. **对账锁 600s**：大批量超时窗口；
8. **skuExists 降级放行**：幽灵 SKU 靠列表 valid 兜底；
9. **TTL 刷新分散**：写脚本只有 add/merge 内刷新，其余靠 `CartService.refreshTTL` 统一续期——维护时两处都要看。
10. **无运行时/压测**：真实 MQ 乱序/重启恢复未实测。
