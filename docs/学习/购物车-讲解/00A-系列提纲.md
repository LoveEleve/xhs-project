## 01 模型与 Redis 三结构（业务）

- **目标问题**：购物车存什么？为什么 Redis 是权威？三结构各管什么？
- **核心结论**：Hash(items sku→qty)、Set(checked)、ZSet(sort 加购时间)、cleared 标记；`{userId}` 同 slot；30 天 TTL（Service refreshTTL + add/merge 双保险）；MySQL 兜底 + 事件流水。
- **小节**：
  1. 例子：加购/改量/勾选/清空，三结构怎么变
  2. 表模型（t_cart_item/t_cart_event）
  3. Redis 四键与 TTL；Cluster 同 slot
  4. 为什么 Redis 权威、MySQL 兜底
- **证据**：`CartService`、`RedisKeyConstants`、`02-购物车.md` §3。
- **追问链**：Redis 丢了怎么办（→05）→为什么不用 MySQL 权威→TTL 滑动。

## 03 同步链路：顺序消息 + CAS + CLEAR 屏障（分布式）

- **目标问题**：Redis 写成功后，MySQL 怎么同步？乱序/重复/清空竞态怎么处理？
- **核心结论**：`CART_TOPIC:{action}` 以 userId 为分区键 `asyncSendOrderly`；消费端 `ConsumeMode.ORDERLY`；UPSERT + 时间戳 CAS（eventTime）+ CLEAR 屏障跳过旧事件；事件流水 append-only。
- **小节**：
  1. 例子：同用户加购→删除→加购，消息顺序
  2. 顺序消息（分区键/ORDERLY）
  3. 时间戳 CAS + 同毫秒序列号
  4. CLEAR 屏障（进程内、有界、重启降级）
- **证据**：`CartService` 发送、`CartSyncConsumer`、`CartEventSinkConsumer`、C-006。
- **追问链**：为什么 userId 分区→屏障为什么进程内→重启怎么办。

## 04 读路径与匿名合并（业务）

- **目标问题**：购物车列表怎么读？失效商品怎么标？匿名车怎么合并？
- **核心结论**：Pipeline 一次取三结构 → 批量 Feign 查 SKU → `valid/invalidReason` → `checkedAmount` 只算有效项；Redis 为空时 cleared 标记/MySQL 恢复；匿名 items 客户端带入逐项 merge（max）。
- **小节**：
  1. 例子：列表展示/失效项/全选
  2. Pipeline + 批量 SKU + 有效性
  3. checkedAmount/全选语义
  4. 匿名合并（客户端带入、max、上限）
- **证据**：`CartService.getCartList/mergeAnonymousCart`、`ProductFeignClient`。
- **追问链**：库存/优惠为什么不在这里→失效项清理→匿名车伪造。

## 05 对账与 Redis 恢复（一致性）

- **目标问题**：Redis 与 MySQL 不一致怎么办？Redis 丢了怎么办？
- **核心结论**：三场景（Redis 有 MySQL 无→INSERT；不一致→UPDATE 以 Redis 为准；Redis 无 MySQL 有→DELETE）；水位线 300s 跳过在途；`items` 不存在且无 cleared → 跳过删除（防双份全丢）；SCAN 补扫纯 Redis 用户；事件 30 天清理。
- **小节**：
  1. 例子：MQ 丢消息、Redis 故障
  2. 三场景与水位线
  3. 防双份全丢/SCAN 补扫
  4. 锁 600s 的边界
- **证据**：`CartReconcileJob`、`02-购物车.md` §4-E。
- **追问链**：以谁为准→水位线为什么 300s→Redis 全丢。

## 06 下单清车/取消回补（分布式）

- **目标问题**：下单后怎么清车？未支付取消/超时怎么回补？乱序/重复怎么处理？
- **核心结论**：事件订阅式（ORDER_TRANSACTION_TOPIC 仅 source=CART 清车；ORDER_TERMINATION_TOPIC 回补）；三标记（cleared/restore-pending/restored）+ 定序握手；merge=max+checked=true；直接购买单零副作用；clear 永久失败自愈。
- **小节**：
  1. 例子：正常下单清车；取消回补；秒取消竞态
  2. 清车/回补链路与 source/items 载荷
  3. 三标记 + 定序握手（两到达序）
  4. 重复投递/部分失败重入/直接购买单
- **证据**：`CartOrderLinkageService`、`OrderCreatedCartConsumer`、`OrderTerminationCartConsumer`、C-006。
- **追问链**：为什么不用 Feign→孤儿窗口怎么修→重复投递抬数量怎么防。
