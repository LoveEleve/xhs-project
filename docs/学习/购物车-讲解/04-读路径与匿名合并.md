# 04 · 读路径与匿名合并

> **口径**：先讲**生产环境/行业常见做法**，再对照本项目；代码不代表应然标准。
>
> **一句话**：购物车列表 = **Pipeline 一次取三结构 + 批量 SKU + valid/invalid 标记 + checkedAmount**；
> 匿名车 = **客户端带入 items + 逐项 merge（max/上限）**。
>
> **本篇带走**：① Pipeline ② Redis 空/恢复 ③ 批量 SKU/有效性 ④ 金额/全选 ⑤ 匿名合并。
> 前置：01。证据：`CartService.getCartList/mergeAnonymousCart`、`ProductFeignClient`。

---

## 0. 例子：购物车页

```
用户打开购物车
  → Pipeline：items + checked + sort 一次 RTT
  → 批量 Feign 查 SKU（status/spuStatus/price/name）
  → 组装：valid/invalidReason；checkedAmount=Σ(选中且有效 的 单价×数量)
  → 按加购时间倒序

匿名用户登录
  → 客户端带入匿名 items → 批量校验 → 逐项 merge（max + 上限）
```

## 1. 生产环境怎么做（淘宝/行业常见）

| 能力 | 常见做法 |
|---|---|
| 列表 | 缓存/DB 读取 + 批量商品信息；分页/分组 |
| 有效性 | SKU/SPU 下架、库存、价格变化 → 失效区 |
| 金额 | 单价×数量 + 优惠试算/凑单 |
| 全选 | 只对有效项；取消全选 O(1) |
| 匿名合并 | 服务端匿名车/客户端带入；同 SKU 取 max |
| 多端 | 同一用户车实时同步 |

## 2. 本项目的实现（代码证据）

### 2.1 Pipeline：一次 RTT 取三结构

```java
List<Object> pipelineResults = stringRedisTemplate.executePipelined(
    (RedisCallback<Object>) connection -> {
        connection.hashCommands().hGetAll(itemsKeyBytes);          // items
        connection.setCommands().sMembers(checkedKeyBytes);        // checked
        connection.zSetCommands().zRevRangeWithScores(sortKeyBytes, 0, -1); // sort
        return null;
    });
```

- 三结构一次网络往返（对比 3 次 RTT）；
- 解析顺序固定：0=items Map、1=checked Set、2=sort ZSet；
- Pipeline 结果解析失败/脏 key 会跳过（防脏数据打挂列表）。

### 2.2 Redis 空：cleared 标记 vs MySQL 恢复

```java
if (itemsMap.isEmpty()) {
    if (hasKey(clearedMarkerKey(userId))) {
        return emptyCart();                 // 用户清空 = 真空车
    }
    itemsMap = restoreCartFromDb(userId, itemsKey, checkedKey, sortKey); // Redis 丢了 → MySQL 恢复
    if (itemsMap.isEmpty()) return emptyCart();
    // O-P2-7-1：恢复后必须重读 Pipeline（否则 checked/sort 仍用空结果）
    pipelineResults = reReadPipeline(...);
}
```

- `cleared` 标记区分"用户清空"与"Redis 数据丢失"；
- 恢复回写 `items/checked/sort` 三结构；重读修正首次响应（否则 checked=false）；
- 恢复依赖 MySQL 兜底（异步落库 + 对账保证数据）。

### 2.3 批量 SKU 与有效性

```java
Map<Long, SkuDTO> skuMap = batchGetSkuInfo(skuIds);
// 一次 Feign batchGetSkuDetails；失败返回空 Map（降级，不阻塞列表）
```

有效性判断（SKU + SPU 双维度）：

```java
if (sku.getStatus() != 1 || sku.getSpuStatus() != 1) {
    builder.valid(false).invalidReason("商品已下架");
} else {
    builder.valid(true);
}
// sku == null → valid=false, invalidReason="商品信息获取失败"
```

- **不检查 `sku.stock`**：商品域的 stock 是冗余占位，真实库存在 inventory；
- SKU 不存在/商品服务不可用 → `商品信息获取失败`；
- 下架/删除 → `商品已下架`；不自动清理，只展示标记。

### 2.4 金额与全选

```java
if (isChecked && valid && sku.getPrice() != null) {
    checkedCount += quantity;                                  // 数量，不是品种数
    checkedAmount = checkedAmount.add(price.multiply(quantity));
}
...
totalCount = itemsMap.size();                                   // 品种数（含失效）
allChecked = validCount > 0 && validCheckedCount == validCount; // 只看有效项
```

- `checkedAmount` 是**实时单价 × 数量**，不含优惠（结算价在 order 试算）；
- 失效项不计入金额/数量；`allChecked` 只看有效项；
- `totalCount` 是品种数，不是件数。

- 同 SKU 取 `max(已有, 匿名)`（不累加，避免重复合并抬数量）；
- 新项受 50 种/单品 99 上限；
- **匿名车在客户端**：服务端不存；换设备丢车、请求体可伪造（已知边界）；
- 合并幂等：多次合并结果一致（max）。

### 2.6 边界与缺口

| 能力 | 本项目 | 影响 |
|---|---|---|
| 库存可见 | ❌ | 列表不返回库存；下单校验 |
| 优惠试算 | ❌ | 结算价在 order |
| 失效区/自动清理 | ⚠️ 只标 `valid/invalidReason` | 不自动删 |
| 匿名车 | ⚠️ 客户端带入 | 丢车/可伪造 |
| 多端同步 | ⚠️ 单用户单车 | 简化 |
| 价格快照 | ❌ 实时 SKU 价 | 下单用订单快照 |

## 4. 十二个坑

1. **Pipeline 顺序解析错**：0/1/2 对应 items/checked/sort，别按名称猜。
2. **空车 ≠ Redis 丢失**：没有 cleared 标记就恢复，否则真空车会从 MySQL 拉回旧数据。
3. **恢复后不重读**：checked/sort 仍用空结果，首次响应勾选丢失（O-P2-7-1）。
4. **批量 Feign 失败当全无效**：商品服务不可用会全部 `商品信息获取失败`；要降级/告警。
5. **只看 SKU 状态**：SPU 下架也要判失效（双维度）。
6. **拿 `sku.stock` 判库存**：占位值；真实库存在 inventory。
7. **`checkedAmount` 含失效项**：只算 valid+checked。
8. **`checkedCount` 当品种数**：它是数量（件数）；`totalCount` 才是品种数。
9. **`allChecked` 含失效项**：只看有效项。
10. **匿名车伪造/丢车**：客户端带入；服务端只能做上限/merge。
11. **失效项不清理**：只展示标记；需手动清理/后续演进。
12. **列表价当成交价**：实时 SKU 价；下单用订单快照。

## 5. 值不值得深挖 / 一句话

- **值得**：Pipeline、空车 vs 丢失、批量 SKU/双维度有效性、checkedAmount/allChecked、匿名 merge——购物车读路径核心；
- **一句话带过**：VO 字段、排序；
- **一句话**：**列表 = Pipeline 三结构 + 批量 SKU + valid/invalid + checkedAmount；匿名车 = 客户端带入 + merge max。**
- 写路径见 **02**；同步/对账见 **03/05**。

**面试口径**："购物车列表用 Pipeline 一次取 items/checked/sort，批量 Feign 查 SKU，valid 看 SKU+SPU 状态，checkedAmount 只算选中且有效；Redis 空时先看 cleared 标记，否则从 MySQL 恢复并重读；匿名车客户端带入，逐项 merge 取 max、受 50/99 上限。"
