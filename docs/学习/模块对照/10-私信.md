# 10 · 私信（my-xhs-im）· 梳理

> 系列：模块对照 · 阶段一（梳理）。**只记录，不讨论**（问题线索见 §7，待讨论）。
> 口径：标尺 = **真实 IM 私信系统该有的样子**（见 §2）。
> 规模：18 文件 / 2133 行。端口 19014。无 Job、无测试。深度档：**轻**（WebSocket + 路由 + at-least-once 机制密度高）。
> 建立：2026-10-12。

---

## 1. 定位与职责

**WebSocket 私信**：实时收发 + 离线消息 + 会话管理。技术选型 **Spring MVC WebSocket（Tomcat NIO）非 WebFlux**（注释自述：MyBatis-Plus 阻塞式，混用 Reactive 复杂度爆炸；Tomcat NIO 下空闲连接不占线程）。

单用户单连接（新连接踢旧 + **跨实例踢线**）；不依赖 MQ（纯 WebSocket + Redis Pub/Sub 定向路由）；无 Feign 出入口（网关直连，App 通过 gateway 接入）。

## 2. 应然基准（标尺）与实然对照

| 应然能力 | 我们 | 差距 |
|---|---|---|
| 实时收发 + 会话管理 | ✅ WebSocket 消息分发（CHAT/ACK/READ/TYPING/PING/LOGOUT）+ 会话列表/历史/软删 | — |
| **消息不丢**（投递语义） | ✅ **at-least-once**：先落离线副本（ZSet）→ 推送 → 成功删/失败留守 → 客户端 ACK 才 ZREM；未 ACK 重连补发（客户端按 msgId 去重） | — |
| 消息有序 | ✅ 会话级 **Redis INCR seqNo**（M8）；离线补发按 seqNo 排序 | — |
| 会话 ID 稳定唯一 | ✅ 首条消息在**用户对分布式锁**内分配雪花 ID 并写关系表，双方复用（P0-B：曾用 `min*31+max` 哈希拼接会碰撞串台） | — |
| 多实例路由 | ✅ Redis 路由键（`route`/`online` 双键，90s TTL 心跳续期）+ **定向** Pub/Sub（M4：替代 MQ 广播 N-1 浪费）+ 跨实例踢线 | — |
| 连接与鉴权 | ✅ WS 两步法鉴权（EventSource/WS 不能带 Header → 5min `ws_ticket` JWT + jti 一次性 GETDEL）；连接上限 50000；踢旧连接 | — |

> 附：`ImConsistentHashLoadBalancer`（一致性哈希 LB，150 虚拟节点）**全仓未接线**——见 §7-1。

## 3. 数据模型

**自有库 `my_xhs_im`**（3306/3307，readwrite=true；**无 ShardingSphere 配置——"分片"仅为注释设计预留**）：

| 表 | 键/要点 | 说明 |
|---|---|---|
| `t_chat_message` | idx_conversation / idx_conversation_seq / idx_sender / idx_receiver / idx_created_at | conversation_id（"首条消息分配、双方复用；**勿用哈希拼接**"）+ seq_no（会话内序号） |
| `t_chat_user_relation` | `uk_user_peer(user_id,peer_id)` + idx_user_updated | 双向各一行；last_message/last_content/unread_count/is_deleted（软删后对方新消息自动复活） |

**Redis 键**：

| 键 | 用途 |
|---|---|
| `myxhs:im:route:{u:{uid}` / `myxhs:im:online:{u:{uid}`（hash tag 同 slot） | 路由表（值=serverId）/ 在线标记；TTL 90s=3×心跳，心跳原子续期 |
| `myxhs:im:route:{serverId}` | **Pub/Sub Channel**（定向）：CHAT / 97 踢线 / 98 TYPING / 99 已读回执 |
| `myxhs:im:offline:{uid}` | 离线消息副本（ZSet：member=msgId，score=时间）；≤1000 条、7d TTL（M25 原子脚本） |
| `myxhs:im:unread:{uid}` | 未读 Hash（field=peerId）——**无 TTL**（见 §7-4） |
| `myxhs:im:seq:{conversationId}` | 会话内序号（INCR） |
| `myxhs:im:conv:lock:{min}:{max}` | 会话分配/首条消息的 Redisson 分布式锁 |
| `myxhs:im:ticket:{jti}` | WS 票据登记（5min，握手 GETDEL 一次性消费） |

## 4. 核心链路

### A. 连接建立（两步法 + 踢线 + 补发）

```
POST /api/im/ws/ticket（X-User-Id）→ 5min ws_ticket JWT + jti 登记 Redis
ws GET /api/im/ws?ticket=xxx → ImHandshakeInterceptor：
    解析 JWT → type 必须=ws_ticket（防 access token 冒充）→ jti GETDEL 一次性（防 URL 日志泄露重放）
    → userId/traceId 入 session attributes
afterConnectionEstablished：上限 50000 → put 替换旧连接
    → registerRoute（返回旧路由）→ 本实例踢旧（complete）
    → 旧路由在别的实例 → kickRemote（Pub/Sub msgType=97）
    → pushOfflineMessages（ZSet → DB selectBatchIds → 按 seqNo 排序 → OFFLINE 批次；
       DB 已不存在的副本顺手清理；推送后等客户端 ACK 逐条 ZREM）
心跳：PING → PONG + renewRoute（双键原子 EXPIRE Lua）
断开：remove(userId, session【双参】) 成功才 unregisterRoute（Lua 比较删除：serverId 匹配才删——防旧连接晚到的关闭误删新路由）
```

### B. 发送消息（handleChat：锁 → 事务 → 路由 → 未读 → ACK）

```
校验（receiver 空/自己 → NACK；内容空 → NACK；>2000 截断且防代理对切半）
→ Redisson 会话锁（user 对 min:max，tryLock 3s 失败 → NACK"发送过于频繁"）内：
     resolveConversationId（关系表**双向**查，无则雪花分配——P0-B 防"双向并发首条消息"裂成两个会话）
     seqNo = INCR myxhs:im:seq:{conversationId}（M8）
     MessagePersistService.saveMessageWithTransaction【独立 Bean 保 @Transactional 生效】：
         INSERT 消息 + 双方会话 upsert（updateOnNewMessage 定向列 + unread_count SQL 原子自增；
         并发首条 DuplicateKey → 降级定向更新；极端竞态补插兜底）
→ storeOfflineMessage 先落副本（at-least-once：防 Pub/Sub 即发即忘丢消息）
→ 路由：本实例直推成功→删副本；跨实例→Pub/Sub `route:{serverId}`；不在线→副本留守
→ 未读 HINCRBY myxhs:im:unread:{receiver} peer +1
→ ACK 给发送者（含 msgId/timestamp/traceId）
```

### C. 跨实例订阅（ImRouteSubscriber）与已读/输入

```
ImRouteSubscriber（组内专属 Channel，@PostConstruct 起容器）：
    msgType 97=KICK→closeLocalSession；98=TYPING / 99=READ_NOTIFY→content 即完整 JSON 直接透传；
    普通 CHAT→重建 JSON（含 seqNo）推送
    推送成功→删离线副本；失败→**仅聊天消息**降级存离线（瞬时信号不重放）
handleRead：DB 定向清零（防整行覆盖）→ Redis 清零 → 通知对方（READ_NOTIFY 同路由逻辑）
handleTyping：仅当对方在线才发（不存储）
```

## 6. 机制清单（无 Job）

| 机制 | 说明 |
|---|---|
| 心跳续期 | 客户端 PING；服务端 PONG + 路由双键原子续期（90s=3×间隔） |
| 踢线（跨实例） | registerRoute 返回旧路由 → Pub/Sub KICK → 旧实例 close → 其 unregister 被 Lua 拒绝（不误删新路由） |
| 离线副本三删 | ①推送成功即删 ②客户端 ACK 删 ③DB 已无行清理（防"永远等不到 ACK"挂 7 天） |

## 7. 现状边界与问题线索（仅记录，待讨论）

1. **一致性哈希 LB 未接线**：`ImConsistentHashLoadBalancer`（150 虚拟节点/FNV-1a/m13 指纹缓存）声明用法 `spring.cloud.loadbalancer.configurations=my-xhs-im-consistent-hash`，但**全仓无此配置**——实际路由走 Redis route 键（动态、自愈），LB 是早期"连接粘性"设计的遗留组件（死组件候选）；
2. **"分片"注释 × 单库部署**：ChatMessage/MessagePersistService 注释称"按 conversation_id 分片/同分片本地事务"，实际=单库读写分离（无 ShardingSphere）——设计预留，注释超前；
3. **at-least-once 依赖客户端契约**：不 ACK → 副本压 7 天 × 每次重连整批补发（重复风暴靠客户端按 msgId 去重兜底）——契约写在 Handler javadoc，属"服务端尽力、客户端配合"口径；
4. **无 TTL 家族**：`myxhs:im:unread:{uid}`（HINCRBY 无 EXPIRE）与 `myxhs:im:seq:{cid}`（INCR 无 EXPIRE）——对比通知域 30d 回收策略；IM **无对账 Job** 兜底，残留键只能被读写覆盖收敛；
5. **WS 消息频率无服务端限流**：handleChat 仅靠会话锁（3s tryLock）与长度截断兜底；对比 REST 侧 read/delete 有 @RateLimit——刷消息/滥用面观察点；
6. 小项：`allowed-origins` 默认 `*`（可配，环境债）；消息无外发 MQ（审计/多端同步无扩展位，当前单端模型）；`online` 键仅 isOnline 自用。

## 8. 阶段二讨论结论（2026-10-19 · C-013 私信模块生产化改造）

> 阶段二（讨论）：§7 六条线索逐条核实（两轮深探：18 文件全读 + SQL 基线核对 + 异常窗口逐条推演）。

### 8.1 线索裁决（§7 六条）

| # | 线索 | 裁决 | 落地 |
|---|------|------|------|
| 1 | 一致性哈希 LB 未接线 | **评估后移除** | 死组件删除（无配置声明 + 无 Feign 场景；与"未启用组件不说成已生效"口径一致） |
| 2 | "分片"注释 × 单库 | 修（注释） | ChatService/MessagePersistService 注释对齐："共享存储 + conversation_id 预留分片键（单库）" |
| 3 | at-least-once 依赖客户端契约 | 修（补发送侧） | clientMsgId 可选幂等（F6）：重放 ACK 原 msgId；失败删标记 |
| 4 | 无 TTL 家族 | **修 unread（30d 滑动）+ seq 记录** | unread 补 TTL（miss 由连接重建/DB fallback 收敛）；**seq 有意不加 TTL**（重置破坏排序；演进=锁内 DB 播种） |
| 5 | WS/REST 无限流 | 修 | /ws/ticket 10/min + conversations 30/min + messages 60/min + unread-count 60/min |
| 6 | 小项（online 键/白名单） | **online 键评估后移除** | 死键族（零消费者）；allowed-origins 可配（环境债，记录） |

### 8.2 两轮深探新增发现（D1~D7）

| # | 发现 | 裁决 | 落地 |
|---|------|------|------|
| D1 | **僵尸未读**：软删会话不清 DB unread → 复活时 5+1=6 回归 + 列表(DB)/总数(Redis)口径分裂 | **修（真 bug）** | 软删 SQL 同置 `unread_count=0`（注解断言防回归） |
| D2 | **双写无收敛**：多漂移窗口 + 无对账 Job | **修（轻量）** | 连接时 DB→Redis 重建未读（天然对账点，无需 XXL）+ TTL |
| D3 | **post-persist 无降级**：路由/离线/Redis 异常 → 无 ACK（重发重复） | **修** | 各步降级 + **ACK 必达**（echo C-012 F3 原则） |
| D4 | handleRead Redis 清零未降级 → 中断 READ_NOTIFY | 修 | try/catch 降级继续 |
| D5 | SQL 基线副本漂移 ×2（conversation_id 注释/idx_user_updated——migration 修了库没修基线） | **修** | 4 副本同步（echo C-010 t_note_event 同型） |
| D6 | 死列 is_read + conversationId 实体旧口径 | 修 | 实体字段移除 + javadoc 对齐 |
| D7 | 小项（peerName 恒 null/targetServerId 未用/ver 未校验/0 值 field） | 记录 | 讲 |
| F1 | 幽灵未读竞态（+1 在推送后） | **修** | 未读前移（InOrder 单测锁定） |
| F2 | registerRoute 非原子（同族 renew/unregister 均 Lua） | 修 | REGISTER_LUA 单脚本 |
| F3 | 连接上限缺 containsKey 豁免（SSE 同型有） | 修 | 老用户满员可重连 |

### 8.3 核心设计（学习要点）

- **未读双源收敛**（D1/D2/F1）：前移（消竞态窗口）+ 软删清零（消僵尸）+ 连接重建（轻对账——"连接事件是天然收敛点，不需要 Job"）；
- **ACK 必达**（D3）：持久化=DB 权威 → 后段降级不让发送方重发；与 C-012"能对账收敛的宁可吞"同一原则；
- **发送侧幂等**（F6）：clientMsgId 可选 + SETNX→msgId 映射（重放直接 ACK 原 msgId）+ 失败删标记（家族 removeMark）；
- **踢线竞态三件套**（保留好样本）：双参 remove + Lua 比较删除 + 跨实例 KICK。

### 8.4 记录不做（讲）

多设备/多端；真写扩散（共享存储 1 份保留）；分片落地；seq 播种（演进）；peerName/peerAvatar（资料未接线）；ver 校验；allowed-origins 收紧（环境债）。
