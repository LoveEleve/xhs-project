## 一、目标

用统一的"**先梳理、后讨论**"节奏，把所有核心模块逐个弄明白：

- **阶段一（当前）= 梳理**：一个个模块，把"它是什么 / 有什么对象 / 怎么跑 / 怎么交互 / 现状边界"**梳理清楚**——只记录，不讨论；
- **阶段二（后置）= 讨论**：对照真实世界（应然），把每个模块的 **业务逻辑 / 工程 / 分布式 / 架构 / 解决方案** 五类问题**逐条摆盘重新讨论**，讨论定稿才产出结论与面试口径。
- ⚠️ 两个阶段**不混**：梳理期不做问题裁决；讨论期才开始"你裁决我记录"。

## 四、标准流程（两阶段五步）

**阶段一 · 梳理（当前执行）**
1. **侦察**：读码采事实（每个"有什么"都核过代码，不脑补）；
2. **梳理文档**：按模板写清该模块（六段，见 §五）；
3. **问题线索**：只**记录**疑点/缺口线索（标注"待讨论"），不做定性、不做裁决。

**阶段二 · 讨论（全部门梳理完成后 / 或按模块逐个进入）**
4. **问题摆盘 + 逐条讨论**：应然对照（真实世界怎么做）→ 五类问题定性（真问题/取舍/误解）→ 裁决（修/讲/不做）→ 方案；真 BUG 先证伪再动手，修不修由用户拍板；
5. **沉淀**：讨论结论回写文档 + 缺口三档 + 面试口径。

**每份梳理文档模板（应然锚定版，六段）**：
① 定位与职责（它是什么、服务谁）
② **应然基准（标尺）+ 实然对照**：真实系统该模块该有什么 → 我们有什么/缺什么/简化成什么（逐项）
③ 数据模型（实然细节）
④ 核心链路（怎么跑；与应然的关键差异标注）
⑤ 对外契约 + Jobs/关键机制（实然细节）
⑥ 现状边界与问题线索（**仅记录，待讨论**）

> 口径：**标尺永远是"真实系统该有什么"**，我们的代码只是对照项——防止"以实现为标准"漏掉根本没有的能力。

**"限高"规则（防教科书化，2026-10-11）**：
- 应然项纳入标准：**与交易/内容主线强相关 或 面试高频**；边缘项（B 端治理/批量工具/资质审核等）一句话带过、不展开；
- 每模块应然维度 **≤ 8 项**；梳理文档目标 **120–200 行**（应然部分 ≤ 1/3）；
- **深度分级**（总工作量收敛）：

| 档 | 模块 | 做法 |
|---|---|---|
| 深 | 订单✅ / 库存✅ / **支付** / **优惠券** | 应然+实然+机制+线索全做 |
| 中 | 商品✅ / **购物车** / **内容** / **搜索** | 应然 ≤8 项 + 实然 + 关键机制 |
| 轻 | 计数 / 社交分析 / 通知 / 私信 | 实然快扫 + 应然 3–5 项 + 线索一行制 |
| 支撑轻 | home BFF / gateway（核心） | 按需 |

（阶段二讨论后，另行产出"三档裁决 + 面试口径"章节或独立文档。）

## 六、纪律（沿用既有）

- 实然必须核过代码；数字/口径**先自检再沉淀**（review 制度）；

- 讨论驱动：文档是"讨论的记录+结论"，不是"我单方面写的答案"。
