# 05 · 内容（my-xhs-content）· 梳理

> 系列：模块对照 · 阶段一（梳理）。**只记录，不讨论**（问题线索见 §7，待讨论）。
> 口径：标尺 = **真实内容社区该有的样子（小红书式）**（见 §2）。
> 规模：38 文件 / 3400 行。端口 19002。深度档：**中**。
> 建立：2026-10-11。

---

## 1. 定位与职责

**内容社区核心域**（小红书的主战场）：笔记全生命周期（发布/草稿/编辑/删除/详情/列表）+ 评论（楼中楼）+ **敏感词治理（DFA）** + **Feed 推送源**（本地消息保障）+ 事件/行为流水 + 推荐/搜索数据表。

在生态里的位置：

```
发布 → 本地消息（同事务）→ FEED_TOPIC → home.FeedPushConsumer（分发到粉丝 inbox）
t_note → Canal(note_instance) → 搜索索引（search 域）
互动事件 → SOCIAL_TOPIC:{SHARE|VIEW|COMMENT|UNCOMMENT|NOTE_DELETE} → 计数域
```

## 2. 应然基准（标尺）与实然对照

| 应然能力 | 我们 | 差距 |
|---|---|---|
| 内容创作（图文/视频/话题/标签/草稿） | ✅ 图文 + videoUrl + cover + topicIds + tags + 草稿流 | — |
| 内容审核（机审 → 人审队列 → 发布） | ⚠️ DFA 机审 + `AUDITING` 状态 + 管理端 `auditNote`（驳回写 rejectReason）——**但发布链路直接置 APPROVED，AUDITING 无正常入口**（注释自述"DFA 通过即自动发布"） | **名存实亡** |
| Feed/分发（发布 → 粉丝流） | ✅ 本地消息（同事务）+ FEED_TOPIC + **进度续传** + 重试/死信 | 超配 |
| 互动（评论楼中楼 / 点赞收藏分享） | ⚠️ 评论完整（楼中楼 + 游标分页 + DFA）；**计数交给计数域**（事件驱动，不双写） | — |
| 内容治理（下架/驳回/申诉/恢复） | ⚠️ OFFLINE 状态 + 驳回；无申诉/恢复入口 | 部分 |
| 反垃圾/风控 | ⚠️ 频控（@RateLimit）+ DFA；无设备/行为风控 | 简化 |
| 热搜 / 推荐数据供给 | ⚠️ 表在（`hot_search_snapshot` / `item_feature` / `user_behavior`），生成归 search 域 | 部分 |
| 事件与埋点 | ✅ `t_note_event`（发布时点）+ `user_behavior` | ⚠️ **事件表建表缺失**（见 §7-1） |

## 4. 核心链路

### A. 发布（`publishNote` / `publishDraft`）——本地消息是主角

```
DFA 敏感词检测（标题+正文）→ 入库（PUBLISHED + APPROVED）
→ note_event 记录（同事务，catch 不阻塞）
→ 本地消息 insert（同事务，"{}" 占位 → 回填 body → updateById）
→ afterCommit：asyncSend FEED_TOPIC → onSuccess：markSent
失败路径（**双段兜底**，FeedMessageRetryJob 两个 @Scheduled）：
① **消息补发**（30s）：扫 status=0 重投（SCAN=500 / MAX_RETRY=3 → 死信 status=3）；
② **推送补偿**（60s）：status=1 但 push_status∈(0,1) 且超窗口 → 重投 MQ；**断点续推**（FeedPushConsumer
   按批写 `myxhs:feed:push:progress:{localMsgId}` + MySQL push_cursor 兜底）；重投计数（Redis 24h）超限 → 置终态 3 + 指标；
   **重投即排下次时间**（60→600s 指数退避 ±20%，P3/2026-09-27）
草稿发布：DRAFT→PUBLISHED+APPROVED 条件更新 + 同款 feed 推送 + 详情缓存双删（清草稿期空值占位）
```

### B. 读路径（`readNoteDetail`）

- `CacheHelper.getWithCacheAside`（30min、空值防穿透、miss/hit 打点）；
- **RV30 审核双条件**：详情/列表/分享只返回"已发布 **且** 审核通过"（防审核态异常数据外泄）；
- 浏览计数：**单条详情入口每次请求发 VIEW 事件（缓存命中亦计）**；批量路径不计数（O1 修复，防 Feed 刷新虚增）。

### C. 编辑 / 删除

- 编辑：字段级更新；**已发布态编辑重检 DFA**；afterCommit 详情缓存**延迟双删**；
- 删除：级联逻辑删除评论（**用 delete 返回值替代 selectCount 防 TOCTOU**）+ 缓存失效（详情 + 评论数）+ 事件补偿计数（`UNCOMMENT` 带数量、`NOTE_DELETE` 通知 Feed 清理）。

### D. 互动

- 评论：DFA → 父评论/被回复人校验 → 入库 → 缓存失效 + `COMMENT` 计数事件；**楼中楼=两级**（子评论再回复时 `parentId` 修正为根评论 + `reply_to_id` 记被回复人——"两级平铺 + @回复"，非无限嵌套）；楼中楼 + 游标分页（MAX_PAGE_SIZE=20）；`UserFeignClient.internalUserInfo` 用于评论相关取用户信息（非死代码）；
- 分享：`SHARE` 事件——**统一 MQ 事件驱动计数**（注释：避免 Redis 直写与 MQ 双写导致计数翻倍）。

### E. 敏感词治理（DFA + 动态更新）

- **Trie**（嵌套 Map + `\0` 结束标记）；**预处理防绕过**：全角转半角 + 去干扰符（空白、`*#@!.,。，`）+ 小写——词库与文本两侧同套预处理；
- `detect` 返回命中词集 → 发布/编辑/评论/草稿发布**命中即拒**（错误信息带上命中词）；
- 动态词：Redis Set（`myxhs:sensitive-word:list`）+ **增/删后 PUBLISH 广播所有实例重建 Trie**（`RedisPubSubConfig` 监听；Redis 缺席时 `@Autowired(required=false)` 降级静态词库）；
- 管理端点维护（`SensitiveWordAdminController`）。

### F. 笔记状态机

`DRAFT(0) → {AUDITING, PUBLISHED}`；`AUDITING → {PUBLISHED, OFFLINE}`；`PUBLISHED → {OFFLINE}`；`OFFLINE → {}`（`canTransitTo` 校验；`AUDITING` 状态当前无正常入口）。

## 6. Jobs 与关键机制

- **FeedMessageRetryJob**（非 XXL，两个 `@Scheduled`）：① **消息补发 30s**（SCAN=500 / MAX_RETRY=3 → 死信）；② **推送补偿 60s**（断点续推 + 退避 60→600s + 重投超限置终态 3）；
- DFA Pub/Sub 重建；LocalFileStorageService（`/data/uploads`，5MB，JPEG/PNG/GIF/WebP）；
- 无 XXL-Job（`feedCleanupJob` 属 home 模块）。

## 7. 现状边界与问题线索（仅记录，待讨论）

1. **`t_note_event` 建表缺失（静默丢失）**：建表语句仅在 `init-all.sql` 的 **coupon 段**（543 行）；content 库的两套基线（mysql-content-init / migration）**均无此表**；`recordNoteEvent` catch 后仅打日志（"不阻塞发布"）→ **任何按基线初始化的环境，笔记事件流水都在静默丢失**（发布本身正常）——须手工建表或修正划归；
2. **审核链路"半闭环"**：发布直接 APPROVED（"DFA 通过即自动发布"）、`AUDITING` 无入口；`auditNote` 是后期补的**最小审核闭环**（通过/驳回，注释自述"原实现无任何变更入口 → 新笔记永远不可见"）——现状 = **可人工事后审、无发布前审核队列**；真实内容平台的审核队列仍是应然差距（面试可讲点）；
3. `t_local_message` 同样被 init-all 错划 coupon 段（content 库基线有、init-all 无）——Feed 可靠性的物理基础**在 init-all 场景缺表**（与 §7-1 同型，见 00A 附 3-1）；
4. **JPA 探针**（默认关闭：`content.jpa.enabled=true` 才装配）：`/api/content/internal/jpa-probe` 对照 `jpaCount`/`mybatisCount`——MyBatis vs JPA 技术选型对照实验的遗留件（含 `NoteJpaEntity`/`NoteJpaRepository`/`ContentJpaConfig` 三件套）；
5. 已自清理的"死缓存键"足迹（NOTE_LIST_USER / COMMENT_LIST "只删不填"→ 移除，P2-13/O-Comment-1）——缓存键治理意识；
6. 内容域的"数据表在、生成不在"（热搜/推荐特征/行为流水归 search 域生成）——跨域数据供给的观察点。
