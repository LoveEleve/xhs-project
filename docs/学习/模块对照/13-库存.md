## 1. 定位与职责

为平台提供"**永不超卖、可自愈**"的库存能力：下单预占（preDeduct）/ 支付确认（confirm）/ 取消回退（release）/ 退款回补（refundRestore）。
架构定位：**Redis = 实时主账（L1）；MySQL = 持久备份账（L2，允许慢半拍）；对账 = 收敛（L3）**。明确取舍：**允许少卖，绝不允许超卖**。

## 3. 数据模型

**Redis（C-008 单键家族，全部 `{skuId}` tag）**：

| 键 | 类型 | 用途 |
|---|---|---|
| `inventory:{skuId}:stock` | String | 可用库存（单键） |
| `inventory:{skuId}:prededuct:{orderId}` | String=数量 | 预扣记录（物理 TTL=到期+600s 缓冲） |
| `inventory:{skuId}:terminated:{orderId}` | String | 终结墓碑（04B 拦截迟到预扣） |
| `inventory:{skuId}:prededuct:index` | ZSet | 过期索引（member=orderId，score=到期ms；空则自动消亡） |
| `inventory:{skuId}:refund:{orderId}` | String | 退款累计已受理量（与 stock 同脚本原子） |
| `inventory:confirmed:{orderId}` | String | 确认标记（confirm 缺失时写入；超时任务改判补确认） |

**MySQL 七表**：`t_inventory`（三态 available/locked/freezing）＋ 预扣幂等表（PK order+sku，7 天清理）＋ Outbox（uk order+sku+action）＋ 补偿表（status 0/1/2，90 天）＋ **`t_inventory_l2_event`（C-008 新增，事务内幂等，7 天清理）** ＋ TCC 判定层/资源层（未接线，不讲）。

## 4. 核心链路

```
1. 下单 → order 事务消息 → OrderTransactionConsumer（完成态标记）
   → preDeduct：MySQL 幂等占位（INSERT IGNORE 走主）→ prededuct.lua 单脚本原子
   （墓碑检查 → 幂等 → 库存检查 → DECRBY → 记 String 记录 → ZADD 索引）
   → sendInventoryEvent(PRE_DEDUCT)：Outbox 落 → syncSend → SEND_OK 标记（业务键）
     失败 → 作废 Outbox + 回滚 Redis + 业务失败
2. 支付 → confirmDeduct（items 契约）：逐 (sku,order) 删记录 + CONFIRM 事件；
   任一记录缺失 → 写确认标记（F12）
3. 取消/超时 → releaseStock（items）：逐 (sku,order) 原子「检查+总是写墓碑」→ 回退 + RELEASE 事件
4. 退款 → refundRestore：同槽原子脚本（delta 判定+推进+INCRBY）+ REFUND_RESTORE 事件
5. L2 落账 ← InventoryDeductConsumer：版本门（完成后推进）→ 事务内幂等（inbox+变更同事务）
   条件失败 → INVENTORY_FAILED_TOPIC → 订单侧收口
6. 兜底：PreDeductTimeoutJob（per-sku 索引 SCAN，1 分钟）→ 释放/补确认；
   OutboxSenderJob（5s 补发）/ CompensationJob（30s，3 次转人工）/ DLQ 重放（attempt≤3）
7. 对账 ← InventoryReconcileJob（每小时）：available（Redis 为准 CAS）/ locked（在途重算 CAS）/ 清理
```
