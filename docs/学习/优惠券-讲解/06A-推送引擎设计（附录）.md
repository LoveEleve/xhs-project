# 06A · 优惠券推送引擎设计（附录）

> 定位：**设计稿 + 最小实现**（C-017 P3）。最小版已落地在 coupon 模块 `push/`（hash 分桶）；
> 本文保留完整设计（行为标签画像/多通道/失败表），作为后续演进。目标是把"千万级任务推送引擎"从 JD 话术
> 变成可解释、可落地的设计，并明确哪些是复用、哪些是简化。
> 前置：01–05（领/用/退）、home feed（推拉混合）、notification（站内信 + SSE）。

---

## 0. 用例：优惠券到期提醒

**场景**：用户领了一张 7 天有效期的券，第 6 天推送"明天过期，记得使用"。

```
输入：明天到期的用户券（templateId, userId, validEnd）
输出：notification 站内信 + SSE 实时提醒（离线用户下次登录可见）
量级假设：1000 万用户、单日 100 万条待推
```

**为什么选这个用例**：数据现成（`t_user_coupon` + `valid_end`），不依赖运营配置；
推送内容单一，适合验证"分桶 + 批分割 + 限流"的引擎能力。

## 1. 架构：复用 feed 的"分桶 + 批处理"，复用 notification 的"投递"

```
XXL-Job（分片广播）
  → ① 扫描：T+1 到期的券（user_id, templateId）
  → ② 分桶：hash(user_id) 或 兴趣标签（t_user_behavior + note tags）
  → ③ 批分割：≤800KB / ≤1000 条一批
  → ④ 共享线程池（ThreadPoolExecutor + Semaphore 限流）
  → ⑤ 投递：NotificationEventDTO → NOTIFICATION_TOPIC（MQ）
  → ⑥ notification：落库 + 未读计数 + SSE
  → ⑦ 失败记录 + 重试 + 指标
```

**复用而非新造**：

| 能力 | 复用 |
|---|---|
| 用户分桶/批量 | home `FeedPushConsumer` 的 Pipeline 批量模式 |
| 投递 | notification `processEvent`（落库 + SSE + 未读） |
| 调度 | XXL-Job（已有 coupon/payment/order 任务） |
| 画像原料 | `t_user_behavior`（曝光/点击/点赞/收藏/停留）+ 笔记 tags |

## 2. 核心组件

| 组件 | 职责 | 关键点 |
|---|---|---|
| `CouponPushJob`（实现名 `CouponExpiryPushJob`） | XXL-Job 入口，分片参数 | 每片处理固定 user 范围（如 10 万） |
| `UserBucketSplitter` | 按 800KB/1000 条切批（代码默认 `coupon.push.bucket-size=1000`） | 对齐 RocketMQ 消息体上限 |
| `SharedThreadPool` | 并发推送 + Semaphore 限流 | 设计示例 permits=50/max=100；代码默认 permits=20/max=40；阻塞而非丢弃 |
| `CouponPushSender` | 组装 `NotificationEventDTO` 并发送 | 幂等键 `(templateId,userId,date)` |
| `t_coupon_push_record` | 每用户推送状态 | `uk(template_id,user_id,push_date)` 防重 |
| `t_coupon_push_fail` | 失败记录（设计；最小版用 `t_coupon_push_record.status=2`） | 重试 3 次 → 人工/对账 |

## 3. 画像：轻量聚合，不是"完整画像"

```
t_user_behavior（近 30 天）
  → 按 note 的 tags 聚合
  → 用户 top-N 兴趣标签
  → 分桶：同标签用户放同批（内容匹配）；无标签用户按 user_id hash 兜底
```

**诚实边界**：

- 没有独立画像服务/实时标签平台；这里是**离线/准实时聚合的简化版**；
- 面试讲法："我们复用了行为数据和内容标签做轻量分桶；完整画像/实时特征平台是后续演进"；
- 不用"千万级画像"这类无法验证的说法。

## 4. 幂等、限流与失败

**幂等**：

- `t_coupon_push_record` 唯一键 `(template_id, user_id, push_date)`；
- 发送前 `INSERT IGNORE` 占位，成功置 1；重复任务/重试不会重复推。

**限流**：

- Semaphore permits 控制同时投递的批次数（如 50）；
- 批大小 800KB/1000 条；单批失败只重试该批；
- 对 notification 的下游压力：按 QPS 目标反推 permits（如 5000 QPS → 每批 1000、5 批并发）。

**失败**：

- 发送失败 → `t_coupon_push_fail`，退避重试 3 次；
- 仍失败 → 告警 + 人工（复用 notification DLQ 思路）；
- 用户离线 → 站内信落库，SSE 不推（下次登录可见）。

## 5. 与现有模块的边界

| 模块 | 关系 |
|---|---|
| coupon | 提供"到期券"数据；不直接推送 |
| notification | 唯一投递出口（落库/SSE/未读） |
| home feed | 分桶/批量模式的参考，不混用 feed inbox（券提醒是系统通知，不是 feed） |
| analytics | 行为数据来源（t_user_behavior） |

## 6. 落地选项（若后续实现）

| 选项 | 内容 | 成本 |
|---|---|---|
| **最小版** | hash 分桶 + 批分割 + 共享线程池 + notification 投递；不做画像 | 2 会话 |
| **标准版** | 最小版 + 行为标签分桶 + 失败表/重试/指标 | 3 会话 |
| **完整版** | 标准版 + 实时画像/多通道（短信/邮件）/A/B | 不建议（超出项目范围） |

**建议**：先做最小版（能讲"分桶/批分割/限流"三件事），画像只在设计里讲。

## 7. 能讲 / 不能讲

**能讲**：

- "按用户分桶、800KB 批分割、共享线程池 + Semaphore 限流，投递复用 notification 站内信/SSE"；
- "幂等键 (templateId,userId,date) 防重复推送；失败重试 + 告警"；
- "画像用行为标签做轻量分桶，完整画像平台是演进方向"。

**不能讲**：

- 千万级推送/10 万 QPS（未压测）；
- 实时用户画像/推荐系统（只有行为标签聚合）；
- 生产验证（口径仍是编译 + 单测）。

## 8. 实现结果（2026-10-23）

- 已实现最小版：`CouponExpiryPushJob`（XXL-Job）+ `UserBucketSplitter`（≤1000 条/≤800KB，默认）+ `SharedThreadPool`（Semaphore 背压）+ `CouponPushSender`（`NOTIFICATION_TOPIC`）；
- 幂等：`t_coupon_push_record` 唯一键；已发送跳过、失败重试；
- 画像：**未实现**行为标签分桶，最小版按 `user_id` 游标扫描 + 分桶（`coupon.push.bucket-size` 默认 1000）；文中"画像"部分仍是演进设计；
- 延时过期：RocketMQ 开源版 24h 窗口，已改 **23h 分段排期 + 消费端续排**；不声称"任意延时"。
