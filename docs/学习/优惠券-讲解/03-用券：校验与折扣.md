# 03 · 用券：校验与折扣

> **口径**：先讲**生产环境/淘宝公开形态**，再对照本项目；代码不代表应然标准。
>
> **一句话**：用券 = **校验（归属/状态/门槛/有效期/模板）+ 折扣计算 + 核销（幂等）**；
> 生产环境的核心是"**锁定 → 支付核销 → 取消释放**"，本项目简化为"**下单即核销**"。
>
> **本篇带走**：① 生产的两阶段核销 ② 本项目校验链/折扣/乐观锁 ③ 金额一致与重复提交。
> 前置：01 业务模型、02 领券。证据：`getCouponDiscount/useCoupon`、`validator/*`、`markUsed`、`OrderService`。

---

## 0. 例子：淘宝 300 元订单用券（生产视角）

```
提交订单（300 元，用「满 200 减 20」）
  → 试算：折扣 20，实付 280（只算，不核销）
  → 锁定券（绑定订单，status=LOCKED）
  → 用户去支付（可能几分钟后才付）
  → 支付成功：LOCKED → USED（核销）
  → 取消/超时：LOCKED → UNUSED（释放，券可再用）
```

**为什么要锁定**：从"提交订单"到"支付成功"之间，用户可能放弃、重复提交、或去别的订单再用这张券。
不锁，同一张券会被两个订单同时用；支付失败又要能释放。

> 淘宝/天猫具体实现不公开；"锁定→支付核销→释放"是主流电商的常见做法（也有下单即核销的变体）。

## 1. 生产环境怎么做（淘宝/行业常见）

| 阶段 | 动作 | 关键点 |
|---|---|---|
| **试算** | 算折扣，不核销 | 只读；门槛/有效期/叠加规则 |
| **提交订单** | **锁定**券，绑定 orderId | 防并发复用；锁有超时 |
| **支付成功** | 锁定 → 已用（核销） | 幂等；支付回调驱动 |
| **取消/超时** | 锁定 → 未用（释放） | 与订单终结事件联动 |
| **金额** | 实付 = 订单金额 − 折扣 | 行级分摊（售后按分摊退） |
| **校验** | 归属、状态、门槛、有效期、模板、叠加/互斥 | 规则引擎 |
| **幂等** | 条件更新 + 订单/券唯一绑定 | 重复回调/重复提交 |

## 2. 本项目的实现（代码证据）

### 2.1 试算：`getCouponDiscount`（只算不核销）

```java
public BigDecimal getCouponDiscount(Long userId, Long userCouponId, BigDecimal orderAmount) {
    UserCoupon userCoupon = userCouponMapper.selectByIdAndUserId(userCouponId, userId);
    if (userCoupon == null || !userCoupon.getUserId().equals(userId)) {
        throw new BizException(ResultCode.COUPON_NOT_AVAILABLE, "优惠券不属于当前用户");
    }
    if (userCoupon.getStatus() != 0) {
        throw new BizException(ResultCode.COUPON_NOT_AVAILABLE, "优惠券不可用");
    }
    CouponTemplate template = getTemplateWithCache(userCoupon.getCouponId());
    if (template == null) {
        throw new BizException(ResultCode.COUPON_NOT_FOUND);
    }
    for (CouponValidator validator : validators) {
        validator.validate(template, orderAmount);
    }
    return calculateDiscount(template, orderAmount);
}
```

订单在下单前调用它拿"权威折扣"：

```java
// OrderService：试算失败 → 拒绝下单（避免券被核销但按全价付款）
BigDecimal discountAmount = calculateCouponDiscount(userId, request, totalAmount);
BigDecimal payAmount = totalAmount.subtract(discountAmount);
if (payAmount.compareTo(BigDecimal.ZERO) < 0) {
    payAmount = BigDecimal.ZERO;
}
```

### 2.2 校验链：门槛 → 有效期 → 状态

| 顺序 | 校验器 | 拒绝条件 |
|---|---|---|
| 1 | `AmountValidator` | `minAmount > 0` 且 `orderAmount < minAmount` |
| 2 | `ExpireValidator` | `now < validStart` 或 `now > validEnd` |
| 3 | `StatusValidator` | 模板 `status != 1`（下线后已领的券也不能用） |

> 有效期是**实时校验**：过期 Job 可能还没把券标成 `status=2`，不能只依赖状态字段。

### 2.3 折扣计算

```java
BigDecimal discount = switch (template.getType()) {
    case 1 -> template.getDiscountValue();                              // 满减
    case 2 -> orderAmount.subtract(orderAmount.multiply(template.getDiscountValue())
            .divide(new BigDecimal("10"), 2, RoundingMode.HALF_UP));    // 折扣
    case 3 -> template.getDiscountValue();                              // 无门槛
    default -> BigDecimal.ZERO;
};
return discount.min(orderAmount); // 不能超过订单金额
```

本项目约定：`discountValue=8` 是 **8 折**（不是 0.8）。

### 2.4 核销：下单即核销 + 乐观锁

```java
public BigDecimal useCoupon(Long userId, UseCouponRequest request) {
    UserCoupon userCoupon = userCouponMapper.selectByIdAndUserId(request.getUserCouponId(), userId);
    if (userCoupon == null) {
        throw new BizException(ResultCode.COUPON_NOT_FOUND);
    }
    if (userCoupon.getStatus() != 0) {
        if (userCoupon.getStatus() == 1) {
            throw new BizException(ResultCode.COUPON_NOT_AVAILABLE, "优惠券已被使用");
        }
        throw new BizException(ResultCode.COUPON_NOT_AVAILABLE, "优惠券状态异常");
    }

    CouponTemplate template = getTemplateWithCache(userCoupon.getCouponId());
    for (CouponValidator validator : validators) {
        validator.validate(template, request.getOrderAmount());
    }
    BigDecimal discount = calculateDiscount(template, request.getOrderAmount());

    // 乐观锁：WHERE id=? AND user_id=? AND status=0
    int affected = userCouponMapper.markUsed(userCoupon.getId(), request.getOrderId(), userId);
    if (affected == 0) {
        throw new BizException(ResultCode.COUPON_NOT_AVAILABLE, "优惠券已被使用");
    }
    return discount;
}
```

```sql
UPDATE t_user_coupon
SET status = 1, used_order_id = #{orderId}, used_at = NOW()
WHERE id = #{id} AND user_id = #{userId} AND status = 0
```

**为什么乐观锁**：重复提交/并发用券时，只有一个请求能把 `0→1`；其他请求影响 0 行，直接报"已被使用"。

### 2.5 订单怎么调：先建单，再核销；失败就取消

```java
// OrderService：订单创建后同步核销，绑定 orderId
R<BigDecimal> useResp = couponFeignClient.useCoupon(userId, useReq);
if (useResp == null || !useResp.isSuccess()) {
    terminateOrderQuietly(orderId, userId);   // 核销失败 → 订单取消
    throw new BizException(ResultCode.COUPON_NOT_AVAILABLE, "优惠券核销失败，订单已取消");
}
```

- 下单用的 `orderAmount` 是**订单商品总额**（不是券后实付）——门槛按总额算；
- 试算折扣是订单金额的权威；核销返回的折扣**不一致只告警**（模板在两次调用间被改过）；
- 支付域会回查订单实付（P1-1），确保支付金额 = 订单 `payAmount`。

### 2.6 重复提交与幂等

- **用券**：`markUsed` 条件更新；重复用券 → 0 行；
- **下单**：订单侧有幂等键（`bizIdentifier`），重复提交返回同一订单；
- **没有请求级"用户+券"幂等键**：靠订单幂等 + 券状态兜底。

## 3. 对照表：生产 vs 本项目

| 能力 | 生产环境 | 本项目 | 差异 |
|---|---|---|---|
| 试算 | 只读算折扣 | ✅ `getCouponDiscount` | 对齐 |
| **核销时机** | **锁定→支付核销→释放** | **下单即核销** | 无 `LOCKED` 态；失败靠订单终止退券 |
| 校验 | 归属/状态/门槛/有效期/模板/叠加 | ✅ 前五项 | 缺叠加/互斥 |
| 折扣 | 类型 + 叠加 + 最优组合 | ✅ 单券三类型 | 简化 |
| 分摊 | 行级分摊 | ✅ order 的 `discount_share` | 对齐（在 order 域） |
| 幂等 | 条件更新 + 订单/券唯一绑定 | ✅ `markUsed` + 订单幂等 | 对齐 |
| 金额一致 | 支付金额 = 订单实付 | ✅ 支付域回查（P1-1） | 对齐 |

## 4. 九个坑

1. **试算与核销两次调用**：模板可能在中途被改；核销折扣不一致只告警，订单以试算为准——要不要重新定价是产品决策。
2. **折扣上限**：`min(orderAmount)`；无门槛券在 3 元订单上只能减 3。
3. **折扣值语义**：`8`=8 折；跨系统对接必须确认存的是 8/0.8/80。
4. **门槛口径**：本项目按订单总额；叠加多券时要明确"原价/券后/实付"。
5. **有效期**：实时校验，不能只依赖过期 Job 的 `status=2`。
6. **模板下线**：已领的券也不能用（`StatusValidator`）——产品决策。
7. **下单即核销的回退**：核销失败会取消订单；取消/退款要靠订单终止事件 `returnCoupon`（04）；退券失败用户就丢券。
8. **支付金额一致**：订单 `payAmount` 与支付金额必须一致，否则支付域拒付（P1-1）。
9. **重复提交**：`markUsed` 只保证券不重复用；订单重复由订单幂等键挡。

## 5. 值不值得深挖 / 一句话

- **值得**：生产"锁定→支付核销" vs 本项目"下单即核销"的取舍；乐观锁与金额一致；
- **一句话带过**：校验器实现细节、错误码文案；
- **一句话**：**用券 = 校验 + 折扣 + 条件更新核销；本项目下单即核销，生产环境通常锁定到支付成功才核销——差异是取舍，靠订单终止退券兜底。**
- 退券/过期见 **04**；金额分摊在 **01 §2.5**。

**面试口径**："用券先试算拿权威折扣，下单时核销并绑定 orderId；核销用 `WHERE status=0` 乐观锁保证只成功一次；生产环境通常锁定到支付成功再核销、取消释放，我们是下单即核销，失败靠订单终止退券。"
