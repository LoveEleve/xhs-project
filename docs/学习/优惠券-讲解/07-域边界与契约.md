# 07 · 域边界与契约（微服务）

> **口径**：先讲**生产环境/淘宝公开形态**的服务边界，再对照本项目；代码不代表应然标准。
>
> **一句话**：coupon 拥有**券模板/用户券/名额**；order 是**编排者**；payment 只认**订单实付**、不碰券；
> inventory/notification 各司其职——**互不写对方表，只通过契约咬合**。
>
> **本篇带走**：① 四域职责 ② 双向契约（Feign/MQ） ③ 三种失败语义 ④ 内部鉴权与工程债。
> 前置：01–06。证据：`CouponFeignClient`、`CouponController`、`OrderTerminationConsumer`、`CouponPushSender`。

---

## 0. 例子：一笔用券订单的跨域旅程

```
① 试算：order → coupon  getCouponDiscount（只算不核销）
② 下单：order 建单 → coupon useCoupon（核销，绑 orderId）
③ 支付：payment 只校验"支付金额 = 订单实付"（不碰券）
④ 取消/超时：order 终结事件 → coupon returnCoupon（券 1→0）
⑤ 全退：order → coupon returnCoupon（Feign）+ 失败补偿
⑥ 到期提醒：coupon → NOTIFICATION_TOPIC → notification 落库/SSE
```

每一步都要回答：**谁拥有数据、谁调谁、失败怎么表达、重复怎么办**。

## 1. 生产环境怎么做（淘宝/行业常见）

| 域 | 职责 |
|---|---|
| **营销/优惠** | 活动、券模板、发放、叠加/互斥规则、优惠计算（常独立成"促销中心"） |
| **订单/交易** | 试算、下单、状态机、取消/售后；**编排**各域 |
| **支付** | 资金账本、渠道交互；只认订单应付金额 |
| **库存** | 预扣/确认/回补；不关心券 |
| **通知** | 站内信/推送；只负责投递 |

原则：**数据所有权单一**（谁的表谁写）、**契约化**（RPC/MQ）、**最终一致**（补偿/对账）、
**内部鉴权**（防外部伪造调用）。淘宝具体拆分不公开；这是电商域的常见形态。

## 2. 本项目的实现（代码证据）

### 2.1 谁拥有什么

| 域 | 拥有的表 | 不该做的事 |
|---|---|---|
| coupon | `t_coupon_template` / `t_user_coupon` / `t_coupon_outbox` / `t_coupon_push_record` | 不写订单/支付/库存表 |
| order | `t_order` / `t_order_item` / `t_sub_order` / 本地消息表 | 不写券表（只调契约） |
| payment | `t_payment` / `t_refund` | 不核销券、不退券 |
| inventory | 库存/预扣/流水 | 不关心券 |
| notification | 通知/未读/SSE | 不决定"发不发券" |

**优惠分摊在 order**：`t_order_item.discount_share` 由 `DiscountAllocator` 最大余数法落库；
coupon 只返回整单折扣，不参与行级分摊（01 §2.5）。

### 2.2 契约：order → coupon（三件套）

```java
@FeignClient(name = "my-xhs-coupon",
        fallbackFactory = CouponFeignFallbackFactory.class,
        configuration = InternalCallFeignConfig.class)
public interface CouponFeignClient {

    @GetMapping("/api/coupon/discount/{id}")
    R<BigDecimal> getCouponDiscount(@RequestHeader("X-User-Id") Long userId,
                                    @PathVariable("id") Long userCouponId,
                                    @RequestParam("orderAmount") BigDecimal orderAmount);

    @PostMapping("/api/coupon/use")
    R<BigDecimal> useCoupon(@RequestHeader("X-User-Id") Long userId,
                            @RequestBody Map<String, Object> request);

    @PostMapping("/api/coupon/return")
    R<Void> returnCoupon(@RequestHeader("X-User-Id") Long userId,
                         @RequestBody Map<String, Object> request);
}
```

coupon 侧对内部接口做鉴权：

```java
@GetMapping("/discount/{id}")
public R<BigDecimal> getCouponDiscount(...,
        @RequestHeader(value = "X-Internal-Call", required = false) String internalCall) {
    if (!accessTokenGuard.isInternalCall(internalCall)) return R.fail(403, "仅限内部服务调用");
    return R.ok(couponService.getCouponDiscount(userId, id, orderAmount));
}
// /use、/return 同样校验；/template 用 X-Admin-Call；/claim 用用户身份
```

**coupon → order 没有 Feign**：订单终结通过 **MQ 事件**（`ORDER_TERMINATION_TOPIC`）通知 coupon 退券：

```java
@RocketMQMessageListener(topic = "ORDER_TERMINATION_TOPIC",
        consumerGroup = "coupon-order-termination-consumer-group", maxReconsumeTimes = 5)
public class OrderTerminationConsumer implements RocketMQListener<MessageExt> {
    // 解析 userId/orderId/couponId → returnCoupon（完成态幂等 + 条件更新）
}
```

**coupon → notification**：只发 `NOTIFICATION_TOPIC`，不直接依赖 notification 模块
（`CouponPushSender`）；notification 自己落库/SSE。

### 2.3 三种失败语义（跨域必须分清）

| 结果 | 语义 | 调用方动作 |
|---|---|---|
| 成功（`R.ok`） | 已办成 | 继续 |
| **业务拒绝**（如券已用/不可用） | 终态 | **不重试**；订单取消/换券 |
| **503/超时/异常** | **未知**（可能已办成） | 不判死；补偿/重试/回查 |

具体到链路：

- **试算失败**（`getCouponDiscount` 503/异常）→ 订单**拒绝下单**（不能猜折扣，避免"券核销了却按全价付"）；
- **核销失败**（`useCoupon` 503/业务失败）→ 订单取消；若券其实已核销，终结事件 `returnCoupon` 退回；
- **退券失败**（`returnCoupon` 503/异常）→ 订单发 `RETURN_COUPON` 补偿；终结事件侧由 MQ 重试；
- **通知失败**（`NOTIFICATION_TOPIC` 发送失败）→ 推送记录保留，下次重试；不影响券状态。

### 2.4 内部鉴权与越权

- 内部接口（`/discount`、`/use`、`/return`）必须 `X-Internal-Call`；外部不能直接核销/退券；
- **创建模板/改状态**必须 `X-Admin-Call`；模板详情（`GET /template/{id}`）和可领列表是**公开只读**；
- 用户接口（`/claim`、`/user/*`）从 `X-User-Id` 取用户，并校验券归属（`selectByIdAndUserId`）；
- 启动时 `AccessTokenGuard.requireInternalTokenConfigured/requireAdminTokenConfigured` 校验令牌已配置（fail-fast）。

### 2.5 工程债（诚实清单）

| 债 | 影响 | 说明 |
|---|---|---|
| `OrderCreateRequest.couponId` 实际是 userCouponId | 命名误导 | 历史命名；读代码/对接必须注意 |
| 退券有两条路径（取消/终结 MQ；全退 Feign） | 维护两套 | 按订单状态**互斥**（取消 vs 全退），不是同一事件重复；各自条件更新幂等 |
| 无请求级幂等键（领券） | 重复点击 | 靠限领 + 限流；限领>1 时可能多次领 |
| 单券/无叠加/互斥 | 营销能力弱 | 促销中心/规则引擎是应然缺口 |
| 无"已用券卡住"对账 | 退券永久失败会卡"已用" | 有补偿消息，但没有专门对账修复 |
| 无运行时验证 | 契约行为未真跑 | 项目口径：编译+单测 |

## 3. 对照表：生产 vs 本项目

| 能力 | 生产环境 | 本项目 | 差异 |
|---|---|---|---|
| 营销/优惠计算 | 独立促销中心 + 规则引擎 | coupon 单券计算 | 简化 |
| 订单编排 | 订单编排各域 | ✅ order 试算/核销/退券 | 对齐 |
| 支付边界 | 只认应付金额 | ✅ P1-1 回查 | 对齐 |
| 库存边界 | 不关心券 | ✅ | 对齐 |
| 通知边界 | 独立投递 | ✅ topic | 对齐 |
| 数据所有权 | 不跨域写表 | ✅ | 对齐 |
| 内部鉴权 | mTLS/令牌 | ✅ X-Internal-Call | 简化 |
| 失败语义 | 业务/未知分离 | ✅ 503 vs 业务码 | 对齐 |
| 请求幂等 | 幂等键 | ⚠️ 领券无请求键 | 缺口 |

## 4. 十个坑

1. **coupon 写订单/支付表**：破坏所有权；只通过契约。
2. **order 在本地重算券规则**：两套规则必漂移；试算/核销都调 coupon。
3. **payment 校验券**：支付只认订单实付；券的事归 order/coupon。
4. **把业务拒绝当 503**：券已用还重试/补偿，越补越乱。
5. **把 503 当业务拒绝**：订单明明能收却取消/退款，资损。
6. **`couponId` 当模板 ID**：实际是 userCouponId；调错接口必 404/错券。
7. **退券两条路径按状态互斥**：取消/终结走 MQ，全退走 Feign；不是同一事件重复，但每条都要条件更新幂等，别假设只会走一条。
8. **内部接口不鉴权**：外部可核销/退券；必须 `X-Internal-Call` + 启动校验。
9. **事件字段类型**：Long 全局序列化成 String；消费端要兼容数字/字符串（`resolveLong`）。
10. **没有"已用券卡住"对账**：退券永久失败会卡"已用"；补偿之外要有人工/对账兜底。

## 5. 值不值得深挖 / 一句话

- **值得**：四域所有权、三件套契约、三种失败语义、内部鉴权——微服务边界面试的核心；
- **一句话带过**：Feign 配置、令牌实现；
- **一句话**：**微服务边界不是"拆得细"，而是"谁拥有数据、跨域怎么表达失败、重复怎么幂等"。**
- 规模化/分片见 **06**；可靠性收口见 **09**。

**面试口径**："coupon 拥有券模板/用户券/名额，order 编排试算/核销/退券，payment 只认订单实付；跨域用 Feign + MQ，不写对方表；内部接口带 X-Internal-Call；失败区分业务拒绝和 503/超时，退券靠条件更新幂等。"
