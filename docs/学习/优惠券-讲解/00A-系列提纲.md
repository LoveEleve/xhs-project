## 01 领券：名额锁定与双库存

- **目标问题**：高并发领券怎么不超发？限领怎么保证？Redis 和 MySQL 两个库存怎么配合？
- **核心结论**：Redis Lua 一步完成"库存检查 + 限领检查 + DECR stock + INCR claimed"；
  两个 key 用 `{templateId}` 同 slot（Cluster 安全）；`stock` 是同步闸门，`remain_count` 是异步落账；
  `-3`（库存未初始化）从 DB 实时自愈重试一次。
- **小节**：
  1. 例子：1000 张券、1 万人抢，Lua 的 5 步与 4 种返回（1/-1/-2/-3）
  2. 为什么必须 Lua（读-判-写原子；Cluster 同 slot）
  3. 双库存：Redis 闸门 vs MySQL 落账；对账以谁为准（04）
  4. 限领计数 `claimed:{userId}` 的语义（含已用/已过期）
- **证据**：`CouponService.claimCoupon`、`claim_coupon.lua`、`getTemplateWithCache`、C-007。
- **追问链**：Lua 为什么不能拆成多条命令→库存 key 过期怎么办→Redis 扣了 DB 没落怎么办（→02）。

## 02 超发洞与 Design B：部分失败

- **目标问题**：Redis 扣了名额、但 DB 落账失败/消息丢了，怎么办？回滚 Redis 为什么反而会超发？
- **核心结论**："回滚掩码"：发送失败时回滚 Redis，但消息可能已存 → 回滚 + 后续投递 = **超发**；
  Design B：**名额锁定即成功** + Outbox（先写行再发送）+ 至少一次 + `uk_claim_no` 幂等；
  唯一回滚路径 = Outbox 双次写入失败（可证"无消息在途"）。
- **小节**：
  1. 例子：claim 成功 → MQ 发送超时 → 旧实现回滚 → 消息补投 → 用户有两张券
  2. Design B 的发送链（outbox 写入/发送/失败语义/双次写入）
  3. 消费端幂等（msgId 24h + `uk_claim_no` + `decrementRemainCount` affected≠1 回滚）
  4. 为什么"至少一次"比"回滚"安全（漏损 vs 超发方向）
- **证据**：`sendClaimEventSync`、`CouponClaimConsumer`、`CouponOutboxSenderJob`、C-007 AC。
- **追问链**：outbox 写失败怎么办→重复投递怎么幂等→DLQ 重放会不会超发（→G35，05）。

## 03 用券：校验、折扣、核销

- **目标问题**：下单时券怎么校验？折扣怎么算？怎么防止重复核销/金额不一致？
- **核心结论**：校验链（金额→有效期→状态，`@Order`）；折扣计算用 `min(orderAmount)` 防 0 元购；
  核销是 `markUsed` 乐观锁（`status=0` 条件更新 + `used_order_id`）；**下单即核销**（无锁定态）。
- **小节**：
  1. 例子：120 元订单用满 100 减 20，试算 vs 核销
  2. 校验链与责任链（为什么拆 validator）
  3. 折扣计算与 0 元购防护
  4. 乐观锁核销 + 与订单金额一致性（order 侧校验）
- **证据**：`CouponService.getCouponDiscount/useCoupon`、`validator/*`、`UserCouponMapper.markUsed`。
- **追问链**：重复提交怎么办→核销后支付失败怎么退（→04）→下单即核销 vs 锁定态。

## 04 退券、过期与对账

- **目标问题**：退券为什么不回补库存？过期怎么标？对账修什么、以谁为准？
- **核心结论**：RV30——退券只恢复用户券状态（`status=1 AND used_order_id=orderId → 0`），
  不回补 stock/remain、不减 claimed（防超发敞口 + 防绕限领）；过期 Job 分批 0→2；
  对账三件事：stock 补全/修正（Redis 为准）、claimed 以 DB 已发券数为准、卡住 outbox 告警。
- **小节**：
  1. 例子：退券后为什么 remain 不变？再领为什么被限？
  2. RV30 的两个理由（超发敞口/绕限领）
  3. 过期 Job（T-058 的 UPDATE+LIMIT 坑）
  4. 对账三件事与"以谁为准"
- **证据**：`returnCoupon`、`CouponExpireJob`、`CouponReconcileJob`、`03-优惠券.md` §4-D/E/F。
- **追问链**：退券后库存对不上怎么办→过期券算不算已发→对账发现 remain 多了修谁。

## 05 可靠性收口：DLQ、守卫、指标

- **目标问题**：消息进 DLQ 怎么办？重放会不会超发？整套可靠性怎么收口？
- **核心结论**：DLQ 重放 + **投递时限领守卫**（count ≥ perUserLimit → 跳过 + 告警；stock 漏损是安全方向）；
  Outbox Sender（5s 补发、退避 30→480s）；指标族 claim/use/return/DLQ/reconcile；面试口径。
- **小节**：
  1. 例子：消费失败进 DLQ → 重放 → 与"重新领券"交叉
  2. G35 守卫：为什么"少发"是安全方向
  3. Outbox Sender 与对账告警
  4. 指标与面试口径（三问收口）
- **证据**：`CouponDlqReplayConsumer`、`CouponOutboxSenderJob`、`CouponReconcileJob`、C-007 review。
- **追问链**：重放上限→守卫触发后用户怎么办→怎么证明没有超发向量。
