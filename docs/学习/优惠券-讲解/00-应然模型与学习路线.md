# 00 · 优惠券域：应然模型与学习路线

> **一句话**：优惠券域的核心不是"打折"，而是**在名额有限的前提下，把一张券安全地从"可领"送到"已用/已退/已过期"**——
> 不超发、不重复、必达。
>
> **系列 6 篇**：00 模型与路线（本篇）→ 01 领券 → 02 超发洞与 Design B → 03 用券 → 04 退券/过期/对账 → 05 可靠性收口。
> 前置：交易域（订单/支付）已学；证据：`CouponService`、`claim_coupon.lua`、`CouponClaimConsumer`、C-007。

---

## 1. 一张 20 元券的一生（先建立模型）

**模板**：满 100 减 20，总量 1000 张，每人限领 1 张，有效期 7 天。

```
t0 领券（小王）
   Redis：stock 1000→999；claimed:{userId}=1（Lua 原子）
   Outbox + MQ → MySQL：t_user_coupon(status=0)、模板 remain_count 1000→999

t1 下单（订单 120 元）
   试算：getCouponDiscount → 20（只算，不核销）
   提交：useCoupon → 券 status 0→1，写 used_order_id=O1001
   订单实付 = 120 − 20 = 100

t2 支付成功
   券保持"已用"（支付域不碰券）

t3 取消/退款
   returnCoupon → 券 status 1→0，清 used_order_id
   ⚠️ 不回补 stock/remain、不减 claimed（RV30 语义）

t4 过期（未使用）
   CouponExpireJob → status 0→2
```

**券的状态机**（`t_user_coupon.status`）：

```
0 未用 ──核销──▶ 1 已用 ──退券──▶ 0
0 未用 ──过期──▶ 2 过期
```

**三个"库存"口径**（后面反复出现）：

| 口径 | 在哪 | 作用 |
|---|---|---|
| `stock` | Redis | **领取闸门**（同步、实时） |
| `remain_count` | MySQL 模板 | **落账结果**（异步、允许慢半拍） |
| `claimed:{userId}` | Redis | **限领计数**（每人已领几次） |

## 2. 为什么需要它：三个核心问题

| # | 问题 | 真实场景 | 本项目的答案 |
|---|---|---|---|
| 1 | **不超发** | 1000 张券、1 万人抢；Redis 扣了但 DB 没落、消息丢了 | Redis Lua 原子扣名额 + 双库存对账 + **Design B**（名额锁定即成功） |
| 2 | **不重复** | 用户连点领取/核销/退券；MQ 重投 | 限领计数、`markUsed` 乐观锁、退券条件更新（幂等） |
| 3 | **必达** | 领券成功但落账失败 → 用户"领了却没有券" | Outbox + 至少一次 + `uk_claim_no` 幂等（02 篇） |

**三个关键取舍**（面试要能解释）：

1. **双库存**：Redis 当同步闸门，MySQL 异步落账——用"允许少卖"换"绝不超卖"；
2. **下单即核销**（无锁定态）：提交订单时直接 `0→1`，失败再回退——简单，但依赖订单链路补偿；
3. **退券不回补**（RV30）：只恢复用户券状态，不回补 stock/remain、不减 claimed——
   否则会形成"remain + 已发 > total"的超发敞口，还能"领→用→退→再领"绕过限领。

## 3. 域边界：券是"优惠资源"，不是资金

```
order ──试算/核销/退券（三件套 Feign）──▶ coupon
order ──支付/退款──▶ payment（券不参与）
payment ──退款成功──▶ order ──returnCoupon──▶ coupon
```

- **order 是编排者**：下单试算、提交核销、取消/退款退券；
- **payment 完全不碰券**：支付成功不核销（下单时已核销）、退款成功也不直接退券（由 order 调）；
- coupon 不依赖 payment/order 的表，只提供内部契约（`discount/use/return`）。

## 5. 面试开场（30 秒）

> "优惠券域我按三个问题讲：**不超发、不重复、必达**。领券用 Redis Lua 原子扣名额 + 限领，
> MySQL 异步落账，Redis/MySQL 双库存对账；部分失败用 **Design B**——名额锁定即成功，
> Outbox 至少一次投递，`uk_claim_no` 幂等，避免'回滚掩码'造成的超发；核销用乐观锁，
> 退券只恢复用户券状态、不回补库存（RV30，防超发和绕限领）。"
