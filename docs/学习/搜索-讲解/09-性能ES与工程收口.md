# 09 · 性能 / ES / 工程收口

> **口径**：先讲**生产环境/行业常见做法**，再对照本项目；QPS/延迟数字都是**设计假设**，
> 不是本项目压测结论（项目口径：编译+单测，无运行时）。
>
> **一句话**：搜索性能 = **ES 集群基线 + 异步 Controller + Search After + 限流 + 缓存/并行召回**；
> 工程收口 = **指标/DLQ/测试/工程债**，不吹没压过的数字。
>
> **本篇带走**：① ES 部署/映射 ② 性能手段 ③ 观测/DLQ ④ 测试 ⑤ 工程债与面试口径。
> 前置：01–08。证据：`ElasticsearchConfig`、`IndexMappings`、`IndexAliasManager`、
> `RecommendThreadPoolConfig`、`SearchDlqReplayConsumer`、C-011/C-019。

## 0. 例子：一次大促搜索流量 / 一次全量重建

```
大促搜索
  → Controller 异步（recallExecutor）
  → ES 集群（3 shard/索引，replicas=1）
  → 限流 30/s/用户
  → 热搜/联想缓存；推荐召回并行 2s 超时

全量重建
  → v2 实体 → 全量灌数 → 原子切别名 → 窗口重放 → 删 v1
```

## 1. 生产环境怎么做（淘宝/行业常见）

| 维度 | 常见做法 |
|---|---|
| ES 部署 | 多节点集群、分片/副本、连接池、读写分离（协调节点） |
| 查询 | Search After/PIT、稳定排序、限流、缓存 |
| 重建 | 新索引 + 别名切换 + 窗口重放；限速灌数 |
| 观测 | ES 延迟/错误/队列、查询 P99、缓存命中、重建进度 |
| 容量 | 压测/容量规划/故障演练 |

## 2. 本项目的实现（代码证据）

### 2.1 ES 部署与映射

```yaml
elasticsearch:
  uris: http://192.168.0.142:19200      # 支持逗号分隔多节点（集群）
  connect-timeout: 5000
  socket-timeout: 30000
  io-thread-count: 16                    # 4 在高并发下是解析瓶颈
  max-conn-total: 400
  max-conn-per-route: 200
```

- `note_index` / `product_index`：**3 shards**、replicas `%REPLICAS%`（生产默认 1，单节点开发 0）；
- `suggest_index`：1 shard（派生小索引）；
- 分词：`ik_max_word`（索引）+ `ik_smart`（搜索）；completion 字段用于联想；
- 别名：`{alias}_v{n}`，读/写统一走别名（C-011）；
- T-131：`JacksonJsonpMapper` 注册 `JavaTimeModule`（否则 `LocalDateTime` 序列化失败）。

### 2.2 性能手段

| 手段 | 本项目 |
|---|---|
| 异步 Controller | `CompletableFuture` + `recallExecutor` |
| 深分页 | Search After（无 from/size） |
| 限流 | 搜索/推荐/商家 8 端点 `@RateLimit` |
| 缓存 | 热搜 ZSet、联想缓存（1h/空 5min） |
| 并行召回 | 5 路 + 内层池 + 2s 超时 |
| 线程池隔离 | `recallExecutor`（请求）/`recallInnerExecutor`（召回） |
| 结果缓存 | ❌ 搜索/推荐 Feed 不缓存；Feed 固定 20 条无分页 |

### 2.3 观测与 DLQ

**指标**（当前较薄）：

- `businessMetrics.recordFeedPush("note_search"/"product_search")`：搜索次数；
- `recordOrderCreateLatency(tookMs)`：**借用了订单的指标名**记搜索耗时（语义不干净，工程债）；
- `recordAction("search", "doc_build_failed"/"dlq_replay_*")`：补偿/DLQ；
- 日志：关键词、耗时、失败原因；MQ 消费用 `MqTraceHelper` 恢复 traceId。

**缺口**：没有 ES 查询 P99、缓存命中、召回各路耗时/超时率的专门指标——排障要靠日志。

**DLQ ×5**：note/product/counter-es/behavior/seller-order；`SearchDlqReplayConsumer` 重投源 topic（保留 tag），attempt≤3，超限告警。

### 2.5 工程债：三档

**已修**：

- C-011：别名切换重建、8 端点限流、墓碑统一、失败集收敛、DLQ×5、ThreadLocal 清理、热搜 `{hot}` 同 slot；
- C-019：Search After 游标类型标签（1.0/100.0 不再误判）；
- C-004：商家异构索引 + 回填。

**已记（未修/取舍）**：

| 债 | 影响 |
|---|---|
| 推荐权重硬编码（0.25/0.25/0.30/0.20） | 调权重要发版 |
| 无 ML 精排/重排 | 推荐质量上限 |
| 跨库边界（content 复用 + product 跨库） | 结构耦合 |
| suggest 索引未别名化 | 重建原地 |
| 无 PIT | 深分页跨页快照一致性弱 |
| `total` 默认 10000 | 不能精确统计 |
| 指标语义借用订单（`recordOrderCreateLatency`） | 观测不干净 |
| Feed 固定 20 条无分页 | 刷新换内容 |
| 商家身份=Admin 共享令牌 | 真实身份体系缺失 |
| 无压测/运行时验证 | 不能声称 QPS/延迟 |

**一句带过**：ES 连接池参数、线程池大小、缓存 TTL。

### 2.6 面试口径 + 系列收口

**30 秒**：

> "搜索域三条链路：读、索引、推荐。读是 ES multiMatch/match + filter + 高亮 + 四型排序，深分页 Search After；
> 索引是 Canal 双通道 → MQ → ES，ts+ExternalGte 防乱序、墓碑防复活、失败集收敛、全量重建别名切换；
> 推荐是 5 路召回 + 粗排来源权重 + 精排四维 + 重排过滤/打散。性能和工程上有限流、异步、DLQ、69 个测试；
> 没压测，不吹 QPS。"

**追问**：

- "重建怎么不中断？" → v2 + 原子切别名 + 窗口重放；失败不切（切换前）。
- "失败集为什么不会无限循环？" → conflict 豁免、确定性失败丢弃、仅真失败回填。
- "热搜 Cluster 怎么保证？" → 4 key `{hot}` 同 slot，CRC16 测试。
- "游标类型？" → 类型标签 d/l/s/b/n，旧格式兼容（C-019）。
- "哪些不能吹？" → QPS/延迟、ES 集群运维、ML 推荐、生产验证。

## 3. 值不值得深挖 / 一句话

- **值得**：ES 集群/映射、异步/限流、Search After、失败集/别名、69 测试——搜索工程化核心；
- **一句话带过**：连接池/线程池参数、缓存 TTL；
- **一句话**：**搜索性能 = ES 集群 + 异步 + Search After + 限流 + 缓存/并行；工程化 = 指标/DLQ/测试/债，数字靠压测不靠嘴。**

**面试收口**："搜索域我按读/索引/推荐讲；索引有版本/墓碑/别名，读有 Search After/限流，推荐有四层管线；测试 69 个覆盖别名/失败集/游标/热搜 slot；没压测的 QPS/延迟我不吹。"
