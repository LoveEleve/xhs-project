# 06 · 联想与历史

> **口径**：先讲**生产环境/行业常见做法**，再对照本项目；代码不代表应然标准。
>
> **一句话**：联想 = **ES Completion Suggester + Redis 缓存（空结果短 TTL）**；
> 历史 = **Redis List 最近 20 条**（LREM 去重 + LPUSH + LTRIM + TTL）。
>
> **本篇带走**：① Completion Suggester ② 缓存/空结果 ③ 历史结构/去重 ④ 重建与坑。
> 前置：03。证据：`SuggestService`、`SearchHistoryService`、`IndexMappings`、`IndexRebuildJob`。

## 0. 例子：输入"露" → "露营"

```
输入 "露"
  → Redis 缓存命中？→ 直接返回
  → 未命中 → ES Completion Suggester（prefix="露"）
  → 返回 ["露营装备","露营","露营穿搭"]（最多 10 条）
  → 写缓存（非空 1h / 空结果 5min）

用户搜了"露营装备"
  → 历史 List：LREM 去重 → LPUSH → LTRIM 20 → EXPIRE 30d
  → "我的历史"按最近顺序展示，单条可删/可清空
```

## 1. 生产环境怎么做（淘宝/行业常见）

| 能力 | 常见做法 |
|---|---|
| 自动补全 | Completion Suggester/FST、前缀索引、权重排序 |
| 缓存 | 热门前缀结果缓存；空结果短 TTL 防穿透 |
| 历史 | Redis List/ZSet 最近 N 条；去重、TTL、单删/清空 |
| 降级 | ES 失败返回空；缓存失败不影响主流程 |
| 重建 | 从源数据重建 suggest 索引；删除同步清理 |

## 2. 本项目的实现（代码证据）

### 2.1 Suggest：缓存 → ES Completion

```java
public List<String> suggest(String prefix) {
    if (prefix == null || prefix.isBlank()) return Collections.emptyList();
    prefix = prefix.trim();
    if (prefix.length() > 50) prefix = prefix.substring(0, 50); // 防超长前缀

    String cacheKey = "myxhs:search:suggest:cache:" + md5(prefix);
    String cached = stringRedisTemplate.opsForValue().get(cacheKey);
    if (cached != null) return JSON.parseArray(cached, String.class);

    List<String> suggestions = queryEsSuggester(prefix);

    Duration ttl = suggestions.isEmpty()
            ? Duration.ofMinutes(5)                 // 空结果短 TTL：新热词快速生效
            : Duration.ofSeconds(cacheTtlSeconds);  // 非空 1h
    stringRedisTemplate.opsForValue().set(cacheKey, JSON.toJSONString(suggestions), ttl);
    return suggestions;
}
```

**ES 查询**：

```java
SearchRequest.of(s -> s.index(suggestIndexName)
    .suggest(sg -> sg.suggesters("keyword_suggest", fs -> fs
        .prefix(prefix)
        .completion(c -> c
            .field("keyword")
            .size(maxSuggestions)       // 默认 10
            .skipDuplicates(true)))));
```

- `suggest_index` 的 `keyword` 是 `completion` 类型（FST，专为前缀补全）；
- 缓存 key 用 **MD5(prefix)**，避免特殊字符/超长 key；
- ES 失败 → 返回空列表（降级），不抛给前端。

### 2.2 suggest 索引：从笔记标题重建

`IndexRebuildJob.rebuildSuggestIndex()`：

```sql
SELECT n.id, n.title, COALESCE(c.count_value, 0) AS like_count
FROM t_note n
LEFT JOIN my_xhs_counter.t_counter c
  ON c.target_type = 1 AND c.target_id = n.id AND c.count_type = 1 AND c.deleted = 0
WHERE n.id > ? AND n.deleted = 0 AND n.status = 2
ORDER BY n.id ASC LIMIT ?
```

- 只取**已发布**笔记标题；
- `weight` 用 `log10(1+likeCount)` 缩放（1~101），避免头部权重碾压；
- 批量 `Bulk`；**部分失败即整体失败**（不能"断点不推进却按成功收尾"）；
- 笔记删除时，重建清理会删 `suggest_index` 的 `note_{id}` 文档。

### 2.3 历史：Redis List 最近 20 条

```java
public void addHistory(Long userId, String keyword) {
    if (userId == null || userId <= 0 || keyword == null || keyword.isBlank()) return;
    String key = "myxhs:search:history:" + userId;
    stringRedisTemplate.opsForList().remove(key, 0, keyword);  // 去重
    stringRedisTemplate.opsForList().leftPush(key, keyword);   // 最近在前
    stringRedisTemplate.opsForList().trim(key, 0, maxSize - 1); // 最多 20
    stringRedisTemplate.expire(key, Duration.ofDays(ttlDays));  // 30 天
}
```

- 读：`range(key, 0, maxSize-1)`；
- 单删：`remove(key, 0, keyword)`；
- 清空：`delete(key)`；
- 端点：`GET /history`、`DELETE /history`、`DELETE /history/{keyword}`。

> ⚠️ **重复写入**：`SearchController` 调 `SearchHistoryService.addHistory`，
> `NoteSearchService` 里还有一次 `recordSearchHistory`（Lua 版）——同一 key 写两遍，已知冗余，待清理。

### 2.4 缓存与降级边界

- suggest 空结果 5min（新增热词快速生效）、非空 1h；
- ES 失败返回空，不阻塞搜索；
- 缓存写失败只告警；
- suggest 索引**未别名化**（派生小索引，原地重建可接受；与 note/product 的别名模型不同）。

## 3. 对照表：生产 vs 本项目

| 能力 | 生产环境 | 本项目 | 差异 |
|---|---|---|---|
| 自动补全 | Completion/FST | ✅ Completion Suggester | 对齐 |
| 权重排序 | 热度/点击 | ✅ log10(like) | 简化 |
| 缓存 | 热门前缀 | ✅ 1h/空 5min | 对齐 |
| 历史 | List/ZSet | ✅ List 20 条/30d | 对齐 |
| 建议索引重建 | 独立/别名 | ⚠️ 原地重建 | 简化 |
| 降级 | 空/缓存 | ✅ 空列表 | 对齐 |

## 4. 十个坑

1. **mapping 用错**：`keyword` 必须是 `completion` 类型，普通 text 不支持 Suggester。
2. **空结果缓存太久**：新热词迟迟不出现；本项目空结果 5min。
3. **prefix 不限制长度**：超长前缀攻击；本项目截断 50。
4. **缓存 key 用原字符串**：特殊字符/超长；用 MD5。
5. **suggest 索引不重建**：新笔记标题进不了联想；全量重建会重建 suggest。
6. **部分失败当成功**：断点不推进、索引残缺；本项目抛错。
7. **历史不去重**：同一词重复占位；LREM 后再 LPUSH。
8. **历史不裁剪/不过期**：List 无限增长；LTRIM 20 + 30d TTL。
9. **历史重复写**：Controller + Service 两处写同一 key（已知冗余）。
10. **ES 失败抛给前端**：联想不可用不应拖垮搜索；降级空列表。

## 5. 值不值得深挖 / 一句话

- **值得**：Completion Suggester、空结果 TTL、历史 List 结构——搜索体验的常见面试题；
- **一句话带过**：weight 公式、缓存 TTL；
- **一句话**：**联想 = Completion Suggester + 缓存（空结果短 TTL）；历史 = Redis List 去重 + 裁剪 + TTL。**
- 搜索读路径见 **03**；工程债见 **09**。

**面试口径**："联想用 ES Completion Suggester（completion 字段 + prefix），结果缓存 1h、空结果 5min 防穿透；历史用 Redis List，LREM 去重 + LPUSH + LTRIM 20 + 30 天 TTL；suggest 索引从已发布笔记标题重建，weight 用点赞数 log 缩放。"
