## 01 数据源与边界（微服务）

- **目标问题**：search 为什么没有自己的 MySQL 库？数据从哪来、写到哪去？和 content/product/order/social/counter 怎么咬合？
- **核心结论**：search 是**检索引擎 + 推荐引擎**，没有自己的库；复用 content 数据源（读写 `t_item_feature/t_user_behavior/t_hot_search_snapshot` 等派生表），显式跨库读 `my_xhs_product.t_spu/t_sku`；通过 Canal/MQ 供给、Feign 补全、ES 承载索引。
- **小节**：
  1. 例子：搜笔记/搜商品/商家搜订单，数据分别从哪来
  2. 数据源地图（content 复用 + product 跨库 + Redis + ES）
  3. 契约：Canal topic、SUB_ORDER_INDEX_TOPIC、SOCIAL_TOPIC、RECOMMEND_BEHAVIOR_TOPIC、Feign product/order
  4. 跨库边界：为什么复用/有什么坑（P1-5 缺库前缀）
- **证据**：`06-搜索.md` §1/§3/§5、`SearchApplication`、`feign/*`、`application.yml`。
- **追问链**：为什么不分库→跨库查询风险→哪些表该归 search。

## 02 索引供给与一致性（分布式）

- **目标问题**：MySQL 变更怎么进 ES？乱序/删除/失败/重建怎么处理？
- **核心结论**：Canal 双通道（note/product）→ MQ → ES；external version 防乱序（note `es`/`ts` 域、product `ts`/flat 统一 `ts`）、墓碑防复活（status=-1 + deletedAt + 7 天清理）、失败集 + 增量补偿（60s）、全量重建 **别名原子切换 + 窗口重放**、DLQ×5。
- **小节**：
  1. 例子：改标题/删笔记/全量重建，索引怎么变
  2. Canal 双通道与文档构建（不查库）；Canal filter/partition 配置
  3. 防乱序/防复活/失败集收敛（version_conflict 豁免、确定性失败丢弃）
  4. 全量重建：v2 → 切别名 → 重放 → 删 v1；legacy 回退
- **证据**：`NoteIndexSyncConsumer`/`ProductIndexSyncConsumer`、`IncrementalIndexSyncJob`、`IndexRebuildJob`、`IndexAliasManager`、C-011。
- **追问链**：为什么不用双写→消息乱序怎么办→重建期间更新怎么补。

## 03 搜索读路径（业务/性能）

- **目标问题**：一次搜索请求在 ES 里怎么查？关键词/过滤/高亮/排序怎么组合？
- **核心结论**：Controller 异步化；`multiMatch`（标题/内容）+ filter（status/分类/价格）+ highlight；四型排序（相关/时间/热度/价格/销量）；笔记页 20/50、商品分页；副作用（历史/热搜）异步。
- **小节**：
  1. 例子：搜"露营"笔记 vs 搜"耳机"商品
  2. 查询构造（multiMatch 字段/boost、filter、highlight）
  3. 四型排序与 tie-breaker（noteId）
  4. 异步 Controller + 副作用（history/hot）
- **证据**：`SearchController`、`AbstractSearchService`、`NoteSearchService`、`ProductSearchService`。
- **追问链**：为什么用 multiMatch→高亮怎么配→排序字段缺失怎么办。

## 04 深分页与相关性（性能）

- **目标问题**：深分页为什么不能用 from/size？Search After 怎么保证不跳记录？
- **核心结论**：Search After 游标（`sort` 值序列化/解析，区分 double/long 防精度丢失）；`_score + noteId` 次键保证稳定；`size` 上限；三控制器限流（C-011）。
- **小节**：
  1. 例子：翻到第 100 页，from/size 的问题
  2. Search After 序列化/解析（FieldValue double/long）
  3. 排序稳定性与 tie-breaker
  4. 限流/深分页上限
- **证据**：`AbstractSearchService.serializeSearchAfter/parseSearchAfter/normalizeSize`、C-011 限流。
- **追问链**：游标篡改→排序字段变化→相关性打分。

## 05 热搜（业务/性能）

- **目标问题**：热搜怎么实时统计、防刷、衰减、展示？
- **核心结论**：Lua 原子（屏蔽词→IP 限频→用户同词去重→HINCRBY 分钟桶）；最近 60 桶指数衰减（λ=0.1）；ZSet 临时键 RENAME；`{hot}` 同 slot（Cluster）；置顶/屏蔽/快照/日清；启动预热。
- **小节**：
  1. 例子：一个词从被搜到上榜
  2. Lua 反作弊四步与分钟桶
  3. 指数衰减与 ZSet 原子切换
  4. Cluster slot、置顶/屏蔽、快照、预热
- **证据**：`HotSearchService`、`HotSearchKeySlotTest`、`SearchCacheWarmer`、C-011 补遗。
- **追问链**：为什么用分钟桶→衰减参数→刷榜怎么防。

## 06 联想与历史（业务）

- **目标问题**：输入联想怎么做？搜索历史怎么存/删？
- **核心结论**：ES Completion Suggester + Redis 缓存（空结果短 TTL 防穿透）；历史最近 20 条 + 单删/清空。
- **小节**：
  1. 例子：输入"露"出现"露营"
  2. Completion Suggester 与 suggest 索引
  3. 缓存/空结果 TTL/降级
  4. 历史读写与上限
- **证据**：`SuggestService`、`SearchHistoryService`、`IndexMappings.SUGGEST_INDEX_MAPPING`。
- **追问链**：联想索引怎么建→缓存击穿→历史存哪。

## 07 推荐（业务/分布式）

- **目标问题**：推荐流怎么召回/排序/去重？离线做什么？

- **小节**：
  1. 例子：打开推荐流
  2. 5 路召回与并行/超时降级
  3. 粗排加权/合并/已看过过滤
  4. 离线 Job、行为闭环、冷启动（coldStartRecall）、热门池预热（SearchCacheWarmer）
