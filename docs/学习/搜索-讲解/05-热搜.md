# 05 · 热搜

> **口径**：先讲**生产环境/行业常见做法**，再对照本项目；代码不代表应然标准。
>
> **一句话**：热搜 = **分钟桶 + 指数衰减 + 反作弊 + 原子榜 + 快照**；
> 难点不是"统计词频"，而是**实时、防刷、集群安全、可回看**。
>
> **本篇带走**：① 记录 Lua ② 计算衰减 ③ 榜/置顶/屏蔽 ④ 快照/清理/预热 ⑤ Cluster slot。
> 前置：03。证据：`HotSearchService`、`HotSearchKeySlotTest`、`SearchCacheWarmer`、C-011 补遗。

---

## 0. 例子：一个词从被搜到上榜

```
10:00:01 用户搜"露营"
  → Lua：屏蔽词？IP 限频？用户同词去重？
  → HINCRBY search:{hot}:window:202610231000 "露营" 1

10:01:00 定时计算
  → 取最近 60 个分钟桶
  → score = Σ(count × e^(-0.1 × Δt分钟))
  → 过滤屏蔽词 → Top 50 → 临时 ZSet → RENAME 替换实时榜

10:01:05 用户打开热搜榜
  → 置顶词优先 + Top50 + 标签（爆/热/新）
  → 快照落 t_hot_search_snapshot（按日可回看）
```

## 1. 生产环境怎么做（淘宝/行业常见）

| 环节 | 常见做法 |
|---|---|
| 计数 | 实时流/分钟桶/滑动窗口；Pipeline 批量 |
| 衰减 | 指数衰减/时间窗加权，越近权重越高 |
| 反作弊 | IP/用户/设备限频、同词去重、屏蔽词 |
| 榜单 | 原子替换（临时 key + RENAME/事务），避免空窗 |
| 治理 | 人工置顶/屏蔽、快照、历史回看 |
| 集群 | 同脚本多 key 必须同 slot；RENAME 两 key 同 slot |

## 2. 本项目的实现（代码证据）

### 2.1 记录：Lua 原子四步

```lua
-- KEYS[1] 用户反作弊 / KEYS[2] IP 反作弊 / KEYS[3] 分钟桶 / KEYS[4] 屏蔽词
-- 0. 屏蔽词
if redis.call('SISMEMBER', KEYS[4], ARGV[1]) == 1 then return -1 end

-- 1. IP 限频：每分钟 < N 次（先查 IP，避免 IP 超限时用户 Key 已写入）
local ipCount = redis.call('INCR', KEYS[2])
if ipCount == 1 then redis.call('EXPIRE', KEYS[2], 60) end
if ipCount > tonumber(ARGV[3]) then return 0 end

-- 2. 用户同词去重：N 秒内只计 1 次
if redis.call('EXISTS', KEYS[1]) == 1 then return 0 end
redis.call('SET', KEYS[1], '1', 'EX', tonumber(ARGV[2]))

-- 3. 分钟桶
redis.call('HINCRBY', KEYS[3], ARGV[1], 1)
redis.call('EXPIRE', KEYS[3], tonumber(ARGV[4]))
return 1
```

- 默认：IP 10 次/分钟、用户同词 300 秒、分钟桶 TTL 2h；
- **屏蔽词检查放进 Lua**：避免"先查后写"的 TOCTOU；
- 记录失败只告警，不影响搜索主流程。

**Cluster 关键**：4 个 KEYS 统一 `{hot}` hash tag：

```
myxhs:search:{hot}:antispam:user:...
myxhs:search:{hot}:antispam:ip:...
myxhs:search:{hot}:window:...
myxhs:search:{hot}:blocked
```

`HotSearchKeySlotTest` 用 **CRC16 实算 slot** 锁定四键同 slot（C-011 补遗：修复前跨 4 slot，
真 Cluster 下 EVAL 被 CROSSSLOT 拒绝 → 热搜记录全挂、榜单永远空）。

### 2.2 计算：60 个分钟桶 + 指数衰减

```java
// 1. Pipeline 一次取最近 60 个桶
for (int i = 0; i < windowMinutes; i++) {
    bucketKeys.add(SEARCH_WINDOW + now.minusMinutes(i).format("yyyyMMddHHmm"));
}

// 2. score = Σ(count × e^(-λ × i))，λ=0.1
double decay = Math.exp(-decayLambda * i);
scoreMap.merge(keyword, count * decay, Double::sum);

// 3. 过滤屏蔽词 → Top 50
// 4. 临时 ZSet → RENAME 原子替换
stringRedisTemplate.delete(HOT_REALTIME_TMP);
for (entry : topEntries) zSet.add(HOT_REALTIME_TMP, keyword, score);
stringRedisTemplate.rename(HOT_REALTIME_TMP, SEARCH_HOT_REALTIME);
stringRedisTemplate.expire(SEARCH_HOT_REALTIME, 1, TimeUnit.HOURS);
```

- 1 分钟前权重≈0.9、30 分钟前≈0.05、60 分钟前≈0.002；
- 定时默认 1 分钟（`search.hot.recompute-interval-ms` 可配；注释建议生产 5 分钟降低快照量）；
- Redisson 锁保证多实例只有一个计算。

### 2.3 展示：置顶 + Top + 标签

- `getHotSearchList`：置顶词优先（不占排名），其余按 ZSet 分数降序；
- 标签：排名 1–3 且分数 ≥ 最高分 80% → "爆"；4–10 → "热"；其余 → "新"；
- 屏蔽词在计算阶段已过滤；`blockKeyword` 同时从实时 ZSet 移除。

### 2.4 快照、清理、预热

**快照**：每次计算把 Top N 写入 `t_hot_search_snapshot`（keyword/score/rank/search_count/snapshot_time）：

- 先 `DELETE WHERE snapshot_time = ?`（同一分钟重复计算不插重复行，T-089）；
- 查询按日期范围（`snapshot_time >= start AND < end`），让索引生效。

**清理**：每天一次（Redis SETNX 日切标记），删除 30 天前快照，`LIMIT 5000` 有界排空。

**预热**：`SearchCacheWarmer` 启动时若实时榜不存在 → 触发一次 `calculateHotSearch()`，
避免重启后首屏空榜。

### 2.5 防护与边界

- `/hot` 限流 20 次/秒/用户（C-011）；`/hot/record` 由 Lua 反作弊保护；
- 热搜记录失败 → 搜索不受影响；
- 快照表不存在 → 跳过持久化（不阻塞计算）；
- 清理失败 → 次日重试。

## 3. 对照表：生产 vs 本项目

| 能力 | 生产环境 | 本项目 | 差异 |
|---|---|---|---|
| 实时计数 | 分钟桶/流 | ✅ 分钟桶 + Lua | 对齐 |
| 衰减 | 指数/时间窗 | ✅ λ=0.1 | 对齐 |
| 反作弊 | IP/用户/设备 | ✅ IP+用户+屏蔽词 | 简化（无设备/风控） |
| 原子榜 | 临时 key + RENAME | ✅ | 对齐 |
| 置顶/屏蔽 | 有 | ✅ | 对齐 |
| 快照/回看 | 有 | ✅ 30 天 | 对齐 |
| Cluster | 同 slot | ✅ `{hot}` + CRC16 测试 | 对齐 |

## 4. 十二个坑

1. **Lua 多 key 跨 slot**：4 个 key 必须同 `{hot}`；否则 Cluster 直接 CROSSSLOT。
2. **屏蔽词先查后写**：TOCTOU；必须放进 Lua 原子判断。
3. **IP 限频后写用户 key**：IP 超限时用户 key 已写 → 误拦截；先查 IP。
4. **分钟桶 TTL 太短/太长**：2h 覆盖 60 分钟窗口；太短会丢历史桶。
5. **衰减单位错**：`i` 是分钟索引，λ 按分钟；写成秒会衰减过快。
6. **DELETE+ADD 替换榜**：读会看到空窗；用临时 key + RENAME。
7. **RENAME 两 key 不同 slot**：Cluster 报错；`realtime` 与 `:tmp` 同 tag。
8. **同一分钟重复快照**：先删同分钟再插（T-089）。
9. **快照不清理**：分钟级 Top50 ≈ 7 万行/天；30 天清理 + 索引。
10. **置顶/屏蔽语义**：置顶不占排名；屏蔽要同时从 ZSet 移除。
11. **重启后空榜**：`SearchCacheWarmer` 预热实时榜。
12. **热搜记录失败影响搜索**：必须降级，不影响主流程。

## 5. 值不值得深挖 / 一句话

- **值得**：分钟桶/衰减/Lua 反作弊/RENAME/Cluster slot——热搜是"实时+防刷+集群"的综合题；
- **一句话带过**：λ 参数、Top N、快照表字段；
- **一句话**：**热搜 = 分钟桶计数 + 指数衰减 + Lua 反作弊 + 临时 ZSet RENAME + 快照；多 key 必须同 slot。**
- 搜索读路径见 **03**；推荐见 **07**。

**面试口径**："热搜用分钟桶 + 指数衰减（λ=0.1），Lua 原子做屏蔽词/IP 限频/用户同词去重/计数；计算时取 60 个桶加权，临时 ZSet RENAME 替换实时榜；4 个 key 统一 `{hot}` tag 保证 Cluster 同 slot；快照落 MySQL，30 天清理。"
