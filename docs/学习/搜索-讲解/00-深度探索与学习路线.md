# 00 · 搜索域：深度探索与学习路线

> **口径**：先讲**生产环境/行业常见做法**，再对照本项目；代码不代表应然标准。
> 本文按"域发现 9 步"做探索（入口→执行流→侧扫→设计决策→分类→依赖→拓扑→覆盖），再给学习路线。
>
> **一句话**：搜索域 = **读得准（查询/排序/分页）+ 索引稳（Canal/版本/墓碑/重建）+ 推得动（召回/粗排）+
> 边界清（数据从 content/product/order/social 来）**。
>
> **系列 10 篇**：00 总纲 → 01 数据源与边界 → 02 索引供给 → 03 读路径 → 04 深分页/相关性
> → 05 热搜 → 06 联想/历史 → 07 推荐 → 08 商家搜索/事件同步 → 09 性能/ES/工程。

## 1. 入口与三条主流程（9 步之 1–2）

**入口**：`SearchApplication` + 三个 Controller：

| Controller | 主端点 |
|---|---|
| `SearchController` | `/search/note`、`/search/product`、`/suggest`、`/history`、`/hot`、`/hot/record`、`/index/rebuild` |
| `RecommendController` | `/recommend/feed`、`/recommend/similar/{noteId}`、`/recommend/behavior`、`/recommend/compute` |
| `SellerOrderSearchController` | 商家订单检索/回填（C-004） |

**流程 A：搜索读**（`SearchController` → `NoteSearchService`/`ProductSearchService`）

```
Controller（异步线程池，释放 Tomcat 线程）
→ 副作用：searchHistory.add + hotSearch.record（Lua 反作弊）
→ ES：multiMatch（关键词）+ filter（status/分类/价格）+ highlight
→ 排序四型：relevance/时间/热度/价格/销量
→ Search After 游标（区分 double/long，防精度丢页）
```

**流程 B：索引供给**（Canal → MQ → ES）

```
Canal note_instance → NOTE_INDEX_TOPIC ─┐
Canal product_instance → PRODUCT_INDEX_TOPIC ─┤→ Note/ProductIndexSyncConsumer → ES
                                              └→ ProductCacheCanalEvictConsumer（product 缓存）
失败集 → IncrementalIndexSyncJob（60s）
全量 → IndexRebuildJob（4:00/手动）→ 新实体 v2 → 原子切别名 → 窗口重放 → 删 v1
DLQ → SearchDlqReplayConsumer（5 组）

另两条同步链：
order → SUB_ORDER_INDEX_TOPIC → SellerSubOrderIndexSyncConsumer → seller_sub_order_index
SOCIAL_TOPIC(LIKE/UNLIKE) → LikeCountSyncConsumer → note_index.likeCount（读 analytics 权威 Set）
```

**流程 C：推荐**（`RecommendController` → `RecommendService`）

```
5 路召回并行（Content/Following/Geo/Hot/ItemCF；每路 100、2s 超时）
→ 按 noteId 合并去重
→ 粗排加权（来源 0.25 / 偏好 0.25 / 质量 0.30 / 时效 0.20）
→ 截断
→ 已看过过滤（Redis Set）→ 回写
离线：recommendFeatureJob / recommendHotPoolJob / recommendItemCFJob
行为：RECOMMEND_BEHAVIOR_TOPIC → t_user_behavior（INSERT IGNORE）
```

**流程 D：热搜**（`HotSearchService`）

```
record：Lua 原子（屏蔽词 → IP 限频 → 用户同词去重 → HINCRBY 分钟桶）
calculate：最近 60 个分钟桶 → Score = Σ(count × e^(-0.1·Δt)) → ZSet 临时键 RENAME
展示：置顶优先 + 屏蔽剔除 + 标签；快照落 t_hot_search_snapshot；日清
```

## 2. 目录侧扫与设计决策（9 步之 3–4）

| 目录 | 内容 | 是否有独立设计决策 |
|---|---|---|
| `service/` | 搜索读、热搜、推荐、联想、历史、商家搜索、文档构建 | ✅ 核心 |
| `consumer/` | note/product 索引、点赞数、行为、商家子单、DLQ | ✅ 核心（一致性） |
| `job/` | 增量补偿、全量重建、推荐离线、商家回填 | ✅ 核心（重建/补偿） |
| `recommend/` | 5 路召回策略 | ✅ 核心（推荐） |
| `config/` | ES 客户端、mapping、别名、线程池 | ✅ 支撑（索引/性能） |
| `controller/` | 搜索/推荐/商家 | 薄层，不单列 |
| `dto/` | 请求/响应 | 排除 |
| `feign/` | product/order 契约 | 归入边界 |
| `cache/` | 热搜/推荐池预热 | 归入热搜/推荐 |

**排除**：DTO、纯转换、测试基础设施。**不排除**：alias manager（零中断重建）、DLQ（可靠性）。

## 6. 覆盖报告（9 步之 9）

**基线**：`06-搜索.md` §1/§4（读路径、联想/历史、热搜、索引供给、点赞同步、推荐、商家搜索、ES/别名、限流/观测、跨库边界）——10 项。

**方法输出**：S-1~S-10——10 项，**覆盖率 100%**。

**额外域**：S-10 把"ES 运维/限流/观测/测试"独立出来（基线散落在 §2/§6/§7），便于工程收口；
S-9 把"跨库边界"从问题线索升级为独立域（search 无自有库、复用 content + 跨库 product，是结构事实）。

## 7. 缺口与风险（不藏）

1. **ES 集群运维**：设计基线是集群，但部署/容量/故障演练未落地；
2. **推荐权重硬编码**（0.25/0.25/0.30/0.20 不可配）；无 ML 精排/重排；
3. **跨库边界**：search 复用 content 库 + 显式跨库 product——有意为之，但不是"一模块一库"；
4. **suggest 索引未别名化**（派生小索引，原地重建可接受）；
4.1 **search 写 content 派生表**（特征/行为/热搜快照）——不是"纯只读"，是结构事实；
5. **无运行时/压测**：ES 查询延迟、重建耗时、推荐召回超时都只有单测/配置；
6. **Canal/ES 故障演练**：靠 TTL/失败集/DLQ 兜底，未实测。

## 9. 面试开场（30 秒）

> "搜索域我按三条链路讲：读、索引、推荐。读是 ES multiMatch + filter + 高亮 + 四型排序，
> 深分页用 Search After；索引是 Canal 双通道 → MQ → ES，external version 防乱序、墓碑防复活、
> 失败集 + 增量补偿 + 全量重建别名原子切换；推荐是 5 路召回 + 粗排加权 + 已看过过滤。
> 搜索没有自己的库，复用 content 数据源、跨库读 product。"
