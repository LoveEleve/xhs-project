# 03 · 搜索读路径

> **口径**：先讲**生产环境/行业常见做法**，再对照本项目；代码不代表应然标准。
>
> **一句话**：读路径 = **异步 Controller → ES 查询（关键词 + 过滤 + 高亮）→ 排序 → Search After → 结果裁剪**；
> 笔记和商品是两套查询语义，不要混。
>
> **本篇带走**：① 请求生命周期 ② 笔记/商品查询差异 ③ 排序/高亮/hasMore ④ 副作用与降级。
> 前置：01/02。证据：`SearchController`、`NoteSearchService`、`ProductSearchService`、`AbstractSearchService`。

---

## 0. 例子：搜"露营"笔记 vs 搜"耳机"商品

**笔记**（`GET /search/note?keyword=露营&sort=relevance`）：

```
multiMatch(title^3, content) + filter(status=2)
→ 排序：relevance / time / hot
→ 高亮 title + content
→ 返回 items / total / hasMore / searchAfter
```

**商品**（`GET /search/product?keyword=耳机&categoryId=..&minPrice=..&sort=price_asc`）：

```
match(name) + filter(status=1, categoryId, price range)
→ 排序：relevance / price_asc / price_desc（sales 暂不支持）
→ 高亮 name
→ 返回 items / total / hasMore / searchAfter
```

## 1. 生产环境怎么做（淘宝/行业常见）

| 环节 | 常见做法 |
|---|---|
| 查询 | multi-field match + filter（结构化条件）+ boost |
| 高亮 | 标题/正文片段，`<em>` 标记 |
| 排序 | 相关度/时间/热度/价格/销量；稳定 tie-breaker |
| 分页 | 深分页用 Search After/游标，不用 from/size |
| 异步 | Controller 异步化，释放 Web 线程 |
| 降级 | ES 异常返回空/缓存兜底；限流保护 |

## 2. 本项目的实现（代码证据）

### 2.1 请求生命周期：Controller 异步 + 副作用

```java
@GetMapping("/note")
@RateLimit(windowSeconds = 1, maxRequests = 30, perUser = true, prefix = "myxhs:search:note")
public CompletableFuture<R<SearchResultVO<NoteSearchVO>>> searchNotes(...) {
    return CompletableFuture.supplyAsync(() -> {
        // 副作用：搜索历史 + 热搜记录（含反作弊）
        if (keyword != null && !keyword.isBlank()) {
            searchHistoryService.addHistory(userId, keyword);
            hotSearchService.recordSearchKeyword(keyword, userId, clientIp);
        }
        return R.ok(noteSearchService.searchNotes(request, userId));
    }, searchExecutor);
}
```

- `searchExecutor`（`recallExecutor` bean）异步执行，释放 Tomcat 线程；
- 限流 30 次/秒/用户（C-011）；
- 副作用在搜索前执行（历史/热搜），失败不影响搜索（各自 try/catch）。

### 2.2 笔记查询：multiMatch + status=2

```java
BoolQuery.Builder boolBuilder = new BoolQuery.Builder();
if (keyword != null && !keyword.isBlank()) {
    boolBuilder.must(q -> q.multiMatch(mm -> mm
            .query(keyword)
            .fields("title^3", "content")   // 标题权重 3 倍
            .analyzer("ik_smart")));
} else {
    boolBuilder.must(q -> q.matchAll(m -> m));
}
boolBuilder.filter(f -> f.term(t -> t.field("status").value(2))); // 只搜已发布；-1 墓碑/1 未发布不返回
```

- 空关键词 → `match_all`（配合排序/过滤做"逛"）；
- 高亮：`title` + `content`（content 片段 150 字、1 段）。

### 2.3 商品查询：match + status=1 + 分类/价格

```java
boolBuilder.must(q -> q.match(m -> m.field("name").query(keyword).analyzer("ik_smart")));
boolBuilder.filter(f -> f.term(t -> t.field("status").value(1))); // 只搜上架
if (categoryId != null) boolBuilder.filter(f -> f.term(t -> t.field("categoryId").value(categoryId)));
if (minPrice != null || maxPrice != null) {
    boolBuilder.filter(f -> f.range(r -> r.field("price") ...));
}
```

- 商品只搜 `name`（不是 multiMatch）；
- 价格区间是 `range` filter；
- 高亮 `name`。

### 2.4 排序：两套语义

**笔记**（`applySorting`）：

| sort | 排序 |
|---|---|
| `relevance`（默认） | `_score desc, noteId desc` |
| `time` | `createdAt desc, noteId desc` |
| `hot` | `likeCount desc, noteId desc` |

**商品**（`applyProductSorting`）：

| sort | 排序 |
|---|---|
| `relevance`（默认） | `_score desc, spuId desc` |
| `price_asc` | `price asc, spuId asc` |
| `price_desc` | `price desc, spuId desc` |
| `sales` | **不支持**：无销量数据源 → 告警 + 降级为 relevance |

**tie-breaker（noteId/spuId）**：排序值相同也有稳定顺序，Search After 才能不跳记录。

### 2.5 分页与 hasMore

- `size` 归一化：笔记默认 20/最大 50；商品默认 20/最大 50；
- **多取 1 条**（`size + 1`）判断 `hasMore`，返回时裁掉第 size+1 条（T-085：原 `items.size()>=size` 在尾页误报 true）；
- `searchAfter` 游标：上一页最后一条的排序值 JSON 数组；具体序列化/精度见 **04**；
- `total` 来自 ES `hits.total`，**默认 track_total_hits=10000**（代码未改），不要拿它做全量统计。

### 2.6 失败降级与副作用

- ES 异常 → 捕获后返回**空结果**（items=[], total=0, hasMore=false），不让搜索接口 500；
- 热搜记录失败/反作弊拒绝 → 不影响搜索；
- 历史写入：Controller 调 `SearchHistoryService.addHistory`；`NoteSearchService` 里还有一次 `recordSearchHistory`（**重复写入，已知冗余**，可清理）；
- 搜索结果不缓存（ES 查询实时）；热搜/联想有缓存。

## 3. 对照表：生产 vs 本项目

| 能力 | 生产环境 | 本项目 | 差异 |
|---|---|---|---|
| 多字段检索 | multiMatch + boost | ✅ 笔记 title^3/content；商品仅 name | 商品简化 |
| 结构化过滤 | filter | ✅ status/category/price | 对齐 |
| 高亮 | 标题/正文 | ✅ | 对齐 |
| 排序 | 多维度 | ✅ 笔记 3 种/商品 3 种（sales 降级） | 部分 |
| 深分页 | Search After | ✅ | 对齐 |
| 异步 Controller | 常见 | ✅ | 对齐 |
| 失败降级 | 空/缓存 | ✅ 空结果 | 对齐 |
| 结果缓存 | 可选 | ❌ 不缓存 | 简化 |

## 4. 十一个坑

1. **笔记/商品查询混用**：笔记 multiMatch，商品 match name；别把商品也写成 multiMatch。
2. **状态过滤写错**：笔记 `status=2`、商品 `status=1`；墓碑 `status=-1` 不能返回。
3. **sort 值不校验**：商品 `sales` 无数据源，必须显式降级，不能按缺失字段排序（静默乱序）。
4. **hasMore 用 `items.size()>=size`**：尾页取满会误报；用 `size+1`。
5. **没有 tie-breaker**：排序值相同会不稳定，Search After 可能跳/重。
6. **Search After 精度**：double/long 不能混（04）。
7. **高亮字段不一致**：笔记 title/content，商品 name；前端渲染别写死。
8. **副作用阻塞搜索**：历史/热搜失败不能影响搜索；本项目各自 try/catch。
9. **历史重复写**：Controller + Service 两处写同一 key（已知冗余，待清理）。
10. **ES 异常直接 500**：本项目降级空结果；生产可加缓存/兜底。
11. **`total` 默认上限 10000**：ES `track_total_hits` 未改，深分页/统计不能依赖 `total` 精确值。

## 5. 值不值得深挖 / 一句话

- **值得**：两套查询语义、排序/tie-breaker、hasMore、异步/降级——搜索读路径的核心；
- **一句话带过**：高亮标签、分页大小；
- **一句话**：**搜索读 = 异步 Controller → ES（multiMatch/match + filter + highlight）→ 排序（带 tie-breaker）→ size+1 判 hasMore → Search After。**
- 深分页/精度见 **04**；索引供给见 **02**。

**面试口径**："笔记搜索是 multiMatch(title^3, content) + status=2，商品是 match(name) + status=1/分类/价格；排序都带 noteId/spuId 次键，分页用 Search After，size+1 判 hasMore；Controller 异步化，ES 异常降级空结果。"
