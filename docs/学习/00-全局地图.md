## 一、系统是什么（双域合一的微服务）

**仿小红书**：内容社区（笔记/评论/社交）+ 电商交易（商品/订单/支付/库存）双域合一。

```
接入层：gateway (9000)
公共层：common —— 工具/追踪/Feign 配置/MQ 幂等，不是一个服务
交易域：product(9006) cart(9008) order(9011) inventory(9009) coupon(9010) payment(9012)
内容域：content(9002) analytics(9003) counter(9004) search(9007) home(9005) im(9014) notification(9013)
用户域：user(9001)
AI 线：my-xhs-ai / ai-app / ai-mcp / ai-tools（独立产品线，不在本次学习范围）
```

**库存（inventory）= 交易域里的"资源服务"**：被订单调用（Feign）+ 被消息触发，对外契约只有五个词：预扣 / 确认 / 释放 / 回补 / 查询。

## 二、最外层：网关怎么分发

所有外部流量先到 `gateway(9000)`：鉴权 → HMAC 签名 → Sentinel 限流 → 按路径路由（Nacos 服务发现 + `lb://`）：

| 路径 | 去向 |
|---|---|
| `/api/user/**` | my-xhs-user |
| `/api/content/**`、`/api/note/**`、`/api/comment/**`、`/api/topic/**` | my-xhs-content |
| `/api/search/**`（+recommend） | my-xhs-search |
| `/api/order/**` | my-xhs-order |
| `/api/payment/**` | my-xhs-payment |
| `/api/inventory/**` | my-xhs-inventory |
| `/api/analytics/**`、`/api/social/**` | my-xhs-analytics |
| `/api/counter/**` | my-xhs-counter |
| `/api/product/**` | my-xhs-product |
| `/api/cart/**` | my-xhs-cart |
| `/api/coupon/**` | my-xhs-coupon |
| `/api/home/**` | my-xhs-home |
| `/api/notification/**` | my-xhs-notification |
| `/api/im/**` | my-xhs-im |

> ⚠️ "最外层"只到网关为止——过了网关就按业务分叉成 15 条线，**不存在一条从头走到尾的单一路径**。所以学习只能"按链路/模块纵切"，不能"从最外层顺着走"。

## 三、主链路一张图（交易域）

```
用户 → 网关 → 订单服务（创建订单）
  │
  ├─① Feign 同步调：商品(查SKU/价) · 用户(地址) · 优惠券(试算)
  ├─② MQ 事务消息 ORDER_TRANSACTION_TOPIC ──► 库存：PRE_DEDUCT
  │      （库存内：Redis 预扣 → Outbox → INVENTORY_TOPIC → 落 MySQL available→locked）
  ├─③ 延时消息（兜底 30min 关单）
  └─④ 用户支付 → 支付服务(Mock) → PAY_RESULT_TOPIC ──► 订单(onPaymentSuccess)
                                                      └─Feign─► 库存：CONFIRM（locked--）

取消/超时：订单 ──Feign─► 库存：RELEASE（locked→available）
退款    ：订单/售后 ──Feign─► 库存：CONFIRM(清预扣记录) + REFUND_RESTORE（available++）
失败收口：库存 ──INVENTORY_FAILED_TOPIC──► 订单（未支付自动关单 / 已支付人工）
```

## 四、通道总表

### 4.1 Feign（同步，强依赖）——@FeignClient 全量扫描 ✅

```
order     → payment, product, coupon, user, inventory
payment   → order
inventory → product
product   → inventory
cart      → product
search    → product
home(BFF) → product, content, coupon, counter, notification, user, cart, analytics, inventory
content   → user
analytics → content, user
```

（home 是首页聚合 BFF：一次请求聚合近十个服务。）

### 4.2 MQ（异步，解耦）

| Topic | 方向 | 用途 | 核对 |
|---|---|---|---|
| `ORDER_TRANSACTION_TOPIC` | order → inventory | 下单触发预扣（事务消息） | ✅ |
| `INVENTORY_TOPIC` | inventory 内部 | L2 落账事件（PRE_DEDUCT/CONFIRM/RELEASE/REFUND_RESTORE） | ✅ |
| `INVENTORY_FAILED_TOPIC` | inventory → order | 库存失败收口 | ✅ |
| `PAY_RESULT_TOPIC` | payment → order | 支付结果 | ✅ |
| `REFUND_RESULT_TOPIC` | payment → order | 退款结果 | ⏳ |
| `ORDER_COMPENSATION_TOPIC` | order 内部 | 补偿重试（释放库存/退券失败等） | ✅ |
| `ORDER_CLOSE_TOPIC` | order 内部 | 超时关单延时 | ⏳ |
| `COUPON_CLAIM_TOPIC` | coupon 域 | 领券异步 | ⏳ |
| `CART_TOPIC` | cart 域 | 购物车异步 | ⏳ |
| `NOTIFICATION_TOPIC` | 各服务 → notification | 通知中台 | ⏳ |
| `CACHE_EVICT_TOPIC` | Canal/服务 → 各服务 | 缓存失效广播 | ⏳ |
| `INVENTORY_CACHE_TOPIC` | inventory 缓存相关 | — | ⏳ |
| `FEED_TOPIC` / `SOCIAL_TOPIC` / `RECOMMEND_BEHAVIOR_TOPIC` | 内容/社交/推荐域 | — | ⏳ |
| `PRODUCT_INDEX_TOPIC` / `NOTE_INDEX_TOPIC` | product/content → search | 搜索索引同步 | ⏳ |
| `RETRY_TOPIC` / `DEFAULT_RETRY_TOPIC` | 通用重试 | — | ⏳ |

（所有 topic 均为 6 队列，`-p 6`——这是"消息不保证全局顺序"的事实依据，见 06 落账篇。）

## 六、用法：读代码三问

看到任何一段代码，先问：

1. **谁调它？** —— 入边：Feign（§4.1 反向查）或 MQ（§4.2 找 topic）
2. **它发什么？** —— 出边：MQ 事件 / Feign 调用
3. **谁收？** —— 对应消费者 / 被调方

## 七、与学习路线的关系

- **为什么从库存开始**：简历核心域之一 + "契约式学习"（深挖一个模块，边界处学契约，前置后补）——比"从最外层顺学"高效，因为微服务是图不是树（order→inventory 与 inventory→order 成环）。
- **库存的周边四条边**（都已知道契约）：订单（触发方，事务消息 + Feign）、支付（经订单转发 confirm）、优惠券（下单试算/退券）、商品（SKU 校验）。
- **订单模块侦察**：已产出 `docs/学习/订单-侦察/00-侦察报告.md`（2026-10-11：结构/链路/交互核对/问题分级 + P0 发现与学习篇目草案）。
- **前进路线**：库存讲透 → 交易域其他节点按需补契约或另开模块；内容域 / AI 线暂不进学习范围。
