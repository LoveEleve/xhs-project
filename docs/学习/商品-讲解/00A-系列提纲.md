## 01 商品模型（业务）

- **目标问题**：一件商品由哪些对象定义？SPU/SKU/类目/属性/价格/状态各自管什么？
- **核心结论**：SPU=标准产品单元，SKU=可售最小单元；类目是树、属性是模板、价格有多口径、状态是 0/1；
  本项目 `specs` 是自由 JSON、单商家、无审核/定时上下架——是简化。
- **小节**：
  1. 例子：一件 T 恤的 SPU 与颜色×尺码 SKU
  2. 数据模型（`t_spu/t_sku/t_category/t_product_behavior`；`t_sku.stock` 是占位）
  3. SKU 创建校验：价格非负、划线价≥售价、specs 合法 JSON；SKU 默认上架、SPU 默认下架
  4. 应然 vs 实然：属性体系/多商家/多价格/审核/定时
  5. 状态机：0 下架/1 上架；上架必须至少一个上架 SKU；商品浏览埋点
- **证据**：`Spu`/`Sku`/`Category`、`ProductStatus`、`01-商品.md` §2/§3。
- **追问链**：SPU 与 SKU 区别→库存为什么不在商品→价格快照。

## 02 读路径与缓存三件套（性能）

- **目标问题**：详情页高并发怎么读？缓存穿透/击穿/雪崩怎么防？
- **核心结论**：布隆前置 → Redis 逻辑过期（30min/物理 2h）→ MySQL；空值缓存（2min/5min）防穿透；
  冷 key 分布式锁防惊群；逻辑过期返回旧值 + 异步刷新；分类树预热；读写分离。
- **小节**：
  1. 例子：热点 SPU 与不存在的 SPU
  2. 三级读路径（Bloom/Redis/MySQL）与空值缓存
  3. 逻辑过期 vs 物理过期（击穿）
  4. 防惊群、N1/N2 单查、读写分离
  5. 分类树缓存/刷新/预热；布隆重建接口
- **证据**：`SpuService.getSpuDetail`、`RedisCacheData`、`ProductCacheWarmer`。
- **追问链**：布隆误判怎么办→逻辑过期数据旧怎么办→Redis 挂了怎么办。

## 03 写路径与缓存一致性（一致性）

- **目标问题**：改价/上下架后缓存怎么失效？为什么不用延迟双删？
- **核心结论**：事务后立即删（快路径）+ 删失败 MQ 兜底 + **Canal binlog 最终失效**；
  binlog 是已提交数据的因果链，确定性优于"睡固定时间"的延迟双删；Canal 宕机靠 TTL 兜底。
- **小节**：
  1. 例子：改 SPU 名称/描述/上下架后详情页多久可见（外部直改 SKU 价格也靠 Canal）
  2. 三层一致性（afterCommit / MQ / Canal）
  3. 为什么弃用延迟双删（C-005 决策）
  4. 外部直改 DB、主从延迟、删缓存失败
  5. 建 SKU 后的库存初始化：afterCommit + pending set + `InventoryInitRepairJob`（product→inventory 边界）
- **证据**：`SpuService.updateSpu/updateSpuStatus`、`CacheEvictConsumer`、`ProductCacheCanalEvictConsumer`、C-005。
- **追问链**：Canal 延迟多久→binlog 丢了怎么办→主从延迟回填脏数据。

## 04 索引供给与搜索边界（分布式/微服务）

- **目标问题**：商品变更怎么进 ES？product 和 search 的边界怎么划？
- **核心结论**：Canal 抓 `t_spu/t_sku` → `PRODUCT_INDEX_TOPIC` → search 消费建索引；
  product 不直接写 ES；同一 topic 另有一个消费组做缓存失效（C-005）；按主键分区保序、消费幂等。
- **小节**：

  2. Canal→MQ→ES 链路与消息格式
  3. 双消费组：搜索索引 vs 缓存失效
  4. 幂等/顺序/DLQ/别名切换（→搜索系列）
- **证据**：`ProductCacheCanalEvictConsumer`、`PRODUCT_INDEX_TOPIC`、搜索模块消费者。
- **追问链**：为什么不用双写→消息乱序怎么办→全量重建怎么做。
