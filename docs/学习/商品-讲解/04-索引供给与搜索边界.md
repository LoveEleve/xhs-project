# 04 · 索引供给与搜索边界

> **口径**：先讲**生产环境/行业常见做法**，再对照本项目；代码不代表应然标准。
>
> **一句话**：**商品是源，搜索是索引**——商品不写 ES，搜索不写商品库；
> 中间靠 **Canal → MQ → ES** 供给，增量靠版本/删除墓碑，全量靠**别名原子切换**。
>
> **本篇带走**：① 供给链路 ② 增量语义（版本/逻辑删/父 SPU）③ 全量重建与别名 ④ 边界与坑。
> 前置：03。证据：`ProductIndexSyncConsumer`、`IndexRebuildJob`、`IndexAliasManager`、C-005/C-011。

---

## 0. 例子：改价/上下架后，搜索多久可见

```
改 SKU 价格（DB）
  → Canal 抓 t_sku binlog
  → PRODUCT_INDEX_TOPIC
  → 搜索消费者：按 spu_id 重新索引父 SPU
  → ES 文档更新（秒级延迟，最终一致）

上下架 SPU（DB）
  → Canal 抓 t_spu binlog
  → 搜索消费者：INSERT/UPDATE → 索引；deleted=1 → 墓碑删除

全量重建（mapping 变更/索引损坏）
  → 建 product_index_v2 → 全量写入 → 校验 → 原子切别名 → 重放重建窗口 → 删 v1
```

## 1. 生产环境怎么做（淘宝/行业常见）

| 环节 | 常见做法 |
|---|---|
| 供给 | **CDC/binlog**（Canal/Debezium）→ MQ；不做业务双写 |
| 增量 | 按主键/版本幂等；删除用墓碑；批量事件按父 ID 去重 |
| 全量 | 新索引 + 全量灌数 + **别名原子切换**；失败不切；切换后重放窗口 |
| 一致性 | 最终一致；搜索允许秒级/分钟级延迟；不接受"业务双写 ES" |
| 兜底 | 失败集合 + 补偿 Job + DLQ + 对账 |
| 边界 | 商品域拥有 DB；搜索域拥有索引；互不写对方存储 |

## 2. 本项目的实现（代码证据）

### 2.1 供给链路：一个 topic，两个消费组

```
Canal（my_xhs_product.t_spu/t_sku）
  → PRODUCT_INDEX_TOPIC
      ├─ search: product-index-sync-consumer-group → 写 ES
      └─ product: product-cache-canal-evict-group → 删本地缓存（03）
```

- **product 不直接写 ES**；**search 不写商品库**；
- 同一 topic 两个独立消费组：搜索建索引、商品删缓存，互不影响；
- 按主键分区（C-005 配置），同 SPU 的变更尽量有序。

### 2.2 增量：版本、逻辑删、父 SPU

`ProductIndexSyncConsumer` 消费 Canal 消息：

```java
// Canal 原始格式：{database, table, type, data:[...], ts}
long version = canalMsg.getLongValue("ts", System.currentTimeMillis());
// ts 缺失/为 0 时回退 es 字段（兼容旧消息）

// t_sku 变更：按 spu_id 重新索引父 SPU（批量事件去重）
if ("t_sku".equals(table)) {
    Set<Long> spuIds = new LinkedHashSet<>();
    for (row : data) spuIds.add(row.getLong("spu_id"));
    for (Long spuId : spuIds) indexProductBySpuId(spuId, version);
    return;
}

// t_spu：INSERT/UPDATE → 索引；deleted=1 → 墓碑删除
if (row.getIntValue("deleted", 0) == 1) deleteProduct(spuId, version);
else indexProductBySpuId(spuId, version);
```

关键点：

- **版本 = `ts` 毫秒时间戳**（T-088）：ES 用 `ExternalGte` 拒绝旧版本，防乱序覆盖；
- **t_sku 批量事件按 `spu_id` 去重**（RV32）：一次改多个 SKU，父 SPU 只重建一次；
- **逻辑删 → 墓碑**（带 `deletedAt`）：不是立刻物理删，重建时清理超龄墓碑；
- **失败记录**：ES 通信/文档构建失败 → 写 Redis 失败集合（1h），供 `IncrementalIndexSyncJob` 补偿；
- **DLQ**：消费重试耗尽 → `SearchDlqReplayConsumer` 重放（防丢）。

### 2.3 全量重建：别名原子切换

`IndexRebuildJob`（每天 4 点 / 管理端 `POST /api/search/index/rebuild`）：

```
① 解析别名：product_index → 当前实体 product_index_v1
② 建下一版：product_index_v2（mapping 复用）
③ 全量灌数（分页 + Bulk，断点续传）
④ 清理墓碑/无效文档
⑤ 原子切别名：product_index: v1 → v2（一次 updateAliases）
⑥ 重放重建窗口：updated_at >= rebuildStart 的变更补进 v2
⑦ 删 v1（best-effort）
```

```java
// 原子切换：remove + add 在同一次 updateAliases 调用
esClient.indices().updateAliases(u -> u
    .actions(a -> a.remove(r -> r.index(from).alias(alias)))
    .actions(a -> a.add(add -> add.index(to).alias(alias))));

// 切换后重放窗口（重建期间发生的更新）
replayWindowProducts(productIndexName, rebuildStart);
```

**失败不切换（切换前）**：v2 半成品时别名仍指 v1；重跑续传同一 v2（断点续传）。
> 注意：如果**别名已切换、窗口重放失败**，代码会抛异常且别名可能已指向新实体（日志提示需人工确认）——
> "失败不切换"只对切换前的重建失败成立。
**legacy 兼容**：存量部署"索引名=配置名、无别名"→ 回退原地重建（告警，部署说明迁移）。

### 2.4 兜底与延迟

- 增量失败 → Redis 失败集合 → `IncrementalIndexSyncJob` 周期补偿；
- 消息进 DLQ → `SearchDlqReplayConsumer` 重放；
- 搜索是**最终一致**：Canal/MQ/ES 都有延迟；"写完立刻搜到"不保证。

### 2.5 边界：product ↔ search

| 关注点 | 归属 |
|---|---|
| 商品数据/价格/状态 | **product**（唯一源） |
| ES 索引/mapping/别名/重建 | **search** |
| 变更事件 | Canal → MQ（不由业务双写） |
| 缓存失效 | product 自己消费同一 topic（03） |
| 搜索排序/召回 | search（搜索系列展开） |

## 3. 对照表：生产 vs 本项目

| 能力 | 生产环境 | 本项目 | 差异 |
|---|---|---|---|
| 供给方式 | CDC/binlog | ✅ Canal→MQ | 对齐 |
| 增量幂等 | 版本/主键 | ✅ ts + ExternalGte | 对齐 |
| 删除 | 墓碑/物理清理 | ✅ 墓碑 + 重建清理 | 对齐 |
| 父 SPU 重建 | 批量去重 | ✅ t_sku → spu_id | 对齐 |
| 全量重建 | 别名原子切换 | ✅ v2 + switch + replay | 对齐 |
| 失败兜底 | 补偿/DLQ | ✅ 失败集合 + DLQ | 对齐 |
| 搜索延迟 | 秒级/最终一致 | ✅ | 对齐 |
| 业务双写 ES | 不推荐 | ❌ 没做 | 对齐 |

## 4. 十一个坑

1. **业务双写 ES**：商品事务成功、ES 失败 → 不一致；用 CDC。
2. **消息乱序**：旧版本覆盖新版本；用 `ts + ExternalGte`。
3. **t_sku 批量事件只取 data[0]**：其余父 SPU 漏更新；按 spu_id 去重。
3.1 **t_sku DELETE 在 MINIMAL 行镜像下没有 spu_id**：搜索索引和商品缓存都定位不到父 SPU（需调行镜像/反查）。
4. **逻辑删直接物理删**：无法防复活/审计；用墓碑 + 超龄清理。
5. **全量重建直接写线上索引**：半成品被读到；用 v2 + 别名切换。
6. **切换前删旧索引**：切换失败就没得回退；先切后删。
7. **切换后不重放窗口**：重建期间的更新丢失；`updated_at >= rebuildStart` 补齐。
8. **legacy 无别名**：重建原地进行，风险高；告警并迁移别名模型。
9. **搜索写完立刻查**：最终一致，不保证；产品上要接受延迟。
10. **同一 topic 消费组混用**：搜索索引和缓存失效必须独立消费组，否则互相抢消息。
11. **切换后重放失败**：别名可能已指向新实体；"失败不切换"只覆盖切换前，切换后失败要人工确认。

## 5. 值不值得深挖 / 一句话

- **值得**：CDC 供给、版本幂等、墓碑、别名原子切换、窗口重放——搜索/索引面试核心；
- **一句话带过**：ES mapping、Bulk 参数、Canal 配置；
- **一句话**：**商品是源、搜索是索引；Canal→MQ→ES；增量靠版本/墓碑，全量靠别名原子切换 + 窗口重放。**
- 搜索召回/排序见搜索系列；缓存失效见 **03**。

**面试口径**："商品变更走 Canal→PRODUCT_INDEX_TOPIC→ES，不做业务双写；增量用 ts 版本 + ExternalGte 防乱序，t_sku 变更按父 SPU 重建，逻辑删用墓碑；全量重建建 v2、原子切别名、切换后重放窗口，失败不切。"
