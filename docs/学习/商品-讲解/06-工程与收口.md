# 06 · 工程与收口

> **口径**：先讲**生产环境/行业常见做法**，再对照本项目；代码不代表应然标准。
>
> **一句话**：工程化 = **责任边界清晰 + 测试覆盖分支 + 指标/告警 + 工程债诚实分档**；
> 不是"功能写完"，而是"规则可测、异常可见、失败可兜、债有账本"。
>
> **本篇带走**：① 代码结构/责任 ② 35 个测试 ③ 指标 ④ 工程债与面试口径。
> 前置：01–05。证据：`SpuService`/`SkuService`/`CategoryService`、C-005、测试报告。

---

## 0. 例子：一次商品详情异常，怎么定位

```
详情返回 null / 慢 / 旧值
  ├─ 布隆拦截？        → myxhs_product_bloom_block_total
  ├─ 缓存命中/未命中？ → cache_hit_total / cache_miss_total / null_hit_total
  ├─ 逻辑过期刷新？    → cache_refresh_total
  ├─ 写后缓存没删？    → cache_evict_total{source=write/canal}
  ├─ SKU 库存没初始化？→ inventory_init_fail_total（+ InventoryInitRepairJob）
  └─ 埋点丢了？        → view_drop_total（CallerRuns/队列满）
```

每个环节都有指标/日志/兜底，不是"报个错就完了"。

## 1. 生产环境怎么做（淘宝/行业常见）

| 维度 | 常见做法 |
|---|---|
| 代码结构 | 按域/聚合拆分；读写路径、缓存、补偿、Job 各归其位 |
| 测试 | 单测覆盖分支 + 集成（Canal/ES/Redis）+ 压测 + 故障注入 |
| 可观测 | 命中率/回源/延迟/错误/积压 + 链路追踪 + 告警 |
| 兜底 | MQ/补偿 Job/DLQ/对账；runbook |
| 工程债 | 显式登记、分档、定期清理；不把临时方案当架构 |

## 2. 本项目的实现（代码证据）

### 2.1 代码结构：谁管什么

| 组件 | 职责 |
|---|---|
| `SpuService` | SPU 创建/更新/上下架、详情读路径（布隆/缓存/DB）、布隆、缓存失效 |
| `SkuService` | SKU 创建/查询、价格/JSON 校验、库存初始化（afterCommit + 补偿） |
| `CategoryService` | 类目树缓存/刷新/预热 |
| `cache/` | `RedisCacheData`（逻辑过期包装）、`ProductCacheWarmer`（分类树预热） |
| `consumer/` | `CacheEvictConsumer`（删缓存 MQ 兜底）、`ProductCacheCanalEvictConsumer`（Canal 失效） |
| `job/` | `InventoryInitRepairJob`（库存初始化补偿） |
| `controller/` | 管理端/内部/公开接口 + 限流/鉴权 |

规模：28 文件 / 约 2279 行（模块对照口径）。

### 2.3 指标与告警

| 指标 | 用途 |
|---|---|
| `myxhs_product_cache_hit_total` / `miss_total` | 命中率、回源量 |
| `myxhs_product_cache_null_hit_total` | 空值缓存命中（防穿透） |
| `myxhs_product_bloom_block_total` | 布隆拦截（不存在 ID） |
| `myxhs_product_cache_refresh_total` | 逻辑过期异步刷新 |
| `myxhs_product_cache_evict_total{source=write/canal}` | 写路径/Canal 失效 |
| `myxhs_product_inventory_init_fail_total` | 库存初始化失败 |
| `myxhs_product_view_drop_total` | 埋点丢弃（队列满） |

**缺口**：没有按 key 的热点/QPS/延迟指标；只有总量。

### 2.4 工程债：三档，不藏

**已修（C-005）**：

- 建 SPU 默认下架（原默认上架 → 空商品在架）；
- SKU 价格非负、划线价 ≥ 售价、specs 合法 JSON；
- **Canal 失效替代延迟双删**（binlog 因果链）；
- 库存初始化失败补偿（pending set + `InventoryInitRepairJob`）；
- N1/N2 同请求单查；分类树 refresh；布隆重建；缓存指标。

**已记（未修/取舍）**：

| 债 | 影响 |
|---|---|
| 无属性体系（`specs` 自由 JSON） | 无法做规格矩阵/属性筛选 |
| 无品牌库/店铺/商家后台 | 多商家能力缺失 |
| 无活动价/会员价/阶梯价 | 价格体系简化 |
| 无草稿/审核/定时上下架/版本留痕 | 管理流程简化 |
| **无 SKU 更新/改价接口** | 价格变更只能改库/补接口 |
| **详情 `GET /spu/{id}` 无限流** | 热点详情裸奔 |
| 无 L1/热点 key 拆分/SPU 预热 | 单 key 热点上限 |
| 无按 key 指标 | 定位不到具体热点 |
| 无压测/运行时验证 | 不能声称 QPS/生产验证 |

**一句带过**：参数校验、日志格式、配置命名、类目只读。

### 2.5 面试口径（30 秒 + 追问）

**30 秒**：

> "商品域我按三个问题讲：读得准、写得对、查得快。读路径是布隆 → Redis 逻辑过期 → MySQL，
> 空值缓存防穿透、分布式锁防惊群；写路径是提交后删 + MQ 兜底 + Canal binlog 最终失效，不用延迟双删；
> 索引走 Canal→MQ→ES，全量重建用别名原子切换。商品只存静态描述，库存和下单快照都不在它这里。"

**追问准备**：

- "为什么不用延迟双删？" → 猜时间、覆盖不了外部直改；Canal 是已提交 binlog 的因果链。
- "缓存击穿/穿透怎么防？" → 逻辑过期 + 布隆 + 空值 + 防惊群。
- "热点 key 怎么办？" → 本项目单 key，缺 L1/拆分；生产用本地缓存/热点探测。
- "SKU 价格怎么改？" → 当前**没有改价接口**，只能改库/补接口；下单以 DB 价为准。
- "哪些不能吹？" → QPS/容量、属性体系、多商家/审核、生产验证。

## 3. 值不值得深挖 / 一句话

- **值得**：责任边界、测试覆盖思路、指标族、工程债分档——面试官很吃"你知道边界"；
- **一句话带过**：测试框架、指标实现、配置；
- **一句话**：**工程化不是"功能写完"，而是"规则可测、异常可见、失败可兜、债有账本"。**

**面试收口**："商品域我按读得准/写得对/查得快讲；实现有逻辑过期、布隆、Canal 失效、索引别名切换；
测试 35 个覆盖分支；缺口（属性体系、SKU 改价、详情限流、L1、压测）我明确记录，不吹。"
