## 一、模块全貌（先看体量）

- **26 个主 Java（3,813 行）+ 4 个测试（636 行）+ 4 个 Lua + 配置**，Java 合计 4,449 行
- 一句话职责：为平台提供"**永不超卖、可自愈**"的库存能力：下单预占 / 支付确认 / 取消回退 / 退款回补（TCC 冻结为独立接口能力，本系列不讲）
- 架构定位：**Redis = 实时主账（L1）；MySQL = 持久备份账（L2，允许慢半拍）；对账 = 收敛**

## 二、五个能力域（学什么 + P7 到什么程度）

### 域 1 · 业务链路
- 四步链路：预占（事务消息触发）→ 确认（支付回调）→ 回退（取消/超时）→ 回补（退款）
- 失败收口：预扣/确认的 L2 落账最终失败（重试耗尽）→ INVENTORY_FAILED_TOPIC → 订单侧（待付款自动取消 / 已付款人工）
- **P7 标准**：能画全链路时序；每一步的触发方、幂等、失败路径张口就来

### 域 2 · 数据模型
- MySQL 6 表：`t_inventory`（三态）、预扣幂等表、Outbox、补偿表、`t_tcc_fence`、`t_tcc_freeze_detail`
- Redis 5 类 key：total / bucket:N / bucket:count / prededuct hash（含 `skuId:bucket` 字段）/ index ZSet
- 三段式语义：available（可售）÷ locked（预扣未确认）÷ freezing（TCC 冻结）；实际总量 = available + locked
- **P7 标准**：每个字段/唯一键/索引"为什么存在、防什么"能讲；TTL 缓冲 600s 的原因

### 域 3 · 可靠性机制（模块的含金量核心）
- **幂等三层**：消费者 msgId → Lua HGET → MySQL 幂等占位（防 Redis 丢失）；退款回补用"累计正增量"
- **乱序治理**：L2 落账版本门（Redis Lua 预留→执行→失败回滚）+ 事件 eventTime
- **Outbox**：先落库→同步发送→成功立即标记（防 Job 重发双扣）；PRE_DEDUCT 失败→作废+回滚 Redis；其余动作失败→留表由 Job 补发
- **超时回收**：ZSet 过期索引只回退"真到期"（物理 TTL = 逻辑过期 + 600s 缓冲）
- **补偿**：回滚失败落表（3 次转人工）；退款回补 type=2 补偿
- **对账**：以 Redis 为准修 MySQL + locked 对账 + 幂等表 7 天清理 + Outbox 7 天/补偿 90 天排空
- **P7 标准**：每个机制防哪种故障；背下"失败矩阵"（见第五节）

### 域 4 · 性能与热点
- 分桶（默认 2 → 热点 8）+ `HotSkuDetector`（滑窗 10s/100 次，采样 1/5 触发）+ `resizeBuckets`（pause 标记 + 锁 + Pipeline 重分配）
- ZSet 过期索引：O(N) SCAN → O(logN) ZRANGEBYSCORE
- Lua 脚本 Bean 预加载（EVALSHA）
- **边界（必须主动讲）**：单实例分桶无并发收益；`{skuId}` 同 slot 不兼容集群；正确形态 = 分片 + 桶粒度 tag + 对账兜底
- **P7 标准**：收益边界、演进路径（对照《工程问题台账》问题 1）

### 域 5 · 运维与工程
- **4 个 Job**：PreDeductTimeout（1min）、OutboxSender（5s）、Compensation（30s）、Reconcile（XXL 每小时 `0 0 * * * ?`）——各自 Redisson 锁（TccTimeout 随 09 排除）
- **3 个消费者**：OrderTransaction（订单事务消息入口）、InventoryDeduct（L2 落账）、InventoryCacheEvict（Canal 缓存，回声保护）
- **读路径**：getStock（Redis 命中直接返；未命中读 MySQL——**N7 后不再自动回填**，需 reinit）
- 配置：端口 19009、Sentinel、桶数 2/8、采样率、graceful shutdown；指标埋点 businessMetrics
- 口径红线：TCC 未接线 / 对账与在线写无屏障 / 分桶名不副实 / CODE-REVIEW 部分内容已过时（以代码为准）
- **P7 标准**：主动披露边界 + 改进方向

## 五、失败矩阵（背）

| 失败点 | 谁来接 |
|---|---|
| 重复消息 | msgId + Lua HGET + MySQL 占位 |
| MQ 乱序 | 版本门（预留-回滚） |
| 写完 Outbox、发 MQ 前崩溃 | OutboxSenderJob 补发 |
| MQ 发送失败（PRE_DEDUCT） | 作废 Outbox + 回滚 Redis + 业务失败；其余动作留表由 Job 补发 |
| 并发改同行 | 条件更新 + 3 次退避重试 |
| DB 重试耗尽 | 失败事件 → 订单收口（自动取消/人工） |
| 预扣没人确认（超时） | ZSet 过期索引 + 回退 + RELEASE 事件 |
| Redis 回退失败 | 补偿表（3 次转人工） |
| Redis 数据丢失 | rebuild（available+locked）+ reinit（不做盲目回填） |
| 以上全漏 | L3 对账（Redis 为准） |

## 八、深度 Review 补充（第二轮，2026-10-04 通读全部文件后）

### 8.1 调用方全景（谁在用库存）
| 调用方 | 方式 | 干什么 |
|---|---|---|
| 订单服务 | **RocketMQ 事务消息**（ORDER_TRANSACTION_TOPIC） | 下单成功后触发**预扣**（每 SKU 一次） |
| 订单服务 | Feign | 取消→release（OrderService:569）、支付成功→confirm（:848）、退款→refundRestore（:974） |
| 售后域 | Feign | 退货退款→refundRestore（AftersaleService:495） |
| 商品服务 | Feign | queryStock 展示库存（SkuService） |
| 管理端 / 脚本 | HTTP | init / reinit / reconcile / tcc 接口 |
| （反向）库存 → 订单 | RocketMQ（INVENTORY_FAILED_TOPIC） | L2 落账失败收口（待付款自动取消 / 已付款人工） |
| 内部自转 | @Scheduled + XXLJob + MQ | 4 个 Job；3 个消费者（订单事务 / L2 落账 / Canal 缓存） |

> 关键记忆点：**预扣走 MQ（事务消息），确认/回退/回补走 Feign（同步）**。

### 8.2 接口清单（InventoryController）
- 业务：`/init`、`/preDeduct`、`/confirm`、`/release`、`/refund-restore`、`/reinit`、`/stock/{skuId}`、`/internal/reconcile`
- TCC：`/tcc/try`、`/tcc/confirm`、`/tcc/cancel`
- 防护：init 限流 5/60s、reinit 2/60s（@RateLimit）；@PostConstruct 校验内部 token 配置

### 8.3 三级扣减（模块自己的框架，CODE-REVIEW Q5）
- **L1**：Redis 分桶预扣（Lua 原子，毫秒级）
- **L2**：MQ 异步落 MySQL（Outbox + 版本门 + 条件更新）
- **L3**：定时对账修复（每小时整点，Redis 为准；Canal 把缓存一致性延迟从 24h 降到秒级）

### 8.4 本轮补读的机制细节（原地图没有的）
- **confirmDeduct**：entries 空→幂等返回；逐 SKU 撕欠条；N10 扩容窗口抛 ResizeInProgress 重试；MQ 失败仅 log 等 L3
- **releaseStock**：同结构；脏桶号按 0 + 告警（M12 过滤 `:bucket` 字段）
- **resizeBuckets**：SETNX 锁 + pause(30s) → 收集各桶 → 按新桶数重分配 → Pipeline 写 + 删多余桶 + 更新 count/total
- **reinitStock**：SCAN 清 key（不用 KEYS）→ 从 available+locked 重建
- **rebuildStockFromDb**：Redisson 锁 + 双检查 → available+locked 重建（T-066 自愈）
- **reconcileLockedStock**：SCAN 在途预扣 hash 汇总 → 修 MySQL locked（保守：缺失=0；注明 Cluster 单节点 SCAN 局限）
- **reconcileBuckets**：原子 Lua 求和修正 total（防"读后写"覆盖在途预扣）
- **purgeTablesDaily**：outbox 7 天 / 补偿 90 天，日切 marker + 有界排空（2000×10）
- **Canal 版本号**：`es` 严格递增（降级 ts），Lua GET+SET 原子，版本 key 7 天 TTL

### 8.5 测试清单（学"怎么测"用）

- `InventoryOutboxSenderJobTest`（1 例）：按 eventId 标记

- **CODE-REVIEW 自评 8.5/10**：P0-1 Canal 缓存方案（替代延迟双删）、P0-2 版本号防乱序、P1-1 回填（⚠️ **已被 N7 覆盖：不再自动回填**）、P1-2 KEYS→SCAN、P1-3 canal inventory_instance 配置
