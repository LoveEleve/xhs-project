# 04 · 对账体系

> **一句话**：对账不是"比金额"，而是**以渠道账单为准**，把本地"记错的、漏的、多的"逐笔捞出来**挂账**；
> 人只处理差异，不覆盖事实。
>
> **本篇带走 3 问**：
> ① **拿什么对**——渠道流水（`t_channel_flow`）vs 本地支付/退款（`t_payment`/`t_refund`）
> ② **怎么对**——渠道行驱动 + 本地游标扫描（双向），产出三类差异
> ③ **对完怎么办**——挂账（待处理/已处理/已忽略）+ 账单状态；人工只改状态，不补单、不动钱
>
> 前置：`02-支付回调与订单咬合.md`（对账是四层通知的终线）。证据：`SettlementService`、
> `SettlementRepository`、`SettlementJob`、`t_settlement_*`/`t_channel_flow`。

---

## 0. 场景：一天 1000 笔，三类差异

某渠道 T-1 共 1000 笔，本地也记了 1000 笔，但：

| 现象 | 差异类型 | 谁的问题 |
|---|---|---|
| 渠道多 1 笔 100 元（本地没有） | **渠道有、本地无**（长款） | 本地漏记/回调丢失 |
| 本地多 1 笔 50 元（渠道没有） | **本地有、渠道无**（短款） | 本地多记/渠道未入账 |
| 同一笔金额：本地 199.00，渠道 199.01 | **金额不一致** | 金额/口径错 |

还有两个"比差异更常见"的坑：

- **渠道对账单还没到**就跑了对账 → 本地 1000 笔全被判定"渠道无" → **1000 笔假差异**；
- 差异处理完**重跑** → 不能重复插、不能把"已处理"覆盖回"待处理"。

## 1. 数据模型：谁和谁对

| 表 | 角色 | 关键约束 |
|---|---|---|
| `t_channel_flow` | 渠道流水（对账文件落地） | `uk(channel, channel_no)`——同一渠道流水只落一次 |
| `t_payment` / `t_refund` | 本地事实（收款/退款） | `payment_no` / `refund_no` 唯一 |
| `t_settlement_bill` | 日账单（T-1 × 渠道） | `uk(bill_date, channel)`——重跑幂等；`run_no` 记录重跑次数 |
| `t_settlement_diff` | 差异挂账 | `uk(bill_date, channel, biz_type, diff_type, local_no, channel_no)`——重复对账不重复插 |

**为什么差异要单独挂账，而不是"发现就改单"**：

- 对账的职责是**发现事实**，不是"修数据"；改单/补钱是另一条人工/结算流程；
- 挂账保留证据（本地金额/渠道金额/差异额/处理备注），可审计；
- 人工处理只把状态从"待处理"改成"已处理"，**金额影响在下一日账单体现**。

## 2. 问题一：账单怎么生成（日切 + 幂等重跑）

`settlementBillJob` 每天 02:00 生成 **T-1** 全渠道账单（`SettlementJob`）：

```java
public SettlementBill generateDailyBill(LocalDate billDate, Integer channel, boolean force) {
    return withChannelLock(billDate, channel, () -> doGenerate(billDate, channel, force));
}

private SettlementBill doGenerate(LocalDate billDate, Integer channel, boolean force) {
    LocalDateTime from = billDate.atStartOfDay();
    LocalDateTime to = billDate.plusDays(1).atStartOfDay();

    // SQL 聚合（走 (pay_type, paid_at) / (status, success_at) 索引），不把当日明细拉进 JVM
    SettlementRepository.AmountSummary pays = settlementRepository.aggregatePays(channel, from, to);
    SettlementRepository.AmountSummary refunds = settlementRepository.aggregateRefunds(channel, from, to);

    BigDecimal payAmount = pays.amount();
    BigDecimal refundAmount = refunds.amount();
    BigDecimal netAmount = payAmount.subtract(refundAmount);
    // 手续费按"收款金额（毛额）"计提：退款不退手续费（与渠道实际计费口径一致）
    BigDecimal feeAmount = payAmount.multiply(feeRate).setScale(2, RoundingMode.HALF_UP);
    BigDecimal settleAmount = netAmount.subtract(feeAmount);

    SettlementBill bill = new SettlementBill();
    bill.setBillDate(billDate);
    bill.setChannel(channel);
    bill.setPayCount(pays.count());
    bill.setPayAmount(payAmount);
    bill.setRefundCount(refunds.count());
    bill.setRefundAmount(refundAmount);
    bill.setNetAmount(netAmount);
    bill.setFeeRate(feeRate);
    bill.setFeeAmount(feeAmount);
    bill.setSettleAmount(settleAmount);
    bill.setStatus(SettlementBill.STATUS_GENERATED);
    bill.setRunNo(0);

    SettlementBill existing = settlementRepository.findBill(billDate, channel);
    if (existing == null) {
        settlementRepository.insertBill(bill);
        return settlementRepository.findBill(billDate, channel);
    }

    boolean settled = existing.getStatus() == SettlementBill.STATUS_RECONCILED
            || existing.getStatus() == SettlementBill.STATUS_HAS_DIFF;
    if (settled && !force) {
        throw new BizException(ResultCode.ORDER_STATUS_ERROR, "账单已对账，重算需 force=true");
    }
    int affected = settlementRepository.regenerateBill(existing.getId(), existing.getStatus(), bill);
    if (affected == 0) {
        throw new BizException(ResultCode.IDEMPOTENT_REJECT, "账单状态已变化，请刷新后重试");
    }
    if (force) {
        // 重算成功后再清差异（顺序不能反：条件更新失败时不应破坏已有差异记录）
        settlementRepository.deleteDiffs(billDate, channel);
    }
    return settlementRepository.findBill(billDate, channel);
}
```

三个要点：

1. **金额口径**：`净额 = 收款 − 退款`；`手续费 = 收款（毛额）× 费率`（退款不退手续费）；
   `应结 = 净额 − 手续费`。按净额计费会出现"纯退款日负手续费"，与渠道账单对不上。
2. **幂等重跑**：`uk(bill_date, channel)` 保证一天一渠道一张账单；重跑走 `regenerateBill(run_no+1)`；
   已对账/有差异时**必须 `force=true`**，否则拒绝（防误覆盖已核对的账）。
3. **顺序**：先重算成功，再清旧差异——反过来的话，重算失败会把已有差异删了。

## 3. 问题二：怎么对（渠道行驱动 + 本地游标）

### 3.1 前提：对账单到了才跑

```java
if (!statementArrived(billDate, channel)) {
    businessMetrics.recordSettlementReconcile("skipped");
    log.warn("[结算] 渠道对账单未到, 跳过对账(账单保持已生成): date={}, channel={}", billDate, channel);
    return bill;
}
```

`statementArrived` 读 Redis 标记（导入/演练时写入，保留 30 天）。
**没有这个标记，就会把"渠道还没出账"误判成"本地全量长款"**——这是对账最典型的假差异。

### 3.2 渠道行驱动（逐行核对我方）

对渠道流水的每一行：

| 渠道行 | 本地 | 结论 |
|---|---|---|
| `local_no` 为空 | —— | `TYPE_CHANNEL_ONLY`（渠道有本地无） |
| `local_no` 重复出现 | —— | `TYPE_CHANNEL_ONLY`（渠道多记，单独报而不是覆盖） |
| 本地查不到 | null | `TYPE_CHANNEL_ONLY` |
| 本地有、金额不等 | 有 | `TYPE_AMOUNT_MISMATCH`（差异 = 本地 − 渠道） |

```java
for (ChannelFlow flow : channelFlows) {
    if (flow.getLocalNo() == null || flow.getLocalNo().isEmpty()) {
        diffs.add(buildDiff(billDate, channel, flow.getBizType(), SettlementDiff.TYPE_CHANNEL_ONLY,
                "", flow.getChannelNo(), BigDecimal.ZERO, flow.getAmount()));
        diffAmount = diffAmount.subtract(flow.getAmount());
        continue;
    }
    String flowKey = key(flow.getBizType(), flow.getLocalNo());
    if (!channelKeys.add(flowKey)) {
        // 同一商户单号多行：渠道多记，单独报差异而不是被覆盖
        diffs.add(buildDiff(..., TYPE_CHANNEL_ONLY, flow.getLocalNo(), flow.getChannelNo(),
                BigDecimal.ZERO, flow.getAmount()));
        continue;
    }
    ChannelFlow local = flow.getBizType() == ChannelFlow.BIZ_PAY
            ? settlementRepository.findLocalPay(channel, flow.getLocalNo(), from, to)
            : settlementRepository.findLocalRefund(channel, flow.getLocalNo(), from, to);
    if (local == null) {
        diffs.add(buildDiff(..., TYPE_CHANNEL_ONLY, flow.getLocalNo(), flow.getChannelNo(),
                BigDecimal.ZERO, flow.getAmount()));
    } else if (local.getAmount().compareTo(flow.getAmount()) != 0) {
        BigDecimal gap = local.getAmount().subtract(flow.getAmount());
        diffs.add(buildDiff(..., TYPE_AMOUNT_MISMATCH, flow.getLocalNo(), flow.getChannelNo(),
                local.getAmount(), flow.getAmount()));
    }
}
```

### 3.3 本地侧游标扫描（渠道未声明的 → 本地有渠道无）

- 用 `channelKeys`（渠道声明过的商户单号集合）做判断；
- **游标分页**：`(trade_time, id)` 有序扫描，每页 1000，最多 500 页（安全阀，超限告警）；
- 不用 `LIMIT offset` 深分页（越翻越慢且可能漏/重）。

### 3.4 差异落定与账单状态

```java
for (SettlementDiff diff : diffs) {
    settlementRepository.upsertDiff(diff);   // uk 幂等：重复对账不重复插
    businessMetrics.recordSettlementDiff(channel, diff.getDiffType());
}
// 自动收敛：本轮已无差异的"待处理"挂账 → 已忽略（≤500 笔才做，避免超长 IN）
if (diffs.size() <= 500) {
    settlementRepository.autoConverge(billDate, channel, diffs);
}
List<SettlementDiff> pending = settlementRepository.listDiffs(
        billDate, channel, SettlementDiff.STATUS_PENDING);
int targetStatus = pending.isEmpty() ? SettlementBill.STATUS_RECONCILED : SettlementBill.STATUS_HAS_DIFF;
settlementRepository.markReconciled(bill.getId(), bill.getStatus(), targetStatus,
        pending.size(), pendingAmount);
```

**账单状态口径 = "待处理挂账余额"**，不是"本轮发现数"：

- 人工把差异都处理完 → 下一轮（或状态刷新）`pending` 为空 → 账单自然回到"已对账"；
- 所以 `diff_count/diff_amount` 记的是**未核销**的差异，不是历史累计。

## 4. 问题三：对完怎么办（挂账 / 人工 / 重跑 / 作废）

**人工处理**——只改状态，不补单、不动钱：

```java
public SettlementDiff handleDiff(Long id, String remark) {
    SettlementDiff diff = settlementRepository.findDiff(id);
    if (diff == null) {
        throw new BizException(ResultCode.NOT_FOUND, "差异记录不存在");
    }
    int affected = settlementRepository.handleDiff(id, remark);   // 0 待处理 → 1 已处理
    if (affected == 0) {
        throw new BizException(ResultCode.IDEMPOTENT_REJECT, "差异已处理，请刷新后重试");
    }
    return settlementRepository.findDiff(id);
}
```

**作废重开**——账单状态机 `0 初始 / 1 已生成 / 2 已对账 / 3 有差异 / 4 作废`：

```java
public SettlementBill voidBill(LocalDate billDate, Integer channel, String remark) {
    SettlementBill bill = settlementRepository.findBill(billDate, channel);
    if (bill == null) throw new BizException(ResultCode.NOT_FOUND, "账单不存在");
    if (bill.getStatus() != STATUS_GENERATED
            && bill.getStatus() != STATUS_HAS_DIFF
            && bill.getStatus() != STATUS_RECONCILED) {
        throw new BizException(ResultCode.ORDER_STATUS_ERROR, "当前状态不可作废");
    }
    int affected = settlementRepository.voidBill(bill.getId(), bill.getStatus(), remark);
    if (affected == 0) {
        throw new BizException(ResultCode.IDEMPOTENT_REJECT, "账单状态已变化，请刷新后重试");
    }
    return settlementRepository.findBill(billDate, channel);
}
```

作废后重新生成 = 重开，`run_no` 继续累计（账单历史不丢）。

**重跑时差异怎么处理**（`upsertDiff` 的 `ON DUPLICATE KEY UPDATE`）：

```sql
ON DUPLICATE KEY UPDATE
  handle_remark = IF(status = 2, NULL, handle_remark),
  handled_at   = IF(status = 2, NULL, handled_at),
  local_amount = VALUES(local_amount),
  channel_amount = VALUES(channel_amount),
  diff_amount  = VALUES(diff_amount),
  status = IF(status = 2, 0, status)
```

- `status=1`（已处理）：**保留**——人工结论不被重跑覆盖；
- `status=2`（已忽略/自动收敛）：差异**再次出现**时复活为 `0`（待处理）；
- `status=0`：刷新金额，保持待处理。

**演练扰动**（`simulateChannelStatement`）：`NONE / MISSING（渠道少一笔）/ EXTRA（渠道多一笔）/ AMOUNT（金额 +0.01）`——
在本地流水基础上造渠道账单，用来验证"发现 → 挂账 → 处理 → 收敛"整条闭环。

## 5. 坑清单

1. **对账单未到就跑**：全量假差异。修复 = `statementArrived` 标记 + 跳过。
2. **重跑顺序反了**：先清差异再重算，重算失败就丢了证据。修复 = 先重算成功再清。
3. **差异重复插/覆盖人工结论**：靠 `uk_diff_key` + 上面的 `IF(status=...)` 规则。
4. **自动收敛误伤**：只动 `status=0`，且本轮无差异的才置 `2`；`status=1` 永不覆盖。
5. **只比总额**：总差额为 0 也可能"两笔一多一少"抵消——必须逐笔 + 双向。
6. **对账直接改单/补钱**：不允许；对账只挂账，修正走人工/下一日账单。
7. **深分页**：`LIMIT offset` 越翻越慢、可能漏单；必须游标 + 安全阀。
8. **手续费口径**：按净额计提会出现负手续费；必须按收款毛额。

## 6. 值不值得深挖 / 一句话

- **值得讲透**：对账单未到的假差异、双驱动（渠道行 + 本地游标）、挂账不覆盖规则、账单状态口径；
- **一句话带过**：Redis 锁 TTL、差异表的字段、演练实现；
- **一句话**：**对账 = 以渠道为准，逐笔双向比对，发现差异只挂账；账单状态看"待处理余额"，不看本轮发现数。**
- 结算（资金视角、金额口径、重跑作废）见 **05 半篇**。

**面试口径**："对账以渠道对账单为准：账单到了才跑，渠道行驱动 + 本地游标双向比对，产出三类差异并挂账；重复对账靠唯一键幂等，已处理差异不被覆盖；账单状态按待处理余额收敛，人工只改状态不补单。"
