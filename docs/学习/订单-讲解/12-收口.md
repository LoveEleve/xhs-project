## 一、总图：三层 + 主链 + 两个终态 + 旁路

```
父单 t_order（交易/支付）
  ├─ 子单 t_sub_order（卖家/履约）
  │    └─ 行 t_order_item（SKU/金额/售后）
  └─ 售后单 t_aftersale（挂行 itemId）

主链（父/子同步推进）：
  父单 0 待付款 → 1 已付款 → 2 已发货 → 3 已完成
  子单 0 待付款 → 1 待发货 → 2 已发货 → 3 已完成

终态：
  4 已取消（五条路径：用户/超时/库存失败/券失败/支付失败）
  5 已退款（全退收敛：父+全子）

旁路：
  拆单（下单即拆，父/子/行三层）
  分摊（行级 discountShare，下单落库）
  行级售后（部分退不改主状态）
  查询（买家分片 + 商家 ES 异构索引）
```

**父单状态 = 子单聚合**（2/3/5 走聚合；0/1/4 由支付/终结专属流程）：

```
全取消→4；全退款→5；全终态混合→3；
活跃全待付款→0；活跃全≥已发货→2；其余→1
```

- `recomputeParentStatus` 只处理 2/3/5；0/1/4 由支付/终结专属流程；
- 部分售后**不改变**父/子主状态。

## 二、一条主链 + 三个关键旁路 + 查询

### 2.1 主链

| 阶段 | 谁在动 | 机制 |
|---|---|---|
| 下单 | 父+子+行同一事务 | 幂等键+用户锁；事务消息；本地消息 |
| 支付 | 父 0→1；子 0→1 | 双通道回调 + CAS + false 语义 |
| 履约 | 子 CAS 1→2/2→3；父聚合 | `subOrderNo` + 父单聚合 |
| 取消 | 父 0→4；子 0→4 | 统一终结入口 + 事务消息 |
| 全退 | 父/子 1/2/3→5 | 支付通知 + `refundAll` |

### 2.2 拆单

- 下单本地事务按 `sellerId` 拆子单；`subOrderNo = orderNo-N`；
- 父/子/行金额守恒；子单与父单同 `user_id` 分片；
- 履约/售后下沉子单/行；父单只做聚合。

### 2.3 分摊

- 最大余数法、分单位、平局按行 ID 定序；
- `OrderItem.discountShare` 下单落库；
- 售后以落库份额算应退；部分退向下取整、退满补差。

### 2.4 售后

- `itemId` 行级锚点，唯一键 `(item_id,type)`；
- 三道金额闸门：行可退上限、累计退款、订单实付；
- 退款调用 payment（出金幂等键=售后单号）；失败 3→6，恢复任务重试；
- 部分售后不改主状态；全退才父+全子 5。

### 2.5 查询

- 买家：`userId + orderId` 走分片；`orderNo → mapping → userId` 再路由；
- 商家列表：`sellerId → ES`（Canal `order_instance` → `SUB_ORDER_INDEX_TOPIC`）；
- 商家详情：`subOrderNo → orderNo → mapping → userId → 分片读`；
- ES 是异构索引，不是订单账本事实源。

## 四、可靠性机制对照

| 机制 | 真实电商 | 当前 xhs | 差距 |
|---|---|---|---|
| 幂等 | 业务幂等号 + 唯一键 | 24h 幂等键 + 用户锁 + CAS + 消息 KEYS | 同 |
| 事务消息 / Outbox | 同 | 下单/终结两套事务消息 + 本地消息补发/死信 | 同（轻量） |
| 状态机 | 引擎 + 条件更新 | `appendEvent` 白名单 + 乐观锁 | 轻量可审计 |
| 关单 | 延时 + 扫描兜底 | 30min 延时 + `OrderCloseJob` 每分钟 | 同 |
| 补偿 | 扫描 + 重试上限 + 告警 | 4 类补偿 + 本地兜底集合 + 死信 | 有边界 |
| 对账 | 日终三方 + 差错池 + 人工 | 事件校准 + 子单聚合 + 支付对账 | 缺统一三方 |
| 支付回调 | 验签 + 幂等 + ACK | remote 支付域；order 侧 CAS + false | 已生产化 |
| 自动确认收货 | 延时/Job | ❌ 只有人工确认 | 缺 |
| 集成测试 | Testcontainers/端到端 | 132 个 Mockito/Standalone 单测 | 缺 |

## 五、面试口径（30 秒）

> "订单是父/子/行三层账本：父单管交易和支付，子单按卖家拆、管履约，行管 SKU 和金额。下单用幂等键+用户锁+事务消息，本地事务里落父单、子单、行、事件和本地消息；支付回调用 CAS 收敛，重复/竞态不抛 500；未支付终结统一走五条路径（用户/超时/库存/券/支付失败），父单和全子单同事务取消；拆单后父单状态由子单聚合，发货/确认按子单；优惠按最大余数法摊到行并落库，售后按行分摊退；商家查询走 Canal→ES 异构索引。缺口是自动确认收货、三方对账、完整店铺/优惠生态和集成测试。"

**深水三选一**：

- **关单竞态**：CAS + false=业务拒绝 + 支付侧自动退款；
- **退款防重**：出金幂等键 + 支付域先查事实 + 售后状态机；
- **分摊/金额**：最大余数法 + 行级落库 + 部分退/退满补差。

**缺口讲法**：

- 拆单/分摊/行级售后已经做了，不再说"没做"；
- 仍缺：自动确认、三方对账、店铺/优惠生态、商家分账、`max(a,b)` 数量旧账、集成测试；
- 原则："外围业务对象是取舍，可靠性内核是能力。"
