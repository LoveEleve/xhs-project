## 1. 总览

```
t_spu（商品统称）1 ── N t_sku（规格）1 ── 1 t_inventory（库存主表·三态）

围绕"事件可靠性"的辅助表：
  预扣幂等表（防重扣）｜Outbox（事件不丢）｜补偿表（失败重试）

围绕"TCC 冻结"的两张表：
  t_tcc_fence（判定层·状态机）｜t_tcc_freeze_detail（资源层·冻结明细）
```

Redis 侧：**业务 5 类 key + 辅助 14 类 key**（见第 3 节）。

### 2.0 周边表：`t_spu` / `t_sku`（归属商品模块，但理解库存层级需要）

```sql
CREATE TABLE IF NOT EXISTS t_spu (
    id           BIGINT       NOT NULL COMMENT 'SPU ID',
    name         VARCHAR(256) NOT NULL COMMENT '商品名称',
    category_id  BIGINT       NOT NULL COMMENT '分类ID',
    brand_id     BIGINT       DEFAULT NULL COMMENT '品牌ID',
    description  TEXT         DEFAULT NULL COMMENT '商品描述',
    images       TEXT         DEFAULT NULL COMMENT '商品图片列表(JSON)',
    status       TINYINT      NOT NULL DEFAULT 1 COMMENT '状态：0-下架 1-上架',
    deleted      TINYINT      NOT NULL DEFAULT 0 COMMENT '逻辑删除',
    created_at   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (id),
    INDEX idx_category_id (category_id),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='商品SPU表';

CREATE TABLE IF NOT EXISTS t_sku (
    id              BIGINT        NOT NULL COMMENT 'SKU ID',
    spu_id          BIGINT        NOT NULL COMMENT 'SPU ID',
    name            VARCHAR(256)  NOT NULL COMMENT 'SKU名称',
    price           DECIMAL(10,2) NOT NULL COMMENT '价格',
    original_price  DECIMAL(10,2) DEFAULT NULL COMMENT '原价',
    stock           INT           NOT NULL DEFAULT 0 COMMENT '库存(冗余，实际由库存服务管理)',
    specs           VARCHAR(1024) DEFAULT NULL COMMENT '规格属性(JSON)',
    status          TINYINT       NOT NULL DEFAULT 1 COMMENT '状态：0-下架 1-上架',
    deleted         TINYINT       NOT NULL DEFAULT 0 COMMENT '逻辑删除',
    created_at      DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at      DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (id),
    INDEX idx_spu_id (spu_id),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='商品SKU表';
```

关键点：`t_sku.stock` 是**冗余字段**（注释原话："实际由库存服务管理"）——下单扣减**永远不扣它**；真正的库存在 `t_inventory`。

### 2.1 `t_inventory`（库存主表）

```sql
CREATE TABLE IF NOT EXISTS t_inventory (
    id              BIGINT  NOT NULL COMMENT 'ID',
    sku_id          BIGINT  NOT NULL COMMENT 'SKU ID',
    available_stock INT     NOT NULL DEFAULT 0 COMMENT '可用库存',
    locked_stock    INT     NOT NULL DEFAULT 0 COMMENT '锁定库存',
    freezing_stock  INT     NOT NULL DEFAULT 0 COMMENT 'TCC冻结库存',
    deleted         TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (id),
    UNIQUE INDEX uk_sku_id (sku_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='库存表';
```

| 字段 | 含义 | 为什么 |
|---|---|---|
| `sku_id` + `uk_sku_id` | 一个 SKU 一条库存 | 唯一键 = 防重复建账；所有条件更新都在 `sku_id` 上 |
| `available_stock` | 可售 | 所有"扣/还"都围绕它做**条件更新**（`WHERE available>=qty`） |
| `locked_stock` | 预扣未确认 | 预扣落账时 `available→locked`；确认时清零；回退时还回 available |
| `freezing_stock` | TCC 冻结 | 独立协议用，与 available/locked 互不干扰 |

> 三态公式：**实际总量 = available + locked**（实体注释口径；重建/回补都基于这个；TCC 场景 freezing 独立看）。

### 2.2 预扣幂等表

```sql
CREATE TABLE IF NOT EXISTS t_inventory_prededuct_idem (
    order_id   BIGINT   NOT NULL COMMENT '预扣orderId(pseudoOrderId)',
    sku_id     BIGINT   NOT NULL COMMENT 'SKU ID',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '首次预扣时间',
    PRIMARY KEY (order_id, sku_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='预扣幂等表';
```

- **主键即幂等键**：`INSERT IGNORE` 插入成功=第一次；冲突=已扣过
- 为什么需要：Redis 欠条可能丢（重启/被清），只靠 Lua 的 HGET 幂等会漏
- 生命周期：成功保留；预扣失败（库存不足等）→ 删除允许重试
- 清理：**每轮对账**（当前每小时）删 7 天前的记录、单轮上限 2000 行（推导：预扣 TTL 30min + MQ 重投窗口 << 7 天）

### 2.3 Outbox（本地消息表）

```sql
CREATE TABLE IF NOT EXISTS t_inventory_outbox (
    id          BIGINT      NOT NULL AUTO_INCREMENT COMMENT 'ID',
    order_id    BIGINT      NOT NULL COMMENT '订单ID',
    sku_id      BIGINT      NOT NULL COMMENT 'SKU ID',
    quantity    INT         NOT NULL COMMENT '数量',
    action      VARCHAR(32) NOT NULL COMMENT '事件类型: PRE_DEDUCT/CONFIRM/RELEASE',
    status      TINYINT     NOT NULL DEFAULT 0 COMMENT '0-待发送 1-已发送',
    retry_count     INT      NOT NULL DEFAULT 0 COMMENT '补发失败次数（指数退避+抖动，P2/2026-09-27）',
    next_retry_time DATETIME NULL COMMENT '下次可补发时间（NULL=立即可发）',
    created_at  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    PRIMARY KEY (id),
    UNIQUE INDEX uk_order_sku_action (order_id, sku_id, action),
    INDEX idx_status_created (status, created_at),
    INDEX idx_status_next_retry (status, next_retry_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='库存事件Outbox表';
```

- **`action` 进唯一键**：同一订单同一 SKU 的 PRE_DEDUCT / CONFIRM / RELEASE / REFUND_RESTORE 各是**一条独立事件**，不能互斥（注：源码 DDL 注释只列了前三种，代码实际还有 REFUND_RESTORE——注释滞后于代码）
- `idx_status_next_retry`：补发 Job 按"待发送 + 到期"拉取
- 为什么先落库再发送：**崩溃窗口**（写完 Outbox、还没发送/标记）由 Job 补发；**发送失败**分两种——PRE_DEDUCT 走"作废 + 回滚 Redis"（避免已回滚还补发）、其余动作留在表里由 Job 补发

### 2.4 补偿表

```sql
CREATE TABLE IF NOT EXISTS t_inventory_compensation (
    id          BIGINT       NOT NULL AUTO_INCREMENT COMMENT 'ID',
    order_id    BIGINT       NOT NULL COMMENT '订单ID',
    sku_id      BIGINT       NOT NULL COMMENT 'SKU ID',
    quantity    INT          NOT NULL COMMENT '数量',
    type        TINYINT      NOT NULL DEFAULT 1 COMMENT '补偿类型：1-预扣回滚 2-退款回补',
    user_id     BIGINT       DEFAULT NULL COMMENT '用户ID（退款回补按用户路由库存桶；预扣回滚可空）',
    fail_reason VARCHAR(512) NOT NULL DEFAULT '' COMMENT '失败原因',
    status      TINYINT      NOT NULL DEFAULT 0 COMMENT '0-待处理 1-已处理 2-重试超限(转人工)',
    retry_count INT          NOT NULL DEFAULT 0 COMMENT '已重试次数',
    created_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    PRIMARY KEY (id),
    INDEX idx_status_retry_created (status, retry_count, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='库存回滚补偿表';
```

- `type 1/2` 分流：1=回滚（读真实桶 release）；2=退款回补（累计目标入库，不能存 delta）
- `idx(status, retry_count, created_at)`：Job 按"待处理 + 重试未超限 + 到期"扫

### 2.5 `t_tcc_fence`（TCC 判定层）【本系列不讲，可跳过】

```sql
CREATE TABLE IF NOT EXISTS t_tcc_fence (
    xid VARCHAR(128) NOT NULL COMMENT '全局事务ID',
    branch_id BIGINT NOT NULL COMMENT '分支事务ID',
    action_name VARCHAR(64) NOT NULL COMMENT 'TCC方法名',
    status TINYINT NOT NULL COMMENT '1-已Try 2-已Confirm 3-已Cancel',
    gmt_create DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    gmt_modified DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (xid, branch_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='TCC防悬挂表';
```

- **PK `(xid, branch_id)`**：事务×分支唯一；空回滚=Cancel 无记录则插入 3；悬挂=Try 遇 3 拒绝；幂等=`WHERE status=1` 乐观锁

### 2.6 `t_tcc_freeze_detail`（资源层）【本系列不讲，可跳过】

```sql
CREATE TABLE IF NOT EXISTS t_tcc_freeze_detail (
    xid         VARCHAR(128) NOT NULL COMMENT '全局事务ID',
    branch_id   BIGINT       NOT NULL COMMENT '分支事务ID',
    sku_id      BIGINT       NOT NULL COMMENT 'SKU ID',
    quantity    INT          NOT NULL COMMENT '冻结数量',
    status      TINYINT      NOT NULL DEFAULT 1 COMMENT '1-已冻结 2-已确认 3-已取消',
    created_at  DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '冻结时间',
    updated_at  DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (xid, branch_id, sku_id),
    INDEX idx_status_created (status, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='TCC冻结明细表';
```

- **PK 三元组**：一条冻结明细；`idx(status, created_at)` 支撑超时 Job 按"已冻结且过老"扫描
- T-074 教训：运行库若与此 DDL 漂移（单主键 vs 联合主键），UPSERT 全失败 → Try 全挂

## 3. Redis 结构

### 3.1 业务 5 类 key

| key | 结构 | 例子 | 谁写 | 谁读 | TTL |
|---|---|---|---|---|---|
| `inventory:{skuId}:total` | String | `99` | preDeduct/release/refundRestore/reinit/resize/rebuild（**confirm 不写**） | 全部链路 | 无（重建可恢复） |
| `inventory:{skuId}:bucket:N` | String | `49` | 同上 | Lua 选桶/借桶 | 无 |
| `inventory:bucket:count:{skuId}` | String | `2` | init/resize | preDeduct 定位桶数 | 无 |
| `inventory:prededuct:{orderId}` | Hash | `{"1001":1,"1001:bucket":0}` | prededuct.lua | confirm/release/超时 Job（HGETALL） | 1800+600s |
| `inventory:prededuct:index` | ZSet | `888→到期ms` | prededuct.lua | 超时 Job（ZRANGEBYSCORE） | 无 key TTL；member 由确认/回退/超时清理 |

### 3.2 辅助 key（共 14 类 / 20+ 个 key，完整表见《掌握地图》9.2）

锁类：`init:lock` / `resize` / `rebuild:lock` / 4 个 Job 锁
状态类：`paused` / `canal:version`（7d）/ `event:version`（版本门）
幂等缓存类：`refund:{o}:{s}`（30d）/ `order:consumed:{msgId}`（24h）/ `locked:cache`（5s）/ `hot:window`（30s）
运维类：`anomaly:sku-missing` / `cleanup:{date}` / 三个限流前缀

### 3.3 一个副本例子（sku1001，2 桶）

```
total=100  bucket:0=50  bucket:1=50  count=2
（下单后）total=99  bucket:0=49
prededuct:888 = {"1001":1, "1001:bucket":0}
index: 888 → 1730000000000
```

## 4. 权威模型（背下来）

```
运行期：  Redis（主账，实时）──MQ 落账──▶ MySQL（备份账，慢半拍）
丢失/手改：MySQL ──rebuild/reinit──▶ Redis（available+locked 重建）
对账：    Redis 为准修 MySQL（+ locked 按在途预扣重算）
重大原则：正常运行**不做** MySQL→Redis 自动同步（防旧值回填超卖，N7/T-066）
```

## 5. 一页速查（表/Key ↔ 链路步骤）

| 链路步骤 | 动的表 | 动的 key |
|---|---|---|
| 初始化 | t_inventory 更新 | total/bucket/count（先桶后 total） |
| 预扣 | 预扣幂等表增删 | total/桶 减、欠条、闹钟 |
| 落账 | t_inventory 条件更新 | — |
| 确认 | t_inventory（locked 清） | 撕欠条 + ZREM 闹钟 |
| 回退 | t_inventory（locked→available） | total/桶 加、撕欠条 |
| 回补 | t_inventory（available 加） | total/桶 加、累计幂等键 |
| 对账 | t_inventory 修正 + 表清理 | total/locked 校正、分桶求和 |
