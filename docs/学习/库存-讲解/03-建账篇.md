# 03 · 建账篇：`initStock` 源码全解

> 读完本篇能回答：Redis 里的桶是谁建的、什么时候建的；建到一半崩了怎么办；为什么写顺序是"先桶、后 total"。

---

## 1. 业务/例子

**什么时候需要"建账"**：新 SKU 上架（Redis 里还没有它的任何 key），或管理端重设库存。
没有这一步，预扣无从谈起——Lua 要读的 total 和桶都不存在，直接报"未初始化"。

**例子**：`sku1001`，上架 100 件，拆 2 个桶 → 建完后 `total=100`、`bucket:0=50`、`bucket:1=50`、`count=2`。

**谁在调**：
- 管理端调 `/init`（`X-Admin-Call` 令牌）：上架 / 盘点 / 运维时手动调
- 商品服务建 SKU 后自动调（`X-Internal-Call` 内部令牌）：失败只打点告警、不阻断 SKU 创建

---

## 2. 问题（建账要解决的四个麻烦）

| # | 麻烦 | 不处理会怎样 |
|---|---|---|
| 1 | 两个人同时点"初始化"（并发双建） | 两份数据互相覆盖 |
| 2 | 上次建到一半崩了（半初始化） | 留下一半 key，后续分不清"建没建完" |
| 3 | MySQL 里还没这条库存记录 | Redis 建了账，DB 没账可对 |
| 4 | 写了一半就被读到"已建完" | 别人读到一半数据（比如只有 total、没有桶） |

---

## 3. 源码逐段详解

```java
    public void initStock(InventoryInitRequest request) {
        Long skuId = request.getSkuId();
        int totalStock = request.getTotalStock();
        int bucketCount = request.getBucketCount() != null ? request.getBucketCount() : defaultBucketCount;

        String totalKey = totalKey(skuId);
        String bucketCountKey = bucketCountKey(skuId);
        String initLockKey = "inventory:init:lock:" + skuId;
        Boolean locked = stringRedisTemplate.opsForValue()
                .setIfAbsent(initLockKey, "1", java.time.Duration.ofSeconds(30));
        if (!Boolean.TRUE.equals(locked)) {
            throw new BizException(ResultCode.PARAM_INVALID, "库存初始化中，请稍后重试");
        }
        try {
            // 若 total 和 bucketCount 都存在，视为已完整初始化；仅 total 存在则属于半初始化残留，继续自愈补齐。
            if (Boolean.TRUE.equals(stringRedisTemplate.hasKey(totalKey))
                    && Boolean.TRUE.equals(stringRedisTemplate.hasKey(bucketCountKey))) {
                throw new BizException(ResultCode.PARAM_INVALID, "库存已初始化，如需重新初始化请先清除");
            }

            // 1. 确保 MySQL 中有库存记录
            Inventory inventory = inventoryMapper.selectOne(
                    new LambdaQueryWrapper<Inventory>().eq(Inventory::getSkuId, skuId));
            if (inventory == null) {
                // 自动创建库存记录
                inventory = new Inventory();
                inventory.setSkuId(skuId);
                inventory.setAvailableStock(totalStock);
                inventory.setLockedStock(0);
                inventoryMapper.insert(inventory);
                log.info("[库存] 自动创建MySQL记录: skuId={}, stock={}", skuId, totalStock);
            } else {
                // 以请求的 totalStock 为准更新 MySQL
                inventory.setAvailableStock(totalStock);
                inventory.setLockedStock(0);
                inventoryMapper.updateById(inventory);
                log.info("[库存] 更新MySQL库存记录: skuId={}, stock={}", skuId, totalStock);
            }

            // 2. 均匀分配到 N 个桶
            int perBucket = totalStock / bucketCount;
            int remainder = totalStock % bucketCount;

            for (int i = 0; i < bucketCount; i++) {
                int bucketStock = perBucket + (i == 0 ? remainder : 0);
                stringRedisTemplate.opsForValue().set(bucketKey(skuId, i), String.valueOf(bucketStock));
            }

            // 3. 设置总库存和桶数（最后写 total/bucketCount，避免半初始化时被误判为完整）
            stringRedisTemplate.opsForValue().set(totalKey, String.valueOf(totalStock));
            stringRedisTemplate.opsForValue().set(bucketCountKey, String.valueOf(bucketCount));

            log.info("[库存] 初始化完成: skuId={}, total={}, buckets={}, perBucket={}, remainder={}",
                    skuId, totalStock, bucketCount, perBucket, remainder);
        } finally {
            stringRedisTemplate.delete(initLockKey);
        }
    }
```

### 3.1 参数：要什么

- `skuId`：给哪个 SKU 建账
- `totalStock`：建多少（**权威值**，MySQL 和 Redis 都按它来）
- `bucketCount`：拆几个桶；请求没带就取配置默认 2

### 3.2 上锁：防并发双建

```java
String initLockKey = "inventory:init:lock:" + skuId;
Boolean locked = stringRedisTemplate.opsForValue()
        .setIfAbsent(initLockKey, "1", java.time.Duration.ofSeconds(30));
if (!Boolean.TRUE.equals(locked)) {
    throw new BizException(ResultCode.PARAM_INVALID, "库存初始化中，请稍后重试");
}
```

- `SETNX` = "key 不存在才设成功"——**先到的人建账，后到的人直接报错走人**
- 锁 30 秒过期：拿锁的人如果崩了（没走到 `finally` 删锁），30 秒后锁自动消失，不会把这个 SKU 永远锁死
- 为什么抢不到就**直接抛错、不排队等**：初始化是低频管理操作，等锁没意义；而且请求堆在锁上会越积越多
- 注意锁的粒度：`init:lock:{skuId}`——**按 SKU 锁**，不同 SKU 互不影响

### 3.3 完整性判定：本方法最精妙的三行

```java
// 若 total 和 bucketCount 都存在，视为已完整初始化；仅 total 存在则属于半初始化残留，继续自愈补齐。
if (Boolean.TRUE.equals(stringRedisTemplate.hasKey(totalKey))
        && Boolean.TRUE.equals(stringRedisTemplate.hasKey(bucketCountKey))) {
    throw new BizException(ResultCode.PARAM_INVALID, "库存已初始化，如需重新初始化请先清除");
}
```

对号入座（三种情况）：

| total 在吗 | count 在吗 | 含义 | 动作 |
|---|---|---|---|
| 不在 | 不在 | 从没建过 | 正常往下建 |
| 都在 | 都在 | 建完了 | **拒绝**（防重复建覆盖线上数据） |
| total 在 | count 不在 | **上次崩在"写完 total、没写 count"** | 不报错，**继续往下走**，把缺的补上 = **自愈** |

**为什么"双键都在"才算建完？** 因为写 Redis 的顺序是"**先桶、后 total/count**"（第 3.6 节）——所以"双键都在" ⇔ "上次一定走完了全程"。这个判定和写序是**配对设计**的，缺一不可。

### 3.4 先搞 MySQL：账本先行

```java
// 1. 确保 MySQL 中有库存记录
Inventory inventory = inventoryMapper.selectOne(
        new LambdaQueryWrapper<Inventory>().eq(Inventory::getSkuId, skuId));
if (inventory == null) {
    // 自动创建库存记录
    inventory = new Inventory();
    inventory.setSkuId(skuId);
    inventory.setAvailableStock(totalStock);
    inventory.setLockedStock(0);
    inventoryMapper.insert(inventory);
    log.info("[库存] 自动创建MySQL记录: skuId={}, stock={}", skuId, totalStock);
} else {
    // 以请求的 totalStock 为准更新 MySQL
    inventory.setAvailableStock(totalStock);
    inventory.setLockedStock(0);
    inventoryMapper.updateById(inventory);
    log.info("[库存] 更新MySQL库存记录: skuId={}, stock={}", skuId, totalStock);
}
```

- 没记录 → `insert`（available=本次值，locked=0）
- 有记录 → **覆盖**（available=本次值，locked=0）——注意这是"**权威设定**"，不是增量
- ⚠️ **这就是"5 笔已预扣未支付的订单 + 调一次 initStock"会发生的事**：`locked` 被直接置 0 → 这 5 件"被占"的状态在 MySQL 就丢了（Redis 那边欠条还在，对账还能收；但账面会歪一阵）。**所以 init 只能在"没业务"的时候调（上架/盘点），绝不能对正在卖的 SKU 乱调**——这也是"服务重启不能调 init"的同一个原因

### 3.5 分桶公式：两行

```java
// 2. 均匀分配到 N 个桶
int perBucket = totalStock / bucketCount;      // 整数除法，向下取整
int remainder = totalStock % bucketCount;      // 除不尽的余数

for (int i = 0; i < bucketCount; i++) {
    int bucketStock = perBucket + (i == 0 ? remainder : 0);
    stringRedisTemplate.opsForValue().set(bucketKey(skuId, i), String.valueOf(bucketStock));
}
```

例子：100 件 3 桶 → `perBucket=33`，`remainder=1` → 桶0=34，桶1=33，桶2=33（和=100 ✓）
- **余数全给 0 号桶**：简单、确定性规则（不用轮询，保证每次算出来一样）

> 注：这里只需记住**分配规则**（后面 preDeduct/release 都要用它找桶）。至于"分桶有没有意义"不用再深究——结论见《01-库存.md》补充章《分桶 / 分片 的完整认知》：单实例无并发收益，简历不写，面试可讲边界。

### 3.6 写 total + count：顺序是设计

```java
// 3. 设置总库存和桶数（最后写 total/bucketCount，避免半初始化时被误判为完整）
stringRedisTemplate.opsForValue().set(totalKey, String.valueOf(totalStock));
stringRedisTemplate.opsForValue().set(bucketCountKey, String.valueOf(bucketCount));
```

- **为什么后写**：配合 3.3 的判定——"双键都在=建完"。如果反过来（先写 total+count，再写桶），崩在"桶没写完"时，下次进来看到双键都在 → **误判为完整而拒绝** → 留下一堆缺桶。所以：**判定用的 key，必须最后写**。
- 收尾：`finally` 删锁（成功失败都删，防止锁死）+ 打完成日志（带 sku/total/桶数/每桶/余数，方便事后对账）

### 3.7 串一遍（sku1001 建 100 件、2 桶）

```
1. 抢锁 SETNX init:lock:1001 → 成功
2. 查：total 不在 → 不是"已完整" → 继续
3. MySQL：无记录 → INSERT(1001, available=100, locked=0)
4. 算：perBucket=50, remainder=0
5. 写：bucket:0=50, bucket:1=50
6. 写：total=100, count=2
7. 日志 + 删锁 → 完成
```

## 4. 边界与口径

- **init 是"权威设定"**：MySQL 现有值会被覆盖（available=totalStock 且 locked=0）——适用于"上架/盘点"场景，**不是增量**
- **锁 30s + finally 删**；抢不到直接拒绝，不排队
- `bucketCount` 默认 2（配置可改）；热点时由扩容改成 8（第 12 篇）
- **与 reinit 的区别**：init = "从请求的 totalStock 新建"；reinit = "删掉所有 key，从 `available+locked` 重建"（第 12 篇细讲）
