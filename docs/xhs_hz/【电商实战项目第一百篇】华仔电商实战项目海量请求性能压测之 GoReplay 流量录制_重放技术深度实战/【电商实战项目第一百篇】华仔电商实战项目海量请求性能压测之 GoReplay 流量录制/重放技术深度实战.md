## **2.3 GoReplay 流量录制/重放实战**

这里需要先在链路的起点进行录制：比如 Nginx 网关上进行录制，但是当前机器已经通过 Rancher 安装了 K8s 机器，所以 Rancher 所在的机器是不能安装的。k8s nginx-ingress 已经占用了 80 端口，它底层是 kube-prox 进行端口转发的，因此需要新的机器，后续也会用 Nginx 来作为流量入口捕获的机器。

### **2.3.1 为什么要加 Nginx 网关**

前面通过 Rancher 容器部署了微服务和中间件，那么内部如何获取用户访问的来源 IP 呢？

答案就是需要通过 Nginx 反向代理来透传进去了。

那么你是否会有疑问或者面试官会问你：**为什么有了 Gateway 还需要 Nginx 呢？**

如图所示，这里的 SLB 就可以通过 Nginx 来代理。

  
![](images/Fn8G-BxmpN3EjSAU-s8qTFrmb3Lp.png)

前端请求到 Gateway 在转发到相应的业务微服务，为什么不可以直接从 Nginx 转发到相应的业务中⼼，还要加多⼀层?

> 首先 Nginx 和 Spring Cloud Gateway 在功能上是有⼀些重叠的地⽅，但是各司其职互相配合会更强⼤。
> 
> 1、Spring Cloud Gateway层：
> 
> 可以认为是业务⽹关，针对 SpringCloud 体系专⻔推出，但是如果有其他服务不是⽤ SpringCloud 开发的怎么办？
> 
> 有部分复杂业务逻辑 Nginx 解决不了，可以⽤ Gateway 通过 java 语⾔开发
> 
> 另外容器部署微服务的 ip 地址⼀直在换，需要结合注册中⼼来使⽤，所以 Gateway 更灵活。
> 
> 2、Nginx
> 
> 其关注的是协议和路由的转发，聚合⼊⼝⽅便配置管理
> 
> 在性能、容错机制上⽐ Gateway强，多语⾔多环境下兼容性更好
> 
> ⽇志统计、协议路由转发、业务数据缓存前置、资源压缩等也是⽐较强⼤
> 
> 配置 HTTPS 证书更灵活、Openresty+Lua 开发各个强⼤的功能模块
> 
> 有超多应⽤场景

### **2.3.2.3 配置网关代理**

![](images/FoqwSIENLgu_tGQosaI_yKFClt8W.png)

这里我们对外只暴漏 Gateway 9090 端口，而后面的微服务都会注册到「**Nacos 注册中心**」，那么 Gateway 只要去注册中心拉取对应的服务就能知道对应的网络 IP 就能转发过去，最终可以应对海量请求进行随时扩容。

先修改 Nginx 网关代理：

upstream gateway {

\# Gateway 网关服务地址

server 172.20.8.220:9090;

}

server {

listen 80;

server\_name localhost;

location / {

proxy\_set\_header Host $host;

proxy\_set\_header X-Real-IP $remote\_addr;

proxy\_set\_header X-Forwarded-For

$proxy\_add\_x\_forwarded\_for;

proxy\_pass http://gateway/;

}

}

gor 参数说明：

1.  输⼊

6.  \--output-http ：重播HTTP流量到给定的端点。
7.  \--output-file ：记录传⼊到⽂件的流量。
8.  \--output-tcp ：将传⼊的数据转发到另⼀个 Gor 实例。

### **2.3.4.2 GoReplay 20 倍速度循环重放流量实战**

sudo ./gor --input-file "requests\_0.gor|2000%" --input-file-loop --output-http "http://127.0.0.1:8080" --stats --output-http-stats

\# --input-file 从文件中获取请求数据，重放的时候5倍速度重放；比如原来 10 秒 20 条请求，扩大 20 倍后就是 1 秒就跑完20条请求。

\# --input-file-loop 无限循环，而不是读完这个文件就停止。

\# --output-http 发送请求到 http://127.0.0.1:8080

\# --stats --output-http-stats 每 5 秒输出⼀次 TPS 数据

![](images/Fg5pKavDx14Dk1xuyHqkCn9iAXJY.png)

这里只要不停止就会一直重放，可以根据服务器的压力进行模拟海量请求的性能压测。
