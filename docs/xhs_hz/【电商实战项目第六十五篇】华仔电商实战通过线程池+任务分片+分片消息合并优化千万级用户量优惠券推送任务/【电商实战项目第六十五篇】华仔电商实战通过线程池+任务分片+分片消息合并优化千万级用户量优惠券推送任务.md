**2.2.1.6 如何将任务均分给每台机器**

由于任务执行时间过长，需要搭建集群服务来做到并行任务调度，从而减小 CPU 的开销，那么怎么均分任务呢？

利用 XXL-Job 在集群部署时，配置路由策略中选择「**分片广播**」的方式，可以使一次任务调度会广播触发集群中所有的执行器执行一次任务，并且可以向系统传递分片参数。

![](images/FqXJDNs3reP_xVX_bikFSs7fmEpU.png)

利用这一特性可以根据当前执行器的「**分片序号**」和 「**分片总数**」来获取对应的任务记录。

先来看看 Bean 模式下怎么获取分片序号和分片总数：

![](images/Fk5dxFok94Jl6mmMztcZ87glesAN.png)

有了这两个属性，当执行器扫描数据库获取记录时，可以根据「**取模**」的方式获取属于当前执行器的任务，如下：

![](images/Fsrtk94RZUyKr0pjdErkBYZRsrqo.png)

扫描任务表，根据任务 id 对分片总数「**取模**」来实现对所有分片的均分任务，通过判断是否是当前分片序号，如果是则执行相关任务操作，否则忽略。

![](images/FlJkGaHAqOXcNgPoMHbmANIjMkj3.png)

因此通过 XXL-Job 的「**分片广播**」＋「**取模**」的方式即可实现对集群服务均分任务的操作。

### **2.2.1.7 如何保证任务不会被重复消费**

由于推送任务本身处理时间就会比较长，所以更不允许服务重复执行，虽然上面通过「**分片广播**」＋「**取模**」的方式提高了任务不会被重复执行的机率，但是依旧存在如下情况：

如下图，有三台集群机器和六个任务，刚开始分配好了每台机器两个任务，「**执行器 0 正准备执行任务 3**」时，刚好「**执行器 2 宕机了**」，此时「**执行器 1**」刚好执行一次任务，因为分片总数减小，导致「**执行器 1 重新分片到需要执行的任务刚好也是任务 3**」，那么此时就会出现「**执行器 0 和 1 都在执行任务 3**」的情况。

![](images/FpRXEX1d_nXJyaPXHLEcb9ZZp7LC.png)

那么这种情况就需要实现幂等性了，幂等性有很多种实现方法，这里我们可以采用「**乐观锁**」的方式实现幂等性，具体 sql 如下：

update coupon\_push\_cron set push\_status \= 1

where (push\_status \= 0 or push\_status \= 2) and push\_fail\_num < 3 and id \= #{id}

这里只需要依靠任务的状态即可实现（待推送 0 ；推送中 1；推送失败 2；推送成功 3），可以看到这里类似于 CAS 的方式「**通过比较和设置的方式只有在状态为待推送或者推送失败时才能设置为处理中**」。这样在并发场景下，即使多个执行器同时处理该任务，也只有一个任务可以设置成功进入处理任务阶段。

为了真正达到幂等性，还需要设置一下 XXL-Job 的「**调度过期策略**」和「**阻塞处理策略**」来保证真正的幂等性。分别设置为「**忽略**」(调度过期后，忽略过期的任务，从当前时间开始重新计算下次触发时间） 和 「**丢弃后续调度**」（调度请求进入单机执行器后，发现执行器存在运行的调度任务，本次请求将会被丢弃并标记为失败）。

public static String generateUniquePhone(Faker faker) {

while (true) {

// 生成候选号码

String phone \= faker.phoneNumber().cellPhone();

// 第一重检查（无锁快路径）

if (PHONE\_CACHE.containsKey(phone)) continue;

// 第二重检查（同步锁保护）

synchronized (PHONE\_CACHE) {

if (PHONE\_CACHE.containsKey(phone)) continue;

PHONE\_CACHE.put(phone, true);

return phone;

}

}

}

## **04 千万级用户量推送任务优化方案实现**

接下来，我们来实现下「**千万级用户量推送任务**」的优化方案，这里我们只实现最终的方案。

当创建完成「**优惠券推送任务**」后，不论「**定时推送**」还是「**立即推送**」最终都会发一条 RocketMQ 消息出来。接着我们需要消费这条任务，进行「**千万级用户量推送任务**」。

## **4.1 基于线程池+任务分片+分片消息合并优化消费**

在执行消息消费时，具体的推送逻辑如下：

1.  检查优惠券模板的状态是否正常；
2.  验证优惠券模板的库存余量是否充足；
3.  获取不同策略的用户群体信息；
4.  对这些用户群体进行分桶，每个桶 1000 个用户，将构造消息加入桶中；
5.  对桶进行消息分割，按 100 条一个 batch 进行多线程发送消息。

具体代码实现如下：

/\*\*

\* 千万级优惠券推送任务处理消费者

\* 1、消费满足条件的一个个推送任务 即 coupon\_push\_cron 表数据

\* 2、然后不同的策略获取不同的用户群体 目前分 5 种情况： '推送人群范围 0:全部用户 1:新用户(注册3月内)2:老用户(注册超过3个月)3:会员用户4:女性用户 5:男性用户

\* 3、然后对用户进行分桶处理，每个桶 1000 个用户，构造消息将其加入桶种

\* 4、对桶进行分割，按 100 条为一个 batch 进行多线程发送消息

\*/

@Slf4j

@Component

public class CouponPushUpdateListener implements MessageListenerConcurrently {

/\*\*

\* 注入幂等处理器

\*/

@Autowired

private CouponQueueIdempotentHandler couponQueueIdempotentHandler;

/\*\*

\* 注入 MQ 生产者

\*/

@Autowired

private DefaultProducer defaultProducer;

/\*\*

\* 注入 userFeign 远程服务

\*/

@Autowired

private UserFeignService userFeignService;

/\*\*

\* 注入 mapper

\*/

@Autowired

private CouponPushCronMapper couponPushCronMapper;

/\*\*

\* 注入 mapper

\*/

@Autowired

private CouponTemplateMapper couponTemplateMapper;

/\*\*

\* 注入线程池

\*/

@Autowired

@Qualifier("sharedPushMsgThreadPool")

private SharedThreadPool sharedPushMsgThreadPool;

/\*\*

\* 并发消费

\* @param msgList

\* @param context

\* @return

\*/

@Override

public ConsumeConcurrentlyStatus consumeMessage(List<MessageExt> msgList, ConsumeConcurrentlyContext context) {

for (MessageExt messageExt : msgList) {

String msgId \= messageExt.getMsgId();

try {

String msg \= new String(messageExt.getBody());

// 解析优惠券推送任务消息

CouponPushUpdateMQMessage message \= JsonUtil.json2Object(msg, CouponPushUpdateMQMessage.class);

if (message == null) {

log.warn("优惠券推送任务 MQ 全量/特定群体用户推送-消息为空结束，原始消息内容：{}", msg);

return ConsumeConcurrentlyStatus.RECONSUME\_LATER;

}

log.info("优惠券推送任务 MQ 全量/特定群体用户推送，消息内容：{}", message);

// 1、检查优惠券模板的状态是否正常

CouponTemplateDO couponTemplateDO \= couponTemplateMapper.selectById(message.getCouponTemplateId());

if (couponTemplateDO.getCouponStatus() && couponTemplateDO.getCouponAuditStatus() != 1) {

// 修改任务状态为已完成和完成时间

updateCouponPushCron(message.getId());

log.info("优惠券推送任务 MQ 全量/特定群体用户推送-模板已失效，消费成功, result: {}", ConsumeConcurrentlyStatus.CONSUME\_SUCCESS);

return ConsumeConcurrentlyStatus.CONSUME\_SUCCESS;

}

// 2、验证优惠券模板的库存余量是否充足

if (couponTemplateDO.getCouponReceivedCount() <= 0) {

// 修改任务状态为已完成和完成时间

updateCouponPushCron(message.getId());

log.info("优惠券推送任务 MQ 全量/特定群体用户推送-模板库存余量已不足，消费成功, result: {}", ConsumeConcurrentlyStatus.CONSUME\_SUCCESS);

return ConsumeConcurrentlyStatus.CONSUME\_SUCCESS;

}

// 3、验证领取的优惠券是否在活动有效时间

boolean isInTime \= DateUtil.isIn(new Date(), couponTemplateDO.getCouponStartTime(), couponTemplateDO.getCouponEndTime());

if (!isInTime) {

log.error("优惠券推送任务 MQ 全量/特定群体用户推送-优惠券不在活动有效时间内 isInTime:{}", isInTime);

return ConsumeConcurrentlyStatus.CONSUME\_SUCCESS;

}

// 4、幂等性校验

if (couponQueueIdempotentHandler.isMessageConsumed(RedisKeyConstant.COUPON\_PUSH\_TASK\_IDEMPOTENT\_PREFIX, msgId)) {

// 判断当前的这个消息流程是否执行完成

if (couponQueueIdempotentHandler.isAccomplish(RedisKeyConstant.COUPON\_PUSH\_TASK\_IDEMPOTENT\_PREFIX, msgId)) {

log.warn("优惠券推送任务 MQ 全量/特定群体用户推送-检测到重复消息，当前流程还未执行完，消息内容：{}", message);

return ConsumeConcurrentlyStatus.RECONSUME\_LATER;

}

log.error("优惠券推送任务 MQ 全量/特定群体用户推送 consume error, 消息未完成流程，需要消息队列重试");

return ConsumeConcurrentlyStatus.RECONSUME\_LATER;

}

// 5、拿到最大的用户 id

Long maxUserId \= queryUsersByPushRange(message.getPushRange());

// 6、根据算法，将千万级用户推送任务进行分片，比如一个推送任务包含 1000 个用户

Map<Long, Long> userBuckets = new LinkedHashMap<>();

AtomicBoolean flag \= new AtomicBoolean(true);

// 从 userId = 1 开始

long startUserId \= 1L;

while (flag.get()) {

if (startUserId > maxUserId) {

flag.compareAndSet(true, false);

}

userBuckets.put(startUserId, startUserId + BatchSizeConstant.USER\_BUCKET\_SIZE);

startUserId += BatchSizeConstant.USER\_BUCKET\_SIZE;

}

// 7、将可能成千上万的推送任务进行消息 batch 合并, 以 batch 模式发送任务到 mq 里去，减少网络通信的耗时

List<String> pushUserBucketTaskBatch = new ArrayList<>();

for (Map.Entry<Long, Long> userBucket : userBuckets.entrySet()) {

// 构建消息

CouponPushUserBucketMQMessage userBucketMQMessage \= CouponPushUserBucketMQMessage.builder()

.startUserId(userBucket.getKey())

.endUserId(userBucket.getValue())

.id(message.getId())

.couponTemplateId(message.getCouponTemplateId())

.notifyType(message.getNotifyType())

.build();

String pushUserBucketTaskJson \= JsonUtil.object2Json(userBucketMQMessage);

// 加入桶中

pushUserBucketTaskBatch.add(pushUserBucketTaskJson);

}

log.info("优惠券推送任务 MQ 全量/特定群体用户推送-本次推送消息用户桶总数量, {}", pushUserBucketTaskBatch.size());

// 8、把 message 进行分割并多线程推送

UserBucketSplitter userBucketSplitter \= new UserBucketSplitter(pushUserBucketTaskBatch, BatchSizeConstant.MESSAGE\_BATCH\_SIZE);

while(userBucketSplitter.hasNext()){

List<String> sendBatch = userBucketSplitter.next();

log.info("优惠券推送任务 MQ 全量/特定群体用户推送-本次批次消息数量,{}",sendBatch.size());

// 多线程推送

sharedPushMsgThreadPool.execute(() -> {

// 批量发送消息

defaultProducer.sendMessages(

RocketMQConstant.COUPON\_PUSH\_USER\_BUCKET\_MESSAGE\_TOPIC,

sendBatch,

"优惠券推送任务 MQ 全量/特定群体用户推送 用户分桶 RocketMQ 消息");

});

}

// 9、修改任务状态为已完成和完成时间

updateCouponPushCron(message.getId());

// 设置消费完成表示

couponQueueIdempotentHandler.setAccomplish(RedisKeyConstant.COUPON\_PUSH\_TASK\_IDEMPOTENT\_PREFIX, msgId);

} catch (Exception e) {

// 本次消费失败，下次重新消费

couponQueueIdempotentHandler.delMessageProcessed(RedisKeyConstant.COUPON\_PUSH\_TASK\_IDEMPOTENT\_PREFIX, msgId);

log.error("优惠券推送任务 MQ 全量/特定群体用户推送 consume error, 更新博主美食缓存数据消费失败", e);

return ConsumeConcurrentlyStatus.RECONSUME\_LATER;

}

}

log.info("优惠券推送任务 MQ 全量/特定群体用户推送-消费成功, result: {}", ConsumeConcurrentlyStatus.CONSUME\_SUCCESS);

return ConsumeConcurrentlyStatus.CONSUME\_SUCCESS;

}

/\*\*

解析下我们线程池中的参数为什么这么设置：

1.  [corePoolSize](http://corepoolsize/)：这里设置为 0，是因为消息推送并不是一直要推送的，发优惠券正常情况下是不会推送，发送消息的线程池，corePoolSize 是 0，空闲把线程都回收掉就可以了。
2.  [maximumPoolSize](http://maximumpoolsize/)：运行任务属于 I/O 密集型，最大线程数设置为我们设定线程数的 2 倍即 60。
3.  [workQueue](http://workqueue/)：理论上说我们不会有阻塞的情况，因为设置的线程数不少，所以如果使用不存储任务的同步队列。
4.  [ThreadFactory](http://threadfactory/)：这里我们自定义了一个后台线程类。
5.  [handler](http://handler/)：这里直接默认。

@Slf4j

@Component

public class CouponPushUserBucketUpdateListener implements MessageListenerConcurrently {

/\*\*

\* 注入幂等处理器

\*/

@Autowired

private CouponQueueIdempotentHandler couponQueueIdempotentHandler;

/\*\*

\* 消息推送工厂提供者

@Autowired

private CouponTemplateMapper couponTemplateMapper;

/\*\*

\* 注入 mapper

private CouponPushCronMapper couponPushCronMapper;

\* @param context

@Override

public ConsumeConcurrentlyStatus consumeMessage(List<MessageExt> msgList, ConsumeConcurrentlyContext context) {

for (MessageExt messageExt : msgList) {

String msgId \= messageExt.getMsgId();

try {

// 1、获取到一个推送任务分片 这里包含 100 个用户

String msg \= new String(messageExt.getBody());

// 解析优惠券推送任务消息

CouponPushUserBucketMQMessage message \= JsonUtil.json2Object(msg, CouponPushUserBucketMQMessage.class);

if (message == null) {

log.warn("优惠券推送任务 MQ 用户分桶单分片推送-消息为空结束，原始消息内容：{}", msg);

return ConsumeConcurrentlyStatus.RECONSUME\_LATER;

}

log.info("优惠券推送任务 MQ 用户分桶单分片推送，消息内容：{}", message);

// 幂等性校验，防止重复消费

if (couponQueueIdempotentHandler.isMessageConsumed(RedisKeyConstant.COUPON\_PUSH\_TASK\_USER\_BUCKET\_IDEMPOTENT\_PREFIX, msgId)) {

// 判断当前的这个消息流程是否执行完成

if (couponQueueIdempotentHandler.isAccomplish(RedisKeyConstant.COUPON\_PUSH\_TASK\_USER\_BUCKET\_IDEMPOTENT\_PREFIX, msgId)) {

log.warn("优惠券推送任务 MQ 用户分桶单分片推送-检测到重复消息，当前流程还未执行完，消息内容：{}", message);

return ConsumeConcurrentlyStatus.RECONSUME\_LATER;

}

log.error("优惠券推送任务 MQ 用户分桶单分片推送 consume error, 消息未完成流程，需要消息队列重试");

return ConsumeConcurrentlyStatus.RECONSUME\_LATER;

}

// 2、查询本次推送任务分片对应的用户群体

Long startUserId \= message.getStartUserId();

Long endUserId \= message.getEndUserId();

ApiResult queryResult \= userFeignService.queryAccountByIdRange(startUserId, endUserId);

log.info("优惠券推送任务 MQ 用户分桶单分片推送-调用用户接口获取用户推送范围信息, queryResult: {}", queryResult);

if (queryResult.getCode() != 0) {

// 异常

log.error("优惠券推送任务 MQ 用户分桶单分片推送-基础信息失败：{}", queryResult);

throw new BizException(BizCodes.USER\_ACCOUNT\_NOT\_EXIST);

}

// 拿到用户推送范围信息

List<UserVO> userList = queryResult.getData(new TypeReference<>(){});

if (CollectionUtils.isEmpty(userList)) {

log.info("优惠券推送任务 MQ 用户分桶单分片推送-根据用户桶内的id范围没有查询到用户, startUserId={}, endUserId{}", startUserId, endUserId);

continue;

}

// 3、获取优惠券模板数据, 这里直接从消息中获取即可

// 验证用户是否符合优惠券领取条件

JSONObject receiveRule \= JSON.parseObject(message.getCouponReceiveRule());

String perUserLimit \= receiveRule.getString("perUserLimit");

// lua 脚本优惠券模板 id 缓存 key

String couponTemplateCacheKey \= String.format(RedisKeyConstant.COUPON\_TEMPLATE\_PREFIX, message.getCouponTemplateId());

log.info("优惠券推送任务 MQ 用户分桶单分片推送-执行 Lua 脚本 couponTemplateCacheKey:{}, perUserLimit:{}", couponTemplateCacheKey, perUserLimit);

// 用户领券记录表

List<UserCouponDO> userCouponS = new ArrayList<>();

// 推送任务失败记录表

CouponPushCronFailDO cronFail \= new CouponPushCronFailDO();

cronFail.setCouponPushCronId(message.getId());

List<FailRecordEntity> failRecords = new ArrayList<>();

// 4、遍历用户列表进行优惠券推送

for (UserVO user : userList) {

// 过滤非当前渠道用户 TODO 这里实现不太优雅 后续有时间再进行优化

if (message.getPushRange() == 1) { // 新用户(注册3月内)

LocalDateTime threeMonthsAgo \= LocalDateTime.now().minusMonths(3);

Date threeMonthsAgoTime \= Date.from(threeMonthsAgo.atZone(ZoneId.systemDefault()).toInstant());

if (user.getCreateTime().getTime() <= threeMonthsAgoTime.getTime()) {

// 不是新用户

log.info("优惠券推送任务 MQ 用户分桶单分片推送-过滤非当前渠道新用户 userId:{}", user.getId());

continue;

}

} else if (message.getPushRange() == 2) { // 老用户(注册超过3月)

LocalDateTime threeMonthsAgo \= LocalDateTime.now().minusMonths(3);

Date threeMonthsAgoTime \= Date.from(threeMonthsAgo.atZone(ZoneId.systemDefault()).toInstant());

if (user.getCreateTime().getTime() > threeMonthsAgoTime.getTime()) {

// 不是老用户

log.info("优惠券推送任务 MQ 用户分桶单分片推送-过滤非当前渠道老用户 userId:{}", user.getId());

continue;

}

} else if (message.getPushRange() == 3) { // 会员用户

if (!user.getVip()) {

// 不是vip用户

log.info("优惠券推送任务 MQ 用户分桶单分片推送-过滤非当前渠道 VIP 用户 userId:{}", user.getId());

continue;

}

} else if (message.getPushRange() == 4) { // 女性用户

if (user.getSex()) {

// 不是女性用户

log.info("优惠券推送任务 MQ 用户分桶单分片推送-过滤非当前渠道女性用户 userId:{}", user.getId());

continue;

}

} else if (message.getPushRange() == 5) { // 男性用户

if (!user.getSex()) {

// 不是男性用户

log.info("优惠券推送任务 MQ 用户分桶单分片推送-过滤非当前渠道男性用户 userId:{}", user.getId());

continue;

}

}

// 6、真正用户推送

pushSend(message, user);

}

// 设置消费完成标识

couponQueueIdempotentHandler.setAccomplish(RedisKeyConstant.COUPON\_PUSH\_TASK\_USER\_BUCKET\_IDEMPOTENT\_PREFIX, msgId);

} catch (Exception e) {

// 本次消费失败，下次重新消费

couponQueueIdempotentHandler.delMessageProcessed(RedisKeyConstant.COUPON\_PUSH\_TASK\_USER\_BUCKET\_IDEMPOTENT\_PREFIX, msgId);

log.error("优惠券推送任务 MQ 用户分桶单分片推送 consume error", e);

return ConsumeConcurrentlyStatus.RECONSUME\_LATER;

}

}

log.info("优惠券推送任务 MQ 用户分桶单分片推送-消费成功, result: {}", ConsumeConcurrentlyStatus.CONSUME\_SUCCESS);

return ConsumeConcurrentlyStatus.CONSUME\_SUCCESS;

}

/\*\*

\* 正式进行用户渠道推送

\* @param message

\* @param user

\*/

private void pushSend(CouponPushUserBucketMQMessage message, UserVO user) {

// 获取消息服务工厂

PushSendServiceFactory pushSendServiceFactory \= factoryProvider

.getPushSendServiceFactory(message.getNotifyType());

// 消息发送服务组件

PushSendService pushSendService \= pushSendServiceFactory.createPushSendService();

// 构造消息

CouponPushUserMessage couponPushUserMessage \= CouponPushUserMessage.builder()

.notifyType(message.getNotifyType())

// TODO 消息后续可以抽离出来 根据优惠对象和领取方式来展示不同的消息 这里就不做了

.message("恭喜获得新客礼，请注意查收哦，全平台可用")

.userId(user.getId())

.phone(user.getPhone())

.mail(user.getMail())

.couponTemplateId(message.getCouponTemplateId())

.build();

PushSendEntity pushSend \= pushSendServiceFactory.createPushSendEntity(couponPushUserMessage);

// 6、进行推送

pushSendService.send(pushSend);

}
