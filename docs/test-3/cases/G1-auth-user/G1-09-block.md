# G1-09 拉黑用例

> 组：G1 认证与用户 | 服务：user(19001) | 入口：**gateway(19000)**
> 依赖：两个用户 {A}/{B}（G1-02/03）
> 代码实证：block 数据 = Redis Set `myxhs:user:block:{uid}`（SADD，**TTL 365 天**）；**无 MySQL 落库**；block 对关注/评论等**无跨服务拦截**（analytics 不消费 block 数据——审查观察项）

## 用例清单

### G1-09-01 拉黑
- **入口**：`POST /api/user/block/{B}`（A 的 token）
- **L1 断言**：200
- **L2**：
  ```
  SMEMBERS myxhs:user:block:{A}      # 含 {B}
  TTL myxhs:user:block:{A}           # ~31536000s（365 天）
  ```

### G1-09-02 重复拉黑
- 再次 POST → 200（Set 幂等）或业务码——实测记录
- **L2**：SMEMBERS 无重复

### G1-09-03 拉黑列表
- `GET /api/user/block/list` → 200 含 {B}

### G1-09-04 取消拉黑
- `DELETE /api/user/block/{B}` → 200
- **L2**：SMEMBERS 不含 {B}

### G1-09-05 自拉黑 / 不存在目标
- A 拉黑自己 → 拒绝（实测码）；A 拉黑 88888888（不存在）→ 200 或拒绝（实测——与 T-013 幽灵数据同类观察）

### G1-09-06 拉黑后关注不受限（现状确认）
- A 拉黑 B 后，A 关注 B → **200（block 无业务拦截——现状实证）**
- **说明**：登记观察项：block 数据当前**无人消费**（无拦截逻辑）——"拉黑"目前仅为数据记录，是否应拦截关注/评论/查看待业务决策（T-016）
