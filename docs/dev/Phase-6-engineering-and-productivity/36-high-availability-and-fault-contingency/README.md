# 高可用与故障预案

> 所属维度：架构保障 | 开发阶段：Phase-6 | 可用性目标：99.95%

---

## 🎯 一、高可用目标

> 📖 **知识来源**：《大型网站技术架构》(李智慧) 第2章
> - "大型网站5大核心要素——性能、可用性、可伸缩、可扩展、安全"
> - "99.9%=年宕机8.76小时，99.99%=年宕机52.56分钟"
> - 核心策略："冗余(多实例多副本) + 隔离(熔断降级限流) + 监控(日志指标链路) + 容灾(主从切换)"

| 指标 | 目标 | 说明 |
|------|------|------|
| 可用性 | 99.95% | 年宕机 ≤ 4.38小时 |
| 核心链路RTO | < 30秒 | 下单/支付链路30秒内恢复 |
| 数据RPO | < 1分钟 | 最多丢失1分钟数据 |

## 🏗️ 二、各组件高可用方案

| 组件 | 故障场景 | 高可用方案 | my-xhs落地 | 故障恢复时间 |
|------|----------|-----------|-------------|-------------|
| MySQL | 主库挂 | ShardingSphere主从切换 + 从库升主 | ✅ | < 30秒 |
| Redis | 主节点挂 | Sentinel哨兵自动故障转移 | ✅ | < 30秒 |
| RocketMQ | Broker挂 | 主从同步复制 + DLedger自动切换 | ✅ | < 60秒 |
| Nacos | 节点挂 | 集群部署(3节点) + 本地缓存兜底 | ✅ | 无感知 |
| ES | 节点挂 | 副本分片自动提升为主分片 | ✅ | < 30秒 |
| Gateway | 实例挂 | K8s自动重启 + Nacos摘除 | ✅ | < 60秒 |
| 业务服务 | 实例挂 | K8s重启 + Nacos摘除 + Sentinel熔断 | ✅ | < 60秒 |

## 📋 三、故障等级定义

| 等级 | 定义 | 响应时间 | 通知方式 |
|------|------|----------|----------|
| **P0** | 核心链路不可用(下单/登录) | 5分钟内响应 | 电话+企微 |
| **P1** | 非核心功能不可用(搜索/通知) | 15分钟内响应 | 企微 |
| **P2** | 性能降级(RT升高/错误率升高) | 30分钟内响应 | 企微 |
| **P3** | 告警但未影响用户 | 次日处理 | 邮件 |

## 🛡️ 四、服务容错

| 场景 | 容错策略 | my-xhs落地 |
|------|----------|-------------|
| 服务雪崩 | Sentinel熔断降级 | 库存服务挂了→订单服务熔断→降级返回 |
| 流量突增 | 限流+排队 | 秒杀场景Gateway限流+库存预扣 |
| 调用超时 | Feign超时配置+重试 | 连接5s+读取10s+重试2次(幂等接口) |
| 缓存故障 | 降级+限流 | Redis不可用→走DB+限流降级 |
| 消息故障 | 死信队列+重试 | 消费失败16次重试→死信→人工处理 |
| 部署故障 | 优雅停机 | graceful shutdown + PreStop |

## 📑 五、核心场景故障预案

| 场景 | 影响 | 预案 | 恢复时间目标 |
|------|------|------|-------------|
| Redis主节点宕机 | 缓存不可用 | Sentinel自动故障转移 | < 30秒 |
| MySQL主库宕机 | 写入不可用 | ShardingSphere主从切换 | < 30秒 |
| RocketMQ Broker宕机 | 消息不可用 | 主从切换+本地消息表兜底 | < 60秒 |

## ⚖️ 六、方案对比

### 6.1 Redis高可用方案对比

| 维度 | Sentinel哨兵 | Redis Sentinel | 主从+VIP |
|------|-------------|--------------|---------|
| 自动故障转移 | ✅ | ✅ | ❌ 需脚本 |
| 数据分片 | ❌ 单主 | ✅ 多主 | ❌ |
| 复杂度 | 低 | 高 | 低 |
| 适用场景 | 数据量<32G | 数据量>32G | 简单场景 |

**最终选择**：Sentinel哨兵 — 项目数据量不大，Sentinel简单可靠，自动故障转移30秒内完成。

## 🎤 七、面试考察点

### Q1: 你们系统的高可用怎么保证的？

**推荐回答思路**：

> 1. "四层保障：冗余(多实例多副本)+隔离(Sentinel熔断降级限流)+监控(Prometheus+SkyWalking)+容灾(主从自动切换)"
> 2. "各组件HA：MySQL主从切换30秒、Redis Sentinel 30秒、MQ DLedger 60秒、Nacos集群无感知"
> 3. "故障分级P0-P3，核心链路5分钟内响应"

### Q2: 某个服务挂了，其他服务怎么办？

**推荐回答思路**：

> 1. "Sentinel熔断：异常比例超阈值自动熔断，不再调用挂掉的服务"
> 2. "降级处理：返回默认值/缓存数据/友好提示，不是直接报错"
> 3. "举例：库存服务挂了→订单服务熔断→返回'系统繁忙请稍后'→用户体验不中断"
