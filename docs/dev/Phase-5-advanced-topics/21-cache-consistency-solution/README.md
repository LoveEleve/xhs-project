# 缓存一致性方案

> 跨服务专题 | 开发阶段：Phase-5 | 状态：⏳ 待开发

## 专题概要

本专题聚焦缓存与数据库一致性问题的完整解决方案，涉及多个服务。

## 涉及服务

- my-xhs-common（CacheHelper 封装）
- my-xhs-user（用户信息缓存）
- my-xhs-product（多级缓存）
- my-xhs-note（笔记详情缓存）

## 核心方案

| 策略 | 适用场景 | 说明 |
|------|----------|------|
| Cache Aside | 通用读多写少 | 先更新DB→再删缓存 |
| 延迟双删 | 强一致需求 | 删缓存→更新DB→延时再删缓存 |
| Canal + Binlog | 最终一致性 | MySQL Binlog → Canal → 更新缓存/ES |

## 面试高频问题

- 为什么是"先更新DB再删缓存"而不是"先删缓存再更新DB"？
- 延迟双删的延时时间怎么确定？
- Canal 同步延迟怎么处理？
