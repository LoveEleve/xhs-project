## 📋 文档规范

### 命名规则
- 子文件夹：`{序号}-{功能名称}/`，如 `01-用户注册登录/`
- 主文档：`README.md`（每个子文件夹必须有）
- 附加文件：`schema.sql`（建表语句）、`assets/`（图片/架构图）

### 每个功能文档必须包含的章节

| 章节 | 内容 | 目的 |
|------|------|------|
| 🎯 需求分析 | 业务场景、功能边界、数据量预估 | 说清楚"做什么" |
| 🏗️ 架构设计 | 架构图、模块交互、时序图 | 说清楚"怎么设计" |
| 🗄️ 数据库设计 | 表结构DDL、索引设计、分库分表策略 | 数据层完整可执行 |
| 🔑 缓存设计 | Redis Key规范、过期策略、一致性方案 | 缓存层设计决策 |
| 📡 接口设计 | API列表、请求/响应示例 | 前后端契约 |
| 💻 核心代码实现 | 关键代码片段+注释说明 | 技术实现细节 |
| ⚖️ 方案对比 | 技术选型对比表（至少2个方案） | 展示技术判断力 |
| 🐛 踩坑记录 | 开发中遇到的问题和解决方案 | 经验沉淀 |
| 📊 测试验证 | 关键场景测试用例、压测数据 | 验证方案有效性 |
| 🎤 面试考察点 | 高频面试问题 + 推荐回答思路 | 面试准备 |

### 文档质量标准

1. **代码可运行**：贴的代码片段能直接复制到项目中使用
2. **方案有对比**：每个技术选型至少对比2种方案，说明选择理由
3. **数据有佐证**：性能数据、压测结果要有具体数字
4. **面试能说清**：每个模块的面试考察点要能用2-3句话说清楚核心思路

## 🔄 文档编写流程

```
1. 需求分析  →  复制 _template.md 到新子文件夹
2. 设计阶段  →  填写架构设计、数据库设计、缓存设计
3. 编码阶段  →  同步填写核心代码实现、踩坑记录
4. 测试阶段  →  填写测试验证
5. 复盘阶段  →  填写方案对比、面试考察点
```
