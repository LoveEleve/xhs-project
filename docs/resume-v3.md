# 项目一 · 内容电商平台（15 微服务 / 27 容器）｜核心开发 / 稳定性 Owner

## 项目介绍
内容与交易一体的电商平台：交易侧覆盖商品、购物车、库存、优惠券、订单、支付、售后、结算、通知，内容侧覆盖用户、笔记、Feed、搜索、推荐，另含 IM、计数、网关与认证，共 15 个 Spring Cloud 微服务。基础设施为 MySQL 分库分表（订单 4 库 × 4 表）+ Redis Sentinel + RocketMQ + Elasticsearch + ShardingSphere + Canal + XXL-Job，ELK / Prometheus + Grafana / SkyWalking 全链路可观测，Docker 编排 27 容器；配套故障注入、混沌演练与容量压测环境（单机同城双活仿真口径）。

## 核心成果（Highlight）
- **性能**：定位类加载锁热点（每请求 Class.forName → 92/99 Tomcat 线程 BLOCKED），改静态桥接后 product 1,074→4,871 RPS（4.5x，P99 50ms，无本地缓存）；search 508→1,448 RPS（P99 191→61ms）；user info 5,846 RPS / P99 40ms。
- **一致性**：库存"Redis 分桶 + Lua 原子预扣 + DB 账本 + TCC fence 状态机"——20 并发预扣不超卖、11 场景（幂等 / 空回滚 / 悬挂 / 超量）全通过；注入 75s 事务回查延迟后库存仍只扣一次。
- **容灾**：MySQL 故障转移 RTO≈32s（停主 10.2s / 提升 0.087s / 应用切换 22s）；Redis 切主 2.3s 业务无错乱；同 zone 优先在跨区延迟注入（netem）下吞吐 +34%、P99 降低 33%~47%。
- **分片治理**：订单分片采用哈希取模方案，迁移存量 682 行后 16/16 片均匀、路由抽查全命中。
- **资金安全**：售后应退金额按订单优惠分摊（分单位最大余数法、部分数量向下取整永不超退、退满补差使累计严格闭合），叠加同 SKU 累计 / 订单实付 / 支付域可退三层护栏；退款单号回传实现每笔退款唯一归属。
- **对账自愈**：T-1 日切账单幂等重跑 + 三方对账三类差异挂账自动收敛；8 个对账 / 修复任务（库存、优惠券、购物车、未读、关注、消息补发、超时关单、映射补录）差异自动收敛，Redis 丢失可从 DB 权威源反向重建。

## 职责描述（Responsibilities）

### 一、交易链路（一致性核心）
- **库存一致性**：Redis 分桶 + Lua 原子预扣 + DB 账本 + Outbox 兜底的三级扣减；热点 SKU 由滑动窗口（10s/100 次）自动扩容 2→8 桶；超时回收以 ZSet 过期索引替代全库扫描（O(N)→O(logN)）；幂等占位表（INSERT IGNORE 走主库）杜绝重复扣减；实现 TCC 冻结协议（Try/Confirm/Cancel + fence 状态机），覆盖空回滚、悬挂、超量拒绝（接口与 11 场景验证完成，订单链路当前走事务消息预扣）。
- **订单与分布式事务**：RocketMQ 事务消息 + 本地消息表 + Broker 回查保证下单与预扣一致；订单状态全部条件 UPDATE 流转，事件表以序号唯一键 + 乐观锁收敛并发；4 库 × 4 表分片 + 订单号映射表支持非分片键反查，支付表与映射表走独立数据源绕过分片路由，为支付域独立拆分预留；提供订单状态重建与校准能力——按事件流回放重建状态、dry-run 报告偏差并按条件更新修复。
- **支付与退款**：支付单/退款单双状态机 + 渠道策略化发起与回调（策略 SPI：Mock 渠道 + 回调模拟器驱动全链路；真实渠道验签/查询/关单为接入项）；回调结果三态判定（成功 / 失败 / 无法判定，未知态回 "fail" 让渠道重试）；重复回调不改状态（状态守卫幂等；渠道验签为接入真实渠道的必做项）；退款以"累计退款 = 支付金额"驱动库存回补与退券；支持零元单（全额券抵扣）直接记账；支付 30min / 退款 15 天超时检测 + 通知补偿（5 分钟窗口、最多 10 次、批量 100）+ 每日对账。
- **售后与优惠分摊**：仅退款 / 退货退款状态机全部条件更新，同订单 + SKU + 类型唯一 + 累计额度校验防超退；审核前复核订单状态，通过后走支付域"按订单退款"接口并按 SKU 调库存回补（复用累计正增量幂等链路，失败落补偿表自动重试；跨服务请求未到达由 restock_status + 恢复任务兜底）；应退金额按订单优惠分摊（分单位最大余数法、平局按明细 ID 确定性、部分数量向下取整永不超退、退满补差使累计严格闭合）；三层护栏（同 SKU 跨类型累计上限 / 订单实付上限 / 支付域可退上限）；恢复任务先向支付域核对事实（金额 + 类型 + 时间窗 + 退款单号归属）再决策，退款单号回传实现唯一归属。
- **结算与三方对账**：T-1 日切账单（按渠道聚合收款 / 退款 / 净额 / 手续费），唯一键 (账单日, 渠道) + 条件更新实现幂等重跑；三方对账产出「本地有渠道无 / 渠道有本地无 / 金额不一致」三类差异并挂账（重复对账幂等、人工已处理不被覆盖、消失自动收敛、重现自动复位）；对账单未到按到账标记跳过，避免产出假差异；聚合与扫描走索引、游标分页内存有界 + 50 万笔/日安全阀；账单生成与对账共用 (日期, 渠道) 粒度分布式锁串行。

### 二、缓存、搜索与内容
- **缓存体系**：商品详情布隆过滤器（100 万容量 / 1% 误判）+ 空值缓存 + 逻辑过期异步单飞 + 冷 key 加锁双检；事务提交后删缓存 + 延迟双删（MQ 广播失效为用户域落地，商品域未接入）；启动预热框架（CacheWarmer SPI）预热分类树、热搜榜与推荐池；Lettuce 指标接线与连接池标准键装配（含时长解析修正）。
- **搜索与同步**：Canal + MQ 双通道同步 ES，外部版本号拒绝陈旧写（全量重建同样带版本）、tombstone 防旧消息复活；search_after 深分页；全量重建断点续传 + 完成后清零 + 尾部清理源表已删死文档；热搜榜快照 + 反作弊、搜索建议 completion + 前缀缓存、历史去重截断；DFA 敏感词与文本同预处理。
- **内容与社交**：笔记发布 / 草稿 / 编辑 / 软删（内容与消息同事务）、楼中楼评论（parent_id / reply_to_id）、图片上传魔数校验（存储可切换 MinIO）；点赞 / 收藏 / 关注以 Set / ZSet / 关系表建模 + Lua 原子写入 + 版本窗口防乱序，半成功由对账修复。
- **计数服务**：10 类社交计数 Redis 实时计数 + 内存 Buffer（满 100 条 / 5 秒）批量 upsert 落库，失败回写缓冲、停机强刷、msgId 去重；对账以 Redis 为准修正 DB，并支持从行为权威集重建。
- **推荐与 Feed**：行为上报 → 特征 / 热池 / ItemCF 三个离线任务预计算，线上 6 种召回（含 GeoHash 同城）；Feed 推拉结合——大 V 走发件箱拉模式、普通用户按粉丝批量写收件箱，cursor 断点续推可恢复；删除走 tombstone + 关注流索引清理。
- **IM / SSE / 通知**：会话跨实例经 Redis pub/sub 路由 + 跨实例踢线（新实例接管后定向通知旧实例关闭僵尸连接）；离线消息持久副本 + ACK 删除 + msgId 去重（at-least-once），按序补发（1000 条 / 7 天）；会话 ID 由关系表分配（用户对粒度分布式锁防并发双 ID）；ticket 两步握手一次性消费（GETDEL，防 URL 日志重放）；SSE 跨实例定向推送；通知按自然日窗口聚合（"等 N 人"），未读 INCR/HINCRBY 双键同 slot（Cluster 安全）+ 原子降级 + 对账全量累计防跨批错值。

### 三、网关、安全与认证
- **网关**：WebFlux 8 个 GlobalFilter 组链（Body 缓存 → 日志 → 鉴权 → 染色 → HMAC → 限流 → 灰度 → 版本）；JWT 注入身份并覆盖伪造头，直连服务同等校验；请求体鉴权后缓存 + Content-Length 预检 + 带上限聚合（防未鉴权超大 body 打爆堆）；HMAC 签名（时间窗 + nonce 防重放，默认关闭）；Sentinel 规则 Nacos 托管 + 30s 真空期兜底 + 路由级限流校准；下游超时语义修正为 504。
- **用户与认证**：JWT 双 token（access 30min / refresh 7d）+ 图形验证码（Redis 原子一次性消费）；刷新 Redisson 锁 + 二查黑名单 + 旧 token 拉黑；登出 / 改密 / 删号全量吊销；登录防爆破按 IP 与账号双维度（账号维度需多来源 IP 才锁，防账号 DoS；IP 取可信来源——网关单值注入，杜绝伪造 XFF 锁账号）；改密先吊销凭证再落库（Redis 不可用即拒绝，fail-closed）；地址管理（20 条上限、默认地址切换、分布式锁覆盖事务提交）。
- **并发控制分层**：分布式锁只承担效率职责（显式租期、抢锁失败直接拒绝并回滚幂等标记、Redis 异常不降级放行），正确性由唯一键、条件 UPDATE、fence 状态机、消息去重与对账任务兜底，避免把分布式锁当一致性保证。

### 四、公共组件与工程化
- **公共组件**：限流（ZSet + Lua 滑动窗口）与幂等切面按 @Order 组链（45 处限流点 / 9 处幂等点）；SqlGuard 慢 SQL 指纹熔断 + 白名单阻断 + 豁免；读写分离 Executor 层路由 + 从库故障降级恢复；Feign 统一禁重试 + HC5 池化 + 分级超时 + 内部令牌 fail-closed + 30 个降级工厂；号段 ID 生成器（双 Buffer 预加载）、批量写入执行器、多版本 API、审计独立事务模板等组件完成实现与单测（部分未接入业务链路）。
- **配置中心与调度**：15 个服务统一接入 Nacos 配置中心（命名空间隔离 + `spring.config.import: optional:nacos:` 保证 Nacos 不可用不阻塞启动）；20 个任务 / 10 个执行器组统一接入 XXL-Job，配套兜底型任务与可解释的失败日报口径。
- **工程化与质量基建**：Gitea Actions + act_runner（systemd、Docker 执行器、.m2 缓存复用）覆盖编译 / 单测 / 规范扫描，ci-gate 门禁 + 版本化发布与自动回滚；搭建 117 项测试矩阵 + 混沌注入（Nacos 动态开关 + iptables）+ 影子表压测隔离；订单状态机 8 场景并发对抗、分布式事务故障注入（消费者宕机追平、MQ 暂停下单）、依赖变慢注入（netem 4s → 降级 503）验证通过。

### 五、稳定性、多活与可观测
- **多活与容灾**：Zone 自动发现（env / 文件 / 网段 CIDR）+ X-Zone 跨服务传播（入出站过滤 + 指标）；同 zone 优先路由（数据面 MySQL / Redis zone 感知、运行时热切不重启）；网关反应式 zone 负载均衡（12/12 就近）；Redis 双主仿真（DUMP/RESTORE + LWW + 周期对账）；健康检查摘除与回切（RTO 1.3~4.8s）。
- **可观测与告警**：15 服务 Logback JSON 结构化日志 + Filebeat → Logstash → ES 按天索引 → Kibana；SkyWalking agent 接入（SB3 插件适配、ignore_suffix 降噪）并实测 APM 开销 ≈5.4%；Prometheus 规则 31→40 条分级（severity + Runbook）+ Watchdog + SLO 错误预算（30 天 43m12s）+ Burn Ledger；告警端到端演练验证（firing → 通知 → resolved）。
- **中间件与 JVM**：慢 SQL 由相关子查询改窗口函数 + 复合索引；JVM 参数体系（G1 + MaxGCPauseMillis + Metaspace）+ 线程池隔离 + MDC 包装保证 traceId 跨池；类加载锁热点优化（product 4.5x）；Redis 故障语义设计（Redis 故障时网关 503 可重试、客户端超时配置化使 DB 回退生效）。
- **部署与运维**：27 容器 Docker 编排（restart:always + healthcheck 全覆盖 + depends_on 时序）与运行时零漂移核验；备份体系（MySQL 每日全量 + binlog 30 天、Redis 每 6 小时 BGSAVE、ES 每日快照）；日志保留治理（ILM 30 天 + 环境清理）；优雅停机（先摘注册、缓冲刷盘再停）；RocketMQ topic 全量幂等初始化；混沌演练 7 场景（Redis / MQ 暂停、CPU 满载、磁盘写满、MySQL 暂停、优雅停机）全部通过。
- **分布式 ID 与多框架并存**：订单 Snowflake worker-id 三级取值（环境变量 → 系统属性 → IP 哈希）+ 端口维度防同机多实例重号；ShardingSphere 绑定表 5 张避免同分片键 JOIN 笛卡尔积；MyBatis + MyBatis-Plus + Spring Data JPA 三框架同应用并存（独立 EntityManagerFactory 与事务管理器）；分片与 Zone 动态数据源同应用并存（映射表 master/slave 运行时切换并验证）。

## 关键结果（Key Achievements）
- **性能**：product 1,074→4,871 RPS（4.5x，P99 50ms，无本地缓存）；search 508→1,448 RPS（P99 191→61ms）；home 1,861 RPS / P99 49.6ms；user info 5,846 RPS / P99 40ms；网关代理损耗 ≈0（放行后 4,640 RPS）。
- **库存**：20 并发预扣不超卖（149→129）、超量请求整单拒绝；TCC 11 场景全通过（幂等 / 空回滚 / 悬挂拒绝 / 超量拒绝 / fence 1→2、1→3）；注入 75s 事务回查延迟后库存仍只扣一次。
- **订单**：8 场景并发对抗全通过（取消 vs 支付自动退款闭环、部分退款累计语义）；分片治理：16/16 片均匀（迁移存量 682 行、路由抽查全命中）；Broker 暂停下单无半成品、同单重试仅 1 单。
- **一致性与容灾**：缓存更新后 24ms 读到新值；Redis 切主 2.3s 业务无错乱；MySQL 故障转移 RTO≈32s（停主 10.2s / 提升 0.087s / 应用切换 22s）并沉淀 5 项短板与整改路线。
- **多活**：同 zone 优先在 netem 跨区模拟下吞吐 +34%、P99 降低 33%~47%；X-Zone 跨服务传播 10/10；网关故障切换 5.54s 由对侧 zone 承接；故障注入 RTO 1.31s / 3.25s（进程崩溃）、4.79s（网络分区）；Redis 双主单侧故障不中断、恢复 ≤35s 追平。
- **并发边界**：抢锁超时一律拒绝（"系统繁忙"）并以 DB 乐观锁为最终防线，Redis 故障下不产生幽灵数据；重复下单 / 重复支付回调 / 重复领券分别被幂等标记、状态机与唯一键拦截。
- **售后与分摊**：售后状态流转全部条件更新（并发审核 / 撤销 / 重试只有一个赢家）、重复申请由唯一键兜底；分摊不变量（Σ 分摊 == 优惠额、单项分摊 ≤ 单项金额）由整数运算保证，同一订单可确定性重算。
- **结算与对账**：账单幂等重跑（条件更新 + 重跑计数）；聚合与扫描走索引、内存有界（游标分页 + 页数安全阀）；差异挂账三态（待处理 / 已处理 / 已忽略，含自动收敛与重现复位）；手续费按收款毛额计提，跨日退款使单日净额可为负且口径一致。
- **对账收敛**：8 个对账任务逐项运行验证（17 SKU 差异修复 2 条 / 38ms；计数对账双向注入均可收敛；关注半成功由对账自动补插）；DLQ 积压按 26 个消费组可见并按类清账。
- **内容与计数**：发布保持原子（11ms 写入、3–6s 搜索可见、2 万字敏感词过滤约 2ms）；1 万次点赞合并为约 2000 个计数 key、一次批量 SQL 落库，注入 DB 故障后恢复自动补刷、增量不丢。
- **多框架并存**：同表双栈读取实测并暴露逻辑删除语义差异（MyBatis 33 行 / JPA 36 行）；分片下单在动态数据源切换期间不受影响；同机双实例 Snowflake worker-id 唯一（354 vs 454）。
