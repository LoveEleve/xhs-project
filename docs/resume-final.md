# 项目一 · 小红书电商交易平台

## 项目介绍
xhs 是一个内容与交易并重的社交电商平台，共 15 个 Spring Cloud 微服务：交易侧包含商品、购物车、库存、优惠券、订单、通知，内容侧包含用户、笔记、Feed、搜索、推荐。基础设施使用 RocketMQ、Redis Sentinel、Elasticsearch、ShardingSphere（订单 4 库 × 4 表）、Canal、XXL-Job，监控由 ELK、Prometheus/Grafana、SkyWalking 组成，整体 Docker 化部署。
我在项目中负责交易与内容核心模块的设计开发，并主导稳定性优化：实现库存三层语义（可售/锁定/已扣）与分桶预扣、订单分片与事务消息、优惠券/购物车的一致性方案、Feed 推拉结合、IM 跨实例路由等；在此基础上把测试、故障注入、容量校准和链路追踪补齐。

## 职责描述（Responsibilities）
- **库存**：设计 Redis 分桶 + Lua 原子预扣 + DB 账本 + TCC 三段式的组合方案，处理热点 key、超时回收（ZSet 过期索引替代全库 SCAN）和幂等（预扣幂等表、Outbox 唯一键）；配套超时回补、补偿与对账任务。
- **订单**：基于 ShardingSphere 做 4 库 × 4 表分片（非分片键反查走订单号映射表，Snowflake workerId 按实例动态计算）；用事务消息 + 本地消息表 + Broker 回查保证下单与库存预扣的最终一致，延迟消息 + 状态机 + 事件溯源处理超时关单与状态收敛。
- **优惠券与购物车**：优惠券用单 Lua 脚本完成库存校验、限领与扣减，配合 msgId + 唯一键双层幂等；购物车以 Redis 为权威，多 key 操作收敛到 Lua，设计 CLEAR 屏障与同毫秒事件序号解决并发写和乱序问题，事件流水异步落库。
- **内容与推送**：笔记发布用本地消息表保证"内容 + 消息"同事务；Feed 采用推拉结合——大 V 走拉模式，普通用户用 Pipeline 批量写收件箱并支持 cursor 断点续推，控制存储上限。
- **搜索与推荐**：CDC→MQ 增量 + 定时全量重建的"双通道"同步 ES，用外部版本号（ExternalGte）拒绝陈旧写、tombstone 防旧消息复活；推荐侧完成行为上报 → 特征/热池/ItemCF 的离线任务链路。
- **IM 与通知**：WebSocket 用一致性哈希（150 虚拟节点）把会话固定到实例，跨实例消息走 Redis pub/sub 投递，未送达转离线消息上线补发；通知按自然日窗口聚合（Redis SETNX+Lua 防重复聚合，最短 60s），SSE 支持跨实例投递；两者都用 ticket 两步握手解决长连接鉴权。
- **网关与公共组件**：参与网关 8 个过滤器的顺序设计（BodyCache → 日志 → 鉴权 → 染色 → HMAC（默认关闭、按需启用）→ 限流 → 灰度 → 版本）；沉淀限流/分布式锁/幂等切面、MQ traceId 透传、统一异常与降级。
- **状态与补偿**：以"条件 UPDATE"表达合法状态迁移（取消仅待付、支付仅待付、发货仅已付、确认仅已发、退款仅已付/完成且幂等），事件溯源 `INSERT IGNORE` + 唯一键防重、重复事件改为乐观锁收敛目标状态；补偿按动作分派（释放库存/退券/关单）不依赖订单状态，超限写 pending 集合每分钟重放。
- **缓存体系**：Cache-Aside + 带锁防击穿（tryLock 3/10s 双检）+ 延迟双删 500ms + 空值占位 2min + TTL 随机偏移防雪崩 + 布隆过滤器（100 万/1%）双层防穿透 + L2 逻辑过期（30min 逻辑/120min 物理，异步单飞刷新）；二次删失败经 MQ 广播兜底，库存缓存走 Canal 版本号防乱序。
- **网关与流量治理**：8 过滤器顺序链（BodyCache 1MB/413 → 日志 → 鉴权 fail-closed → 染色 6 头 → HMAC ±5min/nonce → 限流 → 灰度 10% → 版本）；分路由限流阈值（读 300~500、写 5~50）；压测标记仅内网客户端可带；X-User-Id 覆盖注入防伪造；XFF 追加真实 IP 防绕过反作弊。
- **稳定性与容量**：搭建 117 项 L1~L4 测试矩阵与混沌注入（网络延迟/CPU/磁盘 + Docker pause/SIGTERM + 应用级 DELAY/EXCEPTION/RETURN_NULL 热更新，切点覆盖 service/controller/mapper/listener；ChaosBlade 不可得时 iptables 兜底），完成 20 并发预扣、TCC 11 场景、事务回查延迟等一致性验证；wrk 压测后校准网关限流；实现 traceId 贯通服务/MQ/长连接，修复 DLQ 积压指标并补消费者韧性策略。
- **可观测与告警**：自定义业务指标（订单/支付/库存/Feed/DLQ 等 Counter+Timer，P50/P90/P99 分位）；**28 条 Prometheus 告警分级 P0/P1/P2**（服务/支付/MySQL 为 P0）与 10 个 Grafana 看板；指标预注册空标签防"系列被吞"，URI 归一化（≥10 位 ID→{id}）防时间序列爆炸；SkyWalking 采样 10%、ELK 日志 ILM 30 天滚动删除。

## 关键结果（Key Achievements）
- **交易链路整体跑通**：下单 → 库存预扣 → 支付 → 退款 → 库存回补端到端验证通过；按 user_id 分片隔离用户维度数据；固定 4×4 暂无 rehash，扩容走双写迁移（已知短板，主动说明）。
- **库存一致性**：20 并发预扣不超卖；TCC 11 个场景（幂等/空回滚/悬挂/超量）全部通过；给事务回查注入 75 秒延迟后库存只扣一次，无重复。

- **内容与 Feed**：笔记发布保持原子；Feed 批量写收件箱把 500 粉丝的推送压缩到一次往返，大 V 拉模式避免写扩散，支持断点续推。
- **搜索与推荐**：Canal 同步带版本控制，乱序消息不会覆盖新数据；推荐链路产出 feed/similar 结果（相似度 0.913）。
- **IM 与通知**：双实例下跨实例消息路由、离线补发、SSE 跨实例投递全部验证通过，两端 traceId 一致。
- **网关与容量**：按压测结果把 content/product 限流调到 500、home/recommend 调到 300，超限精确拒绝；6 秒慢下游注入下首页仍返回 200、约 2 秒降级。
- **性能基线**：product 1020、note 1096、home 764、recommend 761、search 683 RPS。
- **可观测与稳定**：traceId 覆盖服务、MQ、长连接三跳；DLQ 积压按 26 个消费组可见（原清单漏纳 8 个消费组并修复"指标恒为 0"缺陷）；20 个 @XxlJob 兜底任务、18 个业务 topic（+RETRY 预留）可查；**28 条告警规则 + 10 个 Grafana 看板**上线，覆盖服务可用性/支付成功率/缓存/ES/Canal 延迟等。
- **搜索性能攻坚**：定位 ES 配额瓶颈并扩容 0.5→2 核后，search 吞吐 **175→683 RPS（3.9x）**、**P50 115→29ms**，成为容量基线里提升最大的一项。

- **容灾演练**：混沌演练 7 场景（网络延迟/CPU 满载/磁盘写满 + Redis/MQ/MySQL pause + SIGTERM 优雅停机）全部通过；Chaos 慢下游 11s 注入触发网关 504、listener 75s 注入验证事务回查恰好一次。

# 项目二 · 小红书 AI 运维诊断与知识问答 Agent（从 0 到 1）

## 项目介绍
xhs-ai 是面向上述 15 微服务交易系统的 AIOps 诊断与知识问答 Agent，从 0 到 1 完成设计、实现与生产化收口。以自然语言为入口，自动编排 DLQ/日志/指标/知识/代码等 16 个全自研工具，输出可回链的定位结论；对死信重投等危险变更实施 HITL 审批与可校验审计；配套三层评测体系与按用户 token 预算治理。技术栈 AgentScope 2.0 Java（Harness/HITL/状态存储）、Spring Boot 3.2.5、JDK 17，接入 RocketMQ Admin / Elasticsearch / Prometheus / MySQL / Redis，单机 systemd 托管并接入 ELK 与 Prometheus 告警。

## 职责描述（Responsibilities）
- **工具与 Agent 编排**：设计 16 个全自研工具（业务级扁平参数：日志检索/Top 服务、指标 Top/趋势/ PromQL 兜底、标签探索、消费积压、ES 索引/DSL 兜底、代码定位、知识卡目录/检索/读取、DLQ 诊断/重投），统一错误返回与只读标记；实测并修复"工具注册成功但从不执行"（框架权限默认 ASK 挂起）类隐蔽缺陷，沉淀工具级 E2E 探针门禁。
- **HITL 与变更闭环**：设计"诊断→提案→审批→执行→核验→审计"状态机（超时 fail-closed、跨实例决策事件通知（pub/sub 已落地；业务续跑订阅未接线）、消息队列级消费位点核验），修复重投核验中 ID 语义（uniqId vs 物理 offsetMsgId）与位点聚合两类假阳性；实现审批执行崩溃自动补执行与 executing 卡死回收。
- **评测体系**：建立检索级（hit@1）、答案级（关键词 + 引用存在性硬校验）、Agent 级（工具选择 + 轨迹部分分 + N 次稳定性）三层评测；沉淀门禁脚本（单测 + 审计一致性 + 审计哈希链 + 可选 LLM 评测，本地一键执行）；CI 工作流当前仅跑单测。
- **成本与性能**：模型网关（重试/熔断/降级/指标）+ 按用户 token 预算三段治理（真实 usage 计量 → 软限切轻量模型 → 硬限 429）+ 工具 schema token 预算指标；并发护栏（单用户 2 / 全局 8）与请求幂等（X-Request-Id）。
- **可靠性工程**：MCP 子进程进程级自愈（探测 + 三连击判定 + 限流 + systemd 拉起；默认仅告警、需显式开启，去 MCP 化后不参与 Agent 路径）；框架不支持工具级热替换时做架构决策**去 MCP 化**（工具全自研，kill 两个 MCP 进程仍可完成 ES/Prom 诊断）；Redis 状态丢失时从消息表 + 滚动摘要重建上下文。
- **安全与权限**：审计参数脱敏与密钥形态打码、出网目标收敛（仅 LLM 网关）、提示注入防御（工具白名单 + 参数强校验；数据块隔离列 Roadmap）；RBAC 消费平台 JWT 角色，管理端点收敛 ADMIN；审计哈希链防篡改 + audit-check SQL 抽查；红队 8 项回归。
- **可观测与运营**：traceId 贯穿 HTTP/工具调用/审计；Prometheus 指标（模型调用/token/工具失败率/运行时长/预算拒绝/MCP 健康）与 7 条告警；数据保留清理；ADMIN 运维端点（位点诊断/会话摘要/知识重索引）。
- **检索选型（不建默认 RAG）**：以结构化知识卡 + BM25/元数据为基线，向量方案按"触发+止损"规则不启动（触发：hit@1<90% 且失败以词汇不匹配为主；止损：无 ≥5% 提升即删除向量路径）；知识注入 ≤8K token、多跳 ≤3 次为设计/提示词约束；引用有效性 100% 为评测器硬门禁。
- **容量与降级设计**：资源估算单机约 10 个并发诊断会话（第一瓶颈为 LLM 配额；压测覆盖对话通道）；降级链为"重试→备用 provider→轻量模型→显式报错"（只读检索模式为设计项）；FMEA 设计覆盖 18 种失败模式（Redis 全丢重建已实现；Bulkhead 隔离为设计项）。
- **提示词与工具约束**：系统提示 13 条硬约束（同一工具最多 1 次、参数报错禁止重调、总工具调用 ≤4、系统本体问题必须走知识检索、锚点事实两种关键词各查一次 + 至少读 1 张卡、引用只允许卡片 id）；全部工具参数 clamp 与服务名/索引/PromQL 白名单校验，防止模型越权与资源滥用。
- **模型网关降级链**：仅对传输类错误重试（连接超时/连接重置/流中断），**已出流不降级重放**（PartialStreamException 直接报错）；熔断冷却后半开放行探测（成功清零失败计数）；备用模型 1~2 次尝试后仍失败显式抛错（不返回空答复）。
- **工程治理**：Flyway 迁移（审计链、摘要表）、Maven Enforcer 依赖收敛、61 项单测与门禁脚本；沉淀 20+ 评审报告与 FMEA 演练（停 ES / Redis failover / 滚动重启 / kill MCP）；**17 个自定义指标**覆盖工具失败率/运行时长/预算决策/MCP 健康/保留清理量。

- **可观测与门禁**：7 条告警覆盖可用性/熔断/预算拒绝/MCP 健康/P95/schema 预算；门禁一键通过（61 单测 + 审计一致性 + 哈希链校验），CI 工作流当前仅跑单测。

# 项目三 · 跨语言 Harness Engineering 技能包（开源）

## 项目介绍
huazai-harness-skills 是一套开箱即用的 Harness Engineering 跨语言开发流水线技能包，方法论为"人类设计约束、AI 写代码、机器验证"。覆盖 Java / Python / Go / Rust / PHP / Frontend 6 种语言、107 个框架与 10 个构建工具（框架参数表 111 个块）；沉淀 54 个 SKILL.md（41 个核心技能 + 13 个语言包/入口），以"单一事实源 + 占位符参数化"生成各语言流水线；`npx skills add` 一键安装，适配 19 种 AI 编程工具。开源地址 github.com/LoveEleve/harness-skills，版本 1.4.0，CI 工作流（3 步校验）。

## 职责描述（Responsibilities）
- **流水线架构**：设计"六阶段门禁流水线"（需求拷问 → TDD 编码 → 单测 → 双轴评审 → CI → 部署验证）与变更状态机，每阶段给出机器可判定的出口门禁（0 个严重问题、核心覆盖率 ≥80%、CI 7 项全绿、回滚预案）。
- **评审体系**：10 维度 + Spec/Standards 双轴并行评审（两轴不合并，防止互相掩盖）；12 条领域技能自动混合加载规则（按代码特征注入补充细则）；新增 Agent/MCP 集成检查 A1-A5（权限模式/端到端探针/子进程自愈/空答复语义/工具参数面向 LLM）。
- **知识沉淀**：14 个组件封装 Toolkit（缓存/Kafka/RocketMQ/K8s/安全/日志/调度等）共 60+ 条检查清单；从真实生产事故反哺 **RocketMQ DLQ 治理门禁 10 条**（零积压自动发现/动作契约/Schema 契约/失败分类/双 ID 核验/重放即探针等）。
- **工程化与分发**：`validate-skills.mjs`（5 类结构校验）+ `sync-version.mjs`（四处版本一致性）+ `list-skills.sh` 组成质量闸，`npm run check` 一键执行并接入 GitHub Actions；`install-skill` 适配 19 种 AI 工具（7 种原生 SKILL.md），自动检测/建目录/格式转换三级策略。
- **实战验证与反哺**：在真实 AIOps 项目（15 微服务）上执行 **8 轮评审**（RV06/10/11/12/18/19/21/22），发现并闭环 3 个严重问题、2 个 P0；把评审中的通用缺陷模式固化为门禁（A1-A5、DLQ #9/#10），形成"实战 → 门禁 → 复用"闭环。
- **内容运营**：输出 60 篇技术文章（57 篇编号专栏）+ 案例复盘，沉淀可复用知识资产。

## 关键结果（Key Achievements）
- **覆盖规模**：6 语言 / 107 框架 + 10 构建工具，参数表 111 个框架块对 29 个模板占位符**零缺失**（校验器实测：占位符使用 41 / 定义 53）。
- **单一事实源改造**：54 个 SKILL.md（41 核心 + 13 语言包/入口），消除 6 语言 × 流水线技能的 **60 份重复文件**（1.4.0 版本核心变更）。
- **门禁落地**：六阶段出口全部机器可判定（0 个 🔴 / 覆盖率 ≥80% / CI 7 项 / 回滚预案），GitHub Actions 配置 3 步校验（validate / 版本一致性 / 技能清单），本地 `npm run check` 覆盖结构 + 占位符 + 版本一致性。
- **质量资产**：10 维度 33 检查项 + 双轴评审 + 12 条自动加载 + 14 个 toolkit 60+ 检查项 + DLQ 门禁 10 条 + Agent/MCP 检查 A1-A5。
- **实战反哺**：真实项目 8 轮评审闭环 3 个严重问题与 2 个 P0；被评审项目单测 12→22 全绿（另有 D01 模型网关 18 项单测）、知识检索 hit@1=100%、MTTR 降幅 92.1%、红队 8 项全拦截。
- **分发兼容**：适配 19 种 AI 编程工具，`npx skills@latest add` 可一键安装；5 个版本迭代（1.0 四语言九技能 → 1.4 工程化加固）。
- **内容资产**：60 篇技术文章 + 1 篇案例复盘；仓库自带 PRD 智能解析平台参考实现，验证方法论可在真实工程落地。
