# 项目一 · 小红书电商交易平台

## 项目介绍
xhs 是一个内容与交易并重的社交电商平台，共 15 个 Spring Cloud 微服务：交易侧包含商品、购物车、库存、优惠券、订单、通知，内容侧包含用户、笔记、Feed、搜索、推荐。基础设施使用 RocketMQ、Redis Sentinel、Elasticsearch、ShardingSphere（订单 4 库 × 4 表）、Canal、XXL-Job，监控由 ELK、Prometheus/Grafana、SkyWalking 组成，整体 Docker 化部署。
我在项目中负责交易与内容核心模块的设计开发，并主导稳定性优化：实现库存三级扣减、订单分片与事务消息、优惠券/购物车的一致性方案、Feed 推拉结合、IM 跨实例路由等；在此基础上把测试、故障注入、容量校准和链路追踪补齐。

## 职责描述（Responsibilities）
- **库存**：设计 Redis 分桶 + Lua 原子预扣 + DB 账本 + TCC 三段式的组合方案，处理热点 key、超时回收（ZSet 过期索引替代全库 SCAN）和幂等（预扣幂等表、Outbox 唯一键）；配套超时回补、补偿与对账任务。
- **订单**：基于 ShardingSphere 做 4 库 × 4 表分片（非分片键反查走订单号映射表，Snowflake workerId 按实例动态计算）；用事务消息 + 本地消息表 + Broker 回查保证下单与库存预扣的最终一致，延迟消息 + 状态机 + 事件溯源处理超时关单与状态收敛。
- **优惠券与购物车**：优惠券用单 Lua 脚本完成库存校验、限领与扣减，配合 msgId + 唯一键双层幂等；购物车以 Redis 为权威，多 key 操作收敛到 Lua，设计 CLEAR 屏障与同毫秒事件序号解决并发写和乱序问题，事件流水异步落库。
- **内容与推送**：笔记发布用本地消息表保证"内容 + 消息"同事务；Feed 采用推拉结合——大 V 走拉模式，普通用户用 Pipeline 批量写收件箱并支持 cursor 断点续推，控制存储上限。
- **搜索与推荐**：Canal + MQ 双通道同步 ES，用外部版本号（ExternalGte）拒绝陈旧写、tombstone 防旧消息复活；推荐侧完成行为上报 → 特征/热池/ItemCF 的离线任务链路。
- **IM 与通知**：WebSocket 用一致性哈希（150 虚拟节点）把会话固定到实例，跨实例消息走 Redis pub/sub 投递，未送达转离线消息上线补发；通知按 5 分钟窗口聚合，SSE 支持跨实例补投；两者都用 ticket 两步握手解决长连接鉴权。
- **网关与公共组件**：参与网关 8 个过滤器的顺序设计（BodyCache → 日志 → 鉴权 → 染色 → HMAC → 限流 → 灰度 → 版本）；沉淀限流/分布式锁/幂等切面、MQ traceId 透传、统一异常与降级。
- **稳定性与容量**：搭建 117 项 L1~L4 测试矩阵与混沌注入（AOP 故障注入 + iptables 断连，切点覆盖 mapper/listener），完成 20 并发预扣、TCC 11 场景、事务回查延迟等一致性验证；wrk 压测后校准网关限流；实现 traceId 贯通服务/MQ/长连接，修复 DLQ 积压指标并补消费者韧性策略。

## 关键结果（Key Achievements）
- **交易链路整体跑通**：下单 → 库存预扣 → 支付 → 退款 → 库存回补端到端验证通过；订单分片支持按用户维度水平扩容。
- **库存一致性**：20 并发预扣不超卖；TCC 11 个场景（幂等/空回滚/悬挂/超量）全部通过；给事务回查注入 75 秒延迟后库存只扣一次，无重复。
- **幂等与对账**：回放同一条物理消息，计数与优惠券均不重复；关注链路故障 500 fail-closed 无幽灵关系；Redis 与 MySQL 对账任务可收敛差异。
- **优惠券/购物车**：10 并发领券严格限领 2 张；购物车并发加购无丢失，清空与并发写不串，事件流水完整可回溯。
- **内容与 Feed**：笔记发布保持原子；Feed 批量写收件箱把 500 粉丝的推送压缩到一次往返，大 V 拉模式避免写扩散，支持断点续推。
- **搜索与推荐**：Canal 同步带版本控制，乱序消息不会覆盖新数据；推荐链路产出 feed/similar 结果（相似度 0.913）。
- **IM 与通知**：双实例下跨实例消息路由、离线补发、SSE 跨实例投递全部验证通过，两端 traceId 一致。
- **网关与容量**：按压测结果把 content/product 限流调到 500、home/recommend 调到 300，超限精确拒绝；6 秒慢下游注入下首页仍返回 200、约 2 秒降级。
- **性能基线**：product 1020、note 1096、home 764、recommend 761、search 683 RPS。
- **可观测与稳定**：traceId 覆盖服务、MQ、长连接三跳；DLQ 积压按 26 个消费组可见（修复 8 组监控盲区与"指标恒为 0"缺陷）；19 个 XXL-Job、18 个 topic 的兜底链路可查。

# 项目二 · 小红书 AI 运维诊断与知识问答 Agent（从 0 到 1）

## 项目介绍
xhs-ai 是面向上述 15 微服务交易系统的 AIOps 诊断与知识问答 Agent，从 0 到 1 完成设计、实现与生产化收口。以自然语言为入口，自动编排 DLQ/日志/指标/知识/代码四域 16 个自研工具，输出可回链的定位结论；对死信重投等危险变更实施 HITL 审批与可校验审计；配套三层评测体系与按用户 token 预算治理。技术栈 AgentScope 2.0 Java（Harness/HITL/状态存储）、Spring Boot 3.2.5、JDK 17，接入 RocketMQ Admin / Elasticsearch / Prometheus / MySQL / Redis，单机 systemd 托管并接入 ELK 与 Prometheus 告警。

## 职责描述（Responsibilities）
- **工具与 Agent 编排**：设计四域 16 个全自研工具（业务级扁平参数：日志检索/Top 服务、指标 Top/趋势/ PromQL 兜底、标签探索、消费积压、ES 索引/DSL 兜底、代码定位、知识卡目录/检索/读取、DLQ 诊断/重投），统一错误返回与只读标记；实测并修复"工具注册成功但从不执行"（框架权限默认 ASK 挂起）类隐蔽缺陷，沉淀工具级 E2E 探针门禁。
- **HITL 与变更闭环**：设计"诊断→提案→审批→执行→核验→审计"状态机（超时 fail-closed、跨实例决策广播、消息队列级消费位点核验），修复重投核验中 ID 语义（uniqId vs 物理 offsetMsgId）与位点聚合两类假阳性；实现审批执行崩溃自动补执行与 executing 卡死回收。
- **评测体系**：建立检索级（hit@1）、答案级（关键词 + 引用存在性硬校验）、Agent 级（工具选择 + 轨迹部分分 + N 次稳定性）三层评测；沉淀门禁脚本（单测 + 审计一致性 + 审计哈希链 + 可选 LLM 评测）并接入 CI。
- **成本与性能**：模型网关（重试/熔断/降级/指标）+ 按用户 token 预算三段治理（真实 usage 计量 → 软限切轻量模型 → 硬限 429）+ 工具 schema token 预算指标；并发护栏（单用户 2 / 全局 8）与请求幂等（X-Request-Id）。
- **可靠性工程**：MCP 子进程进程级自愈（探测 + 三连击判定 + 限流 + systemd 拉起）；框架不支持工具级热替换时做架构决策**去 MCP 化**（工具全自研，kill 两个 MCP 进程仍可完成 ES/Prom 诊断）；Redis 状态丢失时从消息表 + 滚动摘要重建上下文。
- **安全与权限**：三级内容捕获与脱敏、出网白名单、提示注入纵深防御（数据块隔离/工具白名单/参数强校验）；RBAC 消费平台 JWT 角色，管理端点收敛 ADMIN；审计哈希链防篡改 + 敏感信息扫描；红队 8 项回归。
- **可观测与运营**：traceId 贯穿 HTTP/MQ/工具调用；Prometheus 指标（模型调用/token/工具失败率/运行时长/预算拒绝/MCP 健康）与 7 条告警；数据保留清理；ADMIN 运维端点（位点诊断/会话摘要/知识重索引）。
- **工程治理**：Flyway 迁移（审计链、摘要表）、Maven Enforcer 依赖收敛、61 项单测与门禁脚本；沉淀 20+ 评审报告与 FMEA 演练（停 ES / Redis failover / 滚动重启 / kill MCP）。

## 关键结果（Key Achievements）
- **故障定位效率**：10 个真实故障案例 10/10 证据完整，Agent 均值 1.63 分钟；人工口径保守重构 20.6 分钟 → **降幅 92.1%**。
- **知识问答质量**：55 张知识卡 BM25 检索 30 条 **hit@1=100%**；答案级 **50/50 全过、引用有效性 100%**（幻觉引用被硬校验拦截）。
- **Agent 评测**：工具选择 **12/12**；轨迹评测支持部分分，4 例 × 3 次稳定性 **0.917**；工具参数优化后同题 P95 排查由 98s 答偏 → **50s 答对**。
- **变更闭环**：审批重投全链路实测（pending→approved→重投→核验），毒丸消息二次入死信被准确判定 `reentered_dlq`，无误报成功；审计 SQL 验证"未审批高危执行 0"。
- **成本治理**：单次诊断 18,292 / 1,433 tokens ≈ **¥0.012–0.048**，较全量上下文直塞输入降幅约 **74%**；预算三态实测（软限自动切轻量、硬限 429、真实计量 5,577 tokens/次）。
- **可靠性**：批准后崩溃 **60s 内自动补执行**；executing 卡死回收为 failed 待人工重试；重复请求 **0s 返回首次结果**、并发同 id 一 200 一 409；删除 Redis 状态后仍能答出历史关键事实（摘要重建）。
- **去 MCP 化**：kill 两个 MCP 子进程后，ES 索引问题 **19s**、PromQL 问题 **39s** 正常作答；Agent 侧 16 个工具全自研，20 个 MCP 工具保留运维直连。
- **安全验证**：红队 **8 项全拦截**（未授权/注入/密钥诱导/越权审批/危险工具/洪水/方法混淆/直调）；审计链篡改可检出（篡改演练校验失败）；RBAC 实测 OPERATOR→403 / ADMIN→200。
- **可观测与门禁**：7 条告警覆盖可用性/熔断/预算拒绝/MCP 健康/P95/schema 预算；门禁一键通过（61 单测 + 审计一致性 + 哈希链校验）并接入 CI 工作流。
- **工程沉淀**：55 知识卡、16 工具、27 篇评审（RV01~RV29）与 14 篇专项设计、10+ 演练/评测报告；systemd 托管单机内测运行，接入真实中间件与监控。
