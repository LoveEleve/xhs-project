# 项目一 · 内容电商平台（15 微服务 / 27 容器）　【起止时间】｜【项目角色】

## 项目介绍
内容与交易一体的电商平台：交易侧覆盖商品、购物车、库存、优惠券、订单、支付、通知，内容侧覆盖用户、笔记、Feed、搜索、推荐，另含 IM、计数、网关与认证共 15 个 Spring Cloud 微服务。基础设施为 MySQL 分库分表（订单 4 库 × 4 表）+ Redis Sentinel + RocketMQ + Elasticsearch + ShardingSphere + Canal + XXL-Job，ELK / Prometheus + Grafana / SkyWalking 全链路可观测，Docker 编排 27 容器；配套故障注入、混沌演练与容量压测环境。

负责交易与内容核心模块的设计开发，并主导稳定性优化：商品域与库存域联动（建 SKU 自动初始化库存、上架校验至少一个上架 SKU、延迟双删改专用调度器不占请求线程）、落地库存三级扣减、订单分片与事务消息、优惠券/购物车一致性方案、Feed 推拉结合、IM 跨实例路由、网关安全链（JWT+黑名单 fail-closed 503 语义、可信 IP 单一来源、鉴权/HMAC 失败分原因指标与告警）、Zone 多活与全链路可观测建设。

## 职责描述（Responsibilities）
- 库存一致性：Redis 分桶 + Lua 原子预扣 + DB 账本 + Outbox 兜底的三级扣减；热点 SKU 由滑动窗口（10s/100 次）自动扩容 2→8 桶；超时回收以 ZSet 过期索引替代全库扫描（O(N)→O(logN)）；幂等占位表（INSERT IGNORE 走主库）杜绝重复扣减；实现 TCC 冻结协议（Try/Confirm/Cancel + fence 状态机），覆盖空回滚、悬挂、超量拒绝（接口与 11 场景验证已完成，订单链路当前走事务消息预扣）。
- 订单与分布式事务：RocketMQ 事务消息 + 本地消息表 + Broker 回查，保证下单与库存预扣一致；订单状态全部条件 UPDATE 流转，事件表以序号唯一键 + 乐观锁收敛并发；4 库 × 4 表分片 + 订单号映射表支持非分片键反查，支付表与映射表走独立数据源绕过分片路由，为支付域独立拆分预留；提供订单状态重建与校准能力——按事件流回放重建状态、dry-run 报告偏差，并按条件更新修复（含里程碑时间补齐），用于状态与事件出现偏差后的数据修复。
- 支付与退款：支付单/退款单双状态机 + 渠道策略化发起与回调（策略 SPI：Mock 渠道 + 回调模拟器驱动全链路；真实渠道验签/查询/关单为接入项）；回调结果三态判定（成功/失败/无法判定，渠道中间态不误判为失败，未知态回 "fail" 让渠道重试）；重复回调不改状态（状态守卫幂等）；退款以"累计退款 = 支付金额"语义驱动库存回补与退券；支持零元单（全额券抵扣）直接记账成功（渠道不可调，避免"发不起支付只能等关单"）；支付 30min / 退款 15 天超时检测 + 通知补偿（5 分钟窗口、最多 10 次、批量 100）+ 每日对账。
- 售后与优惠分摊：售后域支持仅退款 / 退货退款，状态机（待审核 → 已同意/已拒绝 → 退款中 → 已完成，含撤销与退款失败重试）全部条件更新；同一订单 + SKU + 类型唯一，配套累计退款额度校验防超退；审核前复核订单状态（已退款/已取消自动驳回）、审核通过走支付域"按订单退款"接口（上游不感知支付域主键），并按 SKU 调库存回补（复用库存域 orderId+skuId 累计正增量幂等链路，失败落补偿表由补偿任务按类型自动重试；若库存域整体不可用导致请求未到达，由售后单 restock_status + 恢复任务兜底重试，覆盖跨服务调用失败的补偿盲区）。应退金额按订单优惠分摊计算：以"分"为单位按明细金额比例做最大余数法分摊（平局按明细 ID 确定性），退款 = 明细金额 − 分摊优惠，部分数量按比例向下取整保证永不超退、本次退满时补齐差额使多次退款累计严格闭合；审核时按最新占用复核额度（并发双类型申请自动驳回）；分摊为纯函数、按订单快照重算，不落库、不漂移。分布式一致性护栏：同 SKU 跨售后类型的累计应退上限（防同一商品被退两次）、订单实付上限、支付域可退金额上限三层校验；库存回补改为按 (orderId, skuId) 累计应回补数量只放行正增量——重复调用与重试 delta=0 幂等、分次退货不漏补、与全额退款链路叠加不重复补，失败回滚累计值允许重试。异常恢复：恢复任务对"退款中卡死"先向支付域核对事实（金额 + 退款类型 + 时间窗 + 退款单号归属）再决策——已成功则补库存并置完成、仍有进行中则等待、无记录才转失败；退款失败按 10 分钟退避自动重试（上限 3 次）；支付域"按订单退款"接口回传退款单号，使每笔成功退款在订单域唯一归属，避免同订单等额退款被误认。
- 优惠券与购物车：领券的库存校验、限领与扣减收敛进单个 Lua 脚本，配 Outbox 事务发件与 msgId / 唯一键双层幂等；购物车 Hash/Set/ZSet 三结构由 7 个 Lua 保证原子，变更以 userId 为分区键顺序发送 + 消费端 ORDERLY 顺序消费，从源头保证同一用户"清空 / 删除 / 加购"的先后关系（实例内自增序号 + 时间戳 CAS + CLEAR 屏障作为跨分区兜底，屏障带 24h 淘汰与上限清空防无界增长）、匿名合并批量预取 SKU（替代逐条 Feign）、创建路径 Key 在 Lua 内原子设滑动 TTL，Redis 丢失可从 MySQL 完整恢复并回写（退券语义：只恢复用户券状态，不回补库存、不减限领计数）。

# 项目二 · AI 运维诊断与知识问答 Agent　【起止时间】｜【项目角色】

## 项目介绍
面向上述 15 微服务系统的 AIOps 诊断与知识问答 Agent，从零设计并实现：以自然语言为入口，自动编排 DLQ / 日志 / 指标 / 知识 / 代码 / 业务六类共 20 个自研工具，输出可回链的定位结论；死信重投等危险变更实施 HITL 审批与可校验审计；配套检索 / 答案 / Agent 三层评测与按用户 Token 预算治理。技术栈 AgentScope 2.0 Java、Spring Boot 3.2.5、JDK 17，接入 RocketMQ Admin / Elasticsearch / Prometheus / MySQL / Redis，systemd 托管并接入 ELK 与 Prometheus 告警。

## 职责描述（Responsibilities）
- 需求与架构：主导需求工程（34 个业务场景，REQ → AC → TC 全链路追溯，含 NFR 与 STRIDE 威胁模型）；确定分层架构与 23 条 ADR（框架选型、Redis 状态存储、BM25 先行 + 向量止损、模型网关自研、扩展框架两代演进等）；划清框架边界（Flyway 只管 ai_* 表，不碰框架表）。
- 工具与编排：设计 20 个自研工具（运维 16 + 业务 4），业务查询跨订单 / 支付 / 退款 / 库存 / 通知并按订单服务同哈希路由分片；ES DSL 与 PromQL 全部服务端拼装、模型只填业务参数，参数 clamp + 服务名 / 索引 / PromQL 白名单校验；ReAct 循环（maxIters=12、温度 0.2）+ 13 条提示词硬约束（同一工具最多 1 次、总调用 ≤4、系统问题必须走知识检索）。
- 知识层：沉淀 55 张结构化知识卡（架构 11 / 业务 7 / 代码导航 36 / 失败模式 1）+ ES BM25 检索 + 卡片目录 / 检索 / 整卡读取工具 + 代码定位工具（文件行号）；以 BM25 为基线（不默认上向量检索），并写明向量方案的触发条件与止损规则。
- HITL 审批闭环：诊断 → 提案 → 审批 → 执行 → 核验 → 审计状态机；审批超时 fail-closed、同会话同指纹复用、执行前原文复核；崩溃自动补执行、卡死超时回收；重投后按队列消费位点核验是否真被消费，可区分"重回死信 / 已消费 / 无位点证据"。
- 评测体系：检索（30 条 hit@1）/ 答案（50 条关键词 + 引用存在性硬校验）/ Agent（工具选择 12 题、轨迹部分分、4 例 × 3 次稳定性）三层，另设 8 项红队与 4 个性能场景；门禁为通过率 ≥90% 且引用必须全部有效；评测与单测、审计一致性、哈希链校验组成一键门禁脚本。
- 模型网关与成本：仅对传输类错误重试（已出流不降级重放）+ 熔断半开探测 + 备用 / 轻量模型降级链；Token 预算三段（真实计量 → 软限 80% 切轻量 → 硬限 429）+ 工具 schema 预算 + 并发护栏 + 请求幂等（X-Request-Id，重复提交回放、处理中 409）。
- 可靠性与安全：会话状态存 Redis（进程重启可续聊），状态丢失时从消息表 + 滚动摘要重建（保留最近 20 条、超 50 条触发压缩）；消息 90 天 / 审计 365 天保留策略；RBAC（ADMIN / OPERATOR / VIEWER）+ 审计只追加 + SHA-256 前向哈希链防篡改 + 参数脱敏；红队 8 项回归。
- 接口与可观测：对外提供 7 组 REST 接口与三级鉴权（内部令牌 / 平台 JWT / 管理令牌），未授权一律 401；17 个自定义指标（工具调用与失败率、Token、熔断、预算决策、审批事件、MCP 健康等）+ 7 条 Prometheus 告警；traceId 贯穿 HTTP、工具调用与审计。
- 工程决策与依赖治理：框架权限引擎实测默认策略会把无只读注解工具卡死，改为 BYPASS + 应用层工具白名单 / HITL / 审计补偿；因框架不支持工具热替换完成去 MCP 化（20 个工具全部自研）；Enforcer 三规则（Java 17 / 重复类 / 依赖收敛）+ 4 项版本冲突处置（含豁免退出条件）。
