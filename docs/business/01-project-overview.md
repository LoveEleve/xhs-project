# my-xhs 项目总览

> 对标生产环境的小红书，社交+电商微服务系统，可上线运行

---

## 一、项目定位

- **类型**：社交+电商微服务（小红书模式：内容驱动消费）
- **纯后端**：不含前端；支付用模拟实现（不依赖支付宝/微信SDK），链路完整跑通
- **目标**：生产级可上线系统，每个架构决策都有真实场景支撑
- **原则**：不依赖云厂商服务，全部基础设施 Docker 一键拉起

### 核心业务链路

```
用户注册/登录 → 浏览笔记(Feed流) → 社交互动(赞/评/关/藏) → 
浏览商品(搜索/详情) → 加购 → 下单 → 履约
```

### 系统量级目标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| DAU | 100万 | 中大型社交平台 |
| 笔记发布量 | 10万/天 | 内容生产速度 |
| 商品SKU | 100万 | 电商侧规模 |
| 日订单量 | 5万 | 转化率约5% |
| QPS峰值 | 1万 | 秒杀/热门事件场景 |
| 可用性 | 99.95% | 年宕机不超过4.38小时 |
| 数据留存 | 热数据3个月，温数据1年，冷数据3年 | 数据生命周期管理 |

| API文档 | SpringDoc | 2.x | OpenAPI 3.0规范，Springfox已停更 |

### 中间件

| 类别 | 技术选型 | 用途 | 生产场景 |
|------|---------|------|----------|
| 注册/配置中心 | Nacos | 服务注册发现+配置动态刷新 | 服务上下线不停网关，配置热更新 |
| 网关 | Spring Cloud Gateway | 统一入口+鉴权+限流+灰度 | 所有外部请求必经网关，统一安全边界 |
| 限流熔断 | Sentinel | 接口限流+熔断降级+热点参数限流 | 秒杀场景QPS突增，限流保护后端 |
| 消息队列 | RocketMQ | 异步解耦+事务消息+延时消息+顺序消息 | 下单事务消息保证最终一致，评论顺序消息保证有序 |
| 缓存 | Redis (Sentinel) | 缓存+分布式锁+限流+计数+排行榜 | 商品详情页QPS 5000+走缓存，DB只扛500 |
| 搜索 | Elasticsearch 8.x | 商品/笔记/订单全文搜索+搜索建议 | MySQL LIKE查10万商品3秒，ES毫秒级 |
| 数据同步 | Canal | MySQL binlog监听→MQ→ES/缓存 | MySQL→ES实时同步，全量重建每周兜底 |
| 分布式调度 | XXL-Job 3.0 | 定时任务+分片执行+失败重试+执行日志 | 100万人发券分100片并行推，失败自动重试 |
| 链路追踪 | SkyWalking | 全链路追踪+自定义Span | 线上跨15个服务排查问题，没有TraceId根本串不起来 |
| 监控 | Prometheus + Grafana | 指标采集+可视化+告警 | 错误率>1%告警，P95>3s告警，MQ堆积告警 |
| 日志 | Logback + ELK思路 | JSON格式+TraceId+Filebeat采集 | 线上日志必须结构化+可检索，排查问题靠它 |

### 存储

| 类别 | 技术选型 | 用途 | 生产场景 |
|------|---------|------|----------|
| 关系数据库 | MySQL 8.0 (1主1从) | 业务数据存储+读写分离 | 写走主库，读走从库，主库挂了ShardingSphere自动切从库 |

| 文件存储 | 本地磁盘 | 笔记图片存储（不依赖云OSS） | 代码跑起来即可，生产环境可切换为OSS |

### 架构方法论

> 📖 整体方法论来源：
> - DDD：《凤凰架构》第5章 — "限界上下文=微服务边界"
> - 中台：《大型分布式网站架构设计与实践》— 阿里中台方法论
> - 微服务拆分：《微服务：从设计到部署》— Scale Cube三维扩展(X轴复制/Y轴分解/Z轴分区)
> - 架构5要素：《大型网站技术架构》（李智慧）— 性能/可用性/伸缩/扩展/安全

#### DDD（领域驱动设计）视角

| 概念 | my-xhs 落地 | 说明 |
|------|-------------|------|
| **限界上下文** | 每个微服务 = 一个限界上下文 | User/Content/Analytics/Order等，服务边界=领域边界 |
| **聚合根** | 订单(Order)、笔记(Note)、用户(User) | 聚合根拥有完整生命周期，外部通过聚合根访问内部实体 |
| **领域事件** | MQ消息 = 领域事件 | `OrderCreatedEvent`、`NotePublishedEvent`，跨服务通信用事件驱动 |
| **值对象** | Address(地址)、Money(金额) | 无唯一标识，通过属性值相等判断 |
| **防腐层** | Feign Client接口 | 隔离外部服务变化，不让外部模型污染本领域 |

```
┌────────────────────────────────────────────────────────────────┐
│                    my-xhs 限界上下文划分                         │
├────────────┬────────────┬────────────┬────────────┬───────────┤
│   用户域    │   内容域    │  社交分析域  │   交易域    │  营销域    │
│  (User)    │ (Content)  │(Analytics) │  (Order)   │ (Coupon)  │
│            │            │ (Counter)  │(Inventory) │           │
│            │            │   (Feed)   │  (Cart)    │           │
└────────────┴────────────┴────────────┴────────────┴───────────┘
```

#### 中台思想

| 服务 | 中台定位 | 说明 |
|------|----------|------|
| **counter** | 计数中台 | 点赞/收藏/评论数统一由counter服务管理，所有业务复用 |
| **notification** | 消息中台 | 通知能力下沉，业务服务只发事件，notification负责分发 |
| **search** | 搜索中台 | 笔记搜索、商品搜索统一由search服务提供，ES能力复用 |
| **gateway** | 接入中台 | 鉴权、限流、路由、签名验证统一在网关，业务服务不重复实现 |

**中台价值**：
- **能力复用**：计数逻辑写一次，15个服务直接调用
- **统一治理**：限流规则在网关配，不用每个服务单独配
- **独立演进**：搜索需要优化ES配置，只改search服务，不影响业务服务

#### 服务划分依据

| 划分原则 | 示例 | 反例 |
|----------|------|------|
| **业务边界清晰** | 订单和库存分开 | 订单服务直接操作库存表 |
| **数据独立** | 每个服务有自己的数据库 | 多个服务共享一张表 |
| **团队边界** | 2-3人维护一个服务 | 10人维护一个巨石服务 |
| **变化频率** | 营销规则变化快，独立服务 | 与稳定的订单逻辑混在一起 |
| **扩容需求** | 搜索QPS高，独立扩容 | 和低QPS服务绑在一起无法单独扩 |

### 服务间调用关系

```
Gateway → User(鉴权) → Analytics(关注状态) → Content(笔记内容)
       → Product(商品) → Inventory(库存) → Order(下单)
       → Cart(购物车) → Coupon(优惠券)
       → Search(搜索) → Counter(计数) → Notification(通知)```

## 五、与 huazai-ecshop 对比

| 维度 | huazai-ecshop | my-xhs | 改进理由 |
|------|--------------|--------|----------|
| JDK | 17 | 17 | 一致 |
| Spring Boot | 2.6.13（已EOL） | **3.2.x** | 生产环境不能用EOL版本，安全漏洞无人修复 |
| Spring Cloud | 2021.0.5 | **2023.0.x** | 与Boot 3.x配套 |
| 模块数 | 16（含空壳） | **17（每个都有实质代码）** | 不做空壳服务 |
| API文档 | Springfox 3.0（停更） | **SpringDoc 2.x** | Springfox已停更，生产环境需维护 |
| JWT | jjwt 0.7.0（有漏洞） | **jjwt 0.12.x** | CVE漏洞，生产不可用 |
| 搜索 | 耦合在product | **独立搜索服务** | 搜索QPS高，独立扩容 |
| 计数 | 耦合在social | **独立计数服务** | 计数高频写，独立Buffer-Trigger批量写DB |
| 通知 | 无 | **通知中心（MQ+SSE推送+Bitmap）** | 社交平台必须有通知，SSE适合单向推送 |
| 推荐系统 | 无 | **多路召回+粗排+精排（预留ML接口）** | 个性化推荐是社交平台核心，协同过滤+内容+热门+关注+地理5路召回 |
| 热搜榜 | 简单计数 | **滑动窗口实时计算+时间衰减+防刷** | 微博热搜级实现，实时更新+防刷策略 |
| 流量染色 | 简单灰度 | **全链路标记透传（Feign+MQ+异步）** | 灰度/AB测试/压测隔离，染色标记贯穿全链路 |
| 灰度发布 | 无 | **Gateway+Nacos元数据** | 生产上线必须有灰度能力 |
| API版本 | 硬编码 /v1/ | **Gateway Header版本路由** | APP多版本并存，需要版本路由 |
| 签名验证 | 无 | **HMAC-SHA256** | 接口被恶意调用/篡改，签名保证请求未被篡改 |
| 注解式能力 | 0 | **4个（@Idempotent @DistributedLock @RateLimit + JWT）** | 重复代码提取为注解，减少遗漏 |
| MySQL | 单机 | **1主1从+ShardingSphere读写分离** | 单机挂了服务不可用 |
| Redis | 单机 | **Sentinel哨兵模式** | 单机挂了缓存全丢 |
| 分布式调度 | 无 | **XXL-Job 3.0** | 定时任务必须分布式化，否则多实例重复执行 |
| 消息可靠性 | 发出去就行 | **幂等消费+死信队列+本地消息表** | 消息丢失/重复，生产环境必须处理 |
| 测试覆盖 | 0% | **核心链路有测试** | 无测试不敢上线 |
| 部署 | 部分YAML | **Dockerfile+Compose+K8s+Jenkinsfile** | 生产环境需要完整CI/CD |
| 性能测试 | 提到 | **JMeter计划+GoReplay录制脚本** | 上线前必须压测 |
| 文档 | 无 | **架构图+时序图+方案对比+生产场景** | 文档是生产运维的基石 |
| 超时策略 | 拍脑袋(Feign 3秒) | **请求级超时预算(Timeout Budget)** | Google SRE实践，6服务串行不会等18秒 |
| 降级决策 | 人工开关 | **自动降级决策引擎(L0-L3+半开恢复)** | 凌晨故障无人值班也能自动处理 |
| 数据倾斜 | 无 | **倾斜检测+在线扩分片(零停机)** | 分库分表后数据不均匀怎么办 |
| 幂等体验 | 报错"重复请求" | **返回上次成功结果(对标支付宝)** | 网络重试应得到正确结果而非错误 |
| 慢查询治理 | 无 | **自动发现→EXPLAIN→周报闭环** | 慢查询治理全自动化 |
| 数据归档 | 无 | **XXL-Job分批归档+ES ILM Policy** | 数据生命周期全自动化管理 |
| JVM调优 | 无 | **G1科学参数+GC日志分析** | 每个参数都有计算依据 |
| 连接池参数 | 默认值 | **HikariCP/Lettuce/RocketMQ公式计算** | 参数不是抄网上的 |
| API版本管理 | 硬编码 /v1/ | **兼容性矩阵+废弃通知+410 Gone** | 版本生命周期管理 |
| Service Mesh | 无 | **预留Istio演进路径** | 架构演进视野 |
| 事件溯源 | 无 | **订单事件表+快照表互补** | 完整审计轨迹+任意时间点回溯 |

## 六、SLA承诺

| 指标 | 承诺 | 实现手段 |
|------|------|----------|
| 可用性 | 99.95%（月宕机<22分钟） | 多实例+Sentinel熔断+优雅停机 |
| 下单RT | P99 < 500ms | 异步编排+缓存+MQ |
| 搜索RT | P99 < 200ms | ES+缓存 |
| 消息可靠性 | 不丢失、不重复 | 本地消息表+幂等消费+死信队列 |
| 数据一致性 | 最终一致，延迟<1分钟 | Canal+延迟双删+对账修复 |
| 故障恢复 | RTO < 5分钟，RPO < 1分钟 | K8s自动重启+MySQL主从+Redis Sentinel |

## 七、数据生命周期

| 数据类型 | 热数据 | 温数据 | 冷数据 | 归档/删除 |
|----------|--------|--------|--------|-----------|

| 计数 | 实时（Redis） | 1天（MySQL流水） | — | 流水表每天清理 |
