## 二、工程解读

### 质量
- 100 条样本全部通过硬断言/数字一致性检查。
- 幻觉率为 0%，说明证据引用、数字抽取和断言口径在本轮数据上没有发现未匹配业务数字。
- smoke 20 条全量完成；regression 完成率 95%，剩余未完成属于允许通过的 `PARTIAL/BUDGET_STEPS` 复杂归因样本。

### 性能
- 100 条平均耗时约 23.3 秒/条。
- regression 平均耗时低于 smoke，说明回归集平均问题复杂度略低于核心 smoke 集。
- 平均 Token 约 10,324/条；当前只能作为本轮观测值，不能直接等同于月度成本。

### 发散与预算
- 总发散率 35.0%，表示部分 run 出现同工具多窗口/多参数探索。
- 发散不等于失败：本轮所有样本仍通过，说明循环/预算机制能把探索约束在可接受范围内。
- 后续应单独分析高发散样本，决定是优化 prompt/tool description，还是调整复杂归因预算；不建议仅凭一次 nightly 全局提高 `maxSteps`。

## 三、成本换算边界

本轮报告有 Token 统计，但没有把 Token 直接换算成金额，原因是：

- OpenCode Go 的实际计费需要以 workspace 账单为准；
- MiMo V2.5 Pro 的实际价格与当前配置单价可能不同；
- `price-per-1k-tokens` 是应用侧估算参数，不应冒充供应商账单。

因此本轮正式结论只报告 Token、时延和质量，不宣称月度成本或容量上限。

## 四、剩余 bad case 状态

- **没有未通过样本**：regression 80 条已重新跑到 80/80 通过。
- **复杂归因观察点**：少量样本以 `PARTIAL/BUDGET_STEPS` 结束，但满足用例允许状态；它们是模型收敛效率问题，不是质量断言失败。
- **评测器误报**：本轮未发现新的数字一致性误报；此前已修复窗口/排名/序号、零证据拒答、秒/毫秒换算等边界。

## 五、结论

`mimo-v2.5-pro` 在当前真实数据、MCP 工具和 100 条评测集上取得：

- **100% 通过率**
- **96% 完成率**
- **0% 幻觉率**
- **23.3 秒/条平均耗时**
- **10,324 Token/条平均消耗**

当前最值得继续研究的不是系统可用性，而是复杂归因的收敛效率、发散率与 Token/时延之间的关系。
