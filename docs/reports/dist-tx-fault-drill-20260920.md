# 分布式事务故障注入演练（2026-09-20）

> 方法：真实注入 + 终态核对（无 mock 断言）；脚本 `scripts/drill-dist-tx-faults.py`（可复用，2/2 PASS）。
> 证据：`docs/reports/dist-tx-fault-drill-20260920-104305.json`。

## 场景 A：消费者宕机 → 积压 → 恢复追平

| 步骤 | 实测 |
|---|---|
| 停 counter 服务（kill java 进程） | health=000，服务确实不可用 |
| 停服期间发点赞事件（SOCIAL_TOPIC） | **积压 1 条**（队列 Diff=1，LAG>0） |
| release 重启 counter | 消费者 rebalance 后 **LAG 1 → 0**（约 11 秒） |
| 计数核对 | like 计数 **恰好 =1**（Redis 实时值 1；取消点赞后回到 0） |
| DB 侧 | 计数走 Buffer 批量落库，短时滞后属**设计内最终一致**（对账兜底） |

机制印证：消费端 at-least-once + 幂等（msgId / SADD / 唯一键）保证"重复不重计"；宕机只影响时延不影响正确性。

## 场景 B：MQ broker 短暂不可用下的下单事务

| 步骤 | 实测 |
|---|---|
| `docker pause` broker（8s） | 暂停生效 |
| 暂停期间下单 | 事务消息发送失败（**3.1s 超时**），接口返回业务失败、**orderId=null（无半成品）**；日志 `[订单] 事务消息发送失败` |
| `unpause` 后同 `bizIdentifier` 重试 | **成功**（orderId=2101502617097240577）→ 说明失败路径已释放幂等键 |
| 终态核对 | 该用户订单数 **=1**（无孤儿订单、无重复订单） |

机制印证：半消息 + 本地事务原子（发送失败→本地事务不执行/回滚）；失败路径删除幂等键允许安全重试；Broker 恢复后消费者自动续跑（全局 LAG=0）。

## 环境备注（演练过程中的真实扰动）
- 演练前环境发生一次 broker 重启（10:23），导致 order 出现**崩溃重启循环**（短时 5 个进程、单次启动 185s），已清理重复进程恢复 15/15；这也验证了发布脚本的"端口/进程指纹"保护必要性。
- 进程清理教训：`pkill -f` 会误杀命令行含匹配串的调用方 shell；本脚本改为**仅匹配 `comm==java`** 的进程，安全可复用。

## 结论
- 两个故障场景均按设计收敛：**无消息丢失、无重复计数、无孤儿订单**；
- 分布式事务三件套（事务消息 / 幂等 / 补偿）在故障注入下表现与设计一致；
- 唯一口径提醒：计数器 DB 值短时滞后（Buffer 批量），查询以 Redis/对账为准。
