## 二、当场发现并修复的两个真缺陷

### ① 未知路径被报成 500（误导排查）
`GET /api/ai/agent/stats`（不存在）→ `NoResourceFoundException` 被 generic handler 吞成 **500 服务内部错误**。
**修复**：新增 `NoResourceFoundException → 404 资源不存在`；验证 `404 资源不存在: api/ai/agent/stats` ✓。

### ② MCP 子进程死亡后调用长时间挂起且永不恢复
杀掉 MCP 子进程后：工具接口**挂到 60s 超时**（我们客户端 30s 先放弃），且 `initialized` 仍为 true、缓存 client 不逐出 → 永久不可用。
**修复**：`listTools` 15s / `callTool` 30s 超时收敛 + **失败即逐出缓存**（下次调用自动重建）。
**验证**：死进程调用 **15.1s 返回明确错误**；重试 **1.2s 自动重建成功（20 工具）** —— 从"永久挂起"变为"快速失败 + 按需自愈"。

## 三、诚实边界（必须知道，避免过度宣称）

1. **Agent 未注册 MCP 工具**（`mcp-tools-enabled=false`，设计选择：工具全部自研，MCP 仅供运维直连）→ 文档里"kill MCP 19s/39s 自愈、NRestarts=24"属**去 MCP 化之前**的口径；当前 `McpHealthMonitor` 在该开关下不启用。
2. **预算硬拒未实测超限**（500k 阈值），仅验证了计量与 429 映射路径存在。
3. **模型网关主备降级未实测**（断主通道→切 ARK），仅确认双通道配置在。
4. **RAG 质量样本小**（hit@1=100% 为 30 条），且向量检索已封存（BM25 取舍有决策记录）。
5. 外部依赖：模型走公网 `siyu.site`（401 可达），离线环境不可用；ARK 备用未演练。
6. 评测 12/12、红队 11/0 等既有数字未在本轮全部复跑（本轮跑了 e2e/IT/审计链）。

## 四、AI 项目还要做什么（按价值排序）

1. **模型网关主备切换演练**（断主通道 → 备通道生效，验证流式不重放、超时预算与降级话术）。
2. **预算硬拒实测 + 用量看板**：低阈值用户触发 429 全链路（含前端提示与重试策略）。
3. **MCP 生命周期补齐**：stdio 子进程存活探测接入调用前检查（本轮已做失败逐出，可再加主动探测）；或正式宣布 MCP 只作运维旁路并在文档统一口径。
4. **评测体系升级**：样本扩容 + judge 与人工一致性校准 + 把 eval gate 固化进 CI（当前是脚本）。
5. **RAG/知识卡**：真实问题集回归（50-100 条），失效卡治理与命中率趋势；必要时重开向量检索 A/B。
6. **多轮会话与摘要**：summary 任务真实触发证据（600s/≥50 条）+ 会话恢复演练（F7）。
7. **安全红队扩面**：提示注入 × 工具参数 fuzz（含 MCP 工具入参）、越权会话访问、DLP 缺口补齐。
8. **业务联动加深**：在 HITL+核验框架下扩只读诊断工具（订单/支付/库存全链路）与少量受控变更动作（退款/重投已具备）。
9. **可观测与成本**：17 指标 + 告警在真实对话流量下的触发演练；成本周报自动化。

## 五、结论
- **不是"简单测试"**：LLM、Agent 工具链、HITL、审计链、MCP、RBAC、SSE、E2E 均为现场真跑通过，且当场修掉 2 个真缺陷。
- **可以放心演示**，但对外口径按第三节的边界说：MCP 已旁路、预算硬拒与主备切换未演练、RAG 样本小。
- 下一步建议先做"主备切换 + 预算硬拒"两项演练（都是演示时最容易被追问、也最容易翻车的点）。
