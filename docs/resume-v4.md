# 项目一：分布式交易架构 · 内容电商交易平台（15 微服务）｜核心开发 / 稳定性 Owner

项目背景：面向内容创作者与 C 端消费者的一体化内容电商平台，覆盖"商品 → 购物车 → 库存 → 优惠券 → 订单 → 支付 → 售后 → 结算"交易全链路与"笔记 → Feed → 搜索 → IM → 通知"内容社交链路，共 15 个 Spring Cloud 微服务；技术栈以 MySQL 分库分表、Redis、RocketMQ、Elasticsearch、Canal 为核心，配套容器化编排与 ELK / Prometheus / SkyWalking 全链路可观测。

## 职责描述（Responsibilities）
- 负责交易全链路（商品 / 购物车 / 库存 / 优惠券 / 订单 / 支付 / 售后 / 结算）的设计与落地，解决超卖、重复扣减、超退与资金对账问题，支撑大促级并发；
- 负责内容与社交链路（搜索 / 内容 / 社交互动 / 计数 / Feed / IM / 通知）的高并发建设，保障内容分发与互动的性能与数据一致；
- 主导稳定性与多活工程（容灾演练 / 混沌工程 / 发布治理 / 可观测），沉淀 21 项运行态修复与 117 项测试矩阵（含单 traceId 串通 15 服务的全链路脚本）。

## 核心工作与成果（按服务）

**一、库存服务｜预占 → 确认 → 回退 → 回补**
- 设计"Redis + Lua 原子预扣 + MySQL 条件更新 + 对账兜底"方案，解决大促热点 SKU 超卖与重复扣减：20 并发预扣零超卖，注入 75s 事务回查延迟仍只扣一次；
- 解决超时回收：ZSet 过期索引替代全库扫描（提前 60s 回收），只回退真正到期的预扣；
- 补齐兜底与边界：幂等占位表防重复扣减，locked_stock 对账修"幽灵锁"；修复伪订单号算法溢出导致的库存泄漏；交付库存 TCC 冻结接口（fence 状态机），11 项场景验证通过；退款回补按 SKU 累计正增量幂等，分次不漏补；失败收口：预扣 / 确认最终失败发失败事件（INVENTORY_FAILED_TOPIC）→ 订单侧按状态收口（待付款自动取消、已付款告警人工介入），杜绝"订单已提交但库存未锁定"。

**二、订单服务｜下单 / 取消 / 超时关单 / 状态流转（含售后）**
- 用 RocketMQ 事务消息 + 本地消息表 + Broker 回查实现"下单-预扣"最终一致，杜绝下单成功而库存未扣；状态全程条件更新 + 事件序号唯一键收敛并发，支持按事件流回放重建状态（dry-run 报告偏差、条件更新修复）；补偿消息按动作分派（回滚库存 / 退券 / 关单）并以 pending Set 重放；超时关单以延时消息 + 定时兜底扫描双保险；
- 完成订单分库分表改造：4 库 × 4 表 + 订单号映射表支持非分片键反查，绑定表避免同分片键 JOIN 笛卡尔积；定位倾斜根因（Snowflake 增量恒被 16 整除）改哈希取模，从 75% 倾斜治理到 16/16 片均匀（配套分布巡检脚本）；Snowflake worker-id 三级取值 + 端口维度防同机重号；8 场景并发对抗全通过（Broker 暂停下单无半成品、消费者宕机约 11s 追平）；
- 售后：仅退款 / 退货退款状态机 + 唯一键防重 + 三层金额护栏；应退金额按订单优惠分摊（分单位最大余数法）永不超退；修复"部分退款误当全额回补"的资损级问题。

**三、支付服务｜支付 / 退款 / 回调 / 结算对账**
- 搭建支付 / 退款双状态机 + 渠道策略（Mock 渠道 + 回调模拟器），解决回调三态、重复回调、迟到成功、零元单等资金边界；超时通知补偿保证支付状态最终收敛；退款以累计退款额驱动库存回补与退券，退款单号回传保证每笔唯一归属；
- 结算：T-1 日切账单（按渠道聚合收款 / 退款 / 净额 / 毛额手续费）+ 三方对账，三类差异自动挂账、自动收敛（8 类对账任务，17 SKU 差异修复 2 条 / 38ms）；游标分页内存有界。

**四、优惠券服务｜领券 / 核销 / 退券**
- 库存校验、限领、扣减收敛进单个 Lua（模板同 slot），解决高并发领券超发；Outbox 事务发件 + msgId / 唯一键双层幂等，保证券账一致；
- 维护券模板缓存与券过期调度（XXL-Job），支撑模板变更生效与过期券处理。

**五、购物车服务｜加购 / 改量 / 勾选 / 合并 / 清空**
- Hash/Set/ZSet 三结构 + 7 个 Lua 原子写入，解决并发加购与缓存一致性；序列号 CAS + CLEAR 屏障解决"清空与并发写"乱序；
- 支持登录后匿名购物车合并（防重与数量收敛）；Redis 丢失可从 MySQL 完整恢复。

**六、商品服务｜商品模型 / 详情高并发读**
- 管理 SPU/SKU 商品模型与类目树，支撑上下架状态变更（提交后失效缓存）；
- 布隆过滤器（100 万容量 / 1% 误判）+ 空值缓存 + 逻辑过期异步单飞 + 冷 key 加锁的多级缓存，解决穿透 / 击穿 / 雪崩；事务提交后删缓存 + 延迟双删（删除失败走 MQ 兜底）+ TTL 随机偏移防雪崩；缓存更新后 24ms 读到新值；启动预热分类树 / 热搜 / 推荐池；
- 定位类加载锁热点并改静态桥接，商品详情 1,074→4,871 RPS（4.5x，P99 50ms）。

**七、搜索服务｜检索 / 同步 / 热搜**
- 基于 Canal + MQ 双通道同步 ES，外部版本号拒绝陈旧写 + tombstone 防旧消息复活；全量重建断点续传（完成后清零并清理源表已删死文档）；
- search_after 深分页、suggest 前缀缓存、热搜榜快照 + 反作弊；调优 ES 与客户端 IO 后 search 508→1,448 RPS（2.9x，P99 191→61ms）。

**八、内容服务｜笔记 / 评论**
- 笔记发布 / 草稿 / 编辑 / 软删与消息同事务（11ms 原子发布、3-6s 搜索可见）；楼中楼评论 + 游标分页；DFA 敏感词过滤 + 图片魔数校验；笔记详情 1,048→4,171 RPS（P99 71ms）。

**九、社交互动服务｜点赞 / 收藏 / 关注**
- Set / ZSet / 关系表建模 + Lua 原子写入 + 版本窗口防乱序，解决高频互动的并发与一致性；半成功由对账修复，行为权威集可反向重建。

**十、计数服务｜社交计数**
- Redis 实时计数 + 内存 Buffer 批量 upsert（满 100 条 / 5 秒），解决高频写对 DB 的压力；失败回写缓冲防丢增量、停机强刷、事件版本门防旧事件覆盖，对账以 Redis 为准反向修正 DB；
- 1 万次点赞合并约 2000 个计数 key 一次落库，DB 故障恢复自动补刷。

**十一、首页 Feed 服务｜聚合 / 推荐流**
- 推拉结合：大 V 走发件箱拉模式、普通用户按粉丝批量写收件箱，解决大 V 粉丝扩散成本；cursor 断点续推可恢复；删除走 tombstone 防旧内容复活；修复收件箱与召回源双写不一致导致的推荐恒空；
- 并行聚合 + 线程池隔离 + 分层超时；1,861 RPS / P99 49.6ms。

**十二、IM 服务｜长连接消息**
- 会话跨实例经 Redis pub/sub 路由 + 跨实例踢线，解决多实例寻址与僵尸连接；离线消息持久副本 + ACK 删除 + 去重（at-least-once）、按序补发（1000 条 / 7 天）；
- 握手 ticket 一次性消费；会话 ID 由关系表分配，防并发重号。

**十三、通知服务｜聚合 / 未读 / 推送**
- 接入订单事件（下单 / 支付等）驱动通知；按自然日窗口聚合（"等 N 人"），Lua 原子窗口锁防并发重复；未读计数 INCR / HINCRBY 双键同 slot + 原子降级 + 对账防跨批错值；
- SSE 跨实例定向推送（ticket 一次性消费），解决单机连接无法触达其他实例用户，并修复两处跨实例推送失效（本地短路 / 反序列化）。

**稳定性与平台治理（跨服务）**
- 容灾：主导 MySQL 切主（RTO≈32s）、Redis 切主（2.3s）、Zone 切流 / 回切演练（RTO 1.31 / 3.25 / 4.79s），沉淀 5 项短板与整改路线；
- 混沌与发布：自研故障注入框架（方法级 DELAY / EXCEPTION / RETURN_NULL + 概率触发 + Nacos 动态热更）；混沌 7 场景演练全部通过（Redis 不可用、网络延迟 3s、MQ Broker 不可用、CPU 满载、磁盘 IO 高负载、MySQL 不可用、优雅停机）；依赖变慢注入（netem 4s）验证降级 503 语义；根治发布"假成功"（11/15 服务曾跑旧 jar → 监听 PID 指纹校验）；
- Zone 多活：Zone 自动发现 + X-Zone 跨服务传播 + 同 zone 优先路由（应用层与网关就近路由），数据面 zone 感知（MySQL 读本 zone、Redis 读副本写主库，运行时热切不重启），健康检查摘除与回切（RTO 1.3~4.8s）；
- 多活验证：跨区延迟注入（netem）下吞吐 +34%、P99 降低 33~47%；动态热切不重启、流量无中断（content / cart 实测）；Redis 双主（同步 + LWW + 存在优先防误删 + 防回环 + 周期对账，两侧 dbsize 1873=1873）单侧故障不中断（≤35s 追平）；网关故障切换 5.54s；多活方案与成熟框架逐项对比留档；
- 配置与调度：修复 SCA 死配置导致的"写了不生效"，15/15 服务配置真实加载；审计修复 XXL-Job 非法 cron 与丢窗口任务；RocketMQ topic 全量幂等初始化；DLQ 积压按 26 个消费组清账 + 幂等重放 Runbook（限速回放）；CI 门禁（Gitea Actions + act_runner）实测拦截违规提交、版本化发布与自动回滚；
- 公共组件：限流 / 幂等切面组链（45 / 9 处）+ Sentinel 熔断降级（规则 Nacos 托管）、读写分离与从库降级、Feign 禁重试 + HC5 池化 + 分级超时 + 内部令牌、多 ORM 同进程并存、最小连接负载均衡（含单测）、号段 ID 与批量写入等扩展组件（含单测）；分布式锁只做效率（显式租期、失败即拒），正确性由唯一键 / 条件更新 / fence / 对账兜底；Dubbo 双协议试点后评估不引入（+4.9% RPS 不抵改造成本）；
- 数据与资源治理：慢 SQL 由相关子查询改窗口函数 + 复合索引，治理数据库僵尸连接；SqlGuard 慢 SQL 指纹熔断（默认告警、白名单可阻断）；优雅停机（先摘注册 → 缓冲刷盘 → 停线程池）；影子表压测隔离；分片与动态数据源同应用并存（映射表 master/slave 运行时切换）；容器编排（healthcheck 全覆盖 + 依赖时序）；JVM 参数体系（G1 + 停顿目标）+ 线程池隔离 + MDC 跨池 traceId；备份体系（MySQL / Redis / ES）+ 开机自愈；内存占用 45→28Gi；
- 可观测：15 服务 JSON 日志 → Filebeat / Logstash → ES 按天索引（ILM 生命周期）；SkyWalking APM 开销实测 ≈5.4%、traceId 全链路透传；指标预注册空标签防系列被吞 + URI 归一化防时间序列爆炸。

# 项目二：AI 研发流水线（Harness）｜可执行引擎 + 跨语言技能包 · 独立开发（【时间】）

项目背景：把"需求分析 → 编码 → 单测 → 评审 → CI → 部署验证"六阶段研发流程做成可执行系统的 Java 引擎（6 Maven 模块 / 7,000 行 Java / 158 单测），配套跨语言 Harness 技能包（6 语言 / 30+ 技能 / 约 5 万行文档），并在 15 微服务电商工程完成真实演练。

## 职责描述（Responsibilities）
- 独立设计并实现六阶段交付流水线引擎：变更状态机、门禁执行器、证据链、LLM 需求分析与 HITL 审批、CLI 工具；
- 建设跨语言技能包（6 语言参数化 / 30+ 技能），把研发方法论沉淀为可复用的工程资产；
- 用故障注入基准量化门禁有效性，并把引擎接入真实工程完成闭环演练。

## 关键结果（Key Achievements）
- 变更状态机：6 阶段转移表为唯一事实源，StageRun 唯一键 (changeId, stage, attempt)；失败重试 attempt+1 且历史保留，替换引擎实例可断点续跑；
- 门禁执行器与验证：ProcessBuilder 并发读流防"管道假死"，超时按进程树强杀（Maven 会 fork JVM）；测试门禁 fail-closed（0 测试 / 全跳过一律判红），覆盖率解析 JaCoCo XML、PIT 变异识别假测试、增量覆盖率只卡变更行；
- 证据链与 HITL：事件流 SHA-256 链 + verify 定位篡改行；LLM 规格草案必须人工 approve 才能编码（退出码 3），per-change 跨进程 FileLock + 进程内 Semaphore；
- 量化结果：故障注入 7 类 100% 检出、5 项基线零假阳性；xhs 工程注入失败测试被拦截（94 tests / 1 failure）→ 修复后 attempt 2 转绿（行覆盖 22.0% ≥ 20%）；4 个证据包 60+ 文件。
