# 第34题 | 推荐系统：多路召回、离线计算与冷启动

> 难度：★★★★☆｜频率：★★★★☆｜区分度：中
> 关键词：四层架构、5 路并行召回、ItemCF、时间衰减、GeoHash、离线任务、冷启动闭环

## 问题
推荐系统怎么架构？召回怎么做？离线任务算什么？冷启动怎么过？

## 面试可讲版（五段式）

**① 业界背景**
推荐的标准四层：**召回**（万级→千级，多路并行）→ **粗排** → **精排** → **重排**（多样性/打散/业务规则）。工程上是"离线计算 + 在线服务"：离线产特征/相似矩阵/热池，在线并行召回+合并+排序；复杂排序模型不是小团队第一优先级，**多路召回的正确性和性能**才是。冷启动靠内容特征+热门兜底，别硬等协同信号。

**② 项目选择**
- **四层架构**：召回 → 粗排 → 精排 → 重排（本项目实现聚焦召回+打分合并）；
- **5 路并行召回**：Item-CF / 内容标签 / 热门 / 关注 / 地理（GeoHash 同城）；每路 100 条，合并去重 ≈300 条候选；**独立 `recallExecutor` 线程池 + 2s 超时**（一路慢不拖垮整体）；
- **离线任务（XXL-Job）**：行为上报（`BehaviorReportConsumer`）→ **特征提取（每小时）** → **ItemCF 相似矩阵**（`recommendItemCFJob`）→ 热池；产物写 DB/Redis 供在线召回读；
- **召回打分细节**：内容召回按标签权重 × `(1 + quality_score)`；关注召回按**时间衰减**（timestamp 归一化 0~1）；Geo 按距离/城市；
- **冷启动闭环**：新内容靠内容特征（标签）与热池兜底——不依赖协同信号；实测：6 用户 × 3 笔记行为 → 特征 2 条、热池 3 条、ItemCF 相似对 6、feed 2 条、similar 相似度 0.913——**行为到结果的闭环可验证**；
- **相关推荐**：`similar/{noteId}`（ItemCF 相似度）+ feed 流。

**③ 坑**
- **一路召回慢拖垮整体**：并行召回要独立线程池 + 超时兜底（慢路丢弃，可用性优先）；
- **重复候选**：多路召回必然重叠——合并去重按最高分保留，否则重复内容刷屏；
- **冷启动无信号**：新内容没有行为数据，ItemCF 召回为零——内容标签 + 热池兜底是必须的；
- **ItemCF 的流行度偏差**：热门内容相似对过多，打分要衰减/归一化；
- **离线任务空跑**：任务注释"每小时"要有调度入口（本项目用 XXL-Job Handler）——参考支付对账死代码的教训。

**④ 兜底**
- 召回超时/失败：该路丢弃，其余路继续（并发 Future 超时收集）；
- 全空：热池/最新内容兜底；
- 离线未产出：在线降级到热池；
- 观测：各召回路径命中数/耗时、候选合并数、点击率（未做 A/B，诚实边界）。

**⑤ 话术**
> "推荐是四层：召回、粗排、精排、重排；我们重点做了召回——5 路并行：ItemCF、内容标签、热门、关注、地理，每路 100 条合并去重成 300 候选，独立线程池加 2 秒超时，一路慢不拖垮整体。离线用 XXL-Job 算特征、ItemCF 相似矩阵和热池，在线读产物。冷启动靠内容标签和热池兜底，不依赖协同信号；实测 6 用户 3 笔记行为能产出特征、热池、ItemCF 相似对的完整闭环。没做在线 A/B 和精排模型，这是边界。"

## 追问与参考回答
**追问1：ItemCF 怎么算？** 用户-物品行为矩阵 → 物品共现 → 余弦/Jaccard 相似度；支持度/热度做惩罚；离线批量计算写 Redis/DB。
**追问2：5 路召回怎么合并？** 并行 Future 收集（超时丢弃）→ 按来源权重/分数合并去重 → 输出候选集。
**追问3：为什么不用向量召回？** 与 RAG 决策同理——先评测再投入；小规模下 ItemCF + 标签 + 热池够用；向量召回的触发条件是效果瓶颈明确且收益可测。
**追问4：GeoHash 怎么用？** 笔记带地理位置 → GeoHash 编码 → 同城/邻域召回；精度与邻域查询（geohash 前缀 + 边界处理）。
**追问5：怎么评估推荐效果？** 离线指标（命中率/覆盖率/相似度）已验证；在线 CTR/时长需要 A/B 平台（未做，是缺口）。

## 发散追问地图（横向）
- 推荐架构：召回/粗排/精排/重排、多路融合、冷启动、多样性打散。
- 协同过滤：UserCF/ItemCF/矩阵分解、隐式反馈、流行度偏差。
- 特征工程：行为序列、实时特征（Flink）、特征存储。
- 地理：GeoHash/GeoJSON、附近召回、边界问题。
- 评估：离线指标（Recall/NDCG）、在线 A/B、EE（探索利用）。

## 面试官评分点
**高级开发级**：能讲四层与多路召回；知道冷启动靠内容兜底。
**架构师加分**：并行召回的隔离与超时；合并去重的打分策略；离线任务"有产物可验证"的闭环；向量召回"先评测再投入"的止损思路。
**危险信号**：一路召回阻塞整体；冷启动只等协同信号；离线任务无调度入口；把"做了推荐"说成有精排模型。
