# 第55题 | 通知与推送域：聚合、未读与订单事件接入

> 难度：★★★☆｜频率：★★★★｜区分度：中高
> 关键词：通知聚合（uk 约束）、未读对账、推送任务/失败表、订单事件三埋点、SSE 实时

## 问题
通知怎么避免骚扰（聚合）？未读怎么保证准？推送失败怎么办？订单状态变化怎么通知用户？

## 面试可讲版（五段式）

**① 业界背景**
通知域三件事：**聚合**（同类型同目标同天合并成一条，防轰炸）、**未读**（每人每会话小值高基数）、**送达**（推送任务 + 失败表 + 重试）。实时性分层：站内信落库（可靠）+ SSE/长连接推送（实时）。

**② 项目选择**
- **聚合**：`t_notification` 唯一约束 `uk_aggregate(user_id,type,target_id,notify_date)` + `aggregate_count`/`is_aggregated`；订单状态类通知走 `updateOrderLatest` 分支——**同订单当天只保留最新状态**（避免"已付款/已发货"堆两条）；
- **订单接入（本轮修复）**：`OrderNotificationPublisher` 三埋点（支付成功 / 发货 / 退款成功）——此前订单域**未接通知**（业务链缺口，用户下单后无站内信）；
- **未读**：**DB 权威**（与计数相反：未读是高基数小值，DB 更稳）+ Redis 加速；对账 Job 每 5 分钟；
- **推送**：`t_push_task`（任务）+ `t_push_task_fail`（失败）+ `t_push_template`（模板）；失败落表可重试/排查；
- **实时**：SSE 推送（跨实例路由见 10 题）；IM 会话消息见 09 题。

**③ 坑**
- **聚合唯一键与"最新态"**：只做 `ON DUPLICATE UPDATE count` 会保留旧标题（用户看到"已付款"但实际已发货）→ 订单类必须刷新内容（updateOrderLatest）；
- **未读口径**：以 Redis 为准会因丢更新分叉 → 选 DB 权威 + 对账；
- **推送失败静默**：失败必须落表（`t_push_task_fail`），否则"发了但没到"无人知；
- **通知域未接订单域（真事故）**：链路推演发现订单事件没有消费方 → 修复三埋点 + 聚合器分支。

**④ 兜底**
推送失败表重试 + 站内信落库保底（实时通道失败仍可打开 App 看到）；未读 5 分钟对账收敛；SSE 不可用降级为拉取。

**⑤ 架构师加分**
- 聚合设计用**唯一键把"并发合并"交给 DB**（而不是应用层查改，天然幂等）；
- 未读权威源选择与计数相反，说明"按数据特征选权威源"而非一刀切（与对账体系 18 题同一原则）。

## 追问与参考回答
**追问1：聚合并发下会不会重复插？** 唯一键 `uk_aggregate` 兜底，冲突转 UPDATE count；订单类走 UPDATE 最新内容（避免旧标题）。
**追问2：未读为什么不用 Redis 权威？** 高基数小值、易丢更新；DB 权威 + Redis 加速 + 5 分钟对账（与计数权威源选择相反，按数据特征定）。
**追问3：推送失败怎么发现？** 失败落 `t_push_task_fail` + 告警；站内信落库保证可回看（实时通道失败不丢信息）。
**追问4：通知量大会不会拖垮主链？** 通知走 MQ 异步消费 + 聚合降噪；订单事件只发事件不阻塞交易；失败可重试。
**追问5：订单域未接通知这种缺口怎么发现的？** 靠业务全链路推演（29 步主线走一遍发现没有消费方）——这就是链路推演的价值，而非只看单服务。

## 发散追问地图（横向）
- 通知模型：站内信 / 推送 / 短信 / 邮件 / 多通道降级；
- 聚合与降噪：唯一键聚合 / 时间窗合并 / 摘要推送；
- 未读体系：DB 权威 / Redis 加速 / 对账 / 多端同步（已读回执）；
- 推送通道：APNs / FCM / 厂商通道 / 长连接（SSE/WS）；
- 可靠性：任务表 + 失败表 / 重试上限 / 死信 / 幂等；
- 边界：通知风暴 / 用户打扰 / 聚合丢失最新态。

## 评分点
- 讲清聚合的唯一键设计与"最新态刷新"的必要性；
- 能主动讲"订单域未接通知"的真实缺口与修复；
- 未读权威源与计数相反的对比意识。

## 本项目真实证据
- `t_notification` 表结构（`uk_aggregate`/`aggregate_count`/`is_aggregated`）、`OrderNotificationPublisher` 三埋点 + 聚合器 `updateOrderLatest`（本轮修复，E2E 30/30 回归）；
- 未读对账 Job（5 分钟，手册 §R）；`t_push_task`/`t_push_task_fail`/`t_push_template`；SSE 跨实例修复（10 题）。
