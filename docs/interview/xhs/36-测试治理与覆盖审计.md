# 第36题 | 测试治理与覆盖审计：假测试/假修复识别

> 难度：★★★★☆｜频率：★★★★☆｜区分度：高
> 关键词：覆盖审计、假测试模式、假修复识别、117 矩阵、运行态验证、回归矩阵扩充

## 问题
测试覆盖率多少？怎么保证测试是真的？"回归全绿"能说明什么？

## 面试可讲版（五段式）

**① 业界背景**
"测试全绿"经常是幻觉：**只验 HTTP 200**、**Mock 全路径**（测的是测试自己写的 stub）、**无异常路径**、**Mock 返回 Mock**——这些"假测试"让覆盖率数字好看但缺陷照漏。真正的质量保证 = **分层测试（单测/集成/E2E） + 异常路径一等公民 + 运行态验证（真数据对账） + 审计方法可复用**。

**② 项目选择**
- **117 项测试矩阵**（平台级）之外，专门做了**文件级覆盖审计**：购物车 34 个文件、内容 38/38、网关 11 个核心类逐文件核对；
- **识别"假修复/假测试"**（真实审计结论）：
  - 仅验 200：`OrderControllerTest.notifyRefundSuccess` 对 service `doNothing()` + 断言 HTTP 200——没验状态、库存、Redis、多 SKU；
  - Mock 路径漂移：06-cart 测试 mock 了旧实现路径（hashOps），"通过"但与生产行为不一致；
  - 假修复：注释声称"原子"实际非原子、测试未真正执行；
- **审计产出具体缺口清单**（F-007 多 SKU 退款、F-010 退款失败语义、F-016 领券库存漂移、F-039 BFF 依赖失败）——**每个缺口有根因和补测方向**；
- **补测收口**：补跑 common 53 + user 14 单测全绿；关键路径（退款/领券/聚合失败）补进回归矩阵；
- **回归矩阵扩充**：多 SKU、多消息、补偿任务、故障注入进入矩阵（不只是"正常入口可用"）。

**③ 坑**
- **"多轮回归全绿"证明的只是正常路径**：审计结论原话——"证明的是正常入口和正常依赖可用，不是异常后系统仍能收敛"；
- **Controller 测试 mock Service = 绕开状态机**：状态机、条件 UPDATE、补偿这些核心逻辑根本没被覆盖；
- **覆盖率≠质量**：行覆盖高但异常路径零覆盖；要看"异常路径数量"而不是百分比；
- **假修复比不修更危险**：注释说"已修/原子"但实现没有——审计要验代码不验注释；
- **审计方法要沉淀**：模式库（假测试四模式 + 判定标准）比一次性检查有价值。

**④ 兜底**
- 审计方法文档化（`review-method/09-test-quality.md`：识别命令 + 四模式 + 判定）；
- 补测优先级：资金/库存/券（钱相关）> 状态机 > 聚合降级；
- 运行态验证（真库/Redis/MQ 对账）补单测的盲区；
- CI 门禁：`ci-gate.sh`（编译 + common 单测 + 规范扫描）。

**⑤ 话术**
> "我不只看覆盖率。除了 117 项矩阵，我们还做了文件级覆盖审计——购物车 34 个文件、内容 38 个文件、网关 11 个核心类逐个核对，识别出四类假测试：只验 HTTP 200、Mock 全路径、无异常路径、Mock 返回 Mock，还发现注释声称修了但代码没修的假修复。产出的是带根因的缺口清单，比如退款回调只 mock 了 doNothing 断言 200，根本没验状态和库存。结论很直接：多轮回归全绿只证明正常入口可用，不证明异常后能收敛。后面补跑 common 53 加 user 14 个单测，把异常路径补进矩阵。"

## 追问与参考回答
**追问1：覆盖率工具用了吗？** 用了但没有唯覆盖率论——审计重点在"测试断言质量"与"异常路径覆盖"；行覆盖高不代表有效。
**追问2：怎么高效识别假测试？** 模式匹配 + 人工抽样：grep 断言类型分布（isOk vs verify/assertThat）；看 mock 是否覆盖异常分支；对照生产调用路径核对 mock 是否漂移。
**追问3：补测优先级怎么排？** 按业务风险：资金（退款/支付）、库存、券 > 状态机流转 > 聚合降级；先补"错了会丢钱/超卖"的。
**追问4：运行态验证和单测什么关系？** 单测保逻辑分支，运行态验证（真数据对账）保"mock 行为与真实一致"；两者互补，不能互相替代。
**追问5：测试矩阵怎么维护？** 每次事故/修复沉淀为用例（回归入库）；新的补偿任务/异常场景主动补；矩阵与代码同仓库评审。

## 发散追问地图（横向）
- 测试分层：单元/集成/契约/E2E；测试金字塔。
- 测试质量：断言质量、变异测试（mutation testing）、异常路径覆盖。
- Mock 风险：mock 漂移、契约测试（Pact）、Testcontainers。
- 质量门禁：CI gate、静态扫描、覆盖率阈值、PR checklist。
- 审计方法：模式库、抽样策略、审计报告与跟踪闭环。

## 面试官评分点
**高级开发级**：能讲假测试模式；知道覆盖率不等于质量。
**架构师加分**：文件级覆盖审计与带根因的缺口清单；"回归全绿只证明正常路径"的判断；补测按资金风险排序；审计方法模式库化。
**危险信号**：只报覆盖率数字；Mock 全路径当合格；异常路径不测；假修复当已修。
