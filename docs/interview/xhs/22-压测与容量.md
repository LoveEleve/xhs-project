# 第22题 | 压测与容量校准（含影子表）

> 难度：★★★★☆｜频率：★★★☆☆｜区分度：高
> 关键词：饱和点、P99、wrk/ab、影子表隔离、瓶颈定位（profile 先行）、容量口径

## 问题
你们怎么做压测？容量怎么定？压测数据造在哪个环境？

## 面试可讲版（五段式）

**① 业界背景**
压测的核心不是"跑出个高数字"，而是**找饱和点 + 定位瓶颈 + 校准容量**。方法：固定并发阶梯（c=16/32/64/128）看 RPS/P99 拐点；瓶颈定位用 CPU/线程/GC/DB/连接池/下游的分层证据；压测数据要隔离（影子表/影子库），否则污染线上数据。

**② 项目选择**
- **机制**：`ShadowTableInterceptor` 把压测流量 SQL 自动改写 `_shadow` 表——压测造数不碰真实数据；
- **方法**：wrk 主导（ab 有 chunked+keepalive 陷阱），先单发校验业务码再压（HTTP 200 不等于业务成功——限流曾返回 200+业务码，后改为 HTTP 429）；
- **修复后基线（2026-09-17 全量实测）**：
  - product 详情 **4,871 RPS / P99 50ms**（类加载锁修复 4.5x）；
  - home 聚合 **1,861 RPS（c=64）/ P99 49.6ms**（池隔离+类加载修复）；
  - comment 评论 **4,418 RPS / P99 70ms**（ROW_NUMBER 改写+复合索引）；
  - search **1,448 RPS / P99 61ms**（ES CPU 配额 2→6 核等）；
  - 网关代理开销 ≈0（动态放行后 962 RPS ≈ 直连）；
- **经验值**：单机按"服务 512MB 堆 → 千级 RPS"定容量上限，扩容优先加实例而非调参数。

**③ 坑**
- **profile 先行，不要拍脑袋调**：曾按"加本地缓存"直觉优化（L1 Caffeine 27,442 RPS）——但违反一致性/多实例口径被移除；真正的瓶颈是**类加载锁**（TraceContextHolder 每请求 Class.forName）和**DB 僵尸连接**，修复后无缓存也到 4,871；
- **压测期间不要发布/重启**：会产生僵尸连接（本次 459 连接中 318 条僵尸，清理后 comment 才恢复）；
- **数字要同口径复测**：ab 与 wrk、keep-alive 开关、限流阈值都会让数字不可比——报告必须写清工具/并发/限流状态；
- **HTTP 200 骗局**：业务错误可能带 200 返回，必须校验业务码；压测前先单发。

**④ 兜底**
- 压测环境：影子表隔离 + 独立网络路径；
- 限流/超时参数按压测校准（网关路由 QPS、Sentinel 阈值）；
- 报告归档 `docs/reports/`，旧口径标注作废（capacity-20260917 已标"修复前下界"）；
- 观测：压测同时看 P99 分解、线程池、连接池、GC、下游 RPS。

**⑤ 话术**
> "压测我们分三步：影子表隔离流量，wrk 阶梯并发找饱和点，再用 profile 定位瓶颈——不拍脑袋。有个教训是曾经直觉加本地缓存跑出 27k RPS，但违反一致性口径被移除；真正的瓶颈是类加载锁和僵尸连接，修复后无缓存也有 4,871 RPS。数字都写清工具、并发和限流状态，不同口径不复用。"

## 追问与参考回答
**追问1：怎么找饱和点？** 固定并发阶梯看 RPS 与 P99：RPS 不再涨且 P99 陡升的点就是饱和点；本项目 512MB 堆单服务约千级 RPS。
**追问2：P99 高但 RPS 没掉说明什么？** 长尾问题（锁竞争/GC/慢 SQL/连接等待），要看 P99 分解而不是平均值。
**追问3：影子表怎么实现？** MyBatis 拦截器识别压测标记（线程上下文），把表名改写为 `_shadow`；对业务代码零侵入。
**追问4：压测数据会污染线上吗？** 影子表隔离 + 独立数据源/表，压完清理；不隔离的压测是事故源。
**追问5：类加载锁是什么？** 每请求 Class.forName 触发 JVM 类加载锁竞争（同一类并行加载），改成静态 holder 后消除——profile 才发现的。

## 发散追问地图（横向）
- 压测工具：wrk/ab/JMeter/Gatling，keep-alive/chunked 差异。
- 瓶颈定位：火焰图（async-profiler/arthas）、JFR、锁竞争、GC 日志、Lidgren 分析。
- 容量模型：Little's Law、QPS×耗时=并发；扩容策略（水平/垂直）。
- 数据隔离：影子表/影子库/流量染色（网关打标）。
- 混沌：故障注入与性能退化场景（慢下游/连接池耗尽）。

## 面试官评分点
**高级开发级**：能讲压测方法（阶梯/口径/隔离）；知道 HTTP 200 不一定是成功。
**架构师加分**：profile 先行而非直觉优化；类加载锁/僵尸连接这类真实瓶颈；数字口径管理（不可比不复用）；容量与扩容策略。
**危险信号**：只报一个最高数字；压测在线上库；不看 P99/瓶颈；把临时优化当最终方案。
