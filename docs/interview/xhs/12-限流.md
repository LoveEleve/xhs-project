# 第12题 | 限流：Sentinel vs Lua 滑动窗口

> 难度：★★★★☆｜频率：★★★★☆｜区分度：高
> 关键词：Sentinel LeapArray、GatewayFlowRule、Lua ZSet 滑动窗口、单机 vs 集群限流、429、IP 防刷

## 问题
问题：限流怎么做的？为什么不全用 Sentinel？为什么限流算法选滑动窗口而不是令牌桶？

## 面试可讲版（五段式）

**① 业界背景**
限流四算法：固定窗口（简单、有临界突刺）、**滑动窗口（精度与成本平衡）**、令牌桶（允许突发）、漏桶（流量整形）。组件侧：Sentinel（流量控制/熔断/热点参数，Java 生态事实标准）vs Hystrix（停更）vs Resilience4j（轻量函数式）vs 网关自研。争论点：网关限流 vs 服务内限流、单机限流 vs 集群限流、规则动态化。

**② 项目选择**
**双轨**：① 网关层 `RateLimitFilter` 用 **Sentinel `GatewayFlowRule`（LeapArray 滑动窗口）**——按 route ID 限流（如 order-service 500 QPS），统一 `BlockRequestHandler` 返回 429 JSON（与 401 格式一致）；② 业务层 `@RateLimit` 注解用**自研 Redis Lua ZSet 滑动窗口**（`@Order(10)` 第一道切面：移除过期成员→计数判断→ZADD 记录），细腻度到方法级、支持多实例精确限流。另有登录防爆破作为安全限流：账号 5 次 / 单 IP 20 次、锁定 15 分钟；单源攻击只锁 IP 不锁账号（防账号被恶意锁死）。

**③ 坑**
- **规则唯一数据源是 yml 路由 metadata**：`initFlowRules` 从 `GatewayProperties` 逐路由读 `metadata.rate-limit-qps`（未配置走默认 100），`@PostConstruct` 装载进 `GatewayRuleManager`——重启即丢、不依赖 Nacos 异步发现（代码注释写明"唯一数据源"）；Nacos gw-flow converter 只备了 Bean、制品（`config/sentinel/*.json`）需手工导入 Dashboard 才生效；
- **用户级限流没落地**：ParamFlowRule 需要网关从 `X-User-Id` Header 提取参数，注释里写了"后续实现"——当前只有接口级；
- Sentinel 是**单机限流**：多网关实例各自计数，集群限流需要 Token Server（未部署）；
- 注解限流的 Lua 每次请求要 ZADD+ZREMRANGEBYSCORE，热点 key 成本高于本地计数器（可接受，因为只在敏感接口用）。

**④ 兜底**
- 429 统一响应格式（避免前端无法识别）；限流阈值压测校准（100/50 等）；
- 限流与幂等/锁同序（@Order 10/50/100）：先限流再抢锁，防锁被刷爆；
- 服务内 Redis Lua 限流跨实例精确；网关层超限快速失败不把流量打给后端。

**⑤ 话术**
> "网关用 Sentinel 做粗粒度接口限流，业务敏感接口用 Redis Lua 滑动窗口做方法级精确限流；已知短板说清楚：网关规则本地内存、用户级限流未落、集群限流需要 Token Server——这些都是有意留的边界，不是不知道。"

## 追问与参考回答
**追问1：为什么滑动窗口优于固定窗口？** 固定窗口在切换瞬间允许 2 倍突刺（前窗末尾+后窗开头）；滑动窗口按当前时刻回看窗口，平滑但要多存时间戳（ZSet）。
**追问2：为什么不用令牌桶？** 令牌桶允许突发（桶内积攒令牌瞬间消费），API 保护要的是"稳定放行"，且 Sentinel 默认走滑动窗口；漏桶匀速适合流量整形（如出口调外）。
**追问3：ZSet 滑动窗口的内存与成本？** 每请求一条成员，窗口内请求数就是集合大小；密集接口可能很大 → 网关层就没用它，只有敏感方法级限流用；必要时改分段计数器（少精度换内存）。
**追问4：集群限流怎么做？** Redis Lua 天然是集群精确限流（本项目注解版就是）；Sentinel 集群流控需 Token Server（单点/嵌入两种模式），成本高。
**追问5：限流和熔断/降级的关系？** 限流是入口保护（不进来），熔断是下游故障时快速失败（不出去），降级是失败后的兜底响应；三者层次不同，本项目熔断配置较弱（Sentinel 规则手工导入，主动边界）。

## 发散追问地图（横向）
- 算法选型：固定/滑动/令牌桶/漏桶的数学特性与突刺对比；Guava RateLimiter 的预热模式。
- Sentinel 体系：流控/熔断/热点/系统规则四类；规则持久化（Nacos/文件/环境变量）；网关适配器 vs Web Servlet 适配器。
- 集群限流：Token Server 单点、嵌入模式、Redis 集中式、本地预分配+周期同步。
- 压测校准：如何用影子表压测得出安全阈值；限流阈值与容量规划的关系。
- 429 vs 503 语义、Retry-After、客户端退避策略。

## 面试官评分点
**高级开发级**：能讲清算法差异与选择理由；知道单机/集群限流区别；注解与网关限流的定位。
**架构师加分**：规则治理（持久化/动态/版本）、多级限流体系、与熔断降级的分工、压测到阈值的闭环。
**危险信号**：只会说"用了 Sentinel"；不知道规则存哪；混淆限流/熔断/降级。
