# 自我介绍与项目讲述脚本（面试开场用）

> 原则：**数字精确、边界诚实、每段留钩子**。自我介绍不要背简历，要讲"为什么这样做"。

## 一、90 秒总自我介绍（两项目版）

"面试官好，我是 XXX，最近两段经历都围绕'高并发交易系统'和'AI 工程化落地'。

第一个项目是电商微服务平台：15 个 Spring Cloud 服务，我负责交易与稳定性方向——事务消息+本地消息表保证下单不丢、四层幂等保证不重不错、TCC fence 处理资源侧三异常；稳定性侧做过 DLQ 治理、限流、对账任务和混沌演练。

第二个项目是我从 0 到 1 做的运维诊断 Agent：用自然语言做故障根因定位与知识问答，16 个全自研工具覆盖 DLQ/日志/指标/知识/代码五域；危险操作走 HITL 审批+核验闭环；评测做了三层（工具选择 12/12、答案 50 用例、轨迹稳定性 0.917）。

我比较擅长的是：**把'看起来能用'的东西做到'生产可交付'**——指标可观测、失败有兜底、边界说得清。"

## 二、平台项目 3 分钟讲述（按链讲）

**开场定调**："这个项目我讲两条线：一条是钱和库存不能错，一条是流量来了不能崩。"

**线1 交易一致性（90 秒）**：
"下单要跨订单/库存/券/支付，我们不用 2PC，用的是事务消息+本地消息表——本地事务和消息在同一个 DB 事务里，Broker 回查查本地消息表。但消息语义是 at-least-once，所以我们把幂等做成四层防线：入口 token、消息 msgId 去重、DB 唯一键、状态机条件更新；资源侧用 TCC fence 解决空回滚/悬挂/幂等，11 个场景实测通过。中间踩过最有价值的坑是'本地消息不标已投递导致补发双投'——这反而证明了消费端幂等是终线。"

**线2 高并发与稳定性（90 秒）**：
"读靠缓存：双删+逻辑过期+Bloom，接受秒级旧值但绝不允许长期脏数据；写靠原子操作+攒批，计数用 Lua 去重+双 Buffer 刷盘；入口用 Sentinel 和 Lua 滑动窗口两级限流；容量靠订单 4×4 分库分表——这条路我承认短板：没有 rehash，扩容方案只能说思路没落地。稳定性上做过 DLQ 治理，最有价值的事故是'DLQ 指标恒为 0'——监控不是没有数据，是我们自己算错了，修完才谈自动重投。"

**收尾钩子**："这两条线的细节，您想先深挖哪个？"

## 三、AI 项目 3 分钟讲述

**开场**："这个项目的起点是一个真实痛点：我们的 DLQ 积压排查要跨 5 套系统，于是我做了个 Agent，用自然语言完成'定位→取证→给结论'。"

**架构（60 秒）**："单 Agent + ReAct 工具循环，AgentScope Java 原生+Harness；16 个全自研工具，模型只传业务参数，ES DSL/PromQL 由服务端构造——早期让模型直接写 DSL 会幻觉，改成语义工具后 P95 题从 98 秒答偏到 50 秒答对。"

**安全（45 秒）**："危险操作（比如 DLQ 重投）不直接执行：审批落库+CAS+参数指纹+超时 fail-closed，执行后核验——要么队列位点越过、要么消息又回 DLQ，后者说明重投无效，不假装成功。"

**评测（45 秒）**："评估不能只看答案：工具选择 12/12、答案级 50 用例（含拒答安全）、轨迹稳定性 0.917；评测还被预算硬限坑过一次，后来用专用评测用户隔离、失败必须归因到模型/工具/基础设施/评测集。"

**收尾**："这个项目我特意不吹边界：向量检索、多租户、LLM-judge 都没做，理由和替代方案我都可以展开。"

## 五、讲述纪律（四条）

1. **数字带口径**：不说"性能很好"，说"20 并发不超卖（注入回查延迟 75s 后仍只扣一次）"。
2. **坑比成果值钱**：主动讲事故与修复顺序（现象→根因→修复→验证），但**别把自写缺陷包装成团队战绩**。
3. **边界先认**：无 rehash、无向量检索、无 judge、LB 未接线——先认，再讲替代方案。
4. **留钩子**：每段结尾抛"想先深挖哪条"，把话语权接回来。

## 六、高频开场追问接法

- "你负责哪部分？"→ 说清边界："交易一致性链路我主导，平台运维协同；AI 项目从 0 到 1 我主导。"
- "最难的是什么？"→ 挑王炸清单，并在 90 秒内讲完"现象→根因→修复→验证"。
- "有什么不足？"→ 主动给边界清单 + 替代方案（对应各题"必须明确的边界"）。
- "为什么离职/换方向？"→ 对齐目标岗位：想做大模型应用工程化落地（Agent/评测/安全）。

## 七、反问面试官（结束环节，选 2-3 个）

1. 团队现在的 Agent/LLM 应用处于哪个阶段：demo、内测还是生产？质量卡点是什么？
2. 评测体系是自建还是用平台？有没有 LLM-judge 的校准实践？
3. 线上变更（模型/Prompt/工具）的审批与回滚流程是怎样的？
4. 团队更缺"业务闭环能力"还是"基础设施能力"？
5. 未来半年这个方向最重要的里程碑是什么？

## 八、使用说明
- 面试前一天：只读第一、四、五节；面试前 30 分钟：读二/三节并按链复述一遍。
- 每次简历改动：回到"跨题连接地图"的 bullet 映射表核对证据。
