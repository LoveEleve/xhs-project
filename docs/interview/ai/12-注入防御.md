# 第12题 | 提示注入与工具安全

> 难度：★★★★★｜频率：★★★★☆｜区分度：高
> 关键词：提示注入、工具白名单、参数校验、危险模式拦截、SEC5 拒答、DLP 缺口

## 问题
Agent 调用工具的安全怎么保证？提示注入怎么防？工具参数被恶意构造怎么办？

## 面试可讲版（五段式）

**① 业界背景**
LLM 应用的攻击面比传统应用多一层：**模型输出不可信**（Prompt 注入可诱导模型调用危险工具/泄露数据）。防御要"纵深"：① 工具白名单（Agent 只能调允许的工具）；② 参数校验与危险模式拦截（rm -rf/删库/敏感路径）；③ **危险操作走 HITL 人工审批**（DLQ 重投、任务触发）；④ 输出侧 DLP（防密钥/敏感信息外泄）；⑤ 审计全链路。

**② 项目选择**
xhs-ai 纵深防御：
- **工具白名单**：4 域 **16 个自研工具**（log_*/metric_*/es_search 等），工具选择评测 12/12；**MCP 20 工具保留运维直连，不参与 Agent 运行**（去依赖，见 13 题）；
- **危险模式拦截**：审批 `patterns` 字段记录命中的危险模式（如危险命令参数），审批服务入库；
- **HITL 审批**：DLQ 重投、任务触发等**变更类操作**必须人工审批（审批记录 + 执行记录 + 审计三段）；
- **输出侧安全**：`SEC5` 拒答/脱敏——正则识别 `sk-`/`ark-`/`glsa_` 等密钥形态；`AnswerEvalService` 评测拒答行为；
- **审计**：所有变更操作哈希链审计（第 10 题）。

**③ 坑**
- **把模型当可信执行体**：模型输出不可信，工具层必须二次校验（参数范围/路径白名单/幂等键）；
- **只防输入不防输出**：用户输入过滤了，但模型可能从**工具结果**里读到敏感信息再输出——输出侧 DLP 必须有；
- **审批绕过**：Agent 直接调底层 HTTP 不走审批就是漏洞——工具注册层统一收口（注册即受控）；
- **DLP 覆盖不全（诚实缺口）**：当前 DLP 只覆盖**密钥形态**（sk-/ark-/glsa_），个人信息/商业数据未覆盖——主动认，作为生产化缺口（第 18 题）。

**④ 兜底**
- 白名单：非注册工具不可调；参数校验在工具实现内（不靠模型自觉）；
- 审批：敏感操作默认走审批，审批记录可审计；审批超时/失败有恢复任务（14 题）；
- 输出：密钥形态拦截 + 拒答；审计门禁（audit-gate）保证记录完整；
- 评测：注入/越权场景进回归（SEC5 场景）。

**⑤ 话术**
> "Agent 安全核心一句话：模型输出不可信，所以工具层白名单 + 参数校验 + 危险操作人工审批 + 输出侧 DLP。我们 Agent 只能调 16 个注册工具，MCP 20 个工具只做运维直连不参与运行；DLQ 重投这类变更必须 HITL 审批，全链路哈希链审计。输出侧目前 DLP 只覆盖密钥形态（sk-/ark-/glsa_），个人信息还没覆盖，这是明确的生产化缺口。"

## 追问与参考回答
**追问1：提示注入和传统注入区别？** 传统注入是构造输入改变程序语义（SQL/XSS）；提示注入是构造输入改变模型行为（诱导调用/泄露），没有完美防御，只能纵深缓解。
**追问2：为什么 MCP 工具不让 Agent 调？** MCP 工具能力大（进程/文件），直接暴露给模型风险高；收窄到自研 16 工具（只读为主）+ 变更走审批。
**追问3：工具参数怎么校验？** 每个工具内做类型/范围/白名单校验（如日志路径限制、命令参数枚举），模型传错直接拒绝。
**追问4：DLP 怎么做？** 输出前正则/词典匹配敏感形态；密钥类已做，PII 未做（缺口）。
**追问5：审批会不会拖慢运维？** 敏感操作低频（DLQ 重投/任务触发），审批代价可接受；高频只读操作不审批。

## 发散追问地图（横向）
- LLM 安全：提示注入、越狱、数据外泄、模型投毒。
- 工具安全：白名单/最小权限、参数校验、沙箱、命令注入。
- 权限：RBAC（15 题）、租户隔离、审计（10 题）。
- DLP：密钥/PII/商业数据识别、脱敏、外发管控。
- 评测：红队场景、注入用例回归、拒答准确率。

## 面试官评分点
**高级开发级**：能讲白名单+审批+审计三件套；知道模型输出不可信。
**架构师加分**：纵深防御分层（输入/工具/审批/输出/审计）；MCP 收窄的取舍；主动披露 DLP 缺口。
**危险信号**：信任模型输出；只过滤输入；审批可绕过；宣称"注入已防死"。
