# 第17题 | 容量与降级设计（10 并发 / 只读模式）

> 难度：★★★★☆｜频率：★★★★☆｜区分度：高
> 关键词：并发闸门、压测 P50/P95/P99、超载 fast-fail、熔断联动、ADR-23 受控只读、设计边界

## 问题
Agent 的容量怎么评估？超载了怎么办？只读模式是什么？

## 面试可讲版（五段式）

**① 业界背景**
LLM 应用的容量与普通服务不同：单请求耗时长（十几秒）、成本随并发线性涨、下游模型有速率限制。所以容量设计要：① **并发闸门**（不是 QPS，是在途请求数）；② **超载 fast-fail**（宁可拒绝不排队到雪崩）；③ **与熔断/预算联动**（降级链路）；④ 明确容量口径（可持续并发 vs 峰值）。

**② 项目选择**
xhs-ai 容量与降级：
- **并发闸门**：`AgentConcurrencyGuard`——**单用户 2 个在途**、**全局 8 个在途**；超限拒绝；
- **压测结论（load-test-20260913）**：
  - C=5：100/100 成功，**P50 13.5s / P95 39s / P99 46.5s**（可持续基线）；
  - C=20：仅 61/100 在 120s 内完成，P99 95.4s，39 个客户端超时中止；**服务端未崩溃未重启**（NRestarts=0）；
  - **超载行为按设计**：模型网关 primary error=8/breaker_open=4、fallback ok=13 → 熔断打开后 fast-fail，约 83 个请求服务端最终完成；
- **容量估算（D07）**：可持续 ~10 并发（端到端时延约束下），与闸门（全局 8）一致；
- **只读模式（ADR-23，设计边界）**：MCP/DB 接入的受控只读查询（三层防护：工具白名单/只读账号/查询限制）——设计已定、**GRANT 脚本在仓库**（`xhs-ai/deploy/scripts/ai-readonly-grant.sql`），v1 未接线；现状更严：服务账号 `myxhs_ai` 仅自身库权限，**业务库完全不可达**（诚实说明）。

**③ 坑**
- **用 QPS 评估 LLM 服务会错**：单请求 10s+，QPS 很低但并发可能已满——必须按**在途并发 + 时延分布**；
- **无限排队 = 雪崩**：超载时应 fast-fail（429/排队上限），不能让请求堆在队列里等 120s；
- **熔断与容量联动**：模型熔断打开后流量走 fallback，容量反而提升（降级链路必须压测过）；
- **闸门值要压测校准**：全局 8 不是拍脑袋，要压测 + D07 估算 + 线上观测三者对齐；
- **"只读模式"别当已上线讲**：设计文档 + 脚本 ≠ 已启用；面试要讲清状态（设计边界）。

**④ 兜底**
- 超载 fast-fail（明确错误码/提示重试）；
- 熔断降级链（primary→fallback→拒绝）已压测验证；
- 并发闸门用户级+全局级双层；
- 观测：在途数、排队时长、熔断状态、超时中止数。

**⑤ 话术**
> "LLM 服务容量不能看 QPS 要看在途并发。我们压测 C=5 是可持续基线：P50 13.5s、P99 46.5s；C=20 就超载了，客户端 39 个超时中止，但服务端没崩——模型网关按设计熔断 fast-fail，最终 83 个请求服务端完成。容量估算 ~10 并发，和全局闸门 8 对齐。只读模式是 ADR-23 的设计边界：工具白名单+只读账号+查询限制三层，脚本在仓库但 v1 没接线，这个状态我会讲清楚。"

## 追问与参考回答
**追问1：为什么 C=20 会超载？** 模型调用是瓶颈（外部 API + 长时延），并发一高排队拉长尾；闸门 + 熔断防击穿。
**追问2：为什么不加机器？** 瓶颈在外部模型通道（速率/配额），加实例也受模型端限制；扩容要配合配额与多通道。
**追问3：超载时用户体验？** fast-fail + 明确提示（稍后重试），比等 120s 再超时好。
**追问4：只读模式怎么设计？** 工具体系分白名单（只读 allow/写 deny）+ 数据库只读账号（GRANT SELECT）+ 查询限制（LIMIT/超时），三层防护。
**追问5：容量和成本怎么平衡？** 并发上限同时受成本预算约束（Token 预算软/硬限），容量规划要把成本算进去。

## 发散追问地图（横向）
- 容量工程：Little's Law、排队论、压测方法、SLO 与错误预算。
- 过载保护：并发闸门/信号量、fast-fail、队列上限、负载卸载。
- 降级：熔断状态机、fallback 通道、分级服务（fast/full）。
- 成本：Token 预算、模型分级路由、批处理。
- 只读/沙箱：只读账号、SQL 限制、工具沙箱。

## 面试官评分点
**高级开发级**：知道 LLM 按并发评容量；能讲超载 fast-fail。
**架构师加分**：压测数据口径（C=5/C=20 行为）；熔断与容量联动；闸门值三方校准（压测/估算/线上）；只读模式的状态诚实表述。
**危险信号**：用 QPS 评估；无限排队；把设计文档说成已上线；无超载演练。
