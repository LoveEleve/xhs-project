# 第15题 | RBAC 与权限边界

> 难度：★★★☆☆｜频率：★★★☆☆｜区分度：中
> 关键词：AiRole、角色解析、JWT role claim、审批权限、403/200 实测

## 问题
Agent 的权限怎么设计？谁能审批？怎么防止越权？

## 面试可讲版（五段式）

**① 业界背景**
Agent 权限比传统 RBAC 多两个难点：① **工具级权限**（不只是接口，哪个角色能用哪些工具）；② **审批权限**（谁能批危险操作）。原则：最小权限 + 角色从身份推导（不信任客户端）+ 服务端强制（不是前端藏按钮）。

**② 项目选择**
xhs-ai RBAC：
- **角色模型**：`AiRole`（角色枚举）+ `AiRoleResolver`（从请求身份解析角色）——角色来源是 **JWT 的 role claim**（网关/用户服务签发），不信任客户端传参；
- **工具权限**：不同角色可用工具集不同（如运维角色可触发任务、普通用户只能只读问答）；
- **审批权限**：HITL 审批要求审批人角色（危险操作不能自助审批）；
- **实测**：admin 角色访问管理接口 403/200 行为实测（非管理角色 403、管理员 200）；
- 与审计联动：谁在什么角色下做了什么，全链路可回链（第 10 题）。

**③ 坑**
- **角色从请求参数取** = 越权漏洞；必须从可信身份（JWT claim/网关注入头）解析；
- **只控接口不控工具**：Agent 的工具调用也要过权限（模型可能被诱导调危险工具，第 12 题）；
- **审批自批**：提交人 == 审批人 要禁止（职责分离）；
- **角色硬编码散落**：集中在 `AiRoleResolver`，避免每个接口各写各的。

**④ 兜底**
- 服务端强制（工具注册层 + 接口层双检查）；
- 非授权统一 403（不泄露细节）；身份不可信则 401；
- 审计留痕（角色 + 操作 + 结果）；
- 测试覆盖：角色矩阵用例（如 admin 403/200 实测）。

**⑤ 话术**
> "权限我们从身份推导，不信任客户端——角色来自 JWT 的 role claim，用 AiRoleResolver 统一解析。权限控两层：接口层和工具层（模型可能被注入诱导调工具，所以工具注册也查权限）。审批要求审批人角色且禁止自批。测试里有角色矩阵，比如非管理员访问管理接口 403、管理员 200。"

## 追问与参考回答
**追问1：RBAC 和 ABAC 怎么选？** 角色少、边界清晰用 RBAC；需要按属性（部门/资源归属/时间）细粒度再上 ABAC。Agent 场景工具级 RBAC 够用。
**追问2：怎么防止审批人越权？** 审批人角色校验 + 职责分离（提交≠审批）+ 审批动作审计。
**追问3：工具权限怎么落？** 工具注册表带允许角色，调用前检查；模型看不到无权限工具（连 schema 都不给）。
**追问4：多租户怎么扩展？** 角色 + tenant 维度双控；当前未做（生产化缺口，第 18 题）。
**追问5：403 和 401 区别？** 401=未认证（你是谁不知道）；403=已认证但无权限；不要用 404 掩盖（除非防枚举）。

## 发散追问地图（横向）
- 权限模型：RBAC/ABAC/ReBAC、最小权限、职责分离。
- 身份：JWT/SSO/OAuth2、claim 设计、令牌信任边界。
- 工具权限：能力声明、动态授权、沙箱。
- 审计：权限变更审计、越权告警。
- 多租户：隔离模型（库/表/行级）、配额。

## 面试官评分点
**高级开发级**：能讲角色从身份推导、服务端强制。
**架构师加分**：工具级权限（不只是接口）；职责分离；模型看不到无权限工具；角色矩阵测试。
**危险信号**：角色从参数取；只控接口；允许自批；403/401 乱用。
