# 第06题 | 稳定性度量与 LLM-judge 偏差

> 难度：★★★★☆｜频率：★★★★☆｜区分度：高
> 关键词：重复运行、pass^k、方差归因、基础设施抖动、judge 偏差（位置/长度/自偏好）、确定性断言、校准

## 问题
问题：Agent 每次回答都不一样，怎么度量"稳定性"？为什么不用 LLM-judge？

## 面试可讲版（五段式）

**① 业界背景**
非确定性是 Agent 评测区别于传统测试的核心。两个主流话题：① **稳定性度量**——单次评测没有统计意义，要重复运行；pass@k（k 次至少一次成功）与 **pass^k（k 次全成功）** 是两种口径，后者才反映"能不能稳定交付"。② **LLM-judge**——用模型当裁判便宜但有系统性偏差：位置偏差（偏好前/后项）、**长度/详细度偏差**（长答案得分高）、**自偏好**（偏好同族模型的输出）、谄媚（顺着问题答）。所以 judge 要么校准，要么只用于开放式、无确定断言的场景。

**② 项目选择**
- **确定性断言优先**：答案级评测用关键词命中 / 引用卡片与代码位置校验 / 拒答安全检测（禁 `sk-/ark-/glsa_/系统提示` 泄漏）——不做 judge，就没有 judge 偏差；
- **部分给分**：轨迹用例 `expected` 集合匹配按命中比例给分、`sequence` 有序子序列（允许探索，关键顺序必须对）——比"全对才算对"更能区分改进；
- **稳定性重复**：代表 4 例 × 3 次运行，均值 **0.917**（12 次里 11 次满分）；**失败必须归因**：那 1 次是客户端 240s 超时（基础设施抖动），单独标注、不混入模型能力统计；
- 评测鲁棒性：空回答自动重试 1 次、单条超时 200s、评测专用用户隔离（见 05 题）。

**③ 坑**
- **把基础设施抖动算成模型失败**：12 次里 1 次超时如果不归因，稳定性会被误读成 0.83——归因分类（模型/工具/基础设施/评测集）是评测报告的基本功；
- **样本量不足却宣称显著**：4 例×3 次是小样本，我们说"均值 + 失败归因 + 冗余度"而不是"统计显著"；
- **评测集漂移**：工具重构（去 MCP 化）后 expected 里的工具名会失效 → 评测集要跟工具版本同步维护；
- **judge 引入后自己就不稳**：同一答案两次 judge 可能不同分——如果将来用 judge，先做 judge 自身的重复性与人工一致性校准。

**④ 兜底**
- 报告落盘 + 门禁回归（`gate.sh` 第 3 步评测门禁为**手动选项** `with-eval`，会消耗模型额度；≥90%/回退 ≥2% 为文档化判定口径）；
- 线上 17 个 `ai_*` 指标（工具耗时/错误率/P95/预算）做兜底观测，离线评测管质量；
- 探索冗余（平均 1~2 个多余调用）作为效率指标一并跟踪，防止"答对但绕远路"。

**⑤ 话术**
> "稳定性的前提是归因：不把超时抖动算成模型失败、不把小样本说成显著。judge 我们刻意没用——能用确定性断言（关键词/引用/拒绝）就不用模型裁判；真要上 judge，先校准它自己的重复性和人工一致性，再谈用它评别人。"

## 追问与参考回答
**追问1：pass@k 和 pass^k 的区别？** pass@k 是 k 次里有一次成功即可（能力上限），pass^k 是 k 次全成功（稳定交付）；Agent 场景更关心后者，尤其生产变更类任务。
**追问2：为什么不用 LLM-judge？** 主指标不用 LLM 自评（缺口清单里 `LLM-judge kappa` 为 0 命中），三层评测都能落确定性断言（关键词/引用/拒答）；judge 的偏差（长度/位置/自偏好）需要校准成本。若有开放式生成场景再引入，且先做一致性校准。
**追问3：如果要用 judge，怎么压偏差？** 成对比较（减少绝对打分漂移）、随机交换位置、长度归一/盲化、跨模型裁判、与人工标注算一致性（如 Cohen's kappa），并监控 judge 自身的重复稳定。
**追问4：温度对稳定性的影响？** 温度越高方差越大；我们 Agent 温度 0.2，评测重复 3 次；要控方差就先控采样参数，再谈模型能力。
**追问5：怎么判断"变好"而不是抖动？** 同一评测集重复跑 + 部分给分 + 失败归因；变化幅度要超过历史抖动区间才算真变化（回退 ≥2% 阻断是设计口径）。

## 发散追问地图（横向）
- 统计方法：重复次数与置信区间、bootstrap、显著性检验；小样本的表达纪律。
- judge 工程：rubric 评分、pairwise、参考锚定（reference-guided）、多 judge 投票、偏差度量。
- 人机一致性：人工标注协议、kappa 系数、仲裁流程；judge 与人工的偏差画像。
- 采样与温度：temperature/top-p 对稳定性、pass^k 的影响；固定 seed 的可用性。
- 生产监控：在线 A/B、canary、影子流量；离线评测与线上指标的对齐。
- 评测考古：评测集污染、数据泄漏、看过答案的模型；评测集轮换与冻结。

## 面试官评分点
**高级开发级**：能说清重复运行与部分给分；能把失败归因讲成流程；知道 judge 的主要偏差。
**架构师加分**：pass@k vs pass^k 的适用、judge 引入的校准方案、评测与线上指标的配合、统计表达纪律。
**危险信号**：单次运行下结论；把基础设施抖动算模型失败；盲目上 judge 不校准。
