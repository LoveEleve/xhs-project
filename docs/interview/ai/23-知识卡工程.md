# 第23题 | 知识卡工程：55 张结构化卡片怎么建、怎么维护

> 难度：★★★★☆｜频率：★★★★☆｜区分度：高
> 关键词：结构化知识、卡片 schema、BM25、引用硬校验、验证问题集、重索引

## 问题
知识库怎么建的？为什么用卡片不用 RAG？卡片会不会过期？质量怎么保证？

## 面试可讲版（五段式）

**① 业界背景**
RAG 的默认路径是"文档切块 + 向量检索"，但对**语料小、标识符密集**的工程知识（类名/表名/topic/配置项）并不优：切块会破坏结构、向量对精确标识符不敏感、召回不可解释。另一条路是**结构化知识卡**——把知识写成"问题→答案→证据锚点"的最小检索单元（人写、可评审、可验证），检索退化为 BM25/元数据过滤，答案天然可引用。

**② 项目选择（卡片工程四件套）**
- **规模与分层（运行态 55 张）**：architecture 11 / business 7 / **code-map 36** / failure 1——代码导航卡占大头，与 `code_locate` 工具配合把"文件:行号"作为证据锚点；
- **卡片 schema（YAML）**：`id/category/priority`（P0 优先）+ `question`（检索入口）+ `answer_shape/serve_mode`（回答形态与投递方式）+ **`entry/state_anchor/sync_boundary/async_boundary`**（把"链路的因果/边界"显式写出来）+ `phases[components...]`（分阶段组件序列）——卡片不只是内容，是**结构化的事实模型**；样例：`inventory-pre-deduct-mainline`（订单→库存预扣主链）；
- **索引与检索**：ES 索引 `xhs_ai_knowledge`，mapping 里 keyword（id/layer/path/category/priority/source_path）+ text（title/question/answer/keywords/content）+ `verified_at` 日期字段；知识工具三件套：`knowledge_catalog`（目录）→ `knowledge_search`（BM25）→ `card_read`（整卡）；
- **质量与维护**：卡片带 `verified_at`（新鲜度）；`architecture-card-validation-questions.yaml` + 验证报告做**卡片质量抽检**（问题能否被卡片本身回答）；`KnowledgeIndexer` 启动时异步重索引 + `KnowledgeController` 提供管理端点手动 reindex。

**③ 坑（主动承认）**
1. **卡片过期**：代码/链路演进后卡会漂移——用 `verified_at` + 验证问题集抽检，但**没有自动化 TTL/一致性检查**（主动承认的缺口）；
2. **粒度两难**：太细（一个类一张卡）→ 检索噪音、维护爆炸；太粗（一张卡讲全链路）→ 答案不聚焦、引用不精确；当前按"一条主链/一个失败模式一张卡"；
3. **标识符分词**：BM25 对中文+类名混合的分词要配 analyzer，否则 `InventoryService` 这类词命中不稳；
4. **code-map 卡会烂**：行号随代码变——`code_locate` 是动态定位，卡片里锚的是文件+类/方法名（相对稳定），行号交给工具实时给；
5. **样本小的陷阱**：hit@1=100% 是 30 条验证问题集的口径，**样本小**，不能外推成"检索质量完美"。

**④ 兜底**
- 引用硬校验：答案层门禁要求"引用必须全部有效"（卡片 id 必须存在）——幻觉引用会被机械拦截；
- 重索引：启动异步 + 管理端点；知识集 git 版本化（可回滚）；
- 评测联动：知识问答 50 条用例走同一条检索链，回归可测。

**⑤ 拷打追问**
1. **"为什么不做向量检索？"** 语料小 + 标识符密集 + 低 QPS；BM25 可解释、够用；向量路径有**触发+止损**规则（hit@1<90% 且失败是词汇不匹配才启动；无 ≥5% 提升即删除）——ADR-3。
2. **"55 张够吗？"** 够支撑当前 34 个场景的知识问答；覆盖缺口用"未命中→补卡"闭环（评测失败案例回填卡片）。
3. **"卡片质量怎么量化？"** 验证问题集（卡片自身应能回答）+ 评测答案层通过率 ≥90% + 引用有效率 100% 三道。
4. **"知识库和日志/日报的关系？"** 不重复：日志检索是工具（实时数据）、卡片是知识（稳定结论）；复杂问题两者编排组合。
5. **"维护成本谁承担？"** 卡片变更走 git（评审后重索引）；但承认目前是"人工+抽检"，自动化新鲜度检查是待办。

**⑥ 话术**
> "我们没走 RAG，而是 55 张结构化知识卡：架构 11、业务 7、代码导航 36、失败模式 1，每张卡是'问题+答案+代码锚点+链路边界'的结构化事实，检索用 BM25 加元数据，知识工具三件套目录、检索、整卡。质量靠三道：验证问题集、评测通过率、引用硬校验——答案必须引用存在的卡片，幻觉引用直接拦截。代码导航卡只锚文件和方法名，行号由 code_locate 实时定位，避免卡片烂掉。边界也清楚：hit@1 100% 只是 30 条样本，且没有自动化过期检查，靠人工和抽检。"

## 面试官评分点
**高级开发级**：能讲卡片 schema/索引/检索工具链。
**架构师加分**：卡片作为"结构化事实模型"的设计（entry/boundary/phases）；引用硬校验防幻觉；向量路径的触发与止损规则；样本小与过期检查的诚实边界。
**危险信号**：无脑上向量；卡片无锚点/无法验证；把 hit@1=100%（30 条）吹成检索完美。
