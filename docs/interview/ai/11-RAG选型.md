# 第11题 | RAG 选型：为什么不做、何时做

> 难度：★★★★☆｜频率：★★★★★｜区分度：高
> 关键词：知识卡、BM25/multi_match、hit@1 门禁、止损决策、向量检索条件、评测先行

## 问题
你们的 Agent 用 RAG 吗？为什么不用向量检索？什么时候才该上向量？

## 面试可讲版（五段式）

**① 业界背景**
RAG 的默认答案常是"上向量库"，但工程上要先问：**知识规模多大？查询是词汇匹配还是语义匹配？** 小规模结构化知识（几十~几百卡）用 BM25/关键词精确匹配的 hit@1 往往就够了；向量的价值在语义泛化（同义改写、跨表述），但代价是：embedding 成本、索引维护、召回不可解释、调参空间大。正确路径是**评测先行 + 止损规则**：先建可量化门禁，达不到再升级检索方案。

**② 项目选择**
xhs-ai 的知识问答：
- **知识卡体系**：A 级知识卡（架构/业务/代码地图三类）+ `xhs_ai_knowledge` 索引（ES）；
- **检索**：`multi_match(question^3, title^2, keywords^2, answer, content)` top3——本质是"加权词匹配"；
- **评测门禁**：`kb-cases.yaml` **30 条用例**（三层各 10），**hit@1 = 100% / hit@3 = 100%**（门禁 ≥90%）；
- **止损决策（核心）**：按 RV09 规则——只有 hit@1 < 90% 且失败以"词汇不匹配"为主时才启动向量/混合实验，且无 ≥5% 提升即止损。**结果 100%，向量实验不启动**——这是"不做"的量化论证；
- 轻量解析做代码导航（v1），复杂 AST/向量化同样按需。

**③ 坑**
- **不评测就上向量** = 花成本买未知收益；向量检索的收益必须用同一套用例对比才能证明；
- **知识卡不是文档切片**：结构化卡片（问题/答案/关键词）比长文档切片命中率高得多——先把知识"结构化"再谈检索技术；
- **评测集要防污染**：用例由知识卡自动生成（期望=卡 id），但要防"答案泄露在问题里"（同义改写）；
- **检索只是入口**：命中后答案质量还取决于卡片内容——检索 100% ≠ 回答 100%。

**④ 兜底**
- 门禁固化：每次变更跑 kb-eval，低于 90% 拒绝（M3 出口门禁）；
- 检索失败降级：无命中给"未找到 + 建议"而不是编答案；
- 扩展路径预留：向量/混合检索的触发条件已写死在 RV09（可执行、可复现）；
- 观测：hit@1/hit@3 指标 + miss 明细。

**⑤ 话术**
> "我们不是不用 RAG，而是先评测再决定技术。知识是结构化卡片，用 ES 加权词匹配 top3，30 条用例 hit@1 是 100%；按止损规则——只有hit@1 低于 90% 且失败以词汇不匹配为主才上向量，且提升不足 5% 就停——所以向量实验没启动。这是量化的'不做'决策，不是拍脑袋。什么时候会做？知识量上来、查询口语化/语义化明显、词匹配开始 miss 的时候。"

## 追问与参考回答
**追问1：BM25 和向量各适合什么？** 词匹配适合术语/ID/精确问法；向量适合同义改写/语义泛化；混合检索兼顾两者（RRF 融合）。
**追问2：怎么证明向量没用？** 同一套 30 用例 A/B 对比 hit@1/hit@3；门禁规则要求提升 ≥5% 才继续。
**追问3：知识卡怎么维护？** 从代码/文档/事故沉淀（架构/业务/代码地图三类），有评审与版本；更新后重跑评测。
**追问4：为什么不用微调？** 微调贵、更新慢、可解释性差；知识更新频繁场景 RAG 更合适；微调适合风格/格式对齐。
**追问5：命中后幻觉怎么防？** 答案基于卡片内容 + 引用回链（可回链结论）；评测里有答案正确性维度。

## 发散追问地图（横向）
- 检索技术：BM25/TF-IDF、向量（embedding/ANN：HNSW/IVF）、混合检索（RRF）、重排（cross-encoder）。
- 知识工程：知识卡/图谱、切片策略、元数据过滤。
- 评测：hit@k、MRR、NDCG、端到端答案正确性、门禁与回归。
- 成本：embedding 增量更新、索引重建、缓存。
- 演进：GraphRAG、Agentic RAG（多跳检索）。

## 面试官评分点
**高级开发级**：能讲清 BM25 vs 向量取舍；知道要评测。
**架构师加分**：**止损规则**（量化地"不做"）；评测门禁固化；知识结构化先于检索技术；升级触发条件明确。
**危险信号**：默认上向量；没有评测就吹效果；把检索命中率当回答正确率。
