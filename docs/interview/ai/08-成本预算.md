# 第08题 | Token 成本与预算三段

> 难度：★★★★☆｜频率：★★★★★｜区分度：高
> 关键词：日预算、软限切换、硬限拒绝、429、预算拦截评测、成本可观测

## 问题
Agent 的 Token 成本怎么控制？预算超了怎么办？

## 面试可讲版（五段式）

**① 业界背景**
LLM 应用最大的生产风险之一是**成本不可控**：一次循环 Agent 可能烧掉十万 Token。业界做法是"预算三段"：**软限降级**（切便宜模型）→ **硬限拒绝**（返回 429 明示）→ **成本可观测**（按用户/会话/模型统计）。关键是预算要在**网关层统一管**，而不是每个调用点自己算。

**② 项目选择**
`TokenBudgetService`（xhs-ai）：
- **日预算按用户**：默认 `500000 tokens/天`（`MYXHS_BUDGET_DAILY_TOKENS`）；
- **软限 80%**：`softLimit = daily × 0.8`，超过后 `ModelGateway` 切 light 通道（`soft_switch`）——便宜模型继续服务；
- **硬限**：达到 100% 直接拒（`hard_reject` → HTTP 429），不静默降级；
- **成本可见**：`cost-week.sh` 按周统计；评测里专门有"预算拦截"场景（预算耗尽时行为是否正确）；
- 预算是"网关能力"：所有模型调用过 `ModelGateway`，预算检查在出口统一做。

**③ 坑**
- **预算用在哪一层**：放业务代码里会漏（新调用点忘加）；放网关出口是唯一收敛点；
- **软限只降级不拒绝**：用户体验优先（继续用便宜模型），但要**明确标识**（响应里带降级标记）——静默降级用户以为还是原模型；
- **硬限的错误语义**：必须 429 + 明确文案（"今日额度已用完"），不能 500 或空响应；
- **统计口径**：输入/输出 Token 都要算（输出通常更贵）；流式响应要等流结束才能准确计数。

**④ 兜底**
- 软限切换：light 通道（`deepseek-v4-flash`）保可用；
- 硬限拒绝：429 + 明确错误码；管理员可调预算；
- 评测覆盖：预算拦截是固定评测场景（防止改坏）；
- 观测：按用户/模型/日的 Token 消耗指标 + 周报。

**⑤ 话术**
> "成本我们做三段：日预算按用户 50 万 Token，80% 软限切便宜模型继续服务，100% 硬限直接 429 明示；预算检查统一放在模型网关出口，避免新调用点漏查。评测里专门有预算拦截场景，防止后续改动把这块改坏。软限切换会带降级标识，不做静默降级。"

## 追问与参考回答
**追问1：为什么软限是 80%？** 留 20% 缓冲给当天尾部请求；比例可配（`MYXHS_BUDGET_SOFT_RATIO`）。
**追问2：多租户怎么做预算？** 当前按用户；多租户要按 tenant 维度加层（预算树：租户→用户→会话）。
**追问3：预算和限流什么关系？** 限流控制速率（QPS），预算控制总量（Token/天）；两者互补。
**追问4：怎么估算一次 Agent 循环的成本？** 系统提示+历史+工具结果+输出，逐轮累加；循环 Agent 要设最大轮数上限（与预算双保险）。
**追问5：流式怎么统计 Token？** 按增量累计；结束时以最终 usage 为准（供应商返回 usage 时优先）。

## 发散追问地图（横向）
- 成本优化：Prompt 压缩、缓存（KV/语义缓存）、模型分级路由、批处理。
- 预算体系：配额分配、预警（80% 告警）、超卖控制。
- 可观测：Token/费用指标（按用户/模型/租户）、成本归因。
- 与限流关系：RPM/TPM 限流、并发闸门（AgentConcurrencyGuard）。
- 商业：计费系统、成本分摊、毛利监控。

## 面试官评分点
**高级开发级**：能讲软/硬限两段；知道预算要在网关统一。
**架构师加分**：软限带降级标识（不静默）；429 语义；评测固化预算场景；预算树演进（多租户）。
**危险信号**：预算散落业务代码；超限静默降级；500 代替 429。
