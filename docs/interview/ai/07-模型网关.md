# 第07题 | 模型网关：重试/熔断/降级

> 难度：★★★★☆｜频率：★★★★☆｜区分度：中
> 关键词：主备通道、传输类重试、流式不可重放、熔断半开、预算联动降级、指标、OpenAI 兼容协议

## 问题
问题：模型调用失败怎么办？重试几次？流式输出到一半断了怎么办？主备模型怎么切？

## 面试可讲版（五段式）

**① 业界背景**
LLM 网关要解决五件事：**多模型路由、配额/预算、重试熔断降级、可观测、协议兼容**。工程共识：① 重试只对**传输类错误**（连接失败/reset/超时）有效，业务错误（参数/鉴权）重试无意义；② **流式响应一旦出流不能重试**（会重复输出增量），只能切换通道让下游重新发起；③ 熔断和重试是配合关系——重试解决抖动、熔断拦住雪崩；④ 降级不能静默（用户要知道"这是备用模型"）。

**② 项目选择**
`ModelGateway`（D01 最小落地）：
- **主/备通道**：primary=`deepseek-v4-pro`（对话）、Agent 通道 `qwen3.8-flash`、light/fallback=`deepseek-v4-flash`；协议走 OpenAI 兼容（`siyu.site/v1`，api-key 环境变量）；
- **重试**：只对传输类错误（`ConnectException`/`HttpConnectTimeoutException`/消息含 "HTTP transport error"/"SSE/NDJSON stream failed" 等，`ModelGateway:178-184`），`max-attempts=2 / backoff=500ms`；**已出流不重试**（防重复增量），改由备用通道接管；
- **熔断**：连续失败 `threshold=3` → 冷却 `60s`，期间直接走备用通道 + 快速失败；冷却结束**半开探测**放一个请求试水；
- **预算联动**：软限（80%）切换 light 通道（`soft_switch`）；硬限直接拒（`hard_reject` → 429）；
- **降级兜底**：主备皆失败 → 错误向上抛（**不返回静默空答复**——空答复是隐性故障）；
- 指标：`ai_model_budget_total`（soft_switch/hard_reject）、failover/breaker_open 计数等。

**③ 坑**
- **流式重试=重复输出**：一定要区分"未出流"（可重试/可降级）与"已出流"（不可重放）；我们选择向上报错让用户重试；
- **重试放大预算**：每次重试都烧 token，`maxAttempts=2` 是"抗抖动"与"成本翻倍"的折中；
- **主备能力差**：pro→flash 降级后回答质量变化要让用户/指标可见（soft_switch 计数），别让"降级"变成静默的质量滑坡；
- **熔断冷却不是恢复**：冷却结束只是半开探测，失败会立刻再次打开；
- 网关没有限流能力时，上游并发会把模型配额打爆——所以要接预算/并发护栏（见 ai08/ai14 系列）。

**④ 兜底**
- 错误分类显式化：传输类重试、业务类直接上抛、预算类 429；
- 指标兜底（降级/熔断都有计数）+ 审计（模型、耗时、token）；
- Agent 侧 `maxIters`/工具预算防单次请求失控；并发护栏防全局打爆；
- 空答复显式报错（不静默）——这条在 ai01 也强调过。

**⑤ 话术**
> "模型网关的核心不是'重试'，是**错误分类**：传输类才重试、流式不重放、预算触发降级而不是崩、主备都挂显式报错。每个降级路径都有指标，用户能感知到质量变化，不会被静默降级骗到。"

## 追问与参考回答
**追问1：为什么重试只做 2 次？** 抖动通常一次就能恢复；次数多预算翻倍且放大尾延迟，尾延迟会拖垮 Agent 整体 P95。
**追问2：流式断流为什么不续传？** 已输出增量无法回滚/去重（客户端已渲染），续传会重复；换通道重放等于重头输出——所以选择报错让用户重试（幂等由前端请求重发承担）。
**追问3：熔断的阈值怎么定？** 连续 3 次失败在模型 API（低频、长耗时）场景足够灵敏；冷却 60s 避免持续打爆；更精细可做错误率窗口，但复杂度收益比不高。
**追问4：主备模型怎么选？** 主=质量优先（pro），备=成本/可用性优先（flash）；Agent 场景用 flash 是"工具循环多、单次输出短"的匹配选择——模型选型按任务特征，不按品牌。
**追问5：和 API 网关的限流什么关系？** 模型网关管"模型配额与降级"，API 网关管"接口流量"；两层都要，防的是不同问题（预算 vs 并发）。

## 面试官评分点
**高级开发级**：能说清传输/业务/预算三类错误的处理差异；知道流式不可重试。
**架构师加分**：降级链设计（pro→light→报错）、指标与用户可见性、熔断与重试配合、模型选型按任务特征。
**危险信号**：什么都重试；流式断流硬重放；降级无感知/静默空答复。
