# 项目 · 内容电商平台（15 微服务 / 27 容器）　【起止时间】｜【项目角色：核心开发 / 稳定性 Owner】

## 项目介绍
内容与交易一体的电商平台：交易侧覆盖商品、购物车、库存、优惠券、订单、支付、结算，内容侧覆盖用户、笔记、Feed、搜索、推荐，另含 IM、通知、计数、网关与认证，共 15 个 Spring Cloud 微服务。基础设施：MySQL 分库分表（订单 4 库 × 4 表）+ Redis Sentinel + RocketMQ + Elasticsearch + ShardingSphere + Canal + XXL-Job，ELK / Prometheus + Grafana / SkyWalking 全链路可观测，Docker 编排 27 容器；配套故障注入、混沌演练与容量压测环境。
负责交易与内容核心模块的设计开发，并主导稳定性优化：商品域与库存域联动、库存一致性（分桶预扣 + 账本对账）、订单分片与事务消息、支付与售后资金链路、优惠券/购物车一致性方案、Feed 推拉结合、IM 跨实例路由、网关安全链、Zone 多活与全链路可观测建设。

## 职责描述（Responsibilities）
- **库存一致性**：Redis 分桶 + Lua 原子预扣 + DB 账本 + 对账兜底的三级扣减路径；并实现 TCC 冻结接口（Try/Confirm/Cancel + fence 状态机，覆盖空回滚 / 悬挂 / 超量拒绝，11 场景实测）；热点 SKU 由滑动窗口自动扩容（2→8 桶）；超时回收用 ZSet 过期索引替代全库扫描（O(N)→O(logN)），且只回退"真正到期"记录（记录物理 TTL 加缓冲，杜绝窗口内支付确认找不到预扣）；幂等占位表 + 7 天清理任务；locked_stock 单独对账（修"幽灵锁"导致的可售虚增）。
- **订单与分布式事务**：RocketMQ 事务消息 + 本地消息表 + Broker 回查保证下单与预扣一致；订单状态全部条件 UPDATE 流转，事件表以序号唯一键 + 乐观锁收敛并发（冲突直接回滚，避免"状态与事件流分叉"）；4 库 × 4 表分片 + 订单号映射表支持非分片键反查，支付表与映射表走独立数据源绕过分片路由，为支付域独立拆分预留；支持零元单（全额券抵扣）直连支付域记账成功。
- **支付与退款**：支付单/退款单双状态机 + 渠道策略化发起与回调；回调结果三态判定（成功 / 失败 / 无法判定），渠道中间态不误判为失败、未知态回 "fail" 让渠道重试；重复回调不改状态（状态守卫幂等，渠道验签为接入真实渠道时的必做项）；超时失败后"迟到成功"条件翻转补偿（自动退款兜底）；退款以"累计退款 = 支付金额"驱动库存回补与退券，回传退款单号实现唯一归属。
- **售后与结算**：售后域仅退款 / 退货退款状态机 + 唯一键防重 + 累计额度校验；应退金额按订单优惠分摊（最大余数法、分为单位整数运算），部分数量按比例向下取整永不超退；同 SKU 跨类型累计上限 + 订单实付上限 + 支付域可退上限三层护栏；恢复任务先向支付域核对退款事实再决策；结算域 T-1 日切生成渠道账单并三方对账（幂等重跑、差异分类挂账与自动收敛、按 (日期,渠道) 锁串行）。
- **优惠券与购物车**：领券的库存校验、限领与扣减收敛进单个 Lua 脚本，配 Outbox 事务发件与 msgId / 唯一键双层幂等（发送失败回滚 Redis + 作废 Outbox，防超发）；购物车 Hash/Set/ZSet 三结构由 7 个 Lua 保证原子（含滑动 TTL），实例内序号 + 时间戳 CAS + CLEAR 屏障解决"清空与并发写"乱序，事件按 userId 分区顺序消费，Redis 丢失可从 MySQL 完整恢复。
- **缓存与搜索**：商品详情布隆过滤器（100 万容量 / 1% 误判）+ 空值缓存 + 逻辑过期异步单飞 + 冷 key 有界等待锁；事务提交后删缓存 + 延迟双删；Canal + MQ 双通道同步 ES，外部版本号拒绝陈旧写（全量重建同样带版本，冲突按"已最新"跳过）、tombstone 防旧消息复活；全量重建断点续传且完成后清零、尾部清理源表已删死文档；search_after 深分页；推荐特征按"有新行为"刷新（不再一次性冻结）。
- **内容与社交**：笔记发布 / 草稿 / 编辑 / 软删（内容与消息同事务）、楼中楼评论、DFA 敏感词与文本同预处理、图片上传魔数校验；点赞 / 收藏 / 关注以 Set / ZSet / 关系表建模 + Lua 原子写入 + 版本窗口防乱序，对账任务修复半成功；10 类计数走 Redis 实时计数 + 5 秒攒批落库，DB 故障回写缓冲、恢复自动补刷。
- **Feed / IM / 通知**：Feed 推拉结合（大 V 发件箱拉模式、普通用户按粉丝批量写收件箱，cursor 断点续推）；IM 会话跨实例 Redis pub/sub 路由（含跨实例踢线：新实例接管路由后定向通知旧实例关闭僵尸连接），离线消息持久副本 + ACK 删除 + 按 msgId 去重（at-least-once）、ticket 一次性消费（握手 GETDEL）、会话 ID 由关系表分配（用户对粒度分布式锁防并发双 ID）；通知按自然日窗口聚合（"等 N 人"），未读 INCR/HINCRBY 双键同 slot + 原子降级 + 对账全量累计防跨批错值；SSE 跨实例定向推送。
- **网关与安全**：WebFlux 8 个 GlobalFilter 组链（Body 缓存 → 日志 → 鉴权 → 染色 → HMAC → 限流 → 灰度 → 版本）；JWT 注入身份并覆盖伪造头；黑名单校验 fail-closed 且区分语义（Redis 故障 503 可重试 vs 真吊销 401）；**可信 IP 单一来源**（网关写入并覆盖 X-Real-IP，下游限流 / 登录锁定只认它，XFF 取末段）杜绝伪造 IP 锁账号 / 绕限流；鉴权与 HMAC 失败分原因打点 + 告警；Sentinel 规则 Nacos 托管 + 真空期兜底；灰度按用户哈希可配比例打标、版本头默认 v1。
- **公共组件与并发边界**：分布式锁只承担效率职责（显式租期、抢锁失败直接拒绝、Redis 异常不降级放行），正确性由唯一键 / 条件 UPDATE / fence 状态机 / 对账兜底；限流与幂等切面按 @Order 组链，Redis 故障 fail-open 但**打点可观测**；Redis 客户端命令超时归入"不可用"并统一 503 语义；连接池按标准键装配、Lettuce 指标接线；优雅停机（先摘流量再停、缓冲刷盘）；Feign 统一禁重试 + 分级超时 + 内部令牌 fail-closed；启动预热框架（分类树 / 热搜 / 推荐池）；沉淀 23 个 @XxlJob 兜底任务与 40 条分级告警规则。
- **稳定性与多活**：同 zone 优先路由（数据面 MySQL / Redis zone 感知、运行时热切）+ 健康检查摘除；Redis 主从切换与双主仿真、MySQL 故障转移演练；发布链路 PID 校验杜绝旧进程"假成功"；配置中心死配置治理与调度任务治理；全链路 traceId、DLQ 治理与容量压测校准。

## 关键结果（Key Achievements）
- **库存**：20 并发预扣不超卖（149→129）、超量请求整单拒绝；TCC 11 场景全通过（幂等 / 空回滚 / 悬挂拒绝 / 超量拒绝 / fence 1→2、1→3）；注入 75s 事务回查延迟后库存仍只扣一次。
- **订单**：8 场景并发对抗全通过（取消 vs 支付自动退款闭环、部分退款累计语义）；分片倾斜治理后 16/16 片均匀（迁移存量 682 行、路由抽查全命中）；Broker 暂停下单无半成品、同单重试仅 1 单。
- **性能**：product 1,074→4,871 RPS（4.5x，P99 50ms）；search 508→1,448 RPS（P99 191→61ms）；home 1,861 RPS / P99 49.6ms；user info 5,846 RPS / P99 40ms。
- **内容与计数**：发布保持原子（11ms 写入、3–6s 搜索可见）；1 万次点赞合并为约 2000 个计数 key、一次批量 SQL 落库，注入 DB 故障后恢复自动补刷、增量不丢。
- **一致性与容灾**：缓存更新后 24ms 读到新值；Redis 切主 2.3s 业务无错乱；MySQL 故障转移 RTO≈32s（停主 10.2s / 提升 0.087s / 应用切换 22s）并沉淀 5 项短板与整改路线；对账带双源保护（Redis 缺失时反向重建而非删除）与水位线（跳过在途用户）；订单状态可按事件流重建校准（dry-run + 条件更新修复）。
- **结算与对账**：T-1 日切账单幂等重跑（唯一键 + 条件更新 + 重跑计数）；三方对账三类差异挂账、重复对账幂等、已消失自动收敛；按 (日期,渠道) 分布式锁串行 + 双 XXL-Job 调度。
- **多活与发布**：同 zone 优先在 netem 跨区模拟下吞吐 +34%、P99 降低 33%~47%；发布"假成功"根治后批次重启 11 个服务全部真实生效。
- **治理成效**：15/15 服务真实从配置中心加载配置；被调度器自动禁用、"从未执行"的任务修复后恢复调度（日报 633 条"失败"拆解为调度失败 / 未上报 / 真实业务失败 2 条）；告警规则 31→40 条分级 + SLO 错误预算落地。
