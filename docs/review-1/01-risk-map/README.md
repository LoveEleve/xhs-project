# 01-risk-map

## 目标

先建立全局风险地图，避免一开始就陷入局部代码细节。

## 这里放什么

1. 系统级风险分类
2. 每类风险涉及的服务集合
3. 关键入口、关键状态、关键依赖
4. 风险传播路径
5. 最坏影响与优先级

## 建议结构

- `system-overview.md`：全局调用/边界总览
- `risk-categories.md`：风险分类与优先级
- `critical-paths.md`：核心业务路径

## 风险分类建议

1. 身份与权限边界
2. 订单/支付/库存一致性
3. 内容传播与搜索索引一致性
4. 消息重复、乱序、漏消费
5. AI 接口的身份、限流与外部依赖
6. 运维脚本、配置漂移、环境不一致

## 输出要求

- 用图谱思维写，不写代码细节
- 每条风险都要指出涉及服务
- 每条风险都要说明权威状态在哪里
- 每条风险都要有“最坏情况”描述
