## 本轮没有发现的误判

1. F-007 不是“可能漏回补”，而是多 SKU 订单必然只处理第一个 SKU。
2. F-010 不是普通幂等返回，而是会直接误导 payment compensation 判断。
3. F-016 不是单纯库存延迟，而是数据库事务可能提交用户券而不扣模板库存。
4. F-024 不是短暂滞后，而是每次全量重建都主动写零。
5. F-042 发生在正常 Canal 增量链路，不仅是补偿任务问题。

## 测试缺口结论

之前回归没有发现这些问题，主要不是测试数量不足，而是测试层级不对：

1. 只测 API response，不验证 DB/Redis/MQ/ES 最终状态。
2. 只测单 SKU/单用户/单消息，不测多 SKU/重放/乱序/长故障。
3. 不注入 Feign、Redis、MQ、ES、mapping 数据源故障。
4. 不执行或不校验 XXL-Job/补偿任务的真实产物。
5. 一部分脚本绕过 gateway，无法验证真实服务边界。

## 结论

第二轮复核没有推翻主线清单，但将以下问题明确标为“运行态量化”而非代码级确定：

- F-004、F-005、F-012、F-015、F-025、F-037、F-038、F-040

在完成这些运行态验证之前，不应开始修复实施，也不应声称“全项目无遗留问题”。
