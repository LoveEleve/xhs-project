## 2. 运行态已证实

### F-007：多 SKU 退款只回补一个 SKU

隔离订单两个 SKU 实测：

- 调用真实退款成功回调返回 200
- order 日志将两个 SKU 都记为回补成功
- inventory 日志显示订单级幂等键导致后续 SKU 跳过
- MySQL inventory 未发生对应回补

### F-010：退款成功回调吞掉订单侧失败

隔离订单保持待付款状态，调用退款成功回调：

- HTTP 200
- `success=true`
- 订单状态仍为 0

### F-016：无库存仍可生成用户券

隔离模板实测：

- MySQL `remain_count=0`
- Redis stock=1
- 真实领券接口返回成功
- MQ 消费后用户券落库
- 模板 remain_count 仍为 0

### F-039：BFF 将依赖故障伪装成业务 404

product 服务停止期间调用 home 商品聚合：

- 外层 HTTP 200
- body 业务码 404
- message 为“商品不存在”

### F-009：退款补偿持续重复处理

payment 日志已观察到同一补偿任务连续多个 3 分钟周期重复处理 5 条退款记录，去重键未生效。

## 4. 需要合并理解的根因

### 4.1 回调成功语义丢失

F-006、F-009、F-010、F-036 共同体现：

- 下游失败时返回成功或直接 ACK
- 补偿任务无法判断真实状态
- 失败消息无法进入可恢复路径

### 4.2 衍生状态覆盖权威状态

F-004、F-005、F-012、F-023、F-024、F-025、F-037 共同体现：

- Redis/DB/ES/Outbox 使用不同粒度
- 计数、库存、索引文档存在多个来源
- 补偿路径没有复用主路径的权威状态模型

### 4.3 测试只验证接口，不验证收敛

F-007、F-008、F-010、F-016、F-023、F-024、F-039、F-041 都没有被原有回归发现，原因是：

- 单服务 mock 掉关键副作用
- 只测 HTTP 响应
- 不注入依赖故障
- 不执行补偿任务
- 不核对 DB/Redis/MQ/ES
- 不覆盖多 SKU、多消息、长故障窗口
