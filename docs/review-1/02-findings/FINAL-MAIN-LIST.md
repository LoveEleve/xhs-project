# 最终版主问题列表（业务 / 工程 / 分布式主线）

> 说明：这份清单是在 F-001 ~ F-043 的基础上做过合并、降噪、交叉复核后的主问题列表。
> 目标不是罗列所有症状，而是保留真正需要团队投入修复的一线问题。

## A. 资损 / 状态不收敛（最高优先）

### A1. 多 SKU 退款只回补一个 SKU
- 主问题：`F-007`
- 根因：退款回补幂等键只按 `orderId`，而订单侧按 SKU 循环调用库存回补。
- 影响：库存确定性少账，直接影响后续交易。

### A2. 退款成功回调成功语义丢失
- 主问题：`F-010`
- 关联：`F-009`
- 根因：订单侧退款成功回调无条件返回成功，补偿任务误判为已收敛。
- 影响：钱已退但订单/库存/优惠券状态长期分叉。

### A3. 补偿消息会被吞掉
- 主问题：`F-006`
- 关联：`F-036`
- 根因：缺少路由映射时补偿消费者直接 return，不重试；映射补录窗口又只有 1 小时。
- 影响：释放库存/退券等补偿永久丢失。

### A4. 退券链路不可靠
- 主问题：`F-008`
- 关联：`F-016`, `F-038`
- 根因：MySQL 提交后 Redis 失败无补偿；领券消费者不检查模板库存扣减结果；券对账只看启用未过期模板。
- 影响：券库存、用户券、Redis remain_count 持续分叉。

## B. 微服务边界与业务语义错误

### B1. 身份撤销在直连端口失效
- 主问题：`F-001`
- 根因：Gateway 查黑名单，但服务端 trust filter 不查。
- 影响：注销、删号、改密后的旧 token 在直连服务端口仍可用。

### B2. 共享管理/内部令牌模型过粗
- 主问题：`F-002`, `F-003`
- 根因：管理端点/内部调用依赖共享 token；order Feign 还保留公开 fallback。
- 影响：一旦令牌泄漏或配置漂移，跨服务越权面很大。

### B3. AI 会话归属与任务取消权限缺失
- 主问题：`F-013`
- 根因：conversation list/detail 不按当前用户校验；run cancel 无角色边界。
- 影响：跨用户读会话、取消他人任务。

### B4. 互动写操作在目标校验异常时放行
- 主问题：`F-043`
- 根因：like/favorite 调 content 校验失败时降级放行。
- 影响：已删除/不可见内容仍可产生互动、计数和通知副作用。

### B5. BFF 把依赖故障伪装成业务空/不存在
- 主问题：`F-039`
- 根因：home 聚合层将 product/user/cart 下游失败折叠为 404 或空购物车。
- 影响：前端与监控误判业务状态。

## C. 搜索 / 推荐产物错误

### C1. 商品索引正常增量链路也会写坏文档
- 主问题：`F-042`
- 关联：`F-023`
- 根因：product Feign 补全字段失败时，仍继续写 ES；补偿任务本身也会构造半成品文档。
- 影响：搜索结果价格、分类、主图错误。

### C2. 全量重建会系统性清零笔记计数
- 主问题：`F-024`
- 关联：`F-012`
- 根因：全量重建把 like/collect/comment 直接写 0；增量索引又可能读到滞后 counter 值。
- 影响：hot 排序和内容展示退化。

### C3. 推荐行为与离线产物存在“假成功”
- 主问题：`F-021`, `F-041`, `F-025`
- 根因：行为写库失败静默吞掉；推荐任务内部失败仍向 XXL-Job 报成功；质量分继续读滞后计数源。
- 影响：推荐结果质量下降但平台看起来正常。

## D. 分布式补偿 / 平台假成功

### D1. 库存补偿粒度和分桶语义不一致
- 主问题：`F-004`, `F-005`, `F-037`
- 根因：确认事件无可靠重试凭据；Outbox 唯一键不含 action；补偿固定回 bucket0。
- 影响：locked_stock 虚高、异常时序覆盖、分桶失真。

### D2. 运维脚本与监控存在假成功路径
- 主问题：`F-014`, `F-030`, `F-031`, `F-032`, `F-040`
- 根因：健康检查误命中旧实例、compose 失败被吞、mysqldump 失败伪成功、RocketMQ up 指标假阳性、FeedCleanup 节流失效。
- 影响：发布、恢复、巡检、监控都可能给出错误结论。
