# 为什么多轮回归没有发现主线 Bug

## 1. 用例模型偏 happy path

现有 curl 回归主要验证：

- HTTP 是否返回预期状态码
- 主流程字段是否存在
- 单用户、单订单、单 SKU 的同步接口是否成功

但本轮 Bug 多发生在：

- 下游超时/异常
- MQ 发送失败/重复/乱序
- mapping 缺失
- Redis/ES 写入失败
- XXL-Job/补偿任务运行后
- 多 SKU、多实例、多步骤交叉

## 2. 测试入口与生产入口不一致

部分 `full-chain-test*.sh` 直接调用 19001~19016 服务端口，并手工注入 `X-User-Id`，没有统一走 gateway。

因此测试没有覆盖真实生产入口的：

- gateway header 注入
- 路由 Rewrite
- 限流
- HMAC/JWT 组合
- AI `/ai-api/**` 入口
- 真实服务边界

## 3. 断言只看响应，不查副作用

必须补充以下断言模式：

```text
请求响应
+ 主库状态
+ Redis 状态
+ MQ/Outbox 状态
+ ES/搜索投影
+ 补偿任务结果
```

当前很多用例只断言 HTTP 200，无法发现：

- F-007 多 SKU 退款漏回补
- F-008 MySQL 与 Redis 退券分叉
- F-010 退款通知被假成功
- F-023/F-042 ES 半成品文档
- F-024 全量重建清零计数

## 4. 未覆盖故障注入

应补以下故障注入矩阵：

| 故障 | 目标问题 |
|---|---|
| product Feign 超时 | F-042/F-039 |
| content Feign 超时 | F-043 |
| Redis 写失败 | F-008/F-043 |
| MQ producer 失败 | F-004/F-021 |
| MQ consumer DB 写失败 | F-006/F-021 |
| mapping 库不可用 | F-006/F-010/F-036 |
| ES Bulk 部分失败 | F-023/F-024 |
| XXL-Job 内部异常 | F-041 |
| malformed message | F-015 |

## 5. 未覆盖复杂业务组合

### 退款

- 单 SKU正常退款
- 多 SKU全额退款
- 部分退款再全额退款
- 退款回调重复
- 退款通知订单服务失败

### 订单

- mapping 写入失败超过 1 小时
- 支付成功与超时关单竞态
- 支付成功后库存 confirm 失败
- 取消/退款/退券并发

### 优惠券

- remain_count=0 时重放领券消息
- MySQL 提交后 Redis 失败
- 下线/过期模板库存对账

### 索引

- product 服务不可用时 Canal 更新
- 增量补偿失败/部分失败
- 全量重建前后计数一致性

## 6. 测试脚本本身的问题

当前脚本存在：

1. 直连微服务端口
2. 手工构造身份头
3. 把 Redis/测试凭据写入脚本
4. 默认只跑正常链路
5. 没有统一的最终一致性等待与断言
6. 没有注入 MQ/Redis/ES 故障的测试开关

## 7. 回归策略应改成四层

### L0：接口契约

验证状态码、字段、参数校验、权限。

### L1：主库状态

验证订单、支付、库存、券、mapping 等主表。

### L2：异步投影

验证 Redis、MQ、Outbox、ES、通知、IM 离线消息。

### L3：故障与恢复

验证超时、重复、乱序、失败重试、DLQ、补偿任务和恢复窗口。

## 8. 通过标准

一个业务用例只有同时满足以下条件，才能算“通过”：

1. 同步接口响应正确
2. 主库状态正确
3. Redis 状态正确
4. MQ/Outbox 状态可收敛
5. ES/通知/推荐投影正确
6. 重复执行不会扩大副作用
7. 失败后能重试或进入可恢复 DLQ
8. 不把依赖失败伪装成业务成功
