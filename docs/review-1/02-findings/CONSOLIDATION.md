## 2. 建议合并/降级的项

### 2.1 合并进“计数源不一致”主题

- **F-012** NoteIndexSyncConsumer 读 counter 旧源
- **F-025** RecommendComputeJob 读 t_counter 做质量分

这两条本质是同一个根因：

> analytics 权威源 与 counter/t_counter 衍生源混用，导致索引/推荐读到滞后计数。

建议保留一个主问题，另一个作为子证据。

### 2.2 合并进“库存补偿与 Outbox 粒度问题”主题

- **F-004** 库存确认失败 locked_stock 虚高残留
- **F-005** 库存 Outbox 唯一键不含 action
- **F-037** 库存补偿固定回 bucket0

这三条本质上都是：

> inventory 的补偿/Outbox/分桶状态机粒度不一致。

建议保留 1 条主问题 + 2 条子证据，避免把 inventory 团队需要一起修的同类问题拆太散。

### 2.3 合并进“部署默认不安全/配置漂移”附录

- **F-017** IM JWT fallback
- **F-018** Redis fallback
- **F-019** 仓库提交真实凭据
- **F-026** Nacos 快照未开鉴权
- **F-033** host 网络
- **F-034** ES 无 HTTP TLS
- **F-035** RocketMQ ACL 静态凭据
- **F-027** 测试脚本固化直连模式
- **F-028** 文档产品化不安全默认值
- **F-020** Gateway query string 落日志

这些属于一大类：

> 运行环境/凭据/网络暴露面与文档习惯共同放大风险。

按用户当前要求，这一组不应抢占主清单的前排，应统一并入“安全与运维附录”。
