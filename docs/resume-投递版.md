# 项目一 · 内容电商平台（15 微服务）｜核心开发 / 稳定性 Owner

## 一、项目背景
面向内容创作者与 C 端消费者的内容电商场景，业务覆盖商品、购物车、库存、优惠券、订单、支付、售后、结算的交易全链路，以及用户、笔记、Feed、搜索、推荐的内容与社交链路，共 15 个 Spring Cloud 微服务。系统在高并发下单、库存扣减、退款结算与内容分发环节面临超卖、数据一致性与性能瓶颈挑战，需要分布式一致性方案与全链路稳定性体系支撑规模化增长。

## 二、项目架构设计
- 基于 Spring Cloud 构建 15 个业务域微服务，交易链路与内容社交解耦、独立迭代；
- MySQL 4 库 × 4 表分库分表（ShardingSphere）+ 订单号映射表，Canal 增量同步 ES 支撑订单与商品检索；
- Redis Sentinel + RocketMQ 构建缓存与消息层，承担高并发削峰与异步解耦；
- 容器化编排 + ELK / Prometheus + Grafana / SkyWalking 全链路可观测，配套故障注入、混沌演练与容量压测环境。

## 三、个人职责
- 负责库存一致性方案：Redis 分桶 + Lua 原子预扣 + MySQL 条件更新落账 + Outbox 兜底；实现 TCC 冻结协议（Try/Confirm/Cancel + fence 状态机，覆盖空回滚 / 悬挂 / 超量拒绝）；
- 主导订单分布式事务与分片：RocketMQ 事务消息 + 本地消息表 + Broker 回查；4 库 × 4 表哈希分片 + 订单号映射表支持非分片键反查；
- 搭建支付 / 退款双状态机与渠道策略 SPI：回调三态判定、状态守卫幂等、迟到成功条件翻转补偿；
- 负责售后与结算：优惠分摊（分单位最大余数法）+ 三层金额护栏；T-1 日切账单 + 渠道对账三类差异自动收敛；
- 负责缓存与搜索同步：布隆过滤器 + 空值缓存 + 逻辑过期单飞 + 延迟双删；Canal→MQ 增量同步 ES + 版本号拒绝陈旧写；
- 推进稳定性治理：Zone 多活仿真（同 zone 优先路由）、混沌演练 7 场景、发布 PID 校验根治"假成功"。

## 四、技术难点与解决方案
**难点一：大促峰值库存预扣超卖，超时回查与重复请求引发重复扣减。**
解决方案：Redis 分桶 + Lua 原子预扣 + DB 条件更新做双重防线，幂等占位表 + TCC fence 状态机保障仅扣一次；20 并发预扣零超卖，注入 75s 事务回查延迟仍只扣一次。

**难点二：订单分库分表后非分片键查询低效、存量迁移分片不均。**
解决方案：哈希取模分片 + 订单号映射表支持反查，支付 / 映射表独立数据源绕过分片路由；迁移存量 682 行后 16/16 片均匀、路由抽查全命中。

**难点三：类加载锁热点导致 92/99 Tomcat 线程 BLOCKED，商品接口吞吐被压在约 1,000 RPS。**
解决方案：定位每请求 Class.forName 的加载锁竞争，改静态桥接；product 1,074→4,871 RPS（4.5x，P99 50ms，无本地缓存）。

## 五、项目量化成果
- 性能：单机压测 product 1,074→4,871 RPS（4.5x，P99 50ms）、search 508→1,448 RPS（2.9x，P99 191→61ms）、user info 5,846 RPS（P99 40ms）；
- 一致性：20 并发库存预扣零超卖；TCC 11 项场景（幂等 / 空回滚 / 悬挂 / 超量）全通过；75s 回查延迟仍只扣一次；
- 分片与对账：订单 16/16 片均匀、路由抽查全命中；8 类对账任务差异自动收敛；
- 容灾：MySQL 切主 RTO≈32s、Redis 切主 2.3s 业务无错乱、Zone 演练 RTO 1.3~4.8s；
- 稳定性：混沌演练 7 场景全部通过（Redis 不可用、网络延迟 3s、MQ Broker 不可用、CPU 满载、磁盘 IO 高负载、MySQL 不可用、优雅停机）；Redis 双主单侧故障不中断（恢复 ≤35s 追平）。

# 项目二 · AI 研发流水线（Harness）：可执行引擎 + 跨语言技能包｜独立开发（【时间】）

**项目介绍**：把"需求分析 → 编码 → 单测 → 评审 → CI → 部署验证"六阶段流程做成可执行系统的 Java 引擎（6 Maven 模块 / 7,000 行 Java / 158 单测），配套跨语言 Harness 技能包（6 语言 / 30+ 技能 / 约 5 万行文档）。已在 15 微服务电商工程完成真实演练：失败测试被门禁拦截、修复后重试转绿直到 DONE。

1. **变更状态机**：6 阶段转移表为唯一事实源，`StageRun` 唯一键 `(changeId, stage, attempt)`，失败 attempt+1 且历史保留；持久化恢复校验一致性，换引擎实例可断点续跑。
2. **门禁执行器**：ProcessBuilder list 形式不经 shell；stdout/stderr 并发读流防"管道假死"；超时按整棵进程树强杀（Maven 会 fork JVM）；256KB 保尾部截断 + 全量日志落盘。
3. **假绿与变异门禁**：测试门禁 fail-closed（无汇总 / 0 测试 / 全跳过一律判红）；覆盖率解析 JaCoCo XML（关闭外部 DTD 防 XXE）；PIT 变异得分识别"假测试"；增量覆盖率只卡变更行。
4. **证据链**：变更目录自包含（状态 / 事件流 / 版本化产物 / LLM 原文）；原子写入；changeId 白名单防路径穿越；事件流 SHA-256 链 + `verify` 定位篡改行。
5. **HITL 与并发**：LLM 规格草案人工 approve 后才能编码（未审批推进返回退出码 3）；per-change 跨进程 FileLock + 进程内 Semaphore；save 文件版 CAS。

**关键成果**：故障注入 7 类 100% 检出、5 项基线零假阳性；xhs 真实演练 94 tests / 1 failure 被拦截 → 修复转绿（行覆盖 22.0% ≥ 20%）；158 单测全绿；证据包 60+ 文件。
