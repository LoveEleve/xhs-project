# Phase 14: 微调 + 领域适配

## 前置依赖

- **Phase 2 (LLM原理)**：理解 Transformer 架构
- **Phase 3 (RAG)**：知悉 RAG 局限才知道什么时候微调

## 定位

微调是"锦上添花"——RAG+Agent 解决 80%，微调解决 20%。57% 岗位提及（多为加分项）。本 Phase 目标：知道什么时候微调、怎么微调、怎么评估。

## 与 my-xhs 的关联

| 微调场景 | my-xhs 数据源 | 目的 |
|---------|------------|------|
| 运营报告风格微调 | Phase 7-9 的 Agent 对话日志 | 让 Agent 输出的运营分析报告风格一致 |
| 意图分类微调 | 评测集中的用户问题分类标注 | 小模型做意图路由，降低推理成本 |
| 拒答/确认微调 | 高风险操作的 HITL 确认数据（Phase 7/11/13） | 教会模型"该拒绝就拒绝" |

## 学什么

## 生产工程问题

| 问题 | 本 Phase 如何解决 | 验证方式 |
|------|-----------------|---------|
| **过拟合** | 训练集 vs 验证集 loss 曲线监控+早停（patience=3） | 验证集 loss 不升反降 |
| **灾难性遗忘** | 微调前后通用能力评测（保留集 20% 通用数据）+遗忘率 < 5% | 通用评测分数下降 < 5% |
| **幻觉**→微调引入 | 微调后幻觉率对比（与 Phase 9 评测集对照）+若升高则回退 | 微调后幻觉率 ≤ 微调前 |
