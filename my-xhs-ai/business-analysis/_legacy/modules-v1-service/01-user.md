# 01. 用户域（my-xhs-user）业务逻辑

> 服务端口 19001 | 端点：U01-U16、U-B1~B3 | 核心库 my_xhs_user

## 一、业务定位
平台所有用户身份的**入口与权威源**：注册、登录、Token 生命周期、个人信息、地址簿、黑名单（屏蔽）。

## 二、核心状态机
```
未认证 ──获取验证码+登录──→ 已认证
                             ├── Token过期 → refresh换新access（旧入黑名单）
                             ├── 登出 → access+refresh 双入黑名单
                             └── 改密 → 全部活跃Token入黑名单，强制重登
```

## 三、关键业务规则 / 不变量
1. **登录密码锁定**：连续 5 次密码错误 → Redis `login:lock` TTL 15min；计数成功时清除。
2. **验证码一次性**：get+delete 必须原子（防止并发重复使用）。
3. **地址簿**：上限 20 条；首个自动为默认；设新默认则旧默认取消；删默认则剩余首个升级。
4. **屏蔽**：不能屏蔽自己；取消屏蔽幂等；仅 Redis Set 标记，不删物理数据。
5. **缓存一致性**：改资料用**延迟双删** + MQ 兜底（写库后立即读可能命中旧缓存）。

## 四、异常路径
- 验证码错误 / 失效 → 明确报错（key 已删，二次使用也失败）。
- 用户名不存在 / 密码错误分级计数 → 锁定。
- 改密需先校验旧密码，成功后所有 Token 失效。

## 五、对 AI 项目（指标/诊断）的价值
| 指标 | 来源 | 数据就绪度 |
|------|------|-----------|
| DAU/MAU、日注册、登录成功率 | t_user + Redis | ⚠️ 需汇总投影 |
| 登录失败/锁定趋势（异常爆破） | Redis login:fail / lock | ⚠️ Redis 易失，需日志/事件化 |
| 屏蔽列表规模 | Redis Set | ⚠️ 非持久化 |
| 地址/资料完整度 | t_user_address | ✅ |
