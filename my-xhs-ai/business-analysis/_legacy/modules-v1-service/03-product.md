# 03. 商品域（my-xhs-product）业务逻辑

> 端口 19006 | 9 端点（SPU 5 + SKU 3 + 分类 1）+ 搜索端点 | Canal→MQ→ES

## 一、业务定位
**电商支柱的商品主数据**：SPU（商品）/ SKU（规格）模型、三级分类树、商品上下架、通过 Canal 同步到 ES 供搜索。

## 二、核心状态机
```
创建SPU → 默认上架(status=1)
  ├─ 更新 → 删Redis缓存
  ├─ 上下架 → status=0|1，删缓存
  └─ 查询 → 布隆→Redis逻辑过期→MySQL
```

## 三、关键业务规则 / 不变量
1. **1 SPU : N SKU**（颜色/尺寸等规格）；批量查询 SKU 单次限 1-100（防 IN 过大）。
2. **三级分类树**：level1/2/3，Redis 缓存 2h 递归构建。
3. **缓存策略（逻辑过期）**：返回旧值 + 异步重建 + 互斥锁防击穿；布隆过滤器防穿透。
4. **ES 同步链路**：MySQL → Canal(flatMessage=false) → MQ → Consumer → ES；延迟 <1s；凌晨 4 点 IndexRebuildJob 全量兜底。
5. **读写一致性**：更新后延迟双删，写后读走主库（@Transactional）。

## 四、异常路径
- 布隆缺失 → 异步重建（锁保护），期间直查 Redis→MySQL。
- Canal→ES 延迟 → 搜索可能短暂查到旧数据（正常延迟 <1s）。
- MySQL 不可用 → 所有读 500，写直接失败（无降级，靠缓存兜底读）。

## 五、对 AI 项目（指标/诊断）的价值
| 指标 | 来源 | 数据就绪度 |
|------|------|-----------|
| 上架商品数、分类分布 | t_spu/t_sku/t_category | ✅ |
| 商品缓存命中率 / 穿透 | Redis + 布隆 | ⚠️ 需观测 |
| 商品维度的订单/退款归因 | 关联 t_order_item | ⚠️ 退款缺商品级明细 |
| 下架商品对订单的影响 | t_spu.status | ✅ |

> 商品本身偏主数据；其真正的业务价值在「与订单/退款/库存联动」的诊断，需跨模块关联。
