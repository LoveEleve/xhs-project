# 数据保护与 PII（Data Leakage / 观测与审计分离）

## 风险
AI 系统把敏感数据送进 LLM 上下文、写进 trace/日志 → 数据泄漏。my-xhs 含手机号、地址、密钥等。

## my-xhs 现状（已有的有利基础）
- 业务 VO 已脱敏：如 `receiverPhone` 返回 `138****1234`（后端已做）。
- 鉴权四层：JWT + X-User-Id + X-Admin-Call + X-Internal-Call；`@Value` 敏感配置不落日志。
- 观测与审计概念已在项目出现（trace 用 SkyWalking）。

## AI 安全要求（本支柱补充）
1. **数据最小化优先**：工具只返回诊断所需**聚合**数据，不返回用户明细/PII；"先最小化，再谈脱敏"。
2. **工具输出脱敏**：进入 LLM 上下文前，PII（手机号/地址/身份证/银行卡）识别 + 脱敏（手机号→`138****1234`）。
3. **trace/日志/评测产物**：不得含密钥、原始敏感 Prompt、未脱敏 PII。
4. **观测与审计分离**：
   - 调试 trace：可采样、按策略可删除。
   - 合规审计：完整、访问受控、独立保留策略、防篡改（哈希链）。
   - 两者用 `runId/traceId/policyDecisionId` 关联，但**不混入同一索引**。
5. **记忆/Prompt 落库**：会话摘要、长期记忆不得存 PII；支持 TTL、来源、删除。

## 验收
- 关键固定 PII 样例泄漏 = 0。
- 统计识别报告 precision/recall（不承诺"100% 识别"）。
- 密钥扫描 + trace 采样检查在 CI 门禁内。
