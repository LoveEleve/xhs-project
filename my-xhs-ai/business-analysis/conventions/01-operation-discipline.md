# 操作纪律卡（Operation Discipline）

> 版本：v0.1 | 日期：2026-08-10
> 定位：**一页能读完的协作纪律**，约束"AI 与用户如何协作推进 my-xhs-ai 项目"。精简版。
> 来源：借鉴 microsphere-extraction/talk-method 方法论，按"构建生产级 Agent 项目"场景适配（非知识提取）。
> 与 `00-conventions.md`（口径/权限/数据边界）互补：本文件管**操作方式**，00 管**内容约定**。

---

## 1. G0 盘问闸（动手前对齐）
- **动手前** / **每个新单元前** / **出现方向性分歧时**（你说"不对/不理解/感觉不够"），先一问一答对齐：**范围 / 深度 / 顺序**。
- **达成共识才开工**。不自行判定"可以了"就动手。

## 2. 事实自查，决策等你（分工铁律）
- **AI 自己查**：代码/文件/版本/依赖/事实 → 用 bash/grep/glob/MCP 查，**不问用户**。
- **等你定**：范围、深度、优先级、目标读者掌握度、任何"要不要/选哪个" → **绝不 AI 自答**。
- 自答决策 = 破坏纪律。

## 3. 逐单元小步 + review 门（防批量）
- **一次只做 1 个单元**（一篇文档 / 一个模块 / 一个阶段）。
- 每单元完成后**停下来交你 review**，你确认后才进下一个。
- 禁止一次性批量生成多个单元（质量崩塌源头）。

## 4. 需求→自主设计→参考→对比（防"只翻译"）
- 做任何能力：**先想"解决什么生产问题" → 我若实现会怎么设计 → 再对照参考（LangChain4j/opencode/pi/开源只是参考，不是本体）→ 记录差异与取舍**。
- 参考是参考，不是知识本体；知识本体是"需求 + 自主设计 + 取舍"。

## 5. 统一标记约定
| 标记 | 含义 |
|------|------|
| `[待验证]` | 未用源码/事实确认，需核对 |
| `[BLOCKED]` | 阻塞（依赖未就绪）|
| `[缺口:{概念}]` | 知识/数据缺口 |
| `[跳过:{原因}]` | 明确跳过（不静默遗漏）|

## 6. 进度与交接（跨会话）
- 关键阶段推进后，记录**进度**到 `08-execution/`（或对应阶段目录）。
- 重要会话结尾更新 `progress/` 或交接要点，保证下次能接续。

## 触发信号
你说 "盘问 / 先对齐 / 你确定吗 / 理解对吗 / 不对 / 等等 / 我听不懂" → 进入盘问/重述模式，**先对齐再继续**。

## 一句话
> **先对齐、小步走、你review、事实自查、决策你定、参考只是参考。**
