# T14 外部方案对照：Anthropic / OWASP / Promptfoo / Temporal / Langfuse

> 日期：2026-08-18 | 用途：把 `my-xhs-ai` 与外部代表性方案做收官对照，回答"为什么这样做、为什么没那样做"。
> 范围：只比较与本项目直接相关的五个维度：编排、治理、安全、评测、Durable、可观测。

---

## 一、先给结论

`my-xhs-ai` 的路线不是脱离业界自说自话，而是对主流实践做了**收敛式采纳**：

1. 采纳 Anthropic 的 Workflow/Agent 分层、ground truth、停止条件、复杂度后置原则；
2. 采纳 OWASP LLM Top10 的风险视角，重点覆盖越权、输出处理、预算失控；
3. 采纳 Promptfoo 的声明式评测思想，但执行层保留本地 JUnit；
4. 采纳 Temporal 的 Durable 价值，但当前只自研实现单服务子集；
5. 采纳 Langfuse 的可观测目标，但当前先以 run 级指标和评测报告落地。

这五项共同说明：当前项目不是"没见过外部方案所以自研"，而是**先用最小控制面完成可验证闭环，再决定是否引入重平台**。

---

## 二、对照方法

本文只回答三个问题：

- 外部方案解决什么问题；
- `my-xhs-ai` 当前已经覆盖了什么；
- 还缺什么，以及为什么当前不急着补。

评估标准固定为：

- 是否提升编排质量；
- 是否提升治理/安全边界；
- 是否提升评测可重复性；
- 是否提升 Durable 能力；
- 是否提升可观测与面试叙事。

---

## 三、Anthropic：编排方法论对照

### 3.1 采纳点

Anthropic《Building Effective Agents》对本项目最有价值的不是某个框架，而是三条原则：

- 先区分 Workflow 与 Agent；
- 先做最简单可测的方案；
- 让 Agent 持续回到环境中取 ground truth，而不是只靠语言推测。

`my-xhs-ai` 的对应实现是：

- 固定查询走确定性工具路径；
- 归因与排障走受限 Agent；
- Agent 只能基于 MCP/工具证据给结论；
- 有步骤、Token、成本三重停止条件。

### 3.2 不直接照搬的点

Anthropic 文档里更开放的 Agent 形态，默认面对的是更宽泛的助手任务；`my-xhs-ai` 则是企业诊断 Agent，天然更重视：

- 权限边界；
- 证据链；
- 数字一致性；
- HITL；
- 拒答而不是硬答。

所以当前不采用 CodeAct、任意执行、开放写操作，也不把"更像助手"当成优化方向。

### 3.3 结论

Anthropic 给本项目提供的是**编排哲学**，不是可直接替换的产品。当前路线与它一致的地方已经够多，剩余价值主要体现在：

- 模型分层 routing；
- 更系统的 ACI/工具误用分析；
- 更强的多轮上下文工程。

## 四、OWASP：治理与安全对照

### 4.1 已覆盖

`my-xhs-ai` 当前最贴近 OWASP 的部分，不是扫描器，而是架构兜底：

| 风险 | 当前对应机制 | 现状 |
|------|-------------|------|
| LLM01 Prompt Injection | allowlist + 参数白名单 + deny-by-default | 已覆盖 |
| LLM05 Improper Output Handling | 结构化决策 + 存在性校验 + 数字一致性 | 已覆盖 |
| LLM06 Excessive Agency | L1/L2 只读 + L3 审批/拒绝 | 已覆盖 |
| LLM10 Unbounded Consumption | maxSteps/maxTokens/maxCost | 已覆盖 |

### 4.2 仍是边界项

仍然没有完全补齐的是：

- LLM03 供应链的系统化 SBOM/依赖扫描资产化；
- LLM07 Prompt Leakage 的专题红队用例；
- 更完整的可审计安全事件流。

### 4.3 结论

OWASP 对本项目的最大价值，是帮助用户和面试官理解：这里的安全不是"提示词写得更严厉"，而是**越权无法绕过工具治理层**。这一点已经是当前项目的重要卖点。

## 五、Promptfoo：评测体系对照

### 5.1 一致点

Promptfoo 强调：

- 用例声明式管理；
- 自动回归；
- 红队分类；
- 结果可比较。

`my-xhs-ai` 当前已经有：

- `cases.yaml` 与 `cases-regression.yaml`；
- `EvalRunner` / `EvalGate` / nightly 报告；
- 数字一致性、证据存在性、拒答边界等断言；
- 100 条 nightly 首跑归档。

### 5.2 为什么当前不用 Promptfoo 作为主执行层

原因很直接：

- 当前主项目是 Java；
- JUnit 本地执行更贴近现有工程流；
- 真实工具、真实库、真实模型接入已经在当前测试链路里闭环；
- 本地执行避免把业务问句、工具结果和证据外送到 SaaS。

### 5.3 结论

Promptfoo 对本项目更像**评测思想来源**，而不是主执行器。后续如果要补 HTTP 黑盒红队或跨语言评测，可以把它作为补充层，而不是替换当前 JUnit 评测主线。

## 六、Temporal：Durable 能力对照

### 6.1 当前自研覆盖了什么

Temporal 的核心价值是 Durable execution：

- 状态持久化；
- 挂起/恢复；
- 长任务；
- 重试；
- 可测试；
- 可观察。

`my-xhs-ai` 当前已经自研覆盖了其中一个单服务子集：

- Run/Step 持久化；
- checkpoint/resume；
- WAITING_APPROVAL；
- 取消与恢复；
- 终止原因与运行审计。

### 6.2 为什么现在不引入 Temporal

当前不引入的原因不是"不会用"，而是收益尚不足以覆盖复杂度：

- 当前是单服务控制面；
- 工具主要只读；
- 并发规模有限；
- 真实跨服务长工作流还没成为主矛盾；
- 当前阶段重点已转向收官证明，而不是基础设施重构。

### 6.3 什么时候应重新评估

以下条件出现时，Temporal 才会从"可选增强"变成"应认真 PoC"：

- HITL/挂起/恢复跨进程变复杂；
- 真实长任务增多；
- 多服务工作流明显增长；
- 恢复一致性成为频繁故障点；
- 需要更强的可视化运行历史。

### 6.4 结论

当前可以诚实表述为：**我们采纳了 Temporal 的 Durable 价值观，但只实现了适合当前范围的最小子集。**

## 七、Langfuse：可观测与资产化对照

### 7.1 当前已经具备的基础

虽然没有接 Langfuse，但 `my-xhs-ai` 已经不是完全黑盒：

- run 级 token/cost/status 指标已落库；
- 评测报告有 pass/completion/hallucination/divergence；
- nightly 报告、门禁报告、bad case 已归档；
- MCP 有认证/审计日志。

### 7.2 当前缺少的能力

相对 Langfuse，当前明显缺的是：

- LLM trace 可视化；
- prompt 生命周期管理；
- dataset/experiment 操作界面；
- session/user 级观测聚合；
- 更标准化的 OTel/OTLP 接入。

### 7.3 为什么暂不接入

- 当前重点是先证明质量闭环成立；
- 如果没有稳定评测和运行数据，可观测平台只会把不稳定性可视化，而不是解决它；
- 引入 SDK 过早会加重锁定与运维成本；
- 对面试而言，"先自研 run 级指标，再评估 Langfuse/OTel"比无脑接平台更有说服力。

### 7.4 结论

Langfuse 当前属于**后续增量平台**，不是收官阻塞项。它能提升观测和展示，但不改变本项目当前已经完成的工程闭环事实。

## 八、五项方案的总表

| 方案 | 当前采纳 | 当前不采纳 | 对本项目的真实价值 |
|------|----------|------------|--------------------|
| Anthropic | Workflow/Agent 分层、ground truth、停止条件 | 开放式助手形态、CodeAct | 编排方法论 |
| OWASP | 越权/输出处理/预算失控风险视角 | 全量清单式合规包装 | 治理与边界表达 |
| Promptfoo | 声明式评测思想、红队分类 | 作为主执行层 | 评测设计语言 |
| Temporal | Durable 价值观 | 当前主线引入重平台 | Durable 决策标尺 |
| Langfuse | 可观测目标与指标维度 | 当前阶段直接接入 | 可观测升级方向 |

## 九、对面试和作品集的意义

如果面试官问"为什么不直接上现成框架/平台"，最好的回答不是说它们不好，而是：

> 我先把最小闭环做实，再决定是否引入重平台。Anthropic 给了编排方法论，OWASP 给了风险框架，Promptfoo 给了评测语言，Temporal 给了 Durable 标尺，Langfuse 给了可观测目标。当前项目已经把这些方案里最关键的原则收敛到一个受限、可审计、可评测、可恢复的企业 Agent 上；剩下的不是认知空白，而是分阶段引入的工程决策。

---

## 十、本文结论

1. `my-xhs-ai` 不是脱离业界的自研孤岛，而是克制吸收后的收敛实现。
2. 当前最成熟的是编排边界、治理边界和评测边界。
3. 当前最值得补的不是新功能，而是外部对照、状态页、可观测与生产证明。
4. Temporal、Langfuse、Promptfoo 都有价值，但现在更像下一阶段增强，而不是本轮收官前置项。
5. 面试表达上要强调"知道为什么不用"，而不只是"知道有什么可用"。
