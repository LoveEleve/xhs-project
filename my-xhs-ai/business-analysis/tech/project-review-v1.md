## 二、真实缺陷（必须正视，不是克制）

### 2.1 验收闭环是空的
- eval-gate 7/7 失败后**没有修复、没有重跑、没有追查**——这比失败本身更严重
- 行动：跑通 eval-gate（真 key + 真库），修复失败用例，让门禁真实绿一次；跑 2-3 轮校准阈值

### 2.2 部署验证是空的
- Dockerfile 从未构建 → 无法回答"镜像多大/启动多久/健康检查过不过"
- 行动：找一台有 docker 的机器（或云环境）真实构建 + 启动 + 健康检查，产出验证记录

### 2.3 "真实数据"的诚实度
- 8 单/46 单是测试数据——文档里应该**明确标注**，而不是让"真实 MySQL"暗示生产数据
- 行动：README/handoff 中加"数据状态"节：哪些是生产数据、哪些是测试数据、哪些是快照

### 2.4 EmbeddingClient 手写 HTTP
- 有官方 SDK/Spring 集成可用，手写 HttpClient + JSON 手拼是最"手工"的地方
- 行动：评估换官方 Java 客户端（或至少收敛到独立模块+契约测试），面试时不再被问"为什么不写测试用 SDK"

## 三、克制（可讲成设计，但要会讲）

| 克制项 | 为什么是对的 | 面试怎么讲 |
|--------|-------------|-----------|
| 自研 Harness 状态机 | LangGraph 是 Python 生态；Java 侧无成熟等价物；状态机本身是 Durable 的核心 | "不用框架≠不会：Harness 是 15 步预算三重封顶+崩溃恢复+证据链的状态机，每一层都有测试" |
| 单 Agent 无多智能体 | V1 范围声明（PLAN §1.4），多智能体是复杂度权衡 | 能讲清"什么时候才需要多 Agent"（任务拆解/分工）比"我做了 5 个 Agent 互相聊天"值钱 |
| 无记忆 | 决策点冻结（成本 vs 价值） | 讲清记忆的四态分离（Run/Conversation/RAG/Memory） |
| 单模型红线 | 成本红线，防模型分层引入不可控 | "单一模型保证评测可重复性，分层是 M9 决策点" |
| UI 薄壳 | 只消费 API+SSE，无业务逻辑 | "薄壳铁律：UI 不承载任何推断逻辑，一切数字来自后端证据链" |

> 关键：克制本身不是玩具感来源，**不会讲**才是。上面的每一条都要能展开 2 分钟。

## 四、展示问题（东西有，但呈现像玩具）

1. **没有"一镜到底"的演示脚本**：演示时靠人敲 curl——应该有一个 `demo/` 脚本：一键起服务 → 跑 3 个真实场景 → 自动截图/输出（诊断/证据链/拒答/查日志）
2. **C4 图有，但没有可运行的架构验证**：比如一个"故障注入 + 恢复"的可重复演示（kill -9 恢复续跑）
3. **评测集 21 条**：展示"评测体系"时只有 21 条像样吗？至少扩到 50-100 条（可批量造，成本可控）
4. **成本/容量没有实测报告**：跑了上百个真实 run，但没有一份"token/成本/时延分布"报告——M6 有指标但没产出报告
5. **没有多轮/会话演示**：用户看到的永远是"单问题→滚动回答"，没有追问场景（虽然 V1 无会话，但 DECLINE/证据链可以做成对话感）

## 六、结论

**"玩具感"的根源不是代码质量**（192 个单测、状态机/校验/恢复/门禁都是真的），而是**三个"空"**：

1. **验收空**：门禁 0 通过、镜像未构建、CI 未跑——所有"生产级"声明没有一次真实验收
2. **数据空**：真系统假数据，且没有诚实标注
3. **展示空**：深度都在代码里，没有一个能"当场复现"的演示和报告

**先补"验收真"，再补"展示可见"**——这两件事做完，同样的代码就是"生产级作品"，不做就是"玩具"。克制项不是问题，问题是不让它被看见。
