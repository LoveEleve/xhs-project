# AI/Agent 概念词典（零基础向）

> 目的：让没有 AI/Agent 基础的人，先建立"每个概念是啥、为什么这个项目要用它"的最小认知。
> 定位：**先懂名词再谈实现**。每概念 = 一句话 + 本项目用它做什么。
> 与学习路线配套：`learning-path.md`。

---

## 一、LLM 基础类

### LLM（大语言模型）
- **一句话**：能"预测下一个词"、从而理解/生成自然语言的神经网络大模型。
- **本项目**：负责"听懂运营的问题、决定查什么、把结果讲成人话"。它不知道业务事实，只负责理解和表达。

### Prompt（提示词）
- **一句话**：你给模型的指令/输入文本。
- **本项目**：系统提示词（告诉 Agent 它的角色/规则）+ 用户问题。

### 结构化输出（Structured Output）
- **一句话**：强制模型按固定格式（JSON/Schema）返回，而不是自由文本。
- **本项目**：让模型决定"调用哪个工具、传什么参数"，必须是机器可解析的 JSON，否则没法驱动代码执行。

### 工具调用（Tool Calling / Function Calling）
- **一句话**：模型不是直接答，而是"声明要调用某个函数并给参数"，由程序真正执行后再把结果喂回模型。
- **本项目**：Agent 的核心——它说"查订单量"，程序执行真实 SQL/API 拿到数字，再让模型解释。

### Token
- **一句话**：模型计费/上下文的最小单位（约 1 汉字≈1-2 token）。
- **本项目**：成本预算、上下文窗口、计费的度量单位。

### 上下文窗口（Context Window）
- **一句话**：一次请求能塞进模型的输入上限。
- **本项目**：决定能放多少历史/检索结果；超出要压缩/摘要。

## 二、Agent 推理类

### ReAct（Reasoning + Acting）
- **一句话**：Agent 的核心循环 = "思考 → 行动(调工具) → 观察结果 → 再思考……"直到解决。
- **本项目**：排障 Agent 就是这么调查的——查订单量→看到下降→再查支付/库存→归因。

### Plan-and-Execute
- **一句话**：先规划一整步计划，再逐步执行（对比 ReAct 的每步现想）。
- **本项目**：长任务诊断可先用 Plan 定步骤，再逐条取证。

### PlanAct
- **一句话**：在"规划 + 调用工具"之间切换，比 Plan-and-Execute 更强调边执行边修正计划。
- **本项目**：D4 排障归因的一种可选执行模式（JD15 框架研发高频范式）。

### CodeAct
- **一句话**：用"写代码/执行代码"作为 Agent 的行动方式（而不是仅调工具），能表达更复杂逻辑。
- **本项目**：**V1 不用**（违反"不能生成任意 SQL/PromQL/ES DSL"的底线）；仅 L7 了解。这是安全红线与 CodeAct 的天然冲突点。

### Reflection（反思）
- **一句话**：Agent 生成结果后自我审视、纠正再输出（critique → improve）。
- **本项目**：D6 评测/质量优化可用；先不引入（成本高），只在效果不足时上。

### Router（路由）
- **一句话**：先判断请求属于哪类，再分派给对应处理（指标/观测/RAG/Agent）。
- **本项目**：Intent Router 就是它——D1 起就是架构核心。

### Supervisor-Worker（主管-工作者）
- **一句话**：一个主管 Agent 负责任务拆分，多个 Worker Agent 并行执行并回报。
- **本项目**：**V1 单 Agent 够**，Supervisor-Worker 属 L7 多智能体方向。

### Agent as Tool（Agent 即工具）
- **一句话**：把某个 Agent 包装成另一个 Agent 可调用的"工具"。
- **本项目**：多智能体协作的一种组织方式，L7 方向。

### Checkpoint（断点存档）
- **一句话**：把执行到某一步的完整状态落盘，崩溃/暂停后可从此恢复，不重跑已完成的步骤。
- **本项目**：D5 Durable Execution 的核心——Workflow 每步 checkpoint，Worker kill 后 replay 恢复（JD18 高亮）。

### Agent（智能体）
- **一句话**：能自主规划、调用工具、根据结果决定下一步的程序（不止问答）。
- **本项目**：业务/排障诊断 Agent 是本项目的能力面 A/B 核心。

### Agent Harness（智能体框架/外壳）
- **一句话**：支撑 Agent 跑起来的工程骨架：循环、预算、权限、状态、审计、HITL。
- **本项目**：我们要手写的部分（见 tech-selection）——控制 Agent 边界的关键。

### HITL（Human In The Loop，人在回路）
- **一句话**：遇到敏感/高风险动作时，暂停等人工审批。
- **本项目**：L3 运维动作（重启/重投）必须人工批准，Agent 不能自己干。

### 多 Agent / Multi-Agent
- **一句话**：多个分工的 Agent 协作（如一个查业务、一个查系统）。
- **本项目**：V1 不用，单 Agent 够；出现明确瓶颈才引入（对应 A2A）。

### Sub-agent
- **一句话**：主 Agent 临时派生的子任务 Agent。
- **本项目**：L7 高级选修，单 Agent 不够才用。

## 三、知识与记忆类

### RAG（Retrieval-Augmented Generation，检索增强生成）
- **一句话**：先从知识库检索相关内容，再把检索结果喂给模型作答（带出处）。
- **本项目**：指标字典/Runbook/故障手册问答——口径必须可点击回原文。

### Embedding（嵌入/向量）
- **一句话**：把文本转成一组数字（向量），语义相近的文本向量相近，用于"找相似"。
- **本项目**：RAG 的检索基础；用火山 embedding 模型（D3 建接入点）。

### Chunking（切片）
- **一句话**：把长文档切成小块再向量化/检索。
- **本项目**：把 Runbook/文档按语义切块，保证检索精准。

### 混合检索（Hybrid Retrieval）+ Rerank（重排）
- **一句话**：关键词(BM25)+向量 一起检索，再用重排模型把结果排序。
- **本项目**：D3 提升检索质量，先做基线再优化。

### 权限过滤 / ACL-aware（访问控制检索）
- **一句话**：检索结果按访问者角色过滤——"能看哪些文档"由权限决定，不是检索到什么都给。
- **本项目**：D3 关键——运营只能检索其授权范围（L1/L2 数据不同），防止越权看到敏感观测数据（JD18 高亮）。

### 知识库更新（Index Refresh）
- **一句话**：知识库不是一次建好就不动，需按源文档变更定期/触发式重灌与更新。
- **本项目**：指标字典/Runbook 变更后触发重新 chunk/embedding 并版本化（JD18 高亮）。

### 记忆（Memory）
- **一句话**：让 Agent 跨轮记住信息（会话记忆/长期记忆）。
- **本项目**：会话摘要（短期）；长期记忆按需引入，与 Run State 分开。

### Durable Execution（持久执行）
- **一句话**：长任务把每一步状态落盘，崩溃/重启后能恢复继续，不丢进度。
- **本项目**：V1 用本地状态机 + MySQL Run Store；触发条件成立才引 Temporal。

### Run State / Conversation State（运行/会话状态）
- **一句话**：Run State=一次任务的执行状态；Conversation=一次对话的上下文。
- **本项目**：四类状态分离是架构核心（业务事实/Run/Conversation/Memory 分开）。

## 四、协议与规范类

### MCP（Model Context Protocol）
- **一句话**：标准化的"模型 ↔ 工具/数据"连接协议，让 Agent 统一调用外部工具。
- **本项目**：用官方 MCP Java SDK 暴露业务/观测只读工具（L1/L2）。

### A2A（Agent2Agent Protocol）
- **一句话**：不同 Agent（可能跨团队/跨系统）之间协作的标准协议。
- **本项目**：L7 高级选修——只有出现独立部署/独立所有权的 Agent 才需要。

### Agent Skills（技能）
- **一句话**：把"程序知识+指令+脚本+资源"封装成可复用的技能（SKILL.md）。
- **本项目**：L5 学习，与 MCP 是多对多关系，不是替代。

### SDD（Spec-Driven Development，规范驱动开发）
- **一句话**：先写清楚"行为规范/输入输出/验收标准"，再按规范实现，改行为先改规范。
- **本项目**：每个业务能力先写 Spec（输入/权限/失败行为/验收），再开发。

### Spec（规范/说明）
- **一句话**：一段对"系统应该做什么、什么边界、怎么验收"的精确描述。
- **本项目**：D0 起每个能力都要有 Spec，是评测和验收的锚点。

### TDD（Test-Driven Development，测试驱动开发）
- **一句话**：先写会失败的测试，再写代码让它通过，保证行为可验证。
- **本项目**：确定性工具/权限逻辑用 TDD；契约测试先行。

### API 契约 / 契约测试（Contract Testing）
- **一句话**：约定接口输入输出，并用测试保证实现符合约定。
- **本项目**：工具返回格式、MCP 契约的一致性验证。

## 五、安全与评估类

### Prompt Injection（提示注入）
- **一句话**：恶意输入诱导模型"忽略指令/越权/泄密"。
- **本项目**：安全支柱(C)核心威胁；靠确定性权限兜底，不靠模型自辨。

### Guardrails（护栏）
- **一句话**：在输入/输出/数据上加的安全过滤层。
- **本项目**：注入检测、内容过滤、PII 脱敏、权限守卫。

### PII（个人可识别信息）
- **一句话**：能定位到具体人的信息（手机号/地址等）。
- **本项目**：必须脱敏、不进上下文、不进 trace。

### 幻觉（Hallucination）
- **一句话**：模型编造不存在的事实/数字。
- **本项目**：业务数字由确定性工具产生 + 事实性校验，模型不编造。

### 评测集 / Eval（Evaluation）
- **一句话**：一组"输入+期望"的用例，用来量化模型/Agent 好坏。
- **本项目**：smoke/regression/release 三层评测集，CI 回归。

### 效果评估指标（JD18 高亮：评估体系升为一等公民）
- **一句话**：量化 Agent "干得好不好"的可测指标，不止看"答对没"。
- **本项目**（JD18 列的标准）：
  - **任务完成率**：请求是否在预算内完成目标（不超时/不放弃）。
  - **工具调用准确率**：该调的工具/参数是否选对（含权限是否守界）。
  - **幻觉率**：生成的业务数字是否与确定性工具结果一致（事实性校验）。
  - **响应时延 / Token 消耗 / 运行成本**：性能与成本面。
- **本项目**：D6 把这些指标固化为 Dashboard 阈值（§7.1 SLO）。

### Phoenix / Langfuse（LLM 可观测与评测工具）
- **一句话**：给 LLM 应用做 trace/评测/成本的平台（类似给普通服务的 APM）。
- **本项目**：D6 用 Langfuse + OTel 做 run/step/model/tool trace（已在工程类）；Phoenix 列入评测工具备选调研。

### 红队（Red Teaming）
- **一句话**：主动用攻击手段测系统的安全漏洞（注入/越权/泄漏）。
- **本项目**：D6 攻防深化，用攻击成功率度量。

## 六、工程与部署类

### LangChain4j
- **一句话**：Java 的 LLM 应用开发库（调模型/工具/RAG/Agent 的基础）。
- **本项目**：已定为 V1 主框架。

### AgentScope Java 2.0
- **一句话**：阿里出的 Java Agent Harness（权限/HITL/会话/沙箱开箱即用）。
- **本项目**：验证替代框架（贴合度高但新）。

### Spring AI
- **一句话**：Spring 官方的 AI 抽象。
- **本项目**：挑战者（因需升级 Boot 3.2.5，风险高，未选）。

### vLLM（本地推理）
- **一句话**：自托管/高性能跑开源模型的引擎。
- **本项目**：V1 不用；数据主权/规模成立才引入。

### LiteLLM（多模型代理）
- **一句话**：一个网关统一接多个模型 Provider，管配额/路由/成本。
- **本项目**：多 Provider/配额需求成立时引入。

### 推理模型（Reasoning Model）
- **一句话**：专门会"想很久再答"的模型（如 DeepSeek-R1、o1），输出推理链，准确但慢/贵。
- **本项目**：D4 排障归因可用（如 `doubao-seed-*thinking`/`deepseek-r1`）；日常指标问答用普通模型省成本。

### AgentOps
- **一句话**：把 Agent 当产品运营——trace、指标、成本、评测、告警、版本管理。
- **本项目**：D6 用 Langfuse + OTel 做 run/step/model/tool trace 和 Dashboard。

### 语义缓存（Semantic Caching）
- **一句话**：相似的问句复用上次答案，省 token/延迟。
- **本项目**：高频固定查询（如"今日订单量"）可加，降低成本和延迟；V1 可选。

### Fine-tuning（微调）
- **一句话**：用少量领域数据继续训练模型，让它更懂你的业务。
- **本项目**：L7 高级选修——只有 Prompt/RAG/工具仍解决不了稳定领域模式时才用。

### LoRA（低秩适配）
- **一句话**：轻量微调技术，只训一小部分参数，省算力。
- **本项目**：配合微调使用，属于 L7 实验。

### 量化（Quantization）
- **一句话**：把模型参数压缩成更低精度，省显存/加速，可能略降质量。
- **本项目**：本地推理(vLLM)时才涉及，V1 不关心。
