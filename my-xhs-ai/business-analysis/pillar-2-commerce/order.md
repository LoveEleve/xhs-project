# 订单（状态机 / 转化漏斗 / 分布式一致性）

## 业务问题（AI 能回答）
- 订单量、状态分布、客单价、GMV 趋势。
- 转化漏斗：浏览→加购→下单→支付 断点归因（"订单为什么降"）。
- 超时关单、取消、退款率、异常订单。

## 口径与定义
- **订单状态机（单向不可逆）**：
  ```
  0待付款 ──支付──→ 1已付款 ──发货──→ 2已发货 ──确认──→ 3已完成
     │取消                │退款
     ↘                    ↘
    4已取消              5已退款
  ```
- **分库分表**：`user_id%4` 分库 + `(user_id/4)%4` 分表；`t_order_no_mapping` 全局路由。
- **创建订单（事务消息）**：幂等锁 → 取SKU/库存/券 → 本地事务(order+item+local_message) → 半消息 → 库存预扣 Consumer → 回查兜底。
- **一致性**：EventSourcing(t_order_event) + 本地消息表补偿 + 对账游标 + 延时关单。

## 数据来源与就绪度
| 指标 | 来源 | 就绪度 |
|------|------|:---:|
| 订单量/状态/客单价 | t_order | ⚠️ 分片需汇总投影 |
| 超时关单数 | t_order.status + 日志 | ✅ |
| 取消/退款率 | t_order/t_refund | ✅ |
| 漏斗断点 | 行为+购物车+订单 | ⚠️ 缺粒度 |
| 本地消息表积压/死信 | t_local_message | ✅ |

## 关键不变量 / 可信边界
- 状态乐观锁：`UPDATE status=X WHERE status=Y`，affected=0 并发冲突只成功一个。
- 金额以后端计算为准；库存预扣用 pseudoOrderId 幂等防重复。
- 支付失败/超时 → 自动取消 + 释放库存 + 退券。
- 写后读走主库（@Transactional），防主从延迟旧数据。

## 关联诊断
- "订单量下降"归因需要**转化漏斗**（跨 cart/payment/discovery），且依赖行为数据粒度。
