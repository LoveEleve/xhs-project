# 支柱二：电商交易 — 总览

> 业务定位：平台的**交易与履约闭环**——从商品展示、加购、领券、下单、支付到履约（库存）。AI 在此支柱的价值是**转化、交易健康度与异常诊断**。
> 覆盖服务：product、cart、coupon、order、payment、inventory。
> ⚠️ 这是旧 PLAN V1 三个场景（订单/支付/库存）的所在地，也是**数据缺口最严重**的支柱。

## 业务问题清单（AI 应能回答）

| 业务问题 | 类型 | 就绪度 |
|---------|------|:---:|
| 订单量/状态分布/客单价/GMV | 指标 | ⚠️ |
| 支付成功率/渠道分布 | 指标 | ⚠️ |
| 转化漏斗（浏览→加购→下单→支付） | 诊断 | ⚠️ |
| 退款率、超时关单数 | 指标 | ✅ |
| 库存预扣失败/水位/TCC 异常 | 诊断 | ✅ |
| 优惠券核销/营销效果 | 指标 | ✅ |
| 订单/支付/库存为何异常（归因） | 诊断 | ⚠️ |

## 核心业务闭环
```
浏览商品 → 加购(cart) → 领券(coupon) → 下单(order,事务消息)
  → 库存预扣(TCC) → 支付(payment) → 发货 → 确认 → 完成
  异常：取消 / 退款 / 超时关单 / 预扣失败 / 对账
```

## 关键不变量（本支柱）
1. 订单状态机单向：0待付→1已付→2已发→3完成；4取消/5退款。
2. 分布式一致性：事务消息 + 本地消息表补偿 + EventSourcing。
3. 库存 TCC + Fence 防悬挂 + 超时释放。
4. 金额以后端计算为准（真实 SKU 价 + 真实券折扣）。

## 数据就绪度汇总（关键）
| 数据 | 就绪度 | 缺口 |
|------|:---:|------|
| 订单量/状态 | ⚠️ | 分片需汇总投影 |
| **支付失败原因** | ❌ | 仅 status，无 failCode/failStage |
| 库存/TCC | ✅ | — |
| 券核销/营销 | ✅ | — |
| 退款商品级明细 | ⚠️ | 无商品明细 |
| 转化漏斗 | ⚠️ | 缺加购→下单粒度 |
